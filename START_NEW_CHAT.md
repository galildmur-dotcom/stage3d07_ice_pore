## Научный статус, который нужно сохранить

3D сферическая пора радиуса 1 мм в пресноводном льду; нестационарное термомеханическое нагружение, квазистатическая механика; E/ED/EDV и CONST/VAR; R/tz/y20; j6/jpeak/j_safety; GH3 в общей постановке. **Текущая серия:** EDV_VAR, R, ξ=0, горизонт 900 с, область B6, аналитические геометрические производные `ANALYTIC_TET10`.

**Решение P10AO:** прямая и сопряжённая задачи **внутри каждого FEM-расчёта на одной сетке**; сравнение полных согласованных расчётов между сетками разрешено, межсеточное сопряжение отложено. **Пространственная сходимость `D_R jpeak` не доказана.** Малые невязки, совпадение FD/adjoint и близость интегралов не заменяют оценку пространственной ошибки. Требуется аудит геометрии/квадратуры, QP, теплового/механического сопряжения и большой компенсации разнознаковых локальных/компонентных вкладов.

**Новый факт P10BE:** H2 `dt=150/75/50/25 с`, 6/12/18/36 шагов, общий горизонт 900 с; `D_R jpeak = 2.3396363 / 2.3332270 / 2.3345022 / 2.3378099 м⁻¹` — ряд немонотонен. Для двух близких слоёв 200 радиально-полярных ячеек дают коэффициент компенсации различий 150−25 с **≈11.01**, а 50−25 с **≈102.26** (малый знаменатель; не оценка погрешности). В полярных поясах `|μ|≥0.8` сосредоточено **≈94.24%** суммы абсолютных различий 150−25 при **19.49%** QP. Полярные балансы по четырём временным шагам проверены с невязкой ≤`3.33e−16 м⁻¹`. Манифест Δt=25 с подтверждает `completed`, exit 0, 900 с, SHA сетки совпадает с P10BD; `.exe` P10BE — другая цель с иным SHA; Git SHA сборки `UNKNOWN`. Полученный [`P10BE_RESULT.txt`](https://github.com/galildmur-dotcom/stage3d07_ice_pore/blob/research/p10bb-w5b2-20261118/research/evidence/P10BE_H2_20261118/input/P10BE_RESULT.txt) имеет `P10BE_H2_DT25_COMPARE_OK`; независимая проверка даёт 155/200 ячеек и 14/20 радиальных интервалов с уменьшением абсолютной разности при переходе от 75−50 к 50−25 с, но локальное L1 уменьшается лишь на 5.55%.

## Что делать в начале нового чата

1. Открыть **этот файл**, затем **рабочую ветку** GitHub и ссылки выше. Проверить актуальный HEAD, важные отчёты P10AZ/P10BA/P10BB/P10BD/P10BE и наличие свежих коммитов после 19.11.2026; не доверять заранее известному короткому SHA как «последнему».
2. **P10BE манифест, сравнительный `P10BE_RESULT.txt` и все четыре summary/radial/cell/polar CSV получены и проверены.** Не запрашивать эти файлы повторно. Для установления точного Git SHA Windows-бинарника нужны отдельные build-данные, которых в автоматическом manifest нет; не приписывать произвольный SHA. Новый многочасовой FEM и гигабайтные истории пока не требуются.
3. **P10BG Windows SHA уже проверены: 7/7, повторный экспорт/патч/перенос не нужен.** Исследователь прислал `P10BG_LOCAL_SOURCE_REPORT.txt` и `P10BG_SHA256.csv`, оригиналы архивированы в `research/evidence/P10BG_LOCAL_SOURCE_20261119/input/`. На ПК локальный `master`, HEAD `c0498f6...`, пять изменённых и два новых исходника; эти же семь точных файлов уже в архиве GitHub. **Следующий этап P10BH** — в существующем Qt Creator MinGW Release собрать и запустить без FEM цели `stage3d10v_analytic_shape_unit`, `stage3d10y_analytic_shell_unit`, `stage3d10be_temporal_unit` (без аргументов) и `stage3d10be_temporal_polar_audit` (только `--selftest`), после чего запросить только три небольших лога сборки, unit и selftest. Полный протокол `research/evidence/P10BG_LOCAL_SOURCE_20261119/P10BH_WINDOWS_UNIT_CHECK_20261119.md`. Затем отдельно согласовать адресный **локальный Git-коммит семи файлов** и синхронизацию remote. Не делать слепой `git pull`, merge, patch, reset или старый PORE push; историческим EXE не присваивать новый SHA.
4. Следующий научный вопрос — объяснить сосредоточение локальных временных и межсеточных изменений в приполюсных поясах. Сопоставить P10BE с **сеточной** P10BB и P10AZ по сопоставимым физическим окнам, времени и нормировкам; нельзя объявлять отношение величин временной и пространственной разностей отношением ошибок. Подготовить проверяемый минимальный опыт с контролем компонентов, QP/объёма, температуры и сопряжённых полей; до нового многочасового FEM исследовать уже имеющиеся CSV.
5. По результатам анализа внести научные выводы в Git: `docs/RESEARCH_LOG.md`, `article/EVIDENCE_REGISTER_CURRENT.md`, при утверждённом новом решении `docs/DECISIONS.md`, и отчёт эксперимента; сохранять оговорки, исходные CSV, manifests и SHA. Не переписывать исторические версии без причины.
6. При программных изменениях сохранять Windows/Qt Creator C++20 MinGW Release. Для проверки текущих Windows исходников предназначен новый только читающий **P10BG ONE CLICK** (уже успешно опробован на Windows; 7/7 SHA), а P10BF ONE CLICK ранее использовался для экспорта; исторический `PORE_GIT_TOOLS/01_APPLY_PATCH_AND_PUSH` нельзя применять к научной ветке без проверки `git remote -v`, `git status` и пути миграции. Для новых патчей тестировать `git apply --check`, указывать цель Qt Creator, время/ОЗУ на **i7-7700K / 64 ГБ / 4 потока** и только нужные выходы.
