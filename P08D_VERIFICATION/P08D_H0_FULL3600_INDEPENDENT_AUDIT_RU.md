# Stage 3D-08D — независимый аудит GH3, H0, 3600 с

**Дата:** 20 октября 2026 г.  
**База:** пользовательские `P08D_STATUS.txt`, `P08D_SENSITIVITIES.csv`, `P08D_NODES.csv`, `P08D_SAMPLES.csv`, сохранённые рядом в `H0_GH3_t3600_files/`.  
**Область проверки:** арифметика GH3 и внутренняя согласованность экспортированных таблиц, *не* независимое воспроизведение полей FEM. Для перепроверки используется необязательный скрипт `tools/p08d_audit.py`, не участвующий в расчётном C++-приложении.

## 1. Полнота и параметры

- `P08D_STATUS.txt`: `SUCCESS`, H0, `dt=300 с`, `tend=3600 с`, моды `R,tz,y20`.
- 9 строк узлов GH3 и 18 строк FEM-выборок (3 моды × 2 знака × 3 стохастических узла), каждая с 12 шагами.
- 18 записей `source=LOCAL_FEM`, **0** `source=EXTERNAL_XI0`: в данном прогоне внешнее наследование результатов при ξ=0 не применялось.
- В каждой из шести пар «мода × знак» значение экспортируемого `mesh_fnv64` совпадает для всех трёх узлов ξ. При этом сами исходные сетки и поля в комплекте отсутствуют, следовательно, хеши проверены только на согласованность *записей*.
- GH3 для стандартного нормального закона: `ξ=(-sqrt(3),0,+sqrt(3))`, `w=(1/6,2/3,1/6)`; сумма весов равна единице.

## 2. Моменты и производные

Для каждой моды и каждого узла через `j(+δ,ξ)`, `j(-δ,ξ)` при `δ=5 мкм` независимо вычислены:

\[
 M_\pm=\sum_k w_k j_{\pm,k},\quad
 V_\pm=\sum_k w_k(j_{\pm,k}-M_\pm)^2,
\]
\[
 D_aM=(M_+-M_-)/(2\delta),\quad
 D_aV=(V_+-V_-)/(2\delta).
\]

Производная дисперсии также проверена посредством устойчивой ковариационной формулы:

\[
 D_aV=2\sum_k w_k(j_{\mathrm{mid},k}-M_{\mathrm{mid}})
 (D_a j_k-D_a M),\quad
 j_{\mathrm{mid},k}=(j_{+,k}+j_{-,k})/2.
\]

| Мода | D E[j6], м^-1 | D Var[j6], м^-1 | D j6(ξ=0), м^-1 | Относительное отличие D E от D j6(0) |
|---|---:|---:|---:|---:|
| R | +0.110093242568 | +0.000220672534285 | +0.106678779457 | +3.2007% |
| tz | -0.000395909557048 | -0.000000818686964677 | -0.000381545000802 | +3.7648% по модулю |
| y20 | -0.019964438240774 | -0.000040661574550970 | -0.019300277471698 | +3.4412% по модулю |

`M_mid` для трёх мод в интервале `0.008582322750631 ... 0.008582325360009`; `V_mid` в интервале `8.686737043098e-6 ... 8.686742276559e-6`. Разброс трёх значений `M_mid` составляет `2.609378e-9`, что согласуется с вычислением по парным слабо возмущённым геометриям.

Контрольная оценка стандартного отклонения GH3: `σ≈0.0029473`; коэффициент вариации — `34.34%`. Центральный узел при `ξ=0` имеет `j6_mid≈0.008304336`, что меньше GH3-ожидания приблизительно на `3.35%` (относительно значения в центральном узле).

Все исходные девять `D_j6` восстановлены по центральной разности; обе формулы `D_aV` дали один результат с точностью округления double. *Это внутренняя численная проверка, а не доказательство физической точности дискретной модели.*

## 3. Физическая интерпретация и ограничения

При `ξ=-sqrt(3)` окружающая среда холоднее, чем при `ξ=+sqrt(3)`; для всех мод абсолютная производная `D j6(ξ)` убывает в этом порядке. Во всех узлах знак производной одинаков: для `R` положительный, для `tz` и `y20` отрицательный. Моды не одинаково нормированы: сравнивать абсолютные модули как единый рейтинг нельзя.

Дисперсия чувствительна к геометрии, следовательно, ограничиваться производной `j6(0)` при исследовании стохастической формы **нельзя**. Однако единственная грубая сетка H0, один временной шаг `dt=300 с`, единственная амплитуда `δ=5 мкм` и GH3 не являются независимой проверкой сеточной, временной, конечно-разностной или вероятностной сходимости.

Предыдущее Stage 3D-08C на тонкой сетке H4 для `tz` и `y20` при `dt=300 с` дало `-0.0005090564` и `-0.0261416577` (при ξ=0), заметно отличающиеся от нынешнего H0 ξ=0. Для `R` результат H4 `+0.0971812339` вычислялся с `dt=150 с`, поэтому различие с H0 включает и изменение шага времени. Эти данные подтверждают необходимость пространственной проверки, но не являются готовыми стохастическими оценками для H4.

В четырёх небольших отчётных файлах нет невязок CG/Newton, журналов отдельного решения или подробных VTU-полей; эти качества расчёта *не проверялись независимо*.

## 4. Проверки скрипта

Команда, исполняемая в Python 3 (только стандартная библиотека):

```shell
python tools/p08d_audit.py P08D_VERIFICATION/H0_GH3_t3600_files
```

Результат: `P08D AUDIT PASS`, 18 исходных записей, контроль всех производных и моментов GH3. Проведены и два отрицательных теста: намеренное искажение производной одного узла и уменьшение числа шагов одной траектории с 12 до 11. Оба корректно отклонены проверкой. При этом Python **не требуется** для запуска исходного FEM-кода в Qt Creator.

## 5. Рекомендуемый следующий расчёт — H2, GH3, 3600 с

Для отделения грубой пространственной ошибки H0 от действительной стохастической чувствительности выполнить **только сетку H2**, не повторяя H0. Прежний исполняемый файл уже поддерживает такой запуск: изменение C++-кода не требуется.

- Цель в Qt Creator: **`stage3d08d_H0_gh3`** (несмотря на `H0` в названии цели, параметр `--mesh` выбирает H2).
- Конфигурация: **Desktop MinGW Release**.
- **Единственная строка аргументов**:

```text
--mesh H2 --modes R,tz,y20 --dt 300 --tend 3600 --quad 3 --delta-um 5 --threads 4
```

Каталог результата:

```text
Stage3D07/LOCAL_RUNS/SHAPE_STAGE08/P08D/H2_dt300_q3_t3600_EDV_VAR_cutoff5p000mm_delta5p000um_modesR-tz-y20/
```

Прислать **только 4 файла**: `P08D_STATUS.txt`, `P08D_SENSITIVITIES.csv`, `P08D_NODES.csv`, `P08D_SAMPLES.csv` (все из каталога H2). Не присылать полные `LOCAL_RUNS`, VTU и сетки. Результаты H0/08C не удалять. В случае ошибки — текст с `P08D_ERROR` из Qt Creator и статусный файл; не удалять незавершённую ветвь.

После H2 оценить сеточную стабилизацию GH3. Если расхождение велико — переход к H3 и/или целевым расчётам H4; отдельно затем проверить влияние `δ`, `dt` и точность GH3 сравнением с более высоким порядком вероятностной квадратуры. **Не интерпретировать H0 как точную непрерывную производную.**
