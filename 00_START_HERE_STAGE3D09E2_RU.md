# Stage 3D-09E2: контрольные состояния EDV по 6 часам, с восстановлением истории

## Назначение

В режиме `--storage compact` (новая независимая кампания P09E) `restart.bin` по умолчанию записывается **после завершения временного шага, когда прошло не менее 6 часов от предыдущей записи/начала механической траектории**, и **обязательно на последнем шаге**. Это уменьшает объём дискового вывода при HP8 без изменения температуры, механики, шагов Δt, конститутивной модели и функционалов.

`--checkpoint-hours 6`: явно выбрать 6 часов. `--checkpoint-hours 0`: сохранять после каждого шага (исторический режим). Допустимы значения 0–240; при прямом запуске `stage3d06_spatial` по умолчанию остаётся 0. В режиме `--storage legacy` запускатель по умолчанию также сохраняет после каждого шага.

Реализовано только на границах **законченного** шага: это не прерывание PCG/Ньютона каждые ровно 6 часов. При аварии теряется работа с момента последней сохранённой контрольной точки, потенциально до 6 часов плюс длительность текущего шага и записи.

`restart.bin` остаётся совместимым по формату со Stage3D09D5. Для дальнейшей диагностики `--postprocess-only` конечное состояние **всегда** сохраняется. Для будущей сопряжённой задачи редкие checkpoint'ы потребуют воспроизведения пропущенных прямых состояний или расширенной стратегии контрольных точек.

## ВАЖНО: согласование научных CSV после сбоя

При промежутке в 6 часов старые CSV могут содержать больше шагов, чем последний валидный `restart.bin`. На `--resume` программа сначала восстанавливает состояние, затем **проверяет и обрезает** `time_series.csv`, `max_location.csv`, `polar_caps_history.csv`, `P09B_functionals_history.csv` до времени checkpoint. Для `G06_campaign.csv` и включённых профилей удаляются только более поздние записи той же комбинации реологии и модуля. После этого недостающие шаги вычисляются заново. Старые завершённые P09C/H4/HP не затрагиваются.

Незавершённый `restart.bin.part` нельзя использовать для возобновления. Действующий механизм chunked-IO Stage09D5 сохранён.

## Установка в Windows/Qt Creator

1. Остановить расчёты. Распаковать PATCH поверх родительского каталога проекта (`C:\Users\Admin\Downloads`), сохранив `Stage3D07\LOCAL_RUNS`.
2. Открыть Qt Creator → CMake Reconfigure → **Desktop MinGW Release**.
3. Собрать цель `stage3d09e2_checkpoint_test`, запустить **без аргументов**. Ожидается: `P09E2_CHECKPOINT_TEST_OK policy=6h rollback=4/6 final=always`.
4. Собрать `stage3d09c_shape_three` (автоматически подтянет `stage3d02_thermal` и `stage3d06_spatial`). Проверить самотест запускателя `--selftest`.
5. Сначала подтвердить на H0 короткую P09E-кампанию и затем планировать HP8. HP8 не запускать до проверки Windows-сборки.

Короткая Windows-проверка:

```
--mesh H0 --modes y20 --laws EDV --moduli VAR --dt 300 --tend 300 --quad 3 --peak-p 8 --delta-um 5 --cutoff-mm 5 --threads 4 --reuse-p08d off --storage compact --mechanical-vtu none --checkpoint-hours 6
```

Полная HP8 ПОСЛЕ теста:

```
--mesh HP8 --modes y20 --laws EDV --moduli VAR --dt 300 --tend 3600 --quad 3 --peak-p 8 --delta-um 5 --cutoff-mm 5 --threads 4 --reuse-p08d off --storage compact --mechanical-vtu none --checkpoint-hours 6
```

Кампания HP8: `Stage3D07\LOCAL_RUNS\SHAPE_STAGE09\P09E\HP8_dt300_q3_t3600_GH3_p8_delta5p000um_modesy20_lawsEDV_EVAR`.

## Пройденные тесты

- Автономный C++20 тест расписания и аварийного отката 6→4 строк истории: SUCCESS.
- Clang++ C++20: синтаксический анализ и линковка модифицированных `stage3d06_spatial.cpp` и `stage3d09c_shape_three.cpp` на Linux: SUCCESS, без ошибок.
- Реальный Windows MinGW и полный HP8 пока не тестировались. Дополнительное сквозное FEM-тестирование выполняется отдельно; время упрощённой Linux-сборки нельзя сравнивать с оптимизированной Windows Release.

Сохраняйте финальные `restart.bin` для требуемой постобработки. Периодичность шесть часов не заменяет полноценную стратегию хранения всей истории для будущего дискретного сопряжённого решателя.
