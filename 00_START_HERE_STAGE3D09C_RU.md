# Stage 3D-09C — геометрические производные трёх функционалов (23.10.2026)

## Назначение

Новая цель `stage3d09c_shape_three` объединяет проверенные режимы Stage 3D-08D
(сферические моды R, tz, y20, центральные разности, GH3) с тремя функционалами
Stage 3D-09B (`j6`, `jpeak`, `jen`). Исходный тепловой и механический решатель не меняется.

Для фиксированной материальной модели, одной сетки и трёх мод проводится 18 механических
траекторий: 3 моды × 2 знака δ × 3 стохастических узла. Во всех траекториях
сразу вычисляются все три функционала. **Номинальный расчёт для FD моментов
не нужен**: производные GH3 дисперсии получаются из пар значений плюс/минус.

## Установка

Использовать исправленную Stage 3D-09B с рабочим `P09B_SELFTEST_OK`.
Из патча распаковать каталог `Stage3D07` поверх `C:\Users\Admin\Downloads\Stage3D07`.
`LOCAL_RUNS` не удалять. При конфликте файлов заменяются только CMakeLists.txt и новые
файлы Stage09C. В Qt Creator пере-конфигурировать CMake при необходимости.

**Цель:** `stage3d09c_shape_three`; комплект **Desktop MinGW Release**.

1. Запустить `--selftest` — ожидается `P09C_SELFTEST_OK`.
2. Первый исследовательский запуск:

```text
--mesh H2 --modes R,tz,y20 --laws EDV --moduli VAR --dt 300 --tend 3600 --quad 3 --peak-p 8 --delta-um 5 --cutoff-mm 5 --threads 4 --reuse-p08d auto
```

Если исходники P08D находятся в `LOCAL_RUNS`, программа проверит подпись
геометрии, совпадение хеша возмущённой сетки, временных параметров,
сценария ξ и наличие всей тепловой истории. Только после этих проверок
использует температуру из P08D. **Старые механические траектории P08D не
используются:** в них нет историй двух новых функционалов.

Если нужные температурные файлы отсутствуют, `auto` вычисляет их самостоятельно,
не перезаписывая P08D. Строгий режим `--reuse-p08d require` допускается только
при полной совместимости всех нужных P08D-узлов; проверка выполняется до записи
новых файлов, в противном случае запуск завершается ошибкой.

Путь к результатам:

```text
C:\Users\Admin\Downloads\Stage3D07\LOCAL_RUNS\SHAPE_STAGE09\P09C\H2_dt300_q3_t3600_GH3_p8_delta5p000um_modesR-tz-y20_lawsEDV_EVAR\
```

Для следующего анализа нужны только:
- `P09C_STATUS.txt`
- `P09C_SENSITIVITIES.csv`
- `P09C_NODES.csv`
- `P09C_SAMPLES.csv`

## Формулы

Пусть `a` — одна из мод R, tz, y20, `δ=5·10^-6 м`, `ξ_k = -√3, 0, √3`,
`w_k=1/6, 2/3, 1/6`, `j_k^± = j(a±δ, ξ_k)`.

`D_a M = Σ w_k (j_k^+ - j_k^-)/(2δ)`.

`D_a V = (V^+ - V^-)/(2δ)`; проверяется также точно равная ей дискретная
ковариационная формула `D_a V=2 Σ w_k (j_k^mid - M_mid) D_a j_k`,
где `j_k^mid = (j_k^+ + j_k^-)/2`.

Все функционалы безразмерные; все геометрические производные имеют единицы м^-1.
Принята прежняя конвенция нормали: из поры в лёд. Положительный R увеличивает пору.

## Ограничения

- Это центральные конечные разности, не полноценный сопряжённый градиент формы.
- Первое исследование ограничено EDV/VAR, GH3, H2, Δt=300 c, p=8.
- Для p=4/12 текущий решатель потребует отдельные механические траектории;
  одновременное накопление трёх степеней p ещё не реализовано.
- Режим `--report-only` только проверяет и читает готовые данные.
- `P09C` никогда не изменяет папки `P08D` или `P09B`.
- В случае частичного запуска сохраняются охранные подписи, но статус `SUCCESS`
  устанавливается только после завершения всех выбранных случаев.

## Планы проверки

1. Сопоставить производные `j6` на H2 с `P09C_VERIFICATION/P08D_H2_GH3_REFERENCE.csv`.
2. Рассчитать относительные чувствительности новых jpeak и jen.
3. Проверить пространственную и временную сходимость новых функционалов.
4. Затем выполнить геометрические производные других реологических моделей;
   перейти к дискретному сопряжённому решателю и полному поверхностному градиенту.
