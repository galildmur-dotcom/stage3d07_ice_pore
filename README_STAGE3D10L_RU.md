# Stage 3D-10L: полностью дискретная тепловая сопряжённая задача + EDV_VAR

## Для чего этот шаг

В предыдущем P10K производная по форме поры находилась как сумма:

1. механического частного вклада, вычисленного через сопряжённые переменные
   для полной истории EDV_VAR, при фиксированной истории температуры;
2. теплового вклада, для которого требовались **два дополнительных решения
   нестационарной задачи теплопроводности** на `H0+δ` и `H0−δ`.

В P10L второй вклад впервые вычисляется через *дискретную нестационарную
сопряжённую тепловую задачу* на **одной, исходной** сетке. Производные по
геометрии матриц ёмкости, теплопроводности и конвективной теплоотдачи
получены аналитическим дифференцированием отображений Tet10/Tri6 по
координатам узлов, включая криволинейные грани.

Искомое `dJ/ds` — производная функционала по метрам изменения формы в
направлении `y20` (или `R`, `tz`). Для проверки она сравнивается с *другой*
производной, найденной посредством двух полных нелинейных расчётов при
`s=±δ`, где `δ=5 мкм`. Величина `δ` — шаг верификации, а не шаг сопряжённого
метода.

В P10L механическое слагаемое всё ещё является **гибридным**: механические
частные производные по изменению координат сетки построены центральными
разностями локальных операторов при фиксированных состояниях и температуре.
Поэтому P10L не следует называть полностью аналитическим поверхностным
градиентом Адамара. Также пока **не реализован основной третий критерий
`j_safety`**; используется `jen` как контрольный функционал энергии.

## Прямое и сопряжённое уравнения теплопроводности

Прямая схема, точно совпадающая с проверенным Stage3D02:

`(M(s)+Δt K(s)) θ_n = M(s) θ_(n−1) + Δt b(s) a_n`, `θ_0=0`;

`M`: согласованная теплоёмкость, `K`: теплопроводность и Robin верхней
поверхности, `b`: тепловой поток той же границы. В P10L `s=0` соответствует
исходной сфере. Для температурного отклика механических функционалов
`q_n=∂J/∂θ_n` сопряжённые переменные удовлетворяют

`(M+Δt K)^T ψ_n = M^T ψ_(n+1) − q_n`, `ψ_(N+1)=0`.

Искомый температурный вклад вычисляется без тепловых запусков на `±δ`:

`D_s J|heat = Σ_n ψ_n^T [ M'_s(θ_n−θ_(n−1)) + Δt K'_s θ_n − Δt b'_s a_n ]`.

`M'_s`, `K'_s`, `b'_s` вычисляются в квадратурных точках по производным
якобиана и площади треугольных граней. Вектор геометрического направления
узлов берётся из двух сеток с `s=±δ`, полученных Stage3D08, но матрицы
`M'_s`, `K'_s`, `b'_s` **не получают разностным вычитанием**. В сетке H0
это сохраняет исходные ограничения на B6 и все метки Gmsh.

## Установка в G:/ildar/Stage3D07

Архив — минимальное дополнение к уже работающему P10K:

1. Перенести **три файла** из папки `src/` архива в папку `src/`
   существующего проекта:
   - `stage3d10k_h0_coupled_pilot.cpp` — заменяет прежнюю версию, в которую
     добавлена только защитная директива для повторного использования кода;
   - `stage3d10l_thermal_adjoint.hpp` — новый тепловой оператор и адъюнкт;
   - `stage3d10l_h0_full_thermal_adjoint.cpp` — новая проверочная программа.
2. Добавить текст `PATCH_CMAKE_Stage3D10L.txt` в **конец действующего**
   `CMakeLists.txt`, не удаляя предыдущих целей.
3. Qt Creator → Configure → собрать только
   **`stage3d10l_h0_full_thermal_adjoint`** в конфигурации
   `Desktop_MinGW_Release`.

Нужны ранее установленные P10H, P10I, P10K и исполняемые
`stage3d08_geometry.exe`, `stage3d02_thermal.exe`. Путь к исходникам для
механического модуля определяется макросом CMake в момент сборки.
На Windows вспомогательные программы запускаются напрямую через `_wspawnv`
(исправление P10K), без `cmd.exe`.

## Как проверять в Qt Creator

**Сначала** синтетическая регрессия, аргументы: `--selftest` (секунды).

**Затем** тепловой H0-предтест **без механики**, Arguments одной строкой:

```
--preflight --mesh G:/ildar/Stage3D07/meshes/H0.msh --out G:/ildar/Stage3D07/LOCAL_RUNS/P10L_H0_HEAT_PREFLIGHT_20261106 --steps 3 --dt 300 --mode y20 --delta-um 5 --threads 4
```

Ожидаемая строка `P10L_THERMAL_ONLY_ADJOINT_OK`. Она включает три
воспроизведённых прямых тепловых истории только для **верификации**,
аналитическую производную тепловых операторов, тепловой адъюнкт и независимую
конечную разность. Время на ПК i7-7700K: ориентировочно 5–30 секунд,
память менее 2 ГБ (оценка; фактические показатели Windows проверить).

**После успешного предтеста** полная проверка трехшаговой истории:

```
--mesh G:/ildar/Stage3D07/meshes/H0.msh --out G:/ildar/Stage3D07/LOCAL_RUNS/P10L_H0_y20_3step_20261106 --steps 3 --dt 300 --mode y20 --delta-um 5 --threads 4
```

Ожидаемая строка `P10L_FULL_THERMAL_ADJOINT_OK` при выполнении допусков.
Оценка на пользовательском ПК: **5–15 минут** (сопоставима с P10K, так как
включена независимая прямая ±δ-проверка механики). Для пилотной проверки H0
VTU не записываются; EDV checkpoint хранится компактно и восстанавливается
побитно. Новые папки `--out` не должны существовать до запуска: программа
не перезаписывает существующие результаты.

## Что прислать

- строку `P10L_FULL_THERMAL_ADJOINT_OK` (или `FAIL`) из Application Output;
- **один** файл
  `G:/ildar/Stage3D07/LOCAL_RUNS/P10L_H0_y20_3step_20261106/P10L_H0_THERMAL_ADJOINT.csv`;
- при ошибке — последние 15–20 строк Application Output.

Не нужны архив всего проекта, сетки, полные истории, файлы checkpoint и VTU.

## Как интерпретировать CSV

`mechanical_partial_per_m` — механический частный вклад при неизменной
температуре; `thermal_adjoint_per_m` — новый тепловой сопряжённый вклад;
`thermal_chain_reference_FD_per_m` — **только независимая проверка**
температурного вклада; `total_adjoint_per_m` — сумма двух слагаемых;
`full_FD_per_m` — независимые *полные* EDV_VAR истории на изменённых сетках.
Два последних столбца с невязками — относительные невязки сопряжённых
механической и тепловой задач.

Внутренние критерии успешного трёхшагового пилота: максимальная разница
полной производной с разностями менее 0,5%, теплового слагаемого менее 1%,
максимальная невязка механического адъюнкта менее `1e−5`, теплового —
менее `1e−7`. Это тестовые допуски для **H0**, а не доказательство точности
на сеточно-сходящемся решении. Перед публикацией по-прежнему нужны
пространственная/временная сходимость именно **нового градиента**, GH3,
сравнение E/ED/EDV и `j_safety`.
