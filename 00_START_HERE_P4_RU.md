# Stage 3D-06-P4 — блочный IC(0) в полном FEM-проекте

Это **полная самостоятельная папка проекта C++20/CMake**: Stage 3D-06-P2 + P3 + P3.1 + экспериментальный P4.
Назначение: научное сравнение предобусловливателей; не изменяет физическую модель E/ED/EDV,
случайное охлаждение, сетки H0–H4, геометрические нормировки или функционал Psi6.

## Быстрый запуск в Qt Creator (Windows / MinGW)

1. Распаковать ZIP в отдельную папку `Stage3D06P4`.
2. В Qt Creator: **File → Open File or Project → CMakeLists.txt** этой папки.
3. Выбрать имеющийся комплект MinGW, конфигурацию **Release**, выполнить Configure/Build.
4. Выбрать цель **`stage3d06_p4_qt_H0_ic0`** и нажать **Run**. Аргументы **не требуются**.
5. Поля температуры создаются автоматически; затем запускается механика EDV/VAR, H0,
   dt=tend=300 с, четыре потока при сборке OpenMP; без OpenMP используется 1 поток.
6. Исходные результаты Jacobi/P3 не затрагиваются. Выход:
   `LOCAL_RUNS_OPTIMIZED/benchmark_p4_ic0/H0_dt300_q3/`

Отправить после запуска **ровно четыре файла**:
- `QT_RUN_STATUS.txt`
- `mechanics/profile_cg.csv`
- `mechanics/profile_per_step.csv`
- `mechanics/G06_campaign.csv`

Для принудительного пересчёта в параметрах запуска можно указать только `--clean`.
**Не запускать H4 с IC(0)**: ускорения пока не обнаружено. Для H4 сохраняется Jacobi.

## Ключевые изменения

- `src/p4_block_ic0.hpp`: явный нулевой шаблон заполнения BCSR 3x3;
  factorization `M=(I+L)D(I+L)^T` с SPD-проверками каждого диагонального 3x3 блока.
- `src/mechanical.cpp`: `BCSR::ic0`, построение факторизации на текущей матрице Ньютона,
  вызов в PCG и учёт затрат setup/apply.
- `src/spatial_reology.cpp`: новый `--preconditioner ic0`, профиль и метки CSV.
- `src/qt_benchmark_p.cpp`: отдельная цель Qt Creator для P4.
- `tests/p4_ic0_unit.cpp`: численная точность, симметрия, положительная определённость,
  частичные закрепления и диагностика недопустимого опорного блока.
- `scripts/p4_test_h0.py`: строгое физическое сравнение всех шести реологий с checkpoint,
  тест доступен через CTest (может длиться несколько минут).

Варианты `jacobi`, `sgs`, `mcsgs`, `mcsgs-fast` полностью сохранены.
Пользователь не должен изменять исходники для выбора Jacobi: альтернативная цель
`stage3d06_benchmark_p2_projected` либо параметр `--preconditioner jacobi`.

## Верификация здесь (Linux GCC Release, 4 потока OpenMP)

- Полная сборка CMake: PASS, включая прежние цели.
- 10 контрольных тестов CTest P2/P3/P3.1/P4: PASS.
- Отдельная сборка без OpenMP: PASS; 3 IC0-теста + Qt dry-run PASS.
- Полный H0 EDV/VAR: PASS; 302 CG против Jacobi 842 (обычный допуск `2e-7`).
- H0 E, ED, EDV × CONST, VAR: 6/6 физические сравнения и checkpoint PASS
  (с ужесточёнными допусками). Обратитесь к `P4_VERIFICATION/p4_reg_debug.log`.
- Невязки конечной нелинейной системы достигнуты; `Psi6` и напряжения совпали.

### Производительность H0 с одинаковой сборкой и входными данными

| Метрика | Jacobi | IC(0) |
|---|---:|---:|
| CG итерации | 842 | 302 |
| PCG, сек | 0.569 | 1.756 |
| Предобусловливатель: setup, сек | 0.0036 | 0.0591 |
| Предобусловливатель: apply, сек | 0.0383 | 1.4534 |
| Механика (шаг), сек | 1.488 | 2.559 |

Результат: **IC(0) пока медленнее Jacobi** несмотря на меньшее число итераций.
Треугольные проходы последовательные, без распараллеливания по уровням/графу.

### H2: ограничение эксперимента

Пробный расчёт H2 (70389 узлов, 50486 Tet10; EDV/VAR, 4 потока) с IC(0)
**не завершился за контрольные 140 секунд**: процесс дошёл до второй
итерации Ньютона, но итоговых CSV/checkpoint не создано.
Это **не подтверждение численной ошибки**, однако скорость на H2 не доказана.
См. `P4_VERIFICATION/H2_IC0.log`. Не выдавать промежуточный расчёт за успешный.

### SPD и ограничения

IC(0) требует SPD исходной механической матрицы с корректно заданными закреплениями.
Внутри факторизации зафиксированные DOF исключены симметрично, единицы ставятся
на соответствующей диагонали; алгоритм сохраняет нулевые закреплённые компоненты.
Неположительный опорный блок приводит к явному исключению **без скрытого перехода
на Jacobi**. Такой сбой следует расследовать, а не маскировать.
Симметрия предобусловливателя проверена отдельными тестами. Время применения
не распараллелено; для CPU i7-7700K результат нужно перепроверить локально.

Включённые файлы `P2_VERIFICATION`, `P3_VERIFICATION`, `P06_VERIFICATION` — исторические
данные предыдущих версий. Новые результаты P4 находятся только в `P4_VERIFICATION`.
