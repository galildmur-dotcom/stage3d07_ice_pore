# Stage 3D-10D — нестационарная дискретная сопряжённая задача

Дата: 04.11.2026. **Предусловие:** P10C_TET10_GLOBAL_ADJOINT_OK в Qt Creator.

## Назначение

Независимая проверка сопряжённого алгоритма для целой последовательности квазистатических механических равновесий с переносом внутренних переменных $z_n$. Для каждой модельной конфигурации выполняются 12 шагов с $\Delta t=150$ с и 27 точками интегрирования на каждом из двух связанных элементов Tet10.

На каждом шаге решается нелинейная задача равновесия методом Ньютона. В обратном ходе решается сопряжённая система с **транспонированной** касательной, а сопряжённые переменные истории передаются назад во времени.

Сопоставляются две полные производные выбранного тестового интегрального функционала:

- по амплитуде заданной истории узловых температур — аналитический сопряжённый метод против прямых повторных прогонов с центральными разностями;
- по параметру изменения формы маленькой сетки — сопряжённое вычисление с **численной частной производной геометрического блока** против прямых повторных нелинейных прогонов с изменённой сеткой.

Выполняется контрольное отключение передачи сопряжённой реологической памяти. Это должно резко ухудшить правильность градиента для ED и EDV.

## Патч

- `tests/stage3d10d_transient_adjoint.cpp` — полный автономный тест нестационарной задачи.
- `PATCH_CMAKE_Stage3D10D.txt` — добавка к вашему исходному `CMakeLists.txt`.
- `STAGE3D10D_SCIENTIFIC_NOTE_RU.md` — постановка, формулы, анализ и ограничения.

Новый тест использует уже установленные файлы `src/mechanical.cpp`, `src/stage3d10c_tet10_global_adjoint.hpp`, `src/stage3d10b_edv_linearization.hpp` и зависимости предыдущих этапов. Не заменяйте существующие исходники, сборку, папку с результатами и checkpoint.

## Точный запуск на Windows

1. Распакуйте патч и скопируйте только **новый** файл теста в папку `tests` вашего действующего Qt/CMake-проекта.
2. Добавьте содержимое `PATCH_CMAKE_Stage3D10D.txt` в конец действующего `CMakeLists.txt` **один раз**.
3. В Qt Creator выберите конфигурацию **Desktop MinGW Release**, выполните повторную конфигурацию CMake и сборку цели `stage3d10d_transient_adjoint`.
4. Запустите именно цель `stage3d10d_transient_adjoint`.

**Аргументы:** пустая строка.

**Рабочий каталог:** стандартный каталог сборки Qt Creator. Пути к сеткам и температуре не требуются: тест сам создаёт крошечную Tet10-сетку.

**Ожидаемое время на i7-7700K, 64 ГБ:** 20–120 с компиляция; ориентировочно 1–10 с выполнение теста. Оценка, не измерение на Windows. Памяти требуется немного, не создаются VTU, большие CSV или checkpoint.

**Пришлите только** заключительную строку вывода программы, начинающуюся с `P10D_TRANSIENT_ADJOINT_OK`; при ошибке — текст ошибки. Новые тяжёлые расчёты HP4/HP8 не нужны.

## Результат на стороне разработчика (GCC/C++20, Release)

```
P10D_TRANSIENT_ADJOINT_OK models=6 steps=72 newton_iterations=131 worst_temperature_gradient_rel=1.893489429993e-09 worst_geometry_gradient_rel=1.370941348760e-07 worst_adjoint_equilibrium_rel=6.210917432220e-13 ablated_history_temperature_rel=1.462377075947e+00 ablated_history_geometry_rel=8.410872079263e-01
```

Число `steps=72` относится к **основным** траекториям (6 моделей × 12 шагов). Для независимой проверки выполняются ещё четыре полных прямых траектории на каждую модель; поэтому весь тест содержит 360 прямых временных шагов. Полные истории на больших HP-сетках в памяти хранить нельзя: для промышленного варианта необходима стратегия контрольных точек и повторного воспроизведения состояний.

## Важная граница доказанного

Это сквозная проверка **дискретного** сопряжения во времени на маленькой сетке и с специально выбранным линейным диагностическим функционалом. Для геометрии используется численная частная производная при фиксированном состоянии. Не реализованы аналитический поверхностный градиент формы и сопряжение нестационарного температурного МКЭ-решателя. Пока рано утверждать, что получен производственный shape-adjoint для функционалов $j_6$, $j_{\mathrm{peak}}$, $j_{\mathrm{safety}}$ в полной 3D-сфере.

После проверки на Windows следующий этап: заменить плотный тестовый решатель транспонированной системы на разреженный BCSR/PCG (с учётом корректного транспонирования), организовать воспроизводимый обратный проход с редкими checkpoint и добавить производные трёх утверждённых функционалов.
