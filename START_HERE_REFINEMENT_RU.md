# Stage 3D-06 — большая серия проверки сеточной и временной сходимости

Дата: 10.10.2026. Физическая постановка **Stage 3D-00 v4** не изменена: 3D лёд со сферической полостью, квазистатическое равновесие Candidate A, односторонне связанная теплопроводность, EDV, фиксированная наблюдательная сфера B6. Эта серия — **исследование прямой задачи**, не производные по форме и не GH3/GH5.

## 1. Что добавлено

- Новые **криволинейные Tet10 H3/H4**, сформированные Gmsh 4.15.2 из `gmsh/sphere_pore_B6_refined.geo`; исходные H0/H1/H2 оставлены без изменений.
- H3: 112198 узлов, 81891 Tet10; H4: 221782 узла, 164319 Tet10. Размер элемента у поры задавался `nearSize`: **0.190 мм** (H3) и **0.135 мм** (H4); фоновый `farSize=3.9 мм`. Это параметры поля размеров Gmsh, а **не** гарантированный реальный размер каждого элемента. 3D-область, B6 и физические теги — прежние.
- Новые независимые от сетки диагностические величины: среднее **положительного первого главного напряжения** в двух физических приполюсных областях (полярный полуугол 25°, радиальный интервал от 1.0 до 1.3 мм от центра полости). Интегрирование по точкам квадратуры; на дискретных сетках сама отсечённая область аппроксимируется квадратурой. Эти величины помещаются в `polar_caps_history.csv`. Старые `Psi6`/`PsiOmega` **не переопределены**.
- Нативные, не зависящие от PowerShell, Qt Creator цели запуска серии, с проверкой завершённости каждого сценария и безопасным продолжением через `restart.bin`.
- Отдельная цель **`stage3d06_convergence_report`** формирует сводные `CONVERGENCE_TABLE.csv`, `CONVERGENCE_PAIRS.csv` и `CONVERGENCE_STATUS_RU.md`. Полный расчёт при этом не запускается.

## 2. Запуск из Qt Creator на Windows

1. Сделайте резервную копию папки `LOCAL_RUNS` вашего текущего проекта, особенно старых H0/H1/H2.
2. Распакуйте **PATCH** прямо в корень каталога `Stage3D06`, согласившись заменить исходные файлы. В архиве уже есть H3/H4: Gmsh запускать отдельно не требуется.
3. Откройте прежний `CMakeLists.txt` в Qt Creator. Выберите **Desktop MinGW — Release** (не Debug). Выберите «Сборка → Запустить CMake», затем соберите проект.
4. Запустите **`stage3d06_campaign_plan`**: он быстро проверит наличие H3/H4 и составит `LOCAL_RUNS/REFINEMENT_CAMPAIGN/CAMPAIGN_PLAN.csv`. Действительных расчётов он не делает.
5. Запускайте по очереди **`stage3d06_campaign_phase1`**, затем **`stage3d06_campaign_phase2`**, затем **`stage3d06_campaign_phase3`**. Можно сразу выбрать **`stage3d06_campaign_full`** — все 16 сценариев последовательно.
6. После завершения любого этапа запустите **`stage3d06_convergence_report`**. Результаты — в `LOCAL_RUNS/REFINEMENT_CAMPAIGN/`.

**Важно:** qt-цели `stage3d02_thermal` и `stage3d06_spatial` запускать отдельно **не нужно**. Никаких аргументов, PowerShell, Python, Gmsh и внешних инструментов для штатного вычислительного запуска не требуется.

## 4. Как программа восстанавливается после прерывания

Запуская ту же цель повторно, программа проверяет наличие всех принятых шагов и совместимый checkpoint. Завершённые сценарии пропускаются. Недостроенная серия **продолжается**, а при частично сформированной тепловой истории этот этап пересчитывается заново. `QT_RUN_STATUS.txt` и `CAMPAIGN_STATUS.csv` позволяют понять, что реально завершилось. На полностью готовую кампанию нужен не статус «план составлен», а подтверждённые таблицы каждого сценария.

**Не удаляйте `LOCAL_RUNS`, `restart.bin` или `thermal` посреди расчёта!** Разные временные шаги и квадратуры сохраняются по разным папкам `H*_dt*_q*`.

## 5. Научная схема обработки

- Временная сходимость: для **одной сетки**, сравнивать 300→150→75→25 с, не только значение в 3600 с, но и всю историю Φ6 и первые 900 с.
- Пространственная сходимость: сравнивать H0→H4 при **одинаковых Δt, Q и модуле E**.
- Квадратура: на H3 сравнивать Q3/Q4 при 75 с. Q3 = 27, Q4 = 64 точки интегрирования в каждом Tet10; значения из QP max не обязаны совпадать, так как сам набор точек отличается.
- Дополнительные показатели: `polar_caps_history.csv` для сглаженных физически фиксированных областей около полюсов поры; `max_location.csv` и `top100_qp_max_3600s.csv` для экстремумов.
- Показатель j6 интегрируется составной формулой трапеций; при t=0 используется аналитическое значение гладкого положительного напряжения **7.5·10⁻⁷**, при нулевых механических напряжениях. Код отчёта не выводит «PASS по сходимости» автоматически: относительное совпадение двух чисел не доказывает нахождения в асимптотическом режиме.
- H3 и H4 различаются как ненестированные неструктурированные сетки. Для количественной экстраполяции по h потребуется определить физически осмысленный эквивалентный размер элемента у поры, а не просто использовать номер сетки.
- Парные CONST/VAR запускаются при идентичных геометрии, температурной истории и EDV-параметрах. GH-квадратуры и геометрические возмущения в этой кампании не исследуются.

## 6. Ресурсы и передача данных

Используется **CPU**, CUDA/GTX 1060 не требуется. Испытания на Windows / MinGW 13.1 у разработчика недоступны. Linux GCC: CMake собран, 40/40 CTest; H3/H4 прошли независимые геометрические тесты и H4 — тепловой пилот 300 с. Пробный полный механический запуск H3 не был завершён в ограничении времени команды; его не засчитываем.

На H4 EDV хранит состояния в миллионах точек квадратуры; предполагается 64-битный процесс и достаточный свободный диск (рекомендуется **не менее 40 ГБ** для всех временных VTU и контрольных точек; это запас, не измеренное требование). Расчёт на i7-7700K в самой тяжёлой очереди может занять **больше нескольких часов**; точный прогноз без измеренного пилота H3/H4 дать нельзя.

После очереди 1 прикрепите архив папки `LOCAL_RUNS/REFINEMENT_CAMPAIGN` и CSV `time_series.csv`/`polar_caps_history.csv` для H2 и H3; **VTU передавать необязательно**. После очередей 2 и 3 повторите для новых сеток. Файлы checkpoint сохраните локально.
