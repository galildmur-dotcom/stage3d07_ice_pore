# Stage 3D-09B — три функционала на одном прямом FEM-решении

**Дата:** 22 октября 2026 г.  
**Назначение:** физически согласованное сравнение E/ED/EDV × E_CONST/E_VAR при случайном охлаждении; подготовка к геометрическим производным и дискретному сопряжённому методу.

## Что добавлено

В решатель `stage3d06_spatial` добавлен необязательный режим `--functionals triple --peak-p 8`. Режим не меняет уравнения, конститутивные законы, шаги Ньютона, вычисление `Psi6` или формат ранее существовавшего файла `time_series.csv`. При включении режима рассчитываются три **пространственно-временных** безразмерных функционала:

1. **j6 (исходный)**: время усредняется трапециями с базовым значением при t=0 `7.5e-7`; пространственно — среднее `Psi6` в фиксированной B6 по классификации элементов (как было).
2. **jpeak (новый)**: `[ (1/tf) ∫_0^tf (1/|Ω6|) ∫_{Ω6} Σ_i positive(σ_i/σ_ref)^p dV dt ]^(1/p)`, p=8 по умолчанию, диагностические p=4,12. `positive(r) = (r+sqrt(r²+10^-6))/2`, полное пространственно-временное интегрирование проводится над **p-й степенью**, корень берётся **после** интегрирования.
3. **jen (новый)**: `(1/(tf |Ω6| ψ_ref)) ∫_0^tf ∫_{Ω6} free_energy dV dt`, где `free_energy` — **именно сохранённая механическая энергия** из `edv::update`, с историей внутренней деформации ED/EDV, не диссипация. `ψ_ref = σ_ref²/E_ref` — фиксированная для всех реологических моделей энергетическая шкала.

Опорные величины: `σ_ref = E_ref * alpha * 3 / (1-nu)` (исходная шкала `j6`) и `E_ref=9.5 ГПа`, `nu=0.35`, `alpha=149e-6/3`. Начальное напряжение нулевое, поэтому `jpeak` при t=0 имеет **ненулевой малый гладкий** стартовый момент `3*(0.0005)^p`; энергия при t=0 равна нулю.

**Важная методическая оговорка:** `jpeak` не есть настоящий максимум напряжения и не является критерием разрушения; он является его сглаженным регуляризованным приближением. Проверка зависимости от `p=4,8,12` понадобится перед финальными выводами.

## Новый исполняемый файл

Собрать **Release** в Qt Creator: `stage3d09b_three_functionals` (автоматически собирает `stage3d02_thermal`, `stage3d06_spatial`). Параметры первого пилотного расчёта:

```text
--mesh H0 --laws ALL --moduli ALL --xi-set GH3 --dt 300 --tend 300 --quad 3 --peak-p 8 --threads 4
```

**Следующая полная исследовательская серия** (не совпадает с пилотом):

```text
--mesh H2 --laws ALL --moduli ALL --xi-set GH3 --dt 300 --tend 3600 --quad 3 --peak-p 8 --threads 4
```

Для машины без OpenMP собрать с `-DSTAGE3D06P_OPENMP=OFF` и использовать `--threads 1`.

Каталог полной серии:

```text
Stage3D07/LOCAL_RUNS/MODEL_STAGE09/P09B/H2_dt300_q3_t3600_GH3_p8_lawsALL_EALL/
```

Пользователь возвращает только 4 сводных файла:

- `P09B_STATUS.txt`
- `P09B_COMPARISON.csv`
- `P09B_MODULUS_EFFECT.csv`
- `P09B_SCENARIOS.csv`

Поле `mean_jpeak` — математическое ожидание **уже извлечённого корня** из временного интеграла по каждой случайной траектории. Это не корень математического ожидания `peak_power`, и программы не должны их путать.

## Обратная совместимость, защитные проверки, повторное использование

- Прежняя цель `stage3d09a_models` остаётся без изменений. Новая P09B пишет в собственный каталог. Старые P08*, P09A не изменяются.
- Накопленные по времени данные двух новых функционалов отдельно записываются в `mechanics/<LAW>_<MOD>/P09B_functionals_history.csv`.
- `time_series.csv` с `Psi6` не меняется; `j6` из P09B в пилоте **точно совпал** с прежним P09A для шести моделей и трёх GH3-узлов.
- Повторный запуск P09B использует механические результаты только когда **все** требуемые CSV и контрольная точка прочитаны, и их параметры совместимы. Временная история новых функционалов должна содержать столько же строк, сколько механическая.
- Может быть повторно использована **только полностью валидированная** тепловая история P09A при совпадении сетки, контрольной подписи, dt, tf, квадратуры и xi. Механический результат прежнего P09A нельзя безопасно переносить в P09B: прежние сводки не содержат необходимых интегралов.
- Смена `--peak-p` создаёт отдельный каталог и проверяется при resume.
- Если механическая `restart.bin` существует, а новой истории нет — программа выдаст явную ошибку, не подменяя отсутствующие интегралы нулями и не пересчитывая их по конечному состоянию.

## Что было проверено

- CMake Release под Linux, с OpenMP и без него (не заменяет испытания MinGW под Windows).
- Нормировки, сглаживание и интегрирование p=4,8,12; энергия по шести материальным комбинациям.
- Сквозные FEM H0 ZERO и H0 GH3 × 6 моделей: успешно.
- Согласованность последовательной и параллельной сборки трёх показателей: численно идентичные записи.
- Независимый пересчёт GH-моментов из `P09B_SCENARIOS.csv` и совпадение `j6` со старым P09A.
- Повторное чтение 18 готовых сценариев в режиме `--report-only` без новых FEM-расчётов.
- Повторное использование совместимой тепловой истории P09A: подтверждено отдельным сквозным запуском.

Используемые H0 t=300 пилотные значения **не являются данными для итоговых научных выводов** при tf=3600. Для статьи требуются полная серия, анализ зависимости от `p`, затем производные формы каждого из трёх функционалов.
