# Короткие сквозные проверки Stage3D-08C

Linux GCC Release, два отдельных набора `tx` и `y20`, `H0`, `ξ=0`, `q3`, `dt=300 s`, `tend=300 s`, `δ=5 и 2,5 мкм` (по 4 термо- и EDV-расчёта в каждой моде).

Из коротких протоколов (числа для тестов кода, **НЕ** для научной статьи):

- `tx`: `D_tx j6(5 мкм)=1.2664360662593e-7 м⁻¹`, `D_tx j6(2,5 мкм)=1.2661020235699e-7 м⁻¹`.
- `y20`: `D_y20 j6(5 мкм)=-0.0010582053231454 м⁻¹`, `D_y20 j6(2,5 мкм)=-0.0010582138430175 м⁻¹`.
- `stage3d08c_report --tend 300` распознал две моды как `COMPLETE`, шесть ещё как `MISSING`.
- Повторный запуск `tx` не вызывал ни тепловой, ни механический исполняемый модуль; восстановлены записанные истории.
- Группы P08A/P08B совместимых CTest: 16/16 PASS (включая новые P08C), отдельно P08C: 12/12 PASS.

Численные оценки `tx` при очень малой разности функционалов могут быть чувствительны к суммарной погрешности FEM. Факт ненулевой дискретной оценки нельзя объявлять нарушением физической симметрии без сеточного контроля.
