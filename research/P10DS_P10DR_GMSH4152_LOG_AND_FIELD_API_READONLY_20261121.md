# P10DS — источник Gmsh 4.15.2: пределы журнала и оценки размерных полей, без нового запуска

**Дата:** 21.11.2026. **Статус:** самостоятельная проверка *имеющихся* Windows P10DR логов и официального Gmsh API. **Gmsh запуски в этом этапе: 0.** Нет `-1/-2/-3`, новой M2, FEM, forward/adjoint, H0 cache и касаний старых маркеров. Прошлые P10DO/P10DQ/P10DR one-shot закрыты.

## 1. Что действительно нового и почему не повторять P10DR

В P10DO одна разрешённая Gmsh `-3` остановлена wall900s уже на кривых14/17. P10DQ изолировал быстрый F2 от 25-секундной задержки при F5. P10DR впервые реально на Windows разделил F3 и F4 и сообщил STOP обоих по отдельности. Новая задача P10DS — **не ещё раз строить сетку**, а проверить, чего достаточно в ранее собранных логах и можно ли читать поле численно средствами документированного Gmsh 4.15.2 API **без меширования**. Дублировать P10DR C/аналогичные однократные тесты запрещено.

## 3. Что точно поддерживает Gmsh 4.15.2

**Официальный справочник версии4.15.2:** <https://gmsh.info/doc/texinfo/gmsh.html> (командная строка, `Gmsh mesh size fields`, `Namespace gmsh/model/mesh/field`).

- `-log filename` пишет сообщения Gmsh в журнал, `-v int` увеличивает `General.Verbosity`, `-cpu` запрашивает отчёт времени; **никакой из ключей не документирован как вывод значений полей в указанных точках**. При уже остановленном запуске более высокий `-v` **не восстановит потерянные данные**, а повторный native mesh для новых логов — отдельный новый эксперимент и сейчас не разрешён.
- `-parse_and_exit` **только** разбирает входные `.geo` и завершает процесс. Успешные 7 native parses P10DR не означают, что MathEval был численно оценён во время генерации сетки.
- Официальный `gmsh.model.mesh.field` API имеет `list/getType/getNumber/getNumbers/getString` и операции создания/изменения полей, **но не содержит публично документированной функции `evaluate(fieldTag,x,y,z)`**. `getString` возвращает строку формулы, не её численное значение; `gmsh.model.mesh.getSizes` — ограничения размеров на геометрических объектах, не значения arbitrary background MathEval.
- В справочнике `MathEval` допускает пространственные `x,y,z`, `F0,F1,...` для значений других полей и математические функции. Само по себе обращение `F3` или `F4` **разрешённая конструкция**, поэтому наблюдения не доказывают, что синтаксис неверен.
- Gmsh API `gmsh.model.mesh.setSizeCallback` предназначен для **замены/модификации** вычисления размера при генерации сетки; его существование не делает его API чтения оригинального F3/F4 и не даёт права на новый mesh run.

**Чёткое разделение:** математический Python расчёт κ по исходным формулам (полюса, экватор, переход, 6 точек) уже пройден в P10DQ/P10DR; он подтверждает аналитические границы в этих точках, **не** доказывает фактический вывод встроенного в Gmsh MathEval на кривых14/17. Увидеть внутренние численные значения без собственного дополнения Gmsh/plugin/callback в документированном API не удалось. Воспроизводимого официального диагностического метода полевого point-sampling **не найдено** (это отрицательный результат просмотра документации, не доказательство математической невозможности).

## 4. Причина задержки — статус UNKNOWN и следующий минимальный тест

В P10DR B использует F3, но **не объявляет F4/F5**; C использует F4, но **не объявляет F3/F5**. Поэтому **связка F3·F4, C¹ smoothstep, 20%-ный множитель и exp/log не являются необходимыми** для наблюдаемого STOP. Общие особенности B/C — вложенное использование ещё одного MathEval-поля (`F6` ссылается на `F3` или `F4`), а исходные `F3/F4` оба используют `min/max` и пространственные выражения. Данные **не различают** стоимость/особенность вложенного обращения, `min/max` в runtime, геометрию или итерационный алгоритм Gmsh на двух кривых.

Если исследователь разрешит **отдельный новый** короткий mesh-only 1D эксперимент, достаточная предварительная матрица: (1) `F6=F2*(1−0.02*0.5)` (числовая константа); (2) `F3=MathEval("0.5")`, `F6=F2*(1−0.02*F3)` (вложение без пространственной формулы); (3) direct spatial clamp в **самом F6**, без `F3/F4` ссылки (вложение отсутствует). Все три ограничены `Q∈[0,1]`, `h6/h2∈[.98,1]`, по одному bounded `-1` и новому manual one-shot после preflight. Но **этот пакет пока не создан и native запуск не санкционирован**, повтор P10DR и P10DO запрещён. Рассмотреть также статическую проверку вызовов исходной реализации `MathEval` Gmsh4.15.2 перед разрешением нового вычисления.

**Следующий выбор:** сперва передать исследователю факт и договориться о публикации оригинального P10DR ZIP/протокола; любое исправление первого адаптивного M2 только после устранения причины 1D и отдельного mesh-only геометрического gate, физический forward/adjoint/FEM строго отдельно.
