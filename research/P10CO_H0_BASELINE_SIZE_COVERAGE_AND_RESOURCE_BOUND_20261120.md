# Stage3D07 / P10CO — охват B6 известными характеристиками `h0`, ограниченный прогноз адаптивной M1

**Дата:** 20.11.2026. **Статус:** независимый read-only аудит имеющихся P10CI и P10CN CSV. **FEM=0, Gmsh=0, новых `.msh`=0, физические расчёты не запускались.** Цель — установить, позволяют ли уже опубликованные сведения о сетках доказательно назначить исходное 3D поле размера `h0(x)` на всей B6 до M1.

## 2. Сверка составов исходных Tet10 и фактическое покрытие

Для каждой сетки исходный `tet10_count` точно равен сумме категорий, полученных из P10CI centroid entries и count summary. По каждому mesh независимо сверены 200 `(radial,μ)` ячеек слоя 20–100µm и 10 polar ячеек 0–20µm. В таблице ниже категории характеризуют **центры угловых Tet10**, не геометрический охват непрерывного объёма/квадратурных точек.

| Сетка | Всего Tet10 | 0–20µm | 20–100µm | 100µm–5mm B6 | Вне B6 |
|---|---:|---:|---:|---:|---:|
| H4W4B2 | 261 091 | 18 518 | 29 288 | **192 565** | 20 720 |
| H4W4B20 | 323 052 | 18 525 | 29 577 | **254 258** | 20 692 |
| H4W5B2 | 275 549 | 26 465 | 35 331 | **192 965** | 20 788 |

Подтверждённая доля **центров Tet10 внутри B6**, для которых имеется хотя бы ячеечный показатель медианы максимального углового ребра, равна:

- H4W4B2: **19.888%** (остальные **80.112%** B6 без такого локального размерного профиля).
- H4W4B20: **15.909%** (84.091% без профиля).
- H4W5B2: **24.256%** (75.744% без профиля).

Таким образом, опубликованные таблицы покрывают *только приповерхностный слой 0–100µm* по ячеечным метрикам. Агрегированное число элементов в 100µm–5mm известно, но значения `h0(x)`/распределения по радиусу, θ, φ и качества там **не опубликованы**. Выдавать поле на всю B6 или экстраполировать размер на этот объём без источника **нельзя**.

## 3. Что именно можно оценить в известных ячейках

Величина `max_corner_edge_p50_mm` — медиана максимальной длины **углового ребра** отдельных Tet10 внутри соответствующей `(d,μ)` ячейки. Взвешенное среднее по числу центров для таких *ячеечных медиан* — **не** медиана совокупности элементов и **не** заданная mesher функция `h0(x)`:

| Сетка | 0–20µm, среднее ячеечных медиан (мм) | 20–100µm, среднее ячеечных медиан (мм) |
|---|---:|---:|
| H4W4B2 | 0.073000 | 0.094889 |
| H4W4B20 | 0.072842 | 0.094672 |
| H4W5B2 | 0.065739 | 0.089121 |

Сопряжение с 200-cell P10CN даёт демонстрационное произведение `max_corner_edge_p50_mm × q` по H4W4B2 и условный proxy, где число Tet10 в известном слое масштабируется локально как `q^{-3}`. Важно, что **P10CN использовал volume-weighted proxy, а P10CO использует число corner-centroid Tet10 по ячейкам** — эти результаты не должны совпадать в последних цифрах.

| Только условный H4W4B2 сценарий | Число Tet10 / множитель |
|---|---:|
| Исходные centroid Tet10 в 20–100µm | 29 288 |
| Исходные Tet10 во всей модели | 261 091 |
| "Новое" число элементов 20–100µm по `Σ n_K q_K^{-3}` | **40 756.3** — не целочисленная реальная сетка |
| Условный множитель числа элементов этого слоя | **×1.391571** |
| Условный глобальный множитель `1 + (Σ n_K q_K^{-3} − Σ n_K)/N_total`, *если вообще все другие элементы и градационные переходы неизменны* | **×1.043925** |

**Ни ×1.3916, ни ×1.0439 не являются прогнозом настоящего ремешинга M1, RAM или времени FEM.** Нельзя использовать показатель ×1.0439 как верхнюю границу: переходная область, кривизна, сглаживание размеров и качество Tet10 могут потребовать существенно иной сетки. Он лишь проверяет алгебру минимальной стоимости в одной изолированной оболочке при намеренно нереалистичном условии неизменности остальных элементов.

## 4. Приёмка P10CO, STOP и следующий малый этап

- Pinned CSV SHA gates `3/3` P10CI + `2/2` P10CN PASS; count reconciliation всех трех сеток, 600+30 ключей, 200+10 строк на mesh PASS; нулевой `corner_nonpositive_count` и `corner_quality_below_0p1` в указанном 0–100µm объёме PASS (по P10CI straight-corner proxy), без переноса на всю B6 или на новую сетку.
- Доступный baseline `h0` — только ограниченная **ячеечная corner edge proxy**, не continuous h0, не actual Gmsh metric/mesh size; 100µm–5mm остается **NOT_CALIBRATED**. Программа, таблица и рисунок не генерируют `.msh`, не вызывают mesh generator или FEM, не трогают Windows `G:`/`F:`.
- Отчёт и код: `research/P10CO_H0_BASELINE_SIZE_COVERAGE_AND_RESOURCE_BOUND_20261120.md`, `research/proposals/P10CO_BASELINE_H0_AUDIT_20261120/p10co_baseline_h0_coverage_audit.py`. Derived JSON, 200-cell baseline local edge proxy CSV и PNG: `research/evidence/P10CO_OFFLINE_20261120/derived/`. Исходники P10CI и P10CN уже сохранены в соответствующих evidence каталогах. Параметры M1 и физические выходы не появлялись.

**Научно-инженерный вывод:** P10CO закрыл read-only вопрос о *достаточности уже опубликованных* профилей h0: **они недостаточны** для надёжного полного бюджета/градации M1. Следующий **P10CP** допустимо подготовить как новый строгий Windows **READ-ONLY mesh profile** для слоя 100µm–5mm по всем трём pinned старым `.msh` с 3D Cartesian длинами/quality и несколькими агрегированными `(d,μ)` bins, без ремешинга/FEM, возвращающий один компактный evidence ZIP. Это не разрешение произвольно запускать старые однократные P10CI/P10CK, не физический M1, не команда выполнить расчёт сейчас. Для новой M1 `.msh` и любой FEM физики по-прежнему необходимо отдельное согласие исследователя по D-017. Природа больших полярных shape-производных, физические 4D mechanical+thermal поля и сходимость остаются открытыми.
