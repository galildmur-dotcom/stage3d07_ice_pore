# P10EK — новая кандидатная 3D M2 с Delaunay5, затем условный физический расчёт

**22.11.2026.** Исследователь поставил задачу: «создадим сетку M2 и
выполним физический расчёт». Обязательный научный порядок — **новая
геометрическая M2 → независимая QA → только принятая сетка в прямой и
сопряжённой задаче на одном и том же M2**. Отказ QA блокирует FEM.

## 1. Точная геометрическая кандидатная постановка

Исходная M1 — original P10DG SHA
`ca6b6b6588dc72c5dd3ed2e92e24794560ee2407e350c8a44858e9c3c7d0360f`
(ранее независимо проверена). CAD SHA
`8029a6ed22bcf312701cd6abc46bbe5575e52df16fd5218dd936b01d5cd6fcf0`,
Gmsh4.15.2 EXE SHA `317c43391e5b1fab3a1dd80dc5245dad6e2d087910f4b8ebc234bd6d4b8f41a1`.

Оригинальная P10EA 3D M2 Frontal-Delaunay6 была геометрически допустимой,
но не обеспечила заданное полярное сгущение. P10EF R2 показал, что
замена surface-algorithm на Delaunay5 даёт новое полярное сгущение 2D.
Для P10EK **ровно одна новая геометрическая гипотеза**: B GEO SHA
`2765018d8ddd2e83f28bd60af7c87b65172ac5da8389ede187d8bb9eea9d74c5`,
то есть одна строка `Mesh.Algorithm = 5;` перед прежним F6. Всё остальное
неизменно: CAD, Tet10, HXT3D10, гладкая κ, единое 3D/поверхностное
`h/h_M1=(1-0.20κ)^(1/3)`; никаких дополнительных множителей 0.8.
**D-023A:** плавность размеров обязательна, **азимутальная равномерность
конечных элементов не обязательна**.

## 2. Реализованная защищённая Windows mesh-only стадия

Пакет `research/packages/P10EK_R1_ONE_M2_3D_ALG5_WINDOWS_20261122.zip`
собран из точного неизменённого P10EA parent ZIP SHA
`8b1650ae7808b117f5778ca726b2542c9cbc59365a09913128a322713b254009`
и нового отдельного P10EK source-guard. 24 исходных компонента вложены
только в `P10EA_PINNED_PARENT`, в корне **ровно две** P10EK CMD.
Оригинальные P10EA/P10EF source checks, математический F6 test17075,
27QP geometric QA и отрицательные folded/old-M1 guards не меняются.

Новый P10EK marker identity не зависит от израсходованных P10EA/P10EF:
локальная `P10EK_R1_ONE_3D_USED.json` и профильная
`%LOCALAPPDATA%/Stage3D07/P10EK_R1_ONE_3D_<M1_SHA>.json` создаются
эксклюзивно непосредственно перед **одним** `gmsh -3`.
Один запуск расходуется даже при ошибке/timeout/QA STOP, не повторять.
Нативные лимиты900с/8GiB private polled/750MiB mesh/16MiB log/2 потока;
QA300с/8GiB; свободно≥16GiB RAM и≥4GiB disk. **Никаких FEM-команд
в ZIP нет, FEM=0**. Никаких существующих пользовательских исходников,
forward cache, старых результатов и markers не затрагивается.

Проверки на машине ассистента **только source-only**, не Windows-native:
SHA pin parent23+new5, package ZIP CRC30/30, isolated selftest,
tampered GEO negative STOP, Linux preflight STOP без Gmsh, попытка
without proof STOP, local old/new markers untouched. Это не свидетельство
реальной 3D M2. README и launcher лежат в
`research/proposals/P10EK_M2_ALG5_3D_WINDOWS_20261122/`.

## 3. План физического расчёта после полученного M2 evidence

Сначала проверить **оригинальный** `P10EK_EVIDENCE.zip` и (если необходимо
для независимой 27QP проверки) новую raw M2.msh приватно; сопоставить
действительные объёмные размерные профили с M1 в тех же физических
зонах. Полное изменение объёма >20% в устойчивой приоритетной зоне
требует научного разбора, но азимутальная неравномерность сама по себе
не STOP (D-023A). Имеющийся P10EA geometry QA сам по себе **не**
доказывает адаптивный GO: результат рассматривается исследователем.

После geometry/adaptivity GO требуется **свежая прямая история на M2**;
перенос H0/M1 `forward_history.bin` запрещён из-за несовпадения mesh.
Затем сопряжённый расчёт на той же M2, analytic Tet10 geometry partial
(без central FD), signed mechanical+thermal `(r,theta,phi,t)`,
проверка step/global closure и R/EDV_VAR/ξ=0/6×150s/jpeak
как минимальный физический пилот; другие функционалы, модели, GH3 и
направления формы добавляются после соответствующего подтверждения.
Историческая M0=H0 и конкретная M1 должны быть сопоставлены по одному
физическому режиму; отсутствие полной M1 пары означает, что один M2 FEM
не доказывает пространственной сходимости производной формы.

Ориентир ресурсов, **не предел/не измерение для M2**: ранее H1 P10CD
выполнялся≈407с, private≈2.38GiB при другой размерности/режиме.
Для будущего физического пилота ориентировочно планировать **10–30мин**,
RAM **3–8GiB**, но перед запуском проверить фактическое число узлов M2,
target CMake/Qt, состояние кэша и установить отдельные hard resource caps.
**Никакого автоматического FEM из кнопки02 и никакого запуска до геометрического evidence.**
