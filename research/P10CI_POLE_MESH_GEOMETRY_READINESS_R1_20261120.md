## 1. Предмет и существенная поправка к интерпретации P10CH

Исследователь требует продолжить проверку причины приполюсных аномалий и подготовить M1. Предыдущий P10CH дал L1 доли полярных несогласий 87.00575/87.79656% для двух пространственных уточнений и 94.45117% для H2 dt50−25; выделил согласованный top40/200 bins. **Точный радиальный support исходной таблицы P10CH — только `d=r−R` от 0.020 до 0.100 мм** (20×10 bins). Эти проценты описывают *концентрацию локальных межрасчётных разностей в данном тонком слое*, **не** во всей области интегрирования B6 (0–5 мм). Для тонкого слоя baseline два крайних μ-пояса содержат 20.49956% QP count и 20.03495% интегрального QP volume.

**Исследовательский вопрос P10CI:** отличаются ли в candidate top40 и полярных μ-полосах геометрические прокси качества, ориентированность/азимутальный охват и пересечение локальных `(d,μ)` ячеек настолько, что это может участвовать в проявлении mesh sensitivity? Дополнительно **отдельно** проверяем не представленный P10CH приповерхностный слой 0–20 мкм.

Это не интерпретация приполюсного несогласия как истинной численной ошибки. Согласование двух mesh perturbations + temporal comparison без референтного решения не даёт оценку `|D_h−D_exact|` и не отделяет физику от геометрии FEM.

## 3. Что именно вычисляет геометрический аудит

Новая стандартно-библиотечная утилита Python3, read-only Gmsh v2.x ASCII, строго по типу 11 Tet10:

1. Сверяет SHA-256 bytes каждого `.msh` перед каким-либо содержательным разбором, node/Tet10 count после разбора, формат и конечность координат.
2. Для каждого элемента рассчитывает **только straight-sided corner tetra** по четырём вершинам: ориентированный тройной объём, объём-модуль, длины шести рёбер, безразмерный mean-ratio `q=12(3V)^(2/3)/Σl²`. Отдельно максимальное относительное смещение шести срединных Tet10 узлов от прямолинейных средин рёбер. **Это НЕ проверка качества curved Tet10 по настоящим Q3/Q4 якобианам.**
3. На основе центроида четырёх углов разносит элементы в `(d, μ, φ)`, `μ=cosθ`, 12 azimuth sectors. Подсчитывает занятость, коэффициент вариации φ-counts, минимальную покрывающую дугу φ четырёх вершин, случаи неопределённости оси, radial/polar crossing по вершинам. **Это НЕ физические QP-bin интегралы, не поле механической производной.**
4. Записывает 600 строк по 200 candidate cells ×3 meshes; дополнительно 30 строк для ранее пропущенного слоя 0–20 мкм; 12 агрегированных групп (top40, remaining160, polar, middle) и три exact mesh summaries.
5. Отдельно считает centroids вне 20–100 мкм, внутри номинального шара (краевая геометрическая проверка), около поры, до 5мм; эти счётчики **не** дают разложение `D_R jpeak` на всю B6.

Геометрия из проверенных P10AB/P10BB: `R=1 mm`, `center=(0,0,0.03) m`. Заданные пороги `q<0.1` и большие φ-spans служат только скринингом; не объявлены физическими критическими границами качества. Рядом с осью `φ` математически неопределён, поэтому такой случай выделен явно.

Архив распространён отдельно; GitHub хранит проверенный текстовый исходник/README и научный протокол, не обязательно сам ZIP. Внутри:

- `P10CI_mesh_audit.py` — Python3 без NumPy/других внешних пакетов;
- `P10CH_M1_OFFLINE_CANDIDATE_200CELLS.csv` — точный пинованный input;

Штатная кнопка только **читает** три exact `.msh` под `G:\ildar\Stage3D07\P10M_MESHES` и input CSV из своего каталога. Все результаты — в новом отдельном `P10CI_RUNS\P10CI_<UTC>_<id>` **рядом с распакованным ZIP**, не в исходном Git, не в `G:`. Отказ от запуска и неверный SHA дают `P10CI_MESH_ONLY_STOP`, без обхода. НЕТ сборки, запуска EXE решателя, изменения PATH/исходного Windows дерева, remesh/GMsh, H0/H1/H2/H4 физики или `M1.msh`.

Ожидаемый ресурс по исходным ~860k Tet10 трёх сеток, Python3 без NumPy, i7-7700K: **2–10 минут**, память ориентировочно `<1.5 GiB`, новые файлы `<5 MiB`, уверенность ограничена. Это оценка, **не жёсткая квота**. Если более 15 минут без прогресса — ручной STOP и анализ, без автоматического повтора. Возвращается **один небольшой `P10CI_EVIDENCE.zip`** с тремя расчетными CSV, одной таблицей summary и RESULT, либо STOP ZIP.

## 5. Что фактически проверено в данной среде

- Python3 syntax PASS (`python3 -m py_compile`).
- Чистый synthetic unit: `P10CI_SYNTHETIC_GEOMETRY_UNIT_OK regular_tetra_quality=1 bins=10 phi_sectors=12 FEM=0`.
- Отдельный Gmsh2 ASCII мини-Tet10: 10 nodes, 1 Tet10; parser выдаёт `200` candidate rows, `10` first-wall rows, `1` элемент в допустимой radial/μ ячейке.
- Full pipeline с тремя независимо названными **синтетическими** mesh inputs: ZIP CRC 5/5 PASS, 600+30 rows, 12 group rows, status `P10CI_MESH_ONLY_GEOMETRY_OK_NO_FEM`. Это специально подменённые тестовые descriptors внутри local Python process, **не** обход SHA настоящей утилиты.
- Negative-path STOP test: отсутствующая mesh root создаёт `P10CI_MESH_ONLY_STOP` с одним ZIP и точной причиной, без FEM.
- **Не проверено:** Windows Python3/CMD, реальные три mesh SHA и поля качества, curved Tet10 Jacobian, связь геометрии с реальной ошибкой, production 4D exporter, физическое M1 и все convergence claims.

## 6. Следующий критерий исследования

Нужен ровно один `P10CI_EVIDENCE.zip` после однократного ручного mesh-only запуска исследователя. Ассистент обязан сравнить полярные и неполярные top40/other160 на всех трёх сетках, степень azimuth imbalance, качество `q`, radial/polar bin crossing, первые 0–20 мкм; затем сформулировать конкретную **проверяемую** гипотезу и проект Gmsh size-field M1 (новая сетка — отдельный этап). В случае противоречивых статистик — изменить экспериментальный план, а не автоматически сгущать оба полюса.

**STOP научного вывода:** даже сильная корреляция геометрических метрик с P10CH intermesh differences не доказывает причинность. Для реальных `D_R jpeak` требуются полное signed 4D decomposition механики/тепла и локальный временной контроль. Действует D-017 — ни один physical M1/M2/M3/M4 не разрешён; закрытый P10CD H1 не повторять.
