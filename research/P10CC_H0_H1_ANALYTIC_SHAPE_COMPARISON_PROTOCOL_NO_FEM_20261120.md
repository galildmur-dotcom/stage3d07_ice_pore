# P10CC — протокол минимальной межсеточной проверки полной аналитической чувствительности формы H0→H1 (NO FEM)

**20.11.2026. Статус: PREPARED_NO_FEM, НЕ санкционирован к запуску.** Настоящий документ — дизайн следующего научного измерения, а не результат H1. Решение D-015 разрешало одну попытку H0 и уже использовано. P10CB R2 лишь проверил будущий безопасный захват native ExitCode; прежний P10CA H0 native ExitCode остался UNKNOWN.

## Цель и проверяемая гипотеза

Узнать, насколько зависит от пространственной дискретизации **полная** аналитическая `D_R jpeak` для `EDV_VAR, ξ=0`, включая mechanical + thermal contribution. Дополнительный вопрос: меняется ли знак/локализация теплового вклада в окрестности 0–5 mm поддержки B6. Переход от одной сетки H0 к одной более плотной H1 **не является доказательством асимптотической пространственной сходимости**; он даёт парную разность и основание для решения, нужна ли H2. Временная сходимость полного `D_R jpeak` отдельно НЕ доказана.

## Запертый baseline H0 из P10CA

- Одна физическая Windows попытка `H0`, `R`, `EDV_VAR ξ=0`, `6 × 150 s`, analytic Tet10, B6 cutoff 5 mm; `6/6` forward, `18` adjoint.
- `D_R jpeak` total **3.1676918514 m⁻¹**, mechanical **3.1013122993 m⁻¹**, thermal **0.06637955208 m⁻¹**. Максимальная шаговая |thermal QP−CSR| **1.102×10⁻¹⁴** после независимой Decimal-сверки **2 836 992 QP**.
- Наблюдаемое время **104.424 s**, пик RAM ≈ **0.895 GiB**, результаты ≈ **0.145 GiB**; это **измерения H0, не оценка затрат H1**.
- Архив P10CA H0 и его обзор — отдельное опубликованное первичное свидетельство. Прежний Windows `RESULT=P10CA_STOPPED`, `physical_verified=false` и native ExitCode UNKNOWN сохраняются. Второй H0 не нужен для самого минимального сравнения, и не разрешён.

## Preconditions до любого физического разрешения

1. Идентифицировать и хешировать **конкретный H1 mesh, его единицы, Tet10 topology, границы и счётчики DOF/QP**; отдельно подтвердить совместимость с H0 и отсутствие скрытой смены геометрии/материала. Пока exact H1 input/mesh SHA и размер не выверены, выбор сетки **PENDING**.
2. Пиновать exact source/EXE SHA, flags `--help` и selftest, рабочую Windows Git HEAD/status/fingerprint; проверить существование outputs только чтением. Никаких изменений исходного dirty `G:\ildar\Stage3D07`.
3. Проверить доступное RAM/диск и лимиты по H1 по **числу DOF, NNZ/числу QP** и прогнозу solver workload; H0-цифры (104.424s, 0.895 GiB, 0.145 GiB) служат только нижней точкой опоры, **не линейной гарантией**. До запуска предъявить пользователю конкретные soft/hard time, RAM, disk caps и STOP conditions.
4. Для Windows native ExitCode применить R2 проверенный коротким `--selftest` child-only MinGW PATH и ограниченное ожидание; зафиксировать код процесса **до Dispose**, stdout/stderr и snapshot dirty Git. Числовые CSV без `exit0` не именовать verified native pass.
5. После явного разрешения — только **одна H1** в отдельной output директории, никаких H0 replay, H2, preflight с solve или скрытой дополнительной модели.

## План доказательного аудита после H1

- **Внутрисеточный:** forward/adjoint H1 на одинаковой сетке, 6/6 и ожидаемые adjoint маркеры; сравнить thermal QP vs CSR *по каждому шагу*, аналитические знаки, 606-bin+audit схему если форматы строго совпадают. При ошибке, пустом native ExitCode, неверных SHA или нарушении договорённого caps — STOP, не «дочинять» физикой.
- **Межсеточный:** таблица H0 vs H1 для `D_R jpeak` total / mechanical / thermal, `jpeak` и времени/шага peak, абсолютные и относительные Δ (знаменатель для малого thermal отдельно оговорить). Отдельно radial 0–2/2–5 mm и polar decomposition, карты QP sign cancellation; не смешивать локальный перераспределённый thermal вклад с глобальным total.
- **Смысл результата:** H0→H1 даёт только две пространственные точки. Без третьего шага H2 и проверяемого асимптотического порядка писать `SPATIAL_CONVERGENCE_NOT_PROVEN`. `6×150 s` не сравнивает временные шаги, поэтому `FULL_TEMPORAL_CONVERGENCE_NOT_PROVEN`.
