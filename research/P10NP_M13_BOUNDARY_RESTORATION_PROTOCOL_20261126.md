# P10NP — восстановление поверхности после Gmsh HighOrderElastic

P10NO показал очень сильное улучшение метрик (native `minSICN=.3177166`, `minSJ=.6418251`), но во встроенной оптимизации изменились 4 420 граничных узлов. При оценке по исходному массиву связности также выявилось несовпадение, возможно из-за изменения порядка элементов.

В этом эксперименте в память загружается исходная M13 R2 (SHA256 `57403ba43fa299417d519046cebdf50fa4968b670c071a8b7882748b50f51e9c`). Затем вызывается Gmsh `gmsh.model.mesh.optimize('HighOrderElastic',force=True)` с `Mesh.HighOrderFixBoundaryNodes=1`. После него координаты **всех** граничных узлов на физических поверхностях 2..9 явно восстанавливаются по исходным координатам через `setNode` (включая все срединные узлы Tri6).

Независимо сравниваются наборы глобальных идентификаторов, связность Tet10 и Tri6 **по идентификаторам элементов**, а не по порядку записи. Выводятся количество изменённых элементов/узлов, максимальное смещение, канонические показатели Gmsh `minSICN`, `minSJ`, `gamma`, `minDetJac` до оптимизации, сразу после неё и после восстановления границы.

## Windows 11

1. Распаковать ZIP в новый каталог, где установлены Python `numpy` и Gmsh Python API 4.15.2.
2. Запустить `P10NP_RUN_BOUNDARY_RESTORATION.cmd`.
3. Прислать `P10NP_BOUNDARY_RESTORATION_RESULT.json` и `P10NP_GMSH_RESTORE_LOG.txt`.

Файл исходной сетки не изменяется, оптимизированная сетка не сохраняется. FEM, генерация сетки и одноразовые маркеры не используются. Даже успешное восстановление границы и качество D031 **не означают автоматического принятия M13 R3**.
