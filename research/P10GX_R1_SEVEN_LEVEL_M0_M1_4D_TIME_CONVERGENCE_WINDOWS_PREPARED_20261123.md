# P10GX R1 — семь уровней временной сходимости на двух физических сетках M0/M1

**Дата 23.11.2026. `SOURCE/ZIP/CXX_COMPILE/SELFTEST/NEGATIVE_GUARDS/REAL_4D_REPLAY PASS`, новые Windows physical FEM=0.**

## Научная задача

После P10GW новой M1 R/EDV_VAR/ξ0 dt150 физика подтверждена, но 4D межсеточное изменение `Σ_bins |ΔG|=6.902424м⁻¹` и его 81.57% на последних 300с нельзя без оценки временной ошибки объявлять пространственным индикатором. Поскольку двух уровней dt150/75 недостаточно для надёжного порядка сходимости, программа продолжена **ещё пятью уменьшенными временными шагами**, с той же целью t_f=900с и на **обеих** физических сетках:

| dt, с | Шаги n=900/dt | M0 | M1 |
|---:|---:|---|---|
| 150 | 6 | P10FS реальный PASS | P10GV/P10GW реальный PASS |
| 75 | 12 | новый one-shot | новый one-shot |
| 60 | 15 | новый one-shot | новый one-shot |
| 50 | 18 | новый one-shot | новый one-shot |
| 45 | 20 | новый one-shot | новый one-shot |
| 36 | 25 | новый one-shot | новый one-shot |
| 25 | 36 | новый one-shot | новый one-shot |

Разные dt соответствуют различному набору временных интервалов. Сравнение полных скаляров `D_R jpeak(t_f)`, J и сумм по физическим пространственным bins возможно непосредственно. Сравнивать **весь 4D** следует только через явно задокументированную консервативную временную реконструкцию на общих физических временных интервалах: не объявлять разные интервалы идентичными и не складывать непересекающиеся понятия `D_R J(t_n)` и вклад шага в `D_R J(t_f)`. Проекции времени фиксировать до оценки локального `L1_time`, отдельно для механического равновесия, истории EDV, явной формы, thermal mass/diffusion/Robin и полной производной. Объёмная плотность G/physical volume требует контроля QP support, не заменять `G` средним по узлам. Не заявлять порядок по двум точкам, проверять поведение всех семи уровней, в особенности dt36→25.

## Реализация

- Пакет `research/packages/P10GX_R1_M0_M1_SEVEN_LEVEL_SIGNED_4D_TEMPORAL_WINDOWS_20261123.zip`, 109 членов, 402461 B, SHA256 **`1e8c5aa70bf1da58d8c6533267a2ba6523f49a9ce6b54c2f67f9efa95ada8fe9`**, CRC PASS. Рецепт сборки `research/proposals/P10GX_TEMPORAL_4D_SERIES_20261123/build_p10gx.py`, source script `P10GX_temporal_series.py` и README опубликованы отдельно.
- Основа — точные P10GV/P10FN производственные термомеханические и аналитические сопряжённые алгоритмы. В изолированной копии исходников **только три точечных изменения защитных ограничений**, с жёстко заданным whitelist из семи пар `steps×dt` и `steps≤36`, плюс допускается полный signed 4D при фиксированном `steps*dt=900` и одной моде R. Все изменённые байты переподписаны новым source inventory (≥90 файлов). Старые EXE/P10GV buttons, предшествующие маркеры и M0/M1 files не перезаписываются.
- `01_P10GX_PREFLIGHT_NO_FEM.cmd` — только проверка source SHA, M0 SHA `926a9c90…`, оригинального private P10GT M1 ZIP SHA `7bff0298…`, исходного M1 SHA `47460969…`, whitelist/dt и вычислительной среды, никаких Gmsh/FEM.
- `02_P10GX_ONE_BOUNDED_12_RUN_CAMPAIGN.cmd` — один ручной старт: по dt75 M0 потом M1, dt60 M0 потом M1, и так до dt25. Все 12 запусков со **своими одноразовыми сохраняемыми markers**; на каждый fresh forward+18 analytic same-mesh adjoints, RAM hard Windows Job ≤8GiB, wall monitored≤2400с, output≤2GiB, 4 threads, не менее 12GiB доступной RAM/4GiB disk до запуска. Первая ошибка останавливает серию, ничего не повторяет. Отслеживаемый результат Windows `P10GX_02_RESULT.txt`. Каждое evidence имеет `P10GX_MANIFEST.json`, исходный log, 5 CSV с `1201×steps` строками 4D и независимое замыкание `D_Rjpeak`.
- В конце создаётся **один** `LOCAL_RUNS/P10GX_CAMPAIGN_*/P10GX_12_RUNS_EVIDENCE.zip`, при STOP `P10GX_PARTIAL_STOP_EVIDENCE.zip`, содержащий лишь вложенные компактные evidence, не бинарные forward-history (хранятся локально с SHA). Не распространять raw MSH и user ZIP на публичный GitHub.
- По реальной предыдущей M0/M1 dt150 (128.8/156.8с) ориентир кампании **1.5–3ч**, возможно больше, без гарантии. Отдельная попытка ограничена 40мин/8GiB/2GiB. Вложения private исходников и output оценивать по пиковым измерениям, а не по одному linearly extrapolated часу.
