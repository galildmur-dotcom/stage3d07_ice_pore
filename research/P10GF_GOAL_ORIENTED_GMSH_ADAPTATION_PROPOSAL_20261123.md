# P10GF — реализуемый в Gmsh алгоритм адаптивных сеток для Stage3D07

**Дата:** 23.11.2026. **Статус:** НАУЧНОЕ ПРЕДЛОЖЕНИЕ ПО ИЗМЕНЕНИЮ ПРОТОКОЛА, а не готовая/одобренная M1. Новых 3D FEM и native Windows Gmsh по этому документу не запускалось; `approvals/M1.json` не создан. Raw MSH, существующие SHA и одноразовые маркеры не менять.

## 0. Основания и новизна

В P10GE установлено: у исходной OCC-сферы есть параметрические полюса, в реальной 2D Gmsh4.15.2 около них `q_corner≈0.23`; плавное изменение size-field даже на 0.45% может изменить число Tri6 у северного полюса на 5; на локальной Gmsh4.13.1 перенос CAD-полюсов дал `q_corner,min=0.638` вместо `0.230`, но **не улучшил** 18-zone 3D плотность (HXT: 9/18→7/18). HXT и Delaunay на одном поле дали совершенно разные числа Tet10 (9657 vs 12622). Windows M1W4.15.2 имела 9624 Tet10, глобальное `Veff(M1W)/Veff(M0)=0.830424`, но только **10/18** узких зон в [0.80,0.85]. Тонкий слой M0 около полюсов содержит около **9.55–11.90 эффективных Tet10 на зону**: ширина полосы 5 процентных пунктов сравнима с дискретным изменением одного элемента.

**Решение:** заменить «подбирать 18 независимых поправок h, пока все узкие зоны попадут в 0.80–0.85» на **геометрически регуляризованную, физически ориентированную адаптацию со стабильными интегральными тестами**. Равномерный M0→M1 оставить отдельной калибровкой перед физической адаптацией M1→M2→… . Это **существенное изменение** P10FV; 18-zone [0.80,0.85] не объявлять выполненным и не скрывать нарушения.

## 1. Литература: что реально переносится

1. **Morin, Nochetto, Pauletti, Verani (2012), _Adaptive finite element method for shape optimization_, ESAIM COCV 18(4), 1122–1149, DOI 10.1051/cocv/2011192.** В работе применяются прямое и сопряжённое уравнения, *dual-weighted residual* (DWR) и цикл `SOLVE → ESTIMATE → MARK → REFINE/COARSEN`, а также контроль геометрии/гладкости границы. Это методическая основа для функционалов и shape derivatives. Их численные примеры не доказывают результат для нашей 3D нестационарной термомеханики: **не переносить их оценку ошибки без вывода для наших уравнений**.
2. **Carpio, Prieto, Bermejo (2013), _Anisotropic 'Goal-Oriented' Mesh Adaptivity for Elliptic Problems_, SIAM J. Sci. Comput., DOI 10.1137/120874606.** Полезна концепция целевого функционала и метрического поля, но исходные численные примеры двумерные, эллиптические. Для текущих Tet10 выбираем **изотропное скалярное** `h(x)`: анизотропию нельзя принимать без независимого доказательства качества искривлённых элементов.
3. **Gmsh 4.15.2 manual**, разделы _Specifying mesh element sizes_ и _Mesh algorithms_: `PostView` для скалярного background field, а `Mesh.Algorithm3D=10` HXT и `=1` Delaunay поддерживают общие поля размеров. **Christophe Geuzaine (2019)** рекомендует **две отдельные модели** для PostView-background и перестраиваемой CAD-модели; без независимой сетки background данные уничтожаются при remesh. Пример: `demos/api/adapt_mesh.py`. `gmsh.model.mesh.refine()` — не необходимый механизм пространственно выборочной адаптации; здесь каждый уровень строится как **новая полная согласованная тетраэдральная сетка**.

## 2. Геометрический инвариант и дискретизация

- Та же физическая геометрия: блок **60×60×50 mm**, сферическая пора **R=1 mm** с центром **(0,0,30 mm)**, интерфейс **B6: r=6 mm**; все физические группы 1–9; единицы SI, `MSH2.2`, `Tet10/Tri6` на физике; аналитический Tet10 shape-adjoint и **forward+adjoint на одной и той же сетке**.
- Сначала независимо проверить `OCC Sphere` без поворота и вариант **с поворотом CAD-параметрической оси на 90° относительно центра сферы до Boolean**. Это математически та же сфера, но иная параметризация. Не подменять реальный physical `z`/полярные зоны повёрнутыми координатами CAD.
- Для каждого варианта сделать **только surface mesh 2D** и оценить `q_corner` Tri6, дефекты полюсов, размеры и нормали Tri6, сферы `|x-c|=R`, метки 2–9, B6 и шов. **Высокий q_corner сам по себе не гарантирует высокое curved Tri6/Tet10 качество.** Если нужен иной CAD-патчинг, сначала обосновать и проверить сохранение геометрии и тегов.
- Далее только среди прошедших surface gate строить 3D HXT10, по **одной воспроизводимой именованной пробе** на кандидат; Delaunay1 только как отдельно калибруемый контроль, не подмена алгоритма без изменения калибровки поля. Проверять `detJ>0` в 27/343/729QP, радиус/объём B6, объём льда, физические теги, 3D aspect/slivers, локальные размерные отношения соседей и фактическую статистику 18 зон. Исходный M0 не перезаписывать.

## 3. Как реально передать C¹ поле в Gmsh

Новый кандидат **не должен** состоять из множества длинных `MathEval`-выражений (предыдущая native ошибка парсера) или бессвязных точечных значений. Реализовать локально Python-препроцессор:

1. Хранить базовое `log h_n(x)` и физический индикатор `κ_n(x)` на **сеточно-независимых физических координатах**, в том числе `d=|x-c|-R`, `μ=(z-c_z)/|x-c|`, `φ=atan2(y-c_y,x-c_x)`. Геометрические полюса должны быть обработаны гладко в декартовых координатах, не через независимую разрывную зависимость от `φ` в полюсе.
2. Для численно строгого `C¹` поля использовать **положительные декартовы C² B-splines** или `C∞` partition-of-unity для `κ` и `log h` с явным ограничением производных и периодичностью по `φ`, если используется угловой базис. Простая линейная интерполяция `PostView` является **только C⁰**, хотя исходные выборки вычислены из гладкой функции: нельзя назвать её точным C¹ без оговорки.
3. **Основной путь:** Gmsh4.15.2 Python API `gmsh.model.mesh.setSizeCallback(...)` возвращает непосредственно аналитически сглаженное значение `h(x)` на запросы Gmsh, без нестабильного парсинга `MathEval`; из файла manifest загружаются только коэффициенты/ограничения поля. **Запасной путь:** скалярный `PostView` на **отдельной фоновой модели**, интерполяция физического h по области и `gmsh.model.mesh.field.add("PostView")`, `setNumber(...,"ViewTag",...)`, `setAsBackgroundMesh(...)` для рабочей CAD-модели; перепроверять интерполяцию вне фоновых узлов и отмечать, что реализованное Gmsh поле лишь C⁰. Ни один способ не гарантирует заданные размеры выходных Tet10.
4. Общая граница на `h`: `h_min≤h≤h_max`, ограничение на пространственное изменение `|∇log h|` / градацию, отдельная физически мотивированная верхняя граница `h_surface(d=0, μ,φ)` для радиуса поры. Конкретные `h_min`, коэффициент градации и порог `q_corner` **пилотно калибруются** и явно фиксируются в manifest; не назначать универсальные значения по одному 4.13 эксперименту.

## 4. Два различных этапа: M0→M1 и M1→M2…MN

### 4.1. Подготовительная M1 — контроль однородного сгущения

Историческое пожелание: уменьшить характерный объём элемента **на 15–20% во всём льду**. Начальное **целевое** поле в M0→M1:

\[
\kappa_0(x)\equiv1,\quad q_{V,\mathrm{target}}=0.825,\qquad
h_{1,\mathrm{target}}(x)=h_0(x)(0.825)^{1/3}\approx0.937889 h_0(x).
\]

Если `h0(x)` извлечено из реализованной M0, надо выделить гладкую **референсную огибающую** размера, а не слепо интерполировать ступенчатые отдельные объёмы Tet10. Отдельно проверить нормальное разрешение реальной криволинейной поверхности и CAD-полюса; M1 не обязана повторять связность M0.

**Предлагаемая честная замена приёмки M1:**

1. **Обязательный hard gate:** точная CAD-геометрия/теги, геометрия Tri6, положительный curved detJ 27/343/729QP, отсутствие pathological slivers у поры, разумная фактическая градация, исполнение бюджета; независимый локальный 343→729QP контроль.
2. **Обязательный глобальный size gate:** `0.80≤Q_V(ice;M1/M0)≤0.85` по интегральному `Veff`. В 18 подписанных зонах сохранять **точные** фактические q, `N_eff`, `QP`, signed north/south, пиковые local mesh anomalies и информацию о том, где сетка разрежена; дополнительно достаточно заполненные укрупнённые зоны и quantile/persistent checks по соседним физическим bins. Цель **для каждой** из 18 зон по-прежнему `[0.80,0.85]`, но **не hard stop только из-за попадания одного малонаселённого полярного bin вне полосы**, если другие геометрические/объёмные проверки проходят. Не утверждать фактическое 15–20% в каждой точке: это не проверено и вообще не означает 15–20% по каждому элементу в несопряжённых сетках.
3. **Локальное препятствие/STOP:** геометрическая непригодность, настоящее грубое приполюсное разрежение, отсутствующие физические QP, либо сохраняющееся после укрупнения или независимого повторения систематическое coarsening у физически важных зон. Порог для «грубого» до Windows-генерации зафиксировать по уровню `N_eff`, разрешению и повторяемости; не подгонять постфактум под одну M1.
4. Для M1 в результатах указывать **две оценки**: `(A) legacy strict P10FV 18/18 GO/STOP` и `(B) proposed P10GF physical-quality GO/STOP`. **По старому контракту M1W навсегда STOP (10/18);** новый критерий не имеет обратной силы и ещё не присвоил ей FEM GO. Предпочтительно получить свежую M1 на Gmsh4.15.2 после новой 2D проверки, не переименовывать M1V/M1W.

Если учёный решит оставить `18/18` как обязательное требование фактических 15–20% без исключений, то **другая техническая ветка**: создать **отдельную новую более мелкую** базу `M0_ref` с существенно большим `N_eff` в каждом тонком bin и выполнять её независимое M0_ref→M1_ref; исходный pinned M0 и его SHA не трогать. Нельзя обещать 18/18 и после этого из-за топологии, но статистическая устойчивость повысится ценой RAM/time.

### 4.2. После принятой и физически рассчитанной M1 — направленная адаптация

Имеем два независимых FEM-решения M0 и M1 (в каждом **fresh forward + same-mesh adjoint**) со сверенными `dt`, схемой, параметрами/законами и B6. На фиксированных **физических**, не сеточных bins \(B=(d,\mu,\phi,t)\) собрать *подписанные* вклады аналитической производной \(G^{f,a,\alpha}_{B,n}\), где `f∈{j6,jpeak,jen}`, `a∈{R,tz,y20}`, `α∈{explicit_geom,equilibrium,EDV_history,thermal_mass,thermal_diffusion,thermal_Robin,...}`. Точную подмодель указать в manifest (`E/ED/EDV`, `GH3`, `ξ`, etc.). Сумма по B, времени и граничным частям **обязана** восстановить соответствующие глобальные `D_a f` без смешения единиц.

**Первый реально вычислимый маркер** для пары принятых сеток (это *heuristic intermesh change*, **не** строгая DWR-оценка ошибки):

\[
\eta_B=\max_{f,a,\alpha}\frac{\left|G^{f,a,\alpha}_{B}(M_n)-G^{f,a,\alpha}_{B}(M_{n-1})\right|}
{\epsilon^{f,a}_{\rm abs}+\sum_{B',\beta}\left|G^{f,a,\beta}_{B'}(M_n)\right|}.
\]

По времени `t` возможна агрегация взвешенных вкладов в spatial bin, но **после** проверки, что временная погрешность локального индикатора меньше полезного spatial signal (P10CG/H2 показали, что глобальные 0.078% не гарантируют локальную временную сходимость). Учитывать знаковую компенсацию: максимум **модулей разностей отдельных компонент**, а не модуль разности глобально просуммированного значения. Высокая амплитуда физического производного сама по себе **не равна** высокой ошибке.

**MARK:** сортировать пространственные bins по \(\eta_B\) или \(\eta_B^2\) (явно закрепить нормировку), выбирать минимальное множество с, например, **50%** суммарного индикатора (Dörfler marking — инженерная адаптация принципа из AFEM, конкретная `θ=0.5` пилотная, не обязательный параметр статьи). Добавить фоновые контрольные bins и физически важные B6/полюса/экватор, **не принуждая** сгущение только на полюсах. Построить `κ_n(x)∈[0,1]` из отмеченных bins через гладкую partition-of-unity + C² smoothing, ограничивая осцилляции и положительность.

**SIZE UPDATE:** для шага `α_n∈[0.15,0.25]`, по умолчанию пилотно `α=0.20`:

\[
h_{n+1,\mathrm{target}}(x)
=h_{n,\mathrm{base}}(x)\,[1-\alpha_n\kappa_n(x)]^{1/3}.
\]

Тогда в **номинальном** объёме элемент уменьшается от **0%** (`κ=0`) до **20%** (`κ=1, α=.20`), без номинального укрупнения; фактический Gmsh `Q_V(x)` может отличаться. Сглаживать `log h`, **не** локальные независимые множители 18 зон. Для контроля перерасхода 64 GB/диска допускается уменьшение `α` или доли отмеченных зон **до** запуска, с записью причины в manifest; фактическое огрубление из-за remeshing должно быть явно показано.

После mesh-only GO рассчитать M2, сравнить с M1 и M0, построить M3 по **новым** физическим результатам. Сетка **M4 независимого контрольного дизайна** (новая CAD-связность или иной генератор/старт, **не использующий физический локальный индикатор M1→M3**) для проверки отсутствия переобучения адаптации.

### 4.3. Позднее — настоящий goal-oriented DWR

Когда код зрелый, вывести для нашей **3D нестационарной сопряжённой задачи и её аналитической геометрической производной** error-representation через невязки **прямого и сопряжённого** решения и подходящие веса (при необходимости более высокого порядка/дополнительные сопряжённые для производной функционала). Контроль `jpeak` с временным `argmax` требует отдельной аккуратности. Только этот выведенный/проверенный estimator можно именовать **DWR estimator of derivative error**. Разностная \(\eta_B\) выше — полезный пилот и явно помеченная эвристика.

## 5. Проверки, на которых алгоритм остановится

| Контур | Обязательные независимые результаты |
|---|---|
| CAD + surface-only | Radius/center/B6, physical groups; 2D Tri6 actual qcorner/curved checks; north/south, seam; rotated vs original Gmsh4.15.2 |
| 3D mesh-only | HXT10 in pinned environment; Tet10 27/343/729QP detJ>0, signed 18 zone `Q_V`/`N_eff`, all-volume Q, 3D element shape/grading, stored SHA/limits |
| Transport/time | Same physical coefficients, same time horizon, dt temporal/qp uncertainty; do not use noisy temporal bins to mark spatial regions |
| Shape-adjoint | Fresh forward + same-mesh adjoint; signed `G` components sum to each analytic global derivative; separate thermal/Robin/history, no double count |
| Scientific convergence | Crossmesh physical spatial bins, signed + `L1` differences, scalar derivatives for R/tz/y20 and j6/jpeak/jen E/ED/EDV/GH3; independent M4 control; stop on stagnation/disagreement |

Для пилота M1→M2 запрашивать сначала **один** режим `jpeak,R,EDV_VAR,ξ=0`; остальное подключать постепенно и явно. Не использовать для публикации статьи кажущуюся сходимость только по двум сеткам; зафиксировать точность относительно независимой M4, временную/квадратурную неопределённость и «дорогостоящую физику» отдельно от mesh-only.

## 6. Точный следующий эксперимент P10GG (ещё не выполнен)

1. Подготовить **Windows Gmsh4.15.2 2D-only** проверку двух точных CAD-вариантов (исходная сфера / поворот параметрических полюсов) с *одним* замороженным гладким `κ=1` размером для M1. Без `-3`, без FEM, без модификации существующих user M0/M1V/M1W и used one-shot markers; запуск без ввода символов, терминал/отчёт остаются видимыми. Сохранить оба `.geo`, 2D `.msh`, native Gmsh console log, SHA в `LOCAL_RUNS`.
2. Независимо проверить 2D curved geometry, полярные Tri6, ориентацию, метки, `q_corner` и размер. Если нет качественной поверхности — STOP и 3D не запускать.
3. Подготовить **одну** 3D HXT10 M1-кандидатуру с C¹ callback и, отдельно, контроль `PostView` interpolation (без 3D Delaunay tuning). Перед сборкой зафиксировать порог 3D acceptance и ресурсы; после native Windows 3D оценить geometry/global Q/legacy18/robust bins. Только после полноценного QC обсуждать GO на физику.

**Состояние на момент записи:** это проверяемая программа научного исследования, **не подтверждённая успешной M1**, не новая физика, не выдача `approvals`. Отличать от действующего старого P10FV hard gate до явного внедрения протокола.
