## CPU diagnosis, confidence boundary
20% is user's Task Manager observation, NOT independently sampled from archive. No process/thread CPU-time telemetry, cannot establish exact bottleneck. With 8 logical CPUs, 4 permanently occupied threads would nominally show ~50%; 20% ≈1.6 logical CPU equivalents on busy-time scale; Windows utility reporting, Turbo Boost, SMT, phase scheduling can change it. The source sets omp_set_dynamic(0) and omp_set_num_threads(c.threads) (stage3d10n_base_m_impl.inc / stage3d10w_analytic_adjoint.cpp), compiled -fopenmp, native regime threads=4. So four are CONFIGURED, not necessarily saturated.
Source mechanical.cpp parallelizes sparse projected SpMV and Jacobi preconditioner only in eligible loops (if(n>2000)); dot/vector parallel only if(n>50000), with sequential assembly/control and frequent synchronization. Native log shows 108 mechanical adjoint solves and many hundreds (~400–480) of CG iterations per solve. Fine-grained parallel regions and nonparallel work may explain low average CPU, but this remains inference. Optional SGS preconditioner triangular sweeps are serial but flags stage06_sgs=false by default and evidence does not prove SGS path used: DO NOT attribute measurement to it. Memory and I/O waits possible but unmeasured.
