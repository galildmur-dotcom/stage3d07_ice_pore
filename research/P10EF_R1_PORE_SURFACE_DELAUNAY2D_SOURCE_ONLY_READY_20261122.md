# P10EF R1 — минимальное контролируемое сравнение 2D Frontal-Delaunay и Delaunay у сферической поры

**Дата:** 22.11.2026. **Статус:** `P10EF_R1_SOURCE_ONLY_PREPARED; NO_NATIVE_GMSH; NO_NEW_M2; FEM0`. По запросу исследователя после P10EE выполнена подготовка **одного нового кандидата только 2D-поверхностного опыта**. Никакая новая native `-1/-2/-3` попытка не разрешалась и не запускалась; исторические P10EA/P10DO/P10DW маркеры не затронуты.

## 1. Что уже доказано и чему посвящён новый тест

- P10ED непосредственно по оригинальным raw M1/M2 (SHA original M1 `ca6b6b6588dc72c5dd3ed2e92e24794560ee2407e350c8a44858e9c3c7d0360f`, M2 `ba1f1a0553a568c1b399acadd52bce1c1dc32e8d1c6b3ab1ce6759c547e5dee5`) показал, что пространственный объёмный полярный коэффициент M2/M1 ≈0.9900, а не0.8; оба полюса не достигли цели.
- P10EE непосредственно по криволинейным Tri6-QP доказал, что характерная площадь поверхностных элементов M2/M1 у полюсов **север1.07696, юг1.03841, оба1.05707**, при целевой `0.8^(2/3)=0.861773876`. Подтверждённый исходный Gmsh -3 лог показывал **2D Frontal-Delaunay**, затем 3D HXT с сохранённой границей.
- Исходная P10EA R1 уже назначала `Background Field=6` **глобально**; «забыли задать сгущение на поверхности» неверно как описание кода. Неизвестно, приведёт ли иной 2D алгоритм к лучшему попаданию в целевой размер. Это и есть **новый единственный диагностический вопрос** P10EF.

Единственная исполняемая разница между оригиналом A и кандидатом B:

```diff
 Field[6].F = "<тот же точно исходный F6 MathEval>";
+Mesh.Algorithm = 5;
 Background Field=6;
```

**Эта запись в таблице — сокращённое представление diff для человека**, фактический проверенный кандидат содержит исходную F6 строку целиком без изменений. `Mesh.Algorithm3D=10`, quadratic `Mesh.ElementOrder=2`, `nearSize=0.42855883184652975м`, κ C¹∈[0,1], все исходные F2/CAD/физические группы и target volume `1−0.20κ` идентичны. Нет дополнительного «сгущения поверхности» или второго κ-множителя.

Согласно [документации Gmsh4.15.2](https://gmsh.info/doc/texinfo/) `Mesh.Algorithm=5` — Delaunay 2D, `6` — Frontal-Delaunay 2D (default); это независимая настройка от `Mesh.Algorithm3D=10` (HXT). Изменение **пока не проверено native Gmsh -parse_and_exit**: оно прошло статическую проверку исходников и отрицательные тесты, но неизвестно, будет ли генерироваться лучшая 2D сетка.

## 3. Почему именно один новый **2D**, а не сразу полноценная новая M2 3D

Старый исходный алгоритм6 уже представлен **реальным оригинальным P10EA M2** — повтор A запрещён и научно избыточен. Для проверки действия 2D mesher достаточно одного будущего нативного `gmsh -2` кандидата B (с quadratic Tri6 и физическим pore wall). Это не новая M2 Tet10, не FEM и не общая сеточная сходимость. Если кандидат B не улучшит поверхность, новая дорогая 3D бессмысленна.

Рекомендуемый *будущий*, **ещё не реализованный** защищённый Windows one-shot протокол после отдельной санкции: новый каталог и новые P10EF-only local/profile markers, исходный P10EA ZIP/EXE SHA, свежий source и два native `-parse_and_exit` **без расхода one-shot** на 01, затем отдельная кнопка 02 с новой точной ручной фразой и одним `-2 -nt 2 -format msh2`. Предлагаемые caps: wall120с, polled private≤2GiB, generated mesh≤25MiB, full log≤4MiB, 2threads, no FEM; маркеры непосредственно перед native запуском, даже STOP расходует попытку. Эти caps **не утверждены исследователем как разрешение на run**. P10EF ZIP не содержит кнопки02 и не может автоматически запустить Gmsh.

После будущего единственного B2D результат необходимо сравнить с оригинальными M1 и P10EA M2 на одной и той же сферической поверхности:

1. По каждой полярной шапке `abs(mu)≥0.8` независимо пересчитать curved Tri6-QP и эффективные площади. Целевой **B2D/M1**≈`0.861773876`; историческое **P10EA M2/M1**≈`1.07696` (север) / `1.03841` (юг) показывает исходный дефект.
2. Контролировать global curved sphere area против точной `4πR²`, а также положение Tri6 узлов на поверхности сферы, физическую принадлежность и отсутствие неположительного surface Jacobian.
3. Для перехода к отдельной будущей M2 3D требуется **отдельное** разрешение и новый Tet10 full27QP gate: обе полярные шапки объёма κ=1 должны приближаться к target0.8, слой0.1–0.5мм — к локальной κ-взвешенной цели; вне поддержки κ изменения должны быть контролируемыми.
4. **Точные числовые допуски GO/STOP пока не утверждены:** скрипт проверки будет экспортировать фактические отношения, а не объявлять приёмку из одного только числа Tri6. Нельзя автоматически разрешать physical FEM даже при хорошем surface 2D.

## 4. Чек-лист выполненных source-only проверок

- Публичная исходная P10EA ZIP SHA фиксирована, ZIP CRC оригинала PASS; исходная control F6 GEO SHA совпала; CAD SHA совпал.
- Candidate B = control A **плюс ровно одна вставленная строка** `Mesh.Algorithm = 5;`. Все остальные байты исходного κ-поля, CAD, F2 и параметров не изменены.
- Сгенерирован неизменяемый при повторе локального builder ZIP; повтор build даёт **тот же SHA256**; ZIP7/7 CRC, pinned6/6; `CMD` CRLF без BOM.
- Проверка извлечённого независимого ZIP `--check` и `--selftest` PASS; **4/4** намеренных in-memory подмен алгоритма, Background Field, повторной строки, CAD отклоняются; отдельно подмена исходного GEO внутри временной распаковки STOP. Linux/assistant новый Gmsh, FEM, old markers **0**.

**Научный вывод/следующий барьер:** P10EF — корректно изолированный **source-only кандидат**, который специально отделяет возможное влияние выбора 2D mesher от κ/геометрии. Для выяснения механизма нужен уже новый физический (но mesh-only!) результат **одного 2D B**; его нельзя считать санкционированным текущим source-only согласием. Если исследователь разрешит такой новый P10EF-only 2D one-shot с отдельно описанными лимитами, следующим кодовым шагом будет безопасный отдельный launcher и затем один Windows evidence. Никакой новый 3D M2 или physical FEM на данном этапе не допускается.
