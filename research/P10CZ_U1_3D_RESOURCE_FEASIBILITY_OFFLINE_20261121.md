# P10CZ — ресурсная выполнимость объёмной U1_geo, только аналитика

**21.11.2026, после P10CY.** D-018A сохраняется. **Нет ни одной новой 3D `.msh`, Gmsh `-3`, Tet10 27QP или FEM**. Поверхностная U1_geo на Windows Gmsh4.15.2 — только 2D geometry PASS (P10CY), не гарантия объёмного качества.

## 1. Барьер новизны

P10CT R2 проверил лишь грубую **глобально равномерную** h2мм U0 и выявил отсутствие nearwall corner-centroids. P10CU показал недоступную цену уменьшения глобального h до 0.1–0.5мм. P10CV ввёл локальный размерный профиль, P10CW/CX/CY проверили только 2D поверхность сферы ~20мкм, включая оба полюса. **Новый вопрос:** ресурсная цена **всего объёма** при P10CV radial size-field, прежде чем создавать дорогую 3D сетку.

## 2. Математическая оценка, воспроизводимая без Gmsh

Для сферической поры R=1мм вводим расстояние `d=r−R` (мм). В P10CV `Field[5]=Max(Field[3],Field[4])` с двумя линейными Threshold; идеализированная непрерывная по `d` функция `h(d)` имеет масштабы 0.02мм у стенки, 0.2мм в средней зоне и 2мм при d≥12мм. Переходы d=0.02;0.8;1.81818;12мм, причём на d=0.8–1.81818мм h=0.2мм из-за операции Max.

Сферические оболочки полностью лежат в коробке 60×60×50мм до r=13мм, поэтому без пересечения с внешними границами вычислим

`I=∫₀¹² [4π(R+d)²/h(d)³] dd + [V_box−(4π/3)(R+12)³]/h_far³`.

Численное интегрирование серединами с 10 000/20 000 шагами на каждом интервале прошло контроль устойчивости: **I=156785.811962** (безразмерно). Для идеального регулярного тетраэдра со стороной h объём `V_tet=(√2/12) h³`, коэффициент числа элементов `C=12/√2≈8.48528`: `N≈C I`. Это *не* математическая нижняя/верхняя оценка фактического Gmsh Tet10, потому что h — заданный размерный параметр, фактические рёбра и качество отличаются.

Независимые масштабы: на старой U0 **90725** Tet10 при target h2мм даёт целообъёмный эмпирический коэффициент **C_U0=4.03232** (не переносится автоматически на nearwall). Реальная Windows поверхность **74578 Tri6** при median hmax20.0128мкм даёт surface coefficient `N h²/A=2.37693`, близкий к регулярному эквиваленту `4/√3=2.30940` (порядок масштаба, не доказательство объёмной регулярности).

| 4.0323 (историческая U0) | 632210 | 10.83 | 108 |

Модель памяти — **исторические `state_buffers_gib=8.14395` на 475544 Tet10 H4W5B20**, линейное масштабирование. Она описывает лишь условный будущий FEM state-buffer proxy, **не пиковую RAM Gmsh/Windows**, не адекватна для разрешения нового FEM и не включает нелинейные истории, Jacobian QA, матрицы, ОС. Объём файла — исторический `16 218 389 B /90725 Tet10` от грубой U0: также не верхняя граница.

## 3. Концентрация элементов возле стенки

При одинаковом C на всех оболочках на физическом слое `d=0–20мкм` приходится **32048.43/I=20.4%** оценки числа элементов; на `d=20–100мкм` — **54501.43/I=34.8%**. Итого **около 55.2%** всех Tet10-proxy уже в зоне `0–100мкм`, объём которой всего ~1.3865мм³ при всём льде почти 180000мм³. Это ключевой источник стоимости и возможной межоболочечной градации; объяснение локальных приполюсных производных из этой доли не следует.

## 4. Консервативный протокол будущего единственного 3D mesh-only gate — проект, не разрешение FEM

- **Цель:** одна U1_geo исходной геометрии, Gmsh4.15.2, `-3`, 2 потока, MSH2 ASCII, Tet10, Tri6, physical groups 1–9; никакого polar/azimuth size-bias и никаких изменений `G:\ildar\Stage3D07`. Каждый FEM forward/adjoint остаётся на одной сетке D-012, но сейчас FEM запрещён.
- **Предлагаемый watchdog** для предварительно аттестованного one-click (ещё не создан): preflight ≥16ГиБ свободной RAM, ≥4ГиБ места; Gmsh максимум **900с /10ГиБ private /750МиБ MSH**. CPU/диск после выхода документировать, не продолжать после timeout. N(Tet10) **>2 000 000** = STOP_RESOURCE_FOR_FEM_BASELINE до дальнейшего решения, а не автоматический FEM.
- **Независимый QA после генерации**: verified MSH SHA, full physical tags, Tet10/side Tri6, 27 positive sampled curved detJ на всех Tet10 по доступному ресурсу; при невозможности full QA — STOP_QUALITY_UNVERIFIED, не выборочная замена по умолчанию. Отдельная проверка straight-corner inversions и качества; 27QP не гарантируют continuous detJ>0.
- Важно вместо corner-centroids использовать **физические криволинейные QP** и их веса/объёмы для `d=0–20мкм`, `20–100мкм`, `0.1–5мм`, вне B6 и `10 μ×12 φ`; полюса сравнить с экватором по элементам, QP-count/volume, local h, качеству. Отдельно учитывать отклонения срединных узлов, особенно полярные элементы.
- Вслед за N estimate 1.33 млн на 27 QP/Tet10 получится ~35.92 млн точек, поэтому контролю нужны потоковая обработка/порог RAM и собственный watchdog (предварительно QA≤1200с, ≤10ГиБ private); недопустима память `O(N×27)` с полным накоплением QP.
- **Критерий научной достаточности** по стенке пока NOT CALIBRATED: наличие QP и positive Jacobian необходимо, но не достаточно для точного D_Rjpeak. Первый physical baseline R/EDV_VAR/ξ0/jpeak, dt/t_f и подписанные mechanical+thermal 4D компоненты — **отдельный санкционируемый этап**, не часть mesh-only.

## 5. Честное заключение

Ресурсная оценка не опровергает выполнимость локально сгущённой U1_geo на i7-7700K/64ГиБ: разумные сценарии **0.63–1.88 млн Tet10** возможны геометрически, но стресс-сценарий 3.14 млн и накладные расходы могут сделать последующий FEM дорогим или недопустимым. Нельзя называть сценарии доказанными границами или автоматически считать U1 пригодной для объёмного расчёта.

**P10CZ_OFFLINE_RESOURCE_FEASIBILITY_OK_NO_MESH_NO_FEM.** Следующий единственный шаг ассистента: подготовить и синтетически испытать один **защищённый Windows mesh-only 3D** пакет по этим ограничениям, обеспечив native exit, остановку на лимитах и переносимый QR/27QP аудит; лишь затем исследователь запускает одну попытку. Новый physical FEM не разрешён. Периодические повторения старых 2D и P10CJ–P10CR: STOP_DUPLICATE.
