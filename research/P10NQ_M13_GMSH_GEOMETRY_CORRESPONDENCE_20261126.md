# P10NQ — геометрическая проверка изменений Gmsh HighOrderElastic

Результат P10NP: после оптимизации на прежних числовых тегах изменились координаты 4 420 граничных узлов, связность по тегам 5 893 Tet10 и 2 306 Tri6. Попытка восстановить границу по старым тегам сделала оценку `minSJ` некорректной. Поэтому нельзя считать, что прежний тег узла обозначает ту же геометрическую точку.

P10NQ повторно загружает **исходную M13 R2** SHA256 `57403ba43fa299417d519046cebdf50fa4968b670c071a8b7882748b50f51e9c`, выполняет `HighOrderElastic` строго **в памяти** и сравнивает:

- наборы узлов, номера Tet10 и Tri6, глобальные связности и множества угловых/всех узлов каждого элемента;
- облака точек физических поверхностей 2–9 и отдельно поверхности поры (физическая группа 8) независимо от номера каждого узла;
- двунаправленное расстояние Хаусдорфа, 95-й процентиль ближайших расстояний, количество точных совпадений (допуск 1e-12 м);
- радиусы всех точек физической группы 8 относительно центра (0, 0, 0.03) м, номинальный R=0.001 м.

Эта проверка выявит, действительно ли изменяется геометрическая поверхность или значительная доля различий по одинаковым тегам вызвана перестановкой/переназначением узлов. Совпадение облаков **само по себе не доказывает** соответствие элементов и сохранение геометрии криволинейных Tri6; проверка используется только для выбора следующего метода.

На Windows 11 распакуйте ZIP и запустите `P10NQ_RUN_GEOMETRY_AUDIT.cmd`. Требуются `numpy` и Python API `gmsh==4.15.2`. Пришлите `P10NQ_GEOMETRY_CORRESPONDENCE_RESULT.json` и `P10NQ_GMSH_GEOMETRY_LOG.txt`.

Ни один изменённый MSH не записывается, FEM/генерация сетки/one-shot маркеры не используются, M13 R3 не объявляется.
