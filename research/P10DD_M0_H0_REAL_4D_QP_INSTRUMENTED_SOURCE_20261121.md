## 2. Точный контракт реализации

Отдельный C++ target `stage3d10dd_m0_h0_full4d`; введён только compile-time flag `STAGE3D10DD_FULL4D` в исходной паре `src/stage3d10p_partial_audit.cpp` / `src/stage3d10w_analytic_adjoint.cpp`. Остальные существующие Targets не включают флаг, их формулы/результаты сохраняются. Физический `forward`, adjoint механики и тепла, жёсткость, вязкоупругая история и нормировка `jpeak` используются **те же**, что P10W. Дополнительный независимый диагностический обход:

1. После вычисления трёх механических adjoints на каждом шаге: для `jpeak` с фактическими `λ_n`, будущими `e_d/e_v`, `weight_n` и `P10V` аналитическим оператором вычислить *в каждом из 27 QP каждого Tet10* `w_n·d(J_B6/V_B6)`, `λ_n·dR_e` и `future_n·dPhi_e`. Все три суммы по 1200 корзинам сверить **отдельно на каждом шаге** с неизменёнными global P10V terms. Для нормированного J_B6 сначала отдельно накопить `J` и `V`, только после этого применить `d(J/V)=(dJ-(J/V)dV)/V` в каждой корзине. Вне B6 явная часть 0, но mechanical residual/history могут быть распределены по другим объёмным элементам.
2. После каждого теплового backward adjoint `ψ_n` заново свернуть 64 QP/Tet10 с **точными** shape terms: `rhocp*dw*ψ*(θ_n−θ_{n-1})` и `dt*k[dw*∇ψ·∇θ+w*(d∇ψ·∇θ+∇ψ·d∇θ)]`, плюс `dt*h*d(area)*ψ*(θ_n−θ_ambient)` на верхней поверхности Tri6. Проверить каждую сумму против исходного unchanged thermal CSR contraction; провал STOP.
3. Координаты — **физические криволинейные x(QP)**, не corner centroid. 10 radial-distance от стенки поры ×10 equal-μ (`μ=cos θ` с экспортом реальных θ границ) ×12 equal φ (−π,π), 6 временных шагов. По φ не усреднять; QP на оси имеют conventional φ bin0 и отдельный счётчик; это не способ вывода приполюсной причины. **TOP_ROBIN** — ровно одна отдельная строка каждого шага вне объёмных корзин.
4. Четыре CSV: `P10DD_SIGNED_R_THETA_PHI_T.csv` (7206 rows), `P10DD_FULL4D_CLOSURE_AUDIT.csv` (6 rows), прежние `P10W_COMPONENTS.csv`/`P10W_ANALYTIC_ADJOINT.csv` и `P10W_STEP_COMPONENTS.csv`. Три механических + три тепловых signed компоненты в m⁻¹; сохраняются QP counts и `volume_m3`. Условие: **механическая компонента на каждом шаге** совпадает с оригинальным P10V, thermal на каждом шаге — с CSR; **итог за шесть шагов** совпадает с P10W полной производной. Отдельный stdlib Python аудит независимо проверяет 7206 строк, `7388×27` и `7388×64` QPs/шаг, 6 STEP totals, global components и total. При любой ошибке STOP, не выпускать результат за PASS.

Формулы не используют центральные конечные разности геометрии, дополнительную вторую сетку для adjoint или смещение физической области наблюдения. **Не гарантируется поточечное равенство с непрерывной плотностью производной формы**: это QP локализация *дискретной* производной с ограниченной на B6 нормировкой, без утверждения о сходимости. Анализ сгущения M1 по D-018D вообще не использует индикаторов; только M2 может учитывать две прошедшие полные физические карты.
