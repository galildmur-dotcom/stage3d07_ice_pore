# P10HC — одношаговая проверка источника κ для Gmsh

Пакет является **только источником**, не запускает построение сеток (ни 2D, ни 3D), физику FEM, Qt/CMake/adjoint и не изменяет старые one-shot markers.

1. Распакуйте ZIP в новый отдельный каталог, например `G:\ildar\Stage3D07\P10HC_SOURCE_TOOLS`.
2. Двойным щелчком запустите только `01_P10HC_PREFLIGHT_PARSE_ONLY.cmd`.
3. В окне будет показана диагностика. Передайте `P10HC_01_PARSE_EVIDENCE.zip`. При ошибке приложите также `P10HC_01_RESULT.txt`.

Нужны Windows, Python `py -3` (установленный в предыдущих этапах), оригинальный Gmsh 4.15.2 по пути `C:\gmsh-4.15.2-Windows64\gmsh.exe`. Научный источник `P10HC_M2_SOURCE_ONLY.geo` ссылается на локальные `P10GT_HXT10.geo`, `M0_ROTATED.geo`, `sphere_pore_B6_refined_rotated.geo` и `P10HC_CONTINUOUS_KAPPA_FIELDS.geo` из пакета. Их SHA до нативного разбора проверяются автоматически.

Ограничение 180 секунд на парсинг. Ожидаемый результат — проверка **синтаксиса** `Gmsh MathEval` длиной ~1.13 млн символов, а не проверка фактической стоимости оценки поля при мезинге. Успешный парсинг *не* даёт GO на M2 и не доказывает D-025; после него отдельно проверяются поле на физических координатах и управление поверхностной/объёмной генерацией.

Номинальная формула характерного объёма `V_target/V_M1=1-0.17 κ` при κ=1 ориентирована на уменьшение 17% в пределах 15–25%; Gmsh не гарантирует это численно. Для текущей непрерывной математической модели κ применяется только механическая чувствительность из 4D-данных M0/M1, все тепловые источники сохранены без участия в score.

Ни `.msh`, ни фактический новый FEM не создаются этим пакетом. В случае неуспешного разбора **не** запускайте прежние P10G* программы для обхода остановки.
