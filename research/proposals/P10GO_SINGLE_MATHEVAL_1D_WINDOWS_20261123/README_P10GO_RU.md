# Stage3D07 P10GO R1 — одно самодостаточное поле размера Gmsh

**Диагностический 1D этап. НЕ выпуск новой M1, НЕТ 3D/FEM.** Старые
P10GL/P10GM/P10GN native one-shot уже израсходованы. Не повторять их `02`,
не удалять маркеры и не перезаписывать M0/P10GK.

## Почему теперь один MathEval

Настоящие Windows Gmsh4.15.2 журналы P10GN доказали: `Field[7].F="F3"`
и `Field[7].F="F3*0.94"` оба TIMEOUT30сек на окружностях14/17; в P10GM
прямой `Background Field=3` завершился за 0.51сек. Ссылка на другой
MathEval поле формально допустима по документации, но в этом pinned CAD
воспроизводимо вызывает задержку. **Точная внутренняя причина неизвестна.**

В P10GO исходное C¹ поле M0 F3 и южная поправка P10GK раскрыты
непосредственно в одной строке `Field[7].F=StrCat(...)`: не остаётся
ссылок `F3/F4/F5` внутри нового выражения. Исходные `.geo` и `.msh`
остаются без изменений; target alpha=0.06, глобальный factor=.9378887276834518,
гладкие зоны влияния и frozen D-027 **полностью сохраняются**.

## Один короткий native опыт Gmsh `-1`

| Случай | Background field | Назначение |
|---|---|---|
| `A_ORIGINAL_F3` | исходное C¹ `F3` прямое | Контроль Gmsh/геометрии |
| `B_SELF_CONTAINED_C1_SOUTH` | новое единое `Field[7]` без ссылок на другие поля | Проверить обход установленного замедления |

Максимум **два** native Gmsh4.15.2 `-1 -nt 2` по **30 секунд каждый**,
Windows Job private RAM≤8GiB, ограничение размера результатов, живые
строки Gmsh+`HEARTBEAT` каждые2с. После A STOP B всё равно запускается —
ограниченно и в отдельной папке для независимого результата.
Ни один driver не содержит команды Meshing 2D/3D, а фактический CLI
содержит только `-1`; никаких HXT10 3D/производных/FEM.

## Что сделать на ПК

1. Распаковать **новый** P10GO ZIP в
   `G:\ildar\Stage3D07\P10GO_TOOLS_R1` отдельно от прежних пакетов.
2. Двойной щелчок `01_P10GO_PREFLIGHT_NO_MESH.cmd`. Получить
   `P10GO_PREFLIGHT_PASS_NO_MESH`: SHA original P10GK source, M0.msh,
   Gmsh.exe, exact F3 StrCat, 10 201 математических точек, C¹ seams.
   01 не запускает Gmsh mesh, только Gmsh `-version`.
3. При PASS в пределах24ч **ровно один раз** запустить
   `02_P10GO_ONE_1D_SINGLE_FIELD_TEST.cmd`, подождать ≈1–1.5мин.
   Вводить пути или подтверждения не нужно. При неудаче native Gmsh
   остановится сам через30с, окно всегда показывает прогресс.
4. Передать **один** файл
   `G:\ildar\Stage3D07\LOCAL_RUNS\P10GO_SINGLE_MATHEVAL_1D_*\P10GO_1D_PROBE_EVIDENCE.zip`.
   При отсутствии ZIP — `P10GO_02_RESULT.txt`/текст окна.

P10GO имеет **собственные** локальный и профильный one-shot markers, которые
создаются до native `-1` и не восстанавливаются. При любом STOP `02` не
повторять. Никакой автоматической новой 3D сетки или FEM после PASS.

## Строго научное значение

- Если A быстро PASS и B быстро PASS, это подтверждает работоспособность
  нового способа вычисления размера **только на 1D**; сам размер/градация
  2D/3D и эффективность локальной адаптации останутся непроверенными.
- Если B TIMEOUT, гипотеза о вложенной ссылке недостаточна: следующий
  шаг — отдельная изоляция сложности выражения или API size callback.
- Математическая эквивалентность полей, положительный h и гладкость C¹
  проверяются source QA, но не заменяют native результаты.
