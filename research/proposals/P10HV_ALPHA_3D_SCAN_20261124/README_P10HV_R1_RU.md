# P10HV — три пробных 3D-сетки для проверки устойчивости адаптации

Независимый P10HU подтвердил геометрию P10HT: 14071 узлов, 9693 Tet10, QP343/729 положительные якобианы, полный объём льда закрывается с относительной погрешностью около 1.2e−8. Однако при α=.17 объёмы в северной приполярной области 0.1–0.5 мм уменьшились на 7.9%, а в южной выросли на 3.6%. Это умеренная перестройка, допускаемая пользователем, но не доказательство 15–25% локального уменьшения при κ=1.

Чтобы понять чувствительность к параметру, **в одном защищённом запуске** будут последовательно построены только три тестовых кандидата на неизменном CAD P10GT и замороженном механическом κ подписанных M0/M1 4D: 

- α=0.15 (номинально 15% объём при κ=1),
- α=0.20 (номинально 20%),
- α=0.25 (номинально 25%).

α=0.17 уже представлен полностью проверенным кандидатом P10HT и **не повторяется**. Между случаями очищается только сетка Gmsh, не CAD/поля. Для служебных запросов внутри воздуха используется P10HT радиальное продолжение к стенке, никогда — изменение κ в реальном льду. На выходе три ASCII MSH Tet10 только для независимого геометрического сравнения, без FEM и принятия M2.

Распаковать и запустить `01_P10HV_THREE_ALPHA_3D_NO_FEM.cmd`. Общие пределы: **600 секунд на всю серию**, 6 млн вызовов, отчёт о ходе каждые 15 с. При вашем i7‑7700K ожидается **1–10 минут** максимум с учётом накладных расходов; возможная первичная установка Gmsh API в локальное окружение 1–5 минут.

Вернуть **только `P10HV_THREE_ALPHA_3D_EVIDENCE.zip`** при PASS. При STOP — `P10HV_GUARD_RESULT.json`, `P10HV_GMSH_LOG.txt` и `P10HV_WORKER_ERROR.txt` при наличии. После этого мы *независимо* применим к каждому кандидату те же 343/729 квадратуры и зональные проверки объёмов против исходной M1, выберем приемлемый вариант без навязывания большого прироста числа элементов. Физические расчёты не разрешены до отдельной проверки.
