# P10IJ — первый реальный физический расчёт на M2

**R2:** исправлен выход Python `SystemExit(0)`, который в R1 ошибочно превращал успешный preflight в `EXIT=2`. Если R1 написал `P10IJ_M2_PREFLIGHT_PASS_NO_FEM`, FEM и one-shot marker ещё не были запущены. Распаковать R2 в новую папку и выполнять описанные ниже действия.

Данные: **неизменённая принятая M2 P10IE**, SHA256 `d1ec65ffcc6e8fac7da925ecd66bbb9508450cf2ea837521442f57f45674c78b`, 9840 Tet10, 14305 узлов, 216 pore Tri6. Исходная CAD и геометрическая постановка сохранены; сфера уже развёрнута на 90° в построении P10IE. Метки MSH2 проверены независимо. **Новый Gmsh запуск не выполняется.**

Физика: `R`, `EDV_VAR`, `ξ=0`, `B6=5 мм`, `t_final=900 с`, `dt=25 с`, 36 шагов, 4 потока, полная свежая прямая задача + согласованное аналитическое same-mesh сопряжение и signed 4D mechanical/thermal. Именно такой временной режим уже есть для M0/M1 в P10GY и P10GZ. Шаг 25 с НЕ объявлен локально временно сошедшимся (P10GZ); это сопоставимая первая серия.

## Запуск на Windows 11

1. Распаковать весь ZIP в **новую** директорию `G:\ildar\Stage3D07\P10IJ_M2_FIRST_PHYSICS_R1`. Не смешивать с прежними пакетами, не заменять старые M0/M1, не удалять старые markers.
2. Двойной клик `01_P10IJ_M2_PREFLIGHT_NO_FEM.cmd` — только проверка SHA исходников и M2, 27 QP curved detJ, физических меток; физического расчёта **нет**. Ожидаем `P10IJ_M2_PREFLIGHT_PASS_NO_FEM` и `P10IJ_PREFLIGHT_EXIT=0`.
3. Двойной клик `02_P10IJ_M2_FIRST_FULL4D_ONE_SHOT.cmd` — **один** FEM только M2, новый компилируемый `stage3d10fn_any_mesh_full4d.exe` с проверяемым `--selftest` (физический EXE наследуется из P10GY R2). Второй клик по тому же успешно подготовленному EXE блокируется permanent one-shot marker. При STOP вручную не перезапускать, сохранить evidence и разбирать причину.

Точный target компиляции: `stage3d10fn_any_mesh_full4d.exe`, MinGW Qt Creator g++ `-std=c++20 -O2 -fopenmp`. Точный физический CLI (автоматически, без ввода): `build\stage3d10fn_any_mesh_full4d.exe --p10fn-authorized --mesh M2.msh --out <новая_директория>\P10FN_M2_DT25_R --mode R --steps 36 --dt 25 --cutoff-mm 5 --threads 4`; EXE требует переменную одноразового маркера, поэтому **не запускать его вручную**.

Лимиты: Windows Job **≤8 GiB private**, **≤40 минут wall**, **≤2 GiB** файлов расчёта; автоматических повторов нет. M2 всего на 2.25% больше M1 по числу Tet10; из P10GY 12 настоящих расчетов совокупное время 94.35 мин, максимальная память около 2.06 GB, поэтому ориентир на отдельный M2/dt25 ~10–25 мин, но это оценка, не гарантия. На ПК 64 GiB доступной оперативной памяти достаточно при обычной загрузке; лимит ограничивает именно процесс.

## Вернуть

Один небольшой `G:\ildar\Stage3D07\LOCAL_RUNS\P10IJ_M2_R_DT25_*\P10IJ_M2_FIRST_FULL4D_EVIDENCE.zip` даже при STOP. Внутри манифест, журнал EXE и пять signed 4D/P10W CSV. **Не присылать** `forward_history.bin`, не удалять его до завершения независимого аудита.

Следующая научная проверка **после** получения настоящего ZIP: независимая 4D/QP/closure QA, сравнение M1 и M2 при `dt=25`, всех шести знаковых частей, полярных физических областей и оценка временной неустойчивости P10GZ. Первый PASS native является результатом FEM, но не окончательным доказательством физической сеточной сходимости.
