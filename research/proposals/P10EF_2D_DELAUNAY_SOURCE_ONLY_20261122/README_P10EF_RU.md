# P10EF R1 — проект одного будущего 2D-only опыта Gmsh для поверхности поры

**Статус 22.11.2026: только подготовленные исходники / no native Gmsh, no FEM.**
Этот ZIP **НЕ содержит кнопку запуска 2D/3D**, только безвредную проверку исходников `01_P10EF_CHECK_SOURCE_ONLY.cmd`. Это не разрешение физического mesh-only запуска.

## Научный вопрос

В P10EE доказано, что поверхность поры M2 не уплотнилась при уже заданном глобальном F6. Gmsh 4.15.2 в P10EA выбрал **2D Frontal-Delaunay (алгоритм 6)** для сферы, затем 3D HXT сохранил границу. Важно отдельно проверить влияние **только 2D алгоритма** на ту же CAD и F6, без новой объёмной M2.

## Строгое сравнение

- `A_P10EA_EXACT_F6_ALG6_CONTROL.geo` — точная исходная P10DV/P10EA F6 GEO, SHA256 `32f8f959002cbd41539e355a80437c2ca3be12fdd3ba12de31eadf2c021b9561`; **исторический контроль уже построен** в существующей M2 P10EA. Алгоритм 2D там default6; **не запускать A заново**.
- `B_P10EF_EXACT_F6_ALG5_SURFACE_ONLY.geo` — **ровно одна вставленная строка** `Mesh.Algorithm = 5;` непосредственно перед исходным `Background Field=6;`. Никаких изменений κ, F2, CAD, near/far, 3D/HXT, physical groups и 20%-ной целевой функции.
- `sphere_pore_B6_refined.geo` — неизменённая исходная CAD SHA256 `8029a6ed22bcf312701cd6abc46bbe5575e52df16fd5218dd936b01d5cd6fcf0`.
- `P10EF_SOURCE_PIN.json` и `P10EF_SOURCE_CHECK.py` закрепляют SHA и отвергают подмены; сценарий `01_P10EF_CHECK_SOURCE_ONLY.cmd` лишь сверяет байты и структуру, не запускает Gmsh.

Изолировать отдельную директорию, не менять существующие P10DG/P10EA/M1/M2, `G:\ildar\Stage3D07`, `LOCAL_RUNS` и старые one-shot markers. Исходная M1 **только** `P10DG_M1_CANDIDATE.msh` SHA `ca6b6b6588dc72c5dd3ed2e92e24794560ee2407e350c8a44858e9c3c7d0360f`. Исходный старый M2 Frontal-Delaunay — `P10EA_M2_CANDIDATE.msh` SHA `ba1f1a0553a568c1b399acadd52bce1c1dc32e8d1c6b3ab1ce6759c547e5dee5`, не новый M2. **Оба raw MSH не включены в публичный ZIP.**

## Предлагаемый следующий native опыт — только ПОСЛЕ отдельной санкции

Один **новый P10EF-only Gmsh4.15.2 `-2`** по B, без `-3` и без FEM. Нужен отдельный новый one-shot launcher: собственные локальный/profile marker непосредственно перед `-2`, source SHA-pin + EXE SHA (Gmsh4.15.2 `317c43391e5b1fab3a1dd80dc5245dad6e2d087910f4b8ebc234bd6d4b8f41a1`), safe native `-parse_and_exit`, свежий preflight, явная ручная фраза, caps wall≤120с, private≤2GiB (периодический polling), `.msh`≤25MiB, log≤4MiB, 2 threads. Это **проект ресурсного протокола, не реализованный запускатель в этом ZIP**. Опасный повтор старого P10EA `-3` исключён.

Сравнение будет выполняться **между новым B-2D, принятым оригинальным M1 и исторической P10EA M2**, исключительно по стенке поры (Tri6) и 2D mesh source. После получения единственного native evidence требуется независимый расчёт curved Tri6-QP на двух фиксированных полярных шапках; требуемый *целевой* множитель площади к исходной M1 при κ=1 — `(1−0.20)^(2/3)=0.861773876`. Не сравнивать B с исторической P10EA M2 как с «базой0.8»: историческая M2 уже была неудовлетворительным алгоритмом6.

Если 2D B **не даёт сближения с целевой площадью в обоих полюсах** — `STOP_SURFACE`, новую 3D M2 не запускать. Даже если 2D B удовлетворителен — это не автоматический допуск к 3D: затем отдельное решение исследователя о новом bounded 3D mesh-only и самостоятельный Tet10-QP gate. **Допуск по числовому отклонению от0.861774 в P10EF R1 ещё не утверждён**; пока только диагностическое сравнение без автоматического GO.

По Gmsh 4.15.2, `Mesh.Algorithm=5` — Delaunay, `6` — Frontal-Delaunay; см. [официальные настройки и tutorial t10](https://gmsh.info/doc/texinfo/). Новая кандидатная GEO **ещё не подтверждена native Gmsh parse**; здесь только source/SHA/diff проверки.

**Ничего нового запускать на ПК исследователя пока не нужно.** Оригиналы, markers, H0/cache, forward/adjoint/FEM не тронуты. Отдельный допуск/кнопка потребуется в следующем этапе, если исследователь одобрит предложенный 2D-only опыт.
