# P10HL R2 — устранена ошибка отсутствующего модуля Python Gmsh

Факт R1: пользовательский Python 3.13 (`C:\Program Files\Python313`) получил `ModuleNotFoundError: No module named 'gmsh'`. Это **не ошибка самой функции κ** и не результат вычисления Gmsh. В R1 ни одной 1D-сетки не построено.

R2 создаёт локальный виртуальный Python-каталог `.p10hl_env` внутри распакованной папки, повторно использует установленный NumPy и при необходимости устанавливает **строго `gmsh==4.15.2`** из официального Python-репозитория пакетов. Готовый Windows x86-64 wheel 4.15.2 (~42 МБ) существует, поэтому компиляция не нужна. Системный Python не изменяется. Для первой установки потребуется интернет; если загрузка не удалась, программа завершится **до любого запуска Gmsh**. Ожидаемый первый запуск: **1–5 минут** в зависимости от сети; повторные запуски около 2–20 секунд.

1. Распаковать R2 в отдельный каталог.
2. Двойной щелчок `01_P10HL_R2_INSTALL_LOCAL_GMSH_AND_1D.cmd`.
3. Если всё прошло, прислать **`P10HL_RESULT.json` и `P10HL_LOG.txt`**.
4. При ошибке установки — **`P10HL_INSTALL_LOG.txt`**; при ошибке нативного теста — **`P10HL_ERROR.txt` и `P10HL_LOG.txt`**.

Единственный нативный опыт — искусственная прямая 5 мм с постоянным фоновой величиной 0.5 мм, проверяющая, что фактически принимает Gmsh callback в аргументе `lc`. **Никаких исходных CAD/M0/M1, M2, 2D/3D, FEM, D-025 GO**. Если результат не подтверждает известный исходный размер, изучить журнал, а не запускать M2.
