# P10EZ — одна короткая проверка MathEx, только Windows Gmsh -1

Исследователь разрешил **один** новый диагностический опыт. Цель — заставить
точный исправленный P10EY `Field[6].F` вычисляться в Gmsh 4.15.2, а не
только проходить `-parse_and_exit`. Это **не** новая M2 и **не** FEM.

1. Распаковать ZIP **в отдельный каталог вне** `G:\ildar\Stage3D07`.
2. Один раз открыть `01_P10EZ_SAFE_PREFLIGHT_ONLY.cmd`. Только если результат
   `P10EZ_PREFLIGHT_PASS_NO_MESH`, продолжить в пределах 24 часов.
3. Один раз открыть `02_P10EZ_ONE_MATHEX_1D_ONLY.cmd`, ввести точную фразу
   `RUN ONE P10EZ MATH 1D` и дождаться завершения (не более 20 секунд
   собственно Gmsh -1). **Не повторять 02 даже после STOP**.
4. Прислать **один оригинальный** `P10EZ_EVIDENCE.zip` из последнего каталога
   `P10EZ_RUNS/P10EZ_...`. Не нужно передавать исходные расчёты или H0/M1.

Проверяются SHA точного P10EY GEO и native Gmsh EXE, версия 4.15.2,
два новые эксклюзивные постоянные маркера (локальный и `%LOCALAPPDATA%`),
fresh-proof, журнал и три физических одномерных линии 101/102/103.
Лимиты: 20 с, private memory 2 ГиБ, mesh 10 МиБ, журнал 2 МиБ, `-nt 2`.
Нужны не менее 4 ГиБ свободной памяти и 300 МиБ диска.

Оценка на i7-7700K: обычно **до 1–5 секунд**, один пакет в пределах
нескольких мегабайт; при зависании автоматическая остановка через 20 с.

В случае любого STOP оставить оба маркера в покое, **не** запускать
P10EX/P10EW/P10EV 02; сообщить результат. Реальная `M2`, D-025,
Tet10/curved27QP и FEM по итогам P10EZ **не подтверждаются**.
