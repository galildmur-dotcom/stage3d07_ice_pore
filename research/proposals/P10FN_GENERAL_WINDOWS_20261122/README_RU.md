# Stage3D07 P10FN — две универсальные программы для Windows 11

**Режим: без ручных фраз, без ожидания ввода, без скрытых повторов.**

Первый пакет включает самостоятельные исходники проверенного P10DL
физического ядра и точный исходный `P10EY` гладкого поля M2. Годен для
M2→M3, затем по новым файлам `recipes/ACTIVE.json` для M3→M4 и далее.
Исходные пользовательские M0/M1/M2 **в ZIP не включены**.

## Единожды подготовить

1. Распаковать ZIP в отдельную папку, например
   `G:\ildar\Stage3D07\P10FN_TOOLS`. Не поверх исходного кода проекта.
2. В `G:\ildar\Stage3D07\meshes` разместить **точные исходные файлы**:

   - `M0.msh` — оригинальный H0, SHA-256 `e28d6049afc4b20b474152d315952361b01dce7052f7642d03a20ce8274d41f8`;
   - `M1.msh` — оригинальный P10DG, SHA-256 `ca6b6b6588dc72c5dd3ed2e92e24794560ee2407e350c8a44858e9c3c7d0360f`;
   - `M2.msh` — исходный P10FB/P10EA, SHA-256 `ff6500e2da4f4697e1788669e2404d33cdeb9435c1230cf14f5cc7619f1f6a44`.

   Допустимо просто **копировать и переименовывать**, не изменяя байты.
   Проверка SHA не позволит незаметно подменить сетку. Если один из
   исторических исходных `.msh` отсутствует, не создавать его заново
   под тем же именем: запросить настоящий файл из старого расчёта.
3. Установлены Python 3 (стандартная библиотека; NumPy не требуется),
   `C:\gmsh-4.15.2-Windows64\gmsh.exe` и MinGW `g++.exe` с OpenMP из Qt Creator.
   Компилятор ищется автоматически в PATH, `C:\Qt\Tools\mingw*\bin`,
   `G:\Qt\Tools\mingw*\bin`, `C:\msys64\mingw64\bin`.
   При необычном месте установки можно единожды задать `P10FN_GPP` в
   системных переменных, без ввода в каждом запуске.
4. Дважды нажать `00_CHECK_PROGRAMS_NO_RUN.cmd`. Без FEM и Gmsh проверяет
   SHA исходников, структуру рецепта и физические допуски.

## Шаг I. Сгенерировать очередную сетку

Дважды нажать **`01_GENERATE_NEXT_MESH.cmd`**. Начальный `ACTIVE.json`
создаёт **M3 по проверенной M2**. Для M4 и далее после анализа предыдущей
физики мы выпускаем **только новый** `recipes/ACTIVE.json` и, после
проверки геометрии, отдельный `approvals/M4.json`. Старые сетки и
результаты не перезаписываются.

Генератор:

- проверяет SHA исходного `.msh`, `.geo`, исходников и цепочку номеров;
- применяет `h_new=h_old*(1-alpha*kappa)^(1/3)` с `alpha=0.15..0.25`;
  `kappa` — C¹-функция `[0,1]` с гладкими радиальным и полярным окнами;
- сохраняет `meshes/M3.geo` и `meshes/M3.msh`; **ничего не удаляет**;
- запускает Gmsh `-3`, 4 потока, один раз; cap 900 с, 8 GiB;
- проверяет MSH2, физические теги, все 27 криволинейных QP/Tet10 и
  положительность detJ на этих точках (не доказательство для всей области);
- считает отношения q=(Vmax/Vmin)^(1/3) для соседних по общей грани
  Tet10, отдельно для приполюсных пар (<0,5 мм и |μ|≥0,6), с p95/p99
  и числом q>1,25. Это измеренная *дискретная* гладкость, а не
  доказательство C¹ поля размера;
- сохраняет один `LOCAL_RUNS/P10FN_MESH_M3_.../P10FN_M3_MESH_EVIDENCE.zip`.
  Raw `.msh` включён в приватный архив, если его размер ≤32 МиБ.

**Прислать мне только этот evidence ZIP** (либо дополнительно `M3.msh`,
если он не вошёл). Я независимо оценю геометрию, приполюсные слои,
фактические отношения эффективных объёмов 343/729QP, гладкость и
соседние отношения Tet10. Только после положительного заключения
выпускается `approvals/M3.json` для следующей программы.

Невозможно гарантировать фактические 15–25% только формулой поля размеров:
это **целевое** изменение объёма; реальные элементы Gmsh проверяются
отдельно. κ0-области и приполюсная геометрия анализируются отдельно.

## Шаг II. Физический расчёт на одобренной сетке

Дважды нажать:

- `02_PHYSICS_LATEST_APPROVED_R.cmd` — самая новая **имеющаяся на диске
  одобренная** сетка (M0/M1/M2/M3/...);
- `03_PHYSICS_M0_R.cmd`, `04_PHYSICS_M1_R.cmd`, `05_PHYSICS_M2_R.cmd` —
  конкретная историческая сетка;
- `06_PHYSICS_LATEST_TZ.cmd`, `07_PHYSICS_LATEST_Y20.cmd` — другие
  направления изменения формы, **самостоятельные расчёты**, а не
  производные, полученные из R.

Для произвольного `Mk` без нового CMD можно запустить уже имеющуюся
программу `P10FN_physics.py` с `--mesh Mk --mode R|tz|y20`, но обычно
удобнее использовать «последнюю одобренную». **Никакой ввод фраз не нужен.**

Решатель проверяет SHA и 27QP, автоматически собирает C++20 MinGW Release
программу (при первом запуске), запускает **новый прямой FEM**, затем
аналитический Tet10 adjoint на **той же** сетке, формирует signed4D 7206
бинов. Он выполняет R/EDV_VAR/ξ=0, j6/jpeak/jen, B6=5 мм,
6×150 с. GH3 и другие законы пока не являются частью этого конкретного
универсального режима и должны иметь дополнительные проверенные профили.

Жёсткие границы: 6 ч, процесс ≤40 GiB и не больше доступной памяти−8 GiB,
новые выходные файлы ≤12 GiB. Реальная длительность определяется размером
сетки; для M2 наблюдалось ~193 с, для существенно больших MN возможно
много часов. До запуска вычисляется доступная RAM, сохраняется исходный
SHA и ставится глобальный маркер **одной попытки на mesh/mode/exe**.
При сбое автоматического повтора **нет**; для научно обоснованного повтора
потребуется новая версия запуска, а не удаление истории/маркера.

Результаты:

```
G:\ildar\Stage3D07\meshes\M3.msh
G:\ildar\Stage3D07\meshes\M3.geo
G:\ildar\Stage3D07\LOCAL_RUNS\P10FN_PHYSICS_M3_R_<timestamp>\
    P10FN_M3_R_PHYSICS_EVIDENCE.zip
    P10FN_PHYSICS_MANIFEST.json
    P10FN_M3_R_R1\forward_history.bin  (сохраняется локально)
```

**Прислать мне один `P10FN_M3_R_PHYSICS_EVIDENCE.zip`.** Он содержит пять
исходных CSV, `P10FN_PHYSICS_MANIFEST.json` и полный stdout/stderr,
но не гигантскую бинарную историю. Я сравню Mk с предыдущими сетками по
производным j6/jpeak/jen, шести signed4D полям, `(r,θ,φ,t)` и полюсам,
затем подготовлю **рецепт M(k+1)**.

## Дисциплина измерений

1. Исторические и новые сетки хранятся в `meshes`; каждый расчёт имеет
   неизменяемый отдельный каталог в `LOCAL_RUNS`.
2. Результаты mesh QA **не** являются разрешением на физику. Нужен
   `approvals/Mk.json` с точным SHA после независимой научной оценки.
3. Соседние сетки не усредняются внутри прямой/сопряжённой задачи;
   сравниваются лишь согласованные отдельные физические расчёты.
4. Ограничение 15–25% относится к **целевому локальному объёму**, не к
   глобальному количеству элементов и не к обязательной равномерности.
5. В производстве запрещены центральные разности по геометрии. Старые
   selftest FD из ядра остаются тестами, не физическим режимом.
6. Предполагаемое наследование поля `F6 -> F8 -> F10` использует
   стандартную Gmsh `MathEval` ссылку на предыдущие поля; в этой среде
   проверены исходный код, M2-парсер и C++ selftest, но нативный Windows
   Gmsh/MinGW запуск на компьютере пользователя ещё должен быть подтверждён
   первым evidence ZIP.
