# P10CT R2 — восстановление проверки готовой U0, без генерации сетки

**21.11.2026.** Это новый **читающий** инструмент для одного конкретного сбоя анализа P10CT R1. Он не повторяет Gmsh и не запускает FEM. Ваш исходный U0 уже построен; повторно строить его **не нужно**.

## Почему нужен R2

Полученный первичный `P10CT_EVIDENCE.zip` SHA256 `06fceca8df77018a706c2de79bcada2978a079b1086114235201a2ed7c47c895` подтвердил: Gmsh exit0, 6.862 s, 131 380 nodes, 102 726 elements (все типы), .msh 16 218 389 bytes SHA256 `1a4690d1c57c8b520d596f9a864f754a8d84151bfd1fdd36f56631488779c6a3`. Gmsh предупреждал об одной инверсии jacobian на одном из этапов оптимизации, но итоговая независимая геометрическая проверка не закончилась: Python traceback был обрезан оболочкой PowerShell, без JSON/CSV. Вывод о реальной инверсии U0 пока преждевременен.

В R2 удалена возможная ошибка старой геометрической классификации (corner-centroid рядом со сферой может лежать внутри поры, не обязательно означая ошибку искривлённого Tet10). Такие центроиды теперь учитываются в **пятой диагностической зоне**, а не аварийно прерывают анализ. Новая самостоятельная проверка выполняет 27 QP **для каждого Tet10**, а не только на выборке; записывает номера и углово-радиальные положения до 30 худших элементов и количество инверсий по зонам. На уровне знаков это по-прежнему sampled-QP, не математическая гарантия на всех точках элемента.

## Как запустить на Windows 11

1. Скачайте ZIP R2 и распакуйте в **новую папку** вне `G:\ildar\Stage3D07` и отдельно от прежнего R1. Старый каталог с полученной сеткой оставьте без изменений.
2. Однократно откройте **`01_RUN_P10CT_R2_READONLY_QA.cmd`**. Установленный Python 3 используется как в R1; Gmsh не вызывается.
3. Инструмент найдёт конкретную исходную сетку по точному адресу из журнала: `G:\Downloads\P10CT_R1_U0_MESH_ONLY_WINDOWS_20261121\P10CT_RUNS\P10CT_20261121_051002_957\P10CT_U0_h2mm.msh`. Если папка была перемещена, он попробует только аналогичные R1-папки в стандартном каталоге загрузок, проверив **точные SHA256 и размер**. При отсутствии/несоответствии остановится, не подменяя исходник.
4. Передайте мне **только `P10CT_R2_EVIDENCE.zip`** из новой папки `P10CT_R2_RUNS/P10CT_R2_...`. Саму .msh (16.22 МБ) пока передавать не нужно.

## Ограничения

- R2 не пишет в исходную .msh и не делает remeshing; нет CMake/Qt/FEM/адаптации M1.
- В выходе будут `P10CT_U0_SUMMARY.json`, CSV геометрии по 5 зонам ×10 μ ×12 φ (600 ячеек), полный stdout/stderr/traceback Python и контроль хешей. Исходная .msh остаётся локально.
- Все Tet10 проверяются в 27 квадратурных точках: примерно 2–5 минут верхней ориентировочной оценки на i7‑7700K (неизмерено); встроенное ограничение времени обработки Python — 600 секунд. Реальное время будет показано в отчёте.
- Если получен `QA_GEOMETRY_ONLY_ACCEPTANCE=False`, это завершённый **отрицательный геометрический результат**, а не технический отказ. Нельзя запускать физический FEM на этой сетке; затем выбираем безопасное равномерное уточнение по всему объёму.
- Сбой Python или отсутствующая .msh даёт `P10CT_R2_STOP_READONLY_NO_FEM` с **полным** traceback — его важно сохранить, не повторять автоматически.

Статус до Windows: Linux selftest/py_compile PASS; настоящий R2 на U0 ещё не выполнен. Следующее действие только одно: полученный R2 evidence ZIP, без прежнего P10CT R1 повторного Gmsh.
