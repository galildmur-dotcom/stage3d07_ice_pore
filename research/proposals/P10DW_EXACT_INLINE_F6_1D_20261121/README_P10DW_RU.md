# P10DW R1 — безопасный разбор GEO и один новый 1D-тест точного поля M2

**СТАТУС ПОСЛЕ ВЫПУСКА ПАКЕТА: SOURCE-ONLY.** Пакет подготовлен и проверен без запуска реального Windows Gmsh. Новых сеток 1D/2D/3D, M2 Tet10, curved27QP, FEM или физических расчётов **пока нет**. До отдельного разрешения исследователя **не нажимать кнопку 02**. Подготовка инструмента не является согласием на нативный запуск.

## Проверяемый научный вопрос

P10DU по оригинальному Windows журналу и исходнику Gmsh4.15.2 локализовал нерекурсивный `MathEval→MathEval` как причину прошлых TIMEOUT. P10DV математически построил точный **одиночный** `Field[6] = MathEval` с единственной внешней ссылкой `F2` (`Threshold`), без промежуточных `F3/F4/F5`. Для **17 075** точек и трёх базовых размеров F2 получено **51 225** сравнений, без расхождения нормированного размера в Python double. Это **не** нативный запуск Gmsh.

Новый независимый вопрос P10DW: может ли **ровно это 494-символьное выражение F6** быть разобрано Gmsh4.15.2 и использовано в коротком 1D mesh runtime без зацикливания? Ранее успешный P10DT тестировал более простое inline пространственное выражение с диагностическими 2% **размера**, а здесь используется исходная полностью развёрнутая **целевая M2 формула 20% локального объёма**:

\[
\kappa\in C^1\cap[0,1],\qquad
V_{\mathrm{target},M2}/V_{\mathrm{target},M1}=1-0.20\kappa,
\qquad h_{M2}/h_{M1}=(1-0.20\kappa)^{1/3}.
\]

Это **целевое** отношение, не измеренное отношение объёмов Tet10 после 3D ремешинга. Приоритетная приполюсная κ остаётся проектной гипотезой, а не доказанной оптимальной адаптацией.

## Два раздельных этапа Windows

1. **Распаковать ZIP в новую папку**, например `G:\Downloads\P10DW_R1_...`, вне `G:\ildar\Stage3D07` и вне папок P10DO/P10DQ/P10DR/P10DT. Нужен Python 3. Gmsh4.15.2 по умолчанию `C:\gmsh-4.15.2-Windows64\gmsh.exe`, SHA256 `317c43391e5b1fab3a1dd80dc5245dad6e2d087910f4b8ebc234bd6d4b8f41a1`. Изменённое расположение *того же* Gmsh можно задать переменной `P10DW_GMSH_EXE`, но другой SHA — STOP.
2. **Кнопка `01_P10DW_SAFE_GEO_PREFLIGHT_ONLY.cmd`**: указать полное имя **оригинального** принятого `P10DG_M1_CANDIDATE.msh` или Enter для уже аттестованного пути `G:\Downloads\P10DG_R1_M1_EMPIRICAL_H0_MESH_ONLY_WINDOWS_20261121\P10DG_RUNS\P10DG_M1_20261121_120324_362583\P10DG_M1_CANDIDATE.msh`. Проверяется SHA256 **`ca6b6b6588dc72c5dd3ed2e92e24794560ee2407e350c8a44858e9c3c7d0360f`**, **9736 Tet10 по прежней аттестации**; новый разбор `.msh` не проводится. Затем source PIN12/12, P10DV κ unit 17 075 точек, CAD/Threshold, исполняемый Gmsh SHA и версия, свободная RAM≥8GiB и диск≥1GiB, **два native `-parse_and_exit`** (исходный `Background Field=2` и точный F6) с таймаутом20с каждый. **Нет `-1/-2/-3` и маркера расходования.** В новой подпапке `P10DW_RUNS/P10DW_...` возникнут JSON/логи/`P10DW_EVIDENCE.zip`; только при `P10DW_READ_ONLY_PREFLIGHT_PASS` создаётся отдельное доказательство preflight сроком24ч. Если STOP/код2 — прислать один `P10DW_EVIDENCE.zip`, **кнопку02 не запускать**.
3. **Кнопка `02_P10DW_ONE_INLINE_F6_1D_ONLY.cmd` — только после нового отдельного явного согласия и PASS кнопки01.** Сценарий повторно сверит все SHA, исходную M1, preflight-доказательство≤24ч и заново выполнит безопасные разборы двух GEO. Затем попросит вручную написать **ровно**:

   `RUN ONE P10DW INLINE F6 1D`

   **Непосредственно перед единственным native `gmsh -1`** создаются P10DW-only маркеры: `%LOCALAPPDATA%\Stage3D07\P10DW_1D_<SHA-M1>.json` и `P10DW_RUNS\P10DW_ONE_1D_USED.json`. Даже при ошибке/TIMEOUT попытка считается израсходованной. Не удалять маркеры и не повторять кнопку 02, ни из новой распаковки, ни из старой.

## Ресурсный и научный предел

- Только **один** native `gmsh -1` на точном Gmsh4.15.2, максимум **15с wall**, 2 потока, private **2GiB**, файл 1D `.msh` ≤**20MiB**, полный лог ≤**1MiB**. Имеющийся P10DT простой inline F6 завершался около0.2с; для длинного нового выражения время заранее неизвестно, таймаут15с является STOP, а не причиной повторить. Дополнительно native parse≤40с и PIN/математические проверки: оценка всей работы с запасом **до 2 минут**, RAM свободно≥8GiB/диск≥1GiB. Контроль private — периодический, не аппаратный абсолютный предел.
- Полный оригинальный Gmsh stdout/stderr захватывается в `.log` (не полагаться только на хвост окна); в ZIP также две точные GEO, CAD, JSON с SHA, exit/wall/peak/private и `_TAIL.txt`. **Один** `P10DW_EVIDENCE.zip` передать для независимого аудита даже при коде2. `P10DW_RESULT.txt` отдельно не требуется.
- **Нет ни `-2`, ни `-3`, ни новой M2 mesh-only попытки, ни physical forward/adjoint/FEM, ни H0 forward cache, ни старых маркеров.** Оригинальная M1 читается только для SHA. Никакой потолок числа узлов будущей M2 здесь не вводится.
- Успешный `gmsh -1` подтвердит только конечное 1D выполнение и журнальные числа nodes/elements. Он **не докажет** качество CAD/Tet10 curved27QP, реальное поле κ во всём 3D льду, глобальные/радиальные объёмные отношения, сходимость формы или физический результат. После аудита оригинального ZIP решение о **новом** 3D M2 mesh-only опыте принимается отдельно.
