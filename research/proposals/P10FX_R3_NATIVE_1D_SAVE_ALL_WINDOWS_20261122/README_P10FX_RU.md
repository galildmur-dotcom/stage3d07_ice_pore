# Stage3D07 — P10FX: новая равномерная M1, целевое уменьшение объёма 15–20%

## Новый выпуск P10FX R3 — причина STOP подтверждена

Пользовательский ZIP R2 `P10FX_PREFLIGHT_STOP_EVIDENCE.zip` SHA256
`33c204edfaa2031090bf106ec7e10cfbf408a153b1bfde6141ff758edf4c9ebf`
содержит точные результаты: `native_1d_exit=0`, `Error=false`,
`Done meshing 1D=true`, MSH существует, размер **280 байт**.
Gmsh сообщает 244 узла, 135 элементов, но экспорт MSH2 при наличии
физических групп поверхностей/объёмов **не сохраняет 1D элементы
кривых, не включённых в физические группы**. Из-за этого проверка
`size>1000` ошибочно закрыла право на 3D. Это не дефект MathEx!

В R3 добавлен официальный ключ Gmsh4.15.2 `-save_all` **строго
только в безопасный диагностический вызов `gmsh -1`**. Проверяются
и отдельно фиксируются не только exit/log/size, но и фактические
количества `$Nodes`/`$Elements` в экспортированном MSH2. Настоящий
3D вызов `gmsh -3` **НЕ имеет** `-save_all` и сохраняет важные для FEM
физические группы. Не требуется изменять исходную геометрию M0 или
сферу; поле размеров и жёсткий научный допуск по18 зонам неизменны.

Текущий пакет: `P10FX_R3_ONE_M1V_NATIVE_1D_SAVE_ALL_WINDOWS_20261122.zip`.
Используйте **новую папку** `G:\ildar\Stage3D07\P10FX_TOOLS_R3`,
не запускать 02 из R1/R2. Общие с R1/R2 одноразовые маркеры `-3`
сохранены и не должны удаляться. R3 ещё не проходил нативный Windows тест.

## История: P10FX R2 (измерение ложного отказа R1)

Реальный журнал P10FX R1 `P10FX_GMSH_1D_FIELD_PROBE.txt`
SHA256 `c01bc28c2ebccad0dd8d3c0103b0c3171ec53d517151bc292d37a3f1be01473c`
содержит `Done meshing 1D`, 244 nodes / 135 elements, успешную
high-order оптимизацию и запись MSH, **без** `Error`. Исходная ошибка
MathEx с `--0.8` устранена. Тем не менее R1 выдал STOP по объединённому
условию, не записав ни кода возврата Gmsh, ни размера 1D MSH.
**Нельзя заключить из лога, какой именно подшлюз остановил R1.**

В R2 была добавлена отдельная, полностью проверяемая диагностика:
`P10FX_1D_GATE_METRICS.json` сохраняет возврат Gmsh, наличие/размер
MSH, сигнатуры разделов MSH2.2, строки `Done meshing 1D` и `Error`.
Если любая часть не пройдена, **3D запрещён**, а пакет сам создаст
`P10FX_PREFLIGHT_STOP_EVIDENCE.zip` с необходимыми логами и метриками.
Никаких ручных подтверждений или ввода текста нет. Если R2 выдаст
PASS, для объёмной генерации сохраняются тот же `M1V_CANDIDATE` и
**общие с R1 постоянные one-shot markers**, так что ни одна попытка
3D не может быть повторена посредством смены выпуска.

**Предыдущие R1/R2 больше не запускать.** Пользуйтесь только
новой папкой `G:\ildar\Stage3D07\P10FX_TOOLS_R3` и архивом R3.

**P10FW/M1U — остановлен, одноразовый запуск уже израсходован.** В его
нативном журнале Gmsh 4.15.2 первое критическое сообщение:
`mathex::parse(): Invalid expression`; формула содержала `--0.8`.
M1U имеет **0 Tet10**, физический расчёт недопустим. Запускать P10FW
снова **нельзя**. P10FX исправляет сериализацию формулы и впервые
проверяет её работающим нативным компилятором Gmsh в безопасном
**одномерном** пробном расчёте до новой объёмной генерации.

**P10FX — актуальная программа.** Исторические P10FU/M1B и старая
`01_GENERATE_NEXT_MESH.cmd` **отменены для первой M1**.
Новая `M1V_CANDIDATE` создаётся от принятой M0 без перезаписи
M0.msh/M0.geo, отклонённой M1.msh/M1.geo или старых журналов.
Физический FEM этим пакетом не запускается.

## Требование и способ компенсации

Реальное уменьшение характерного объёма Tet10 по всему физическому
объёму льда должно быть **15–20%** по сравнению с принятой M0:

`0.80 ≤ Veff(M1V;Z)/Veff(M0;Z) ≤ 0.85`

в **каждой** фиксированной 3D контрольной области Z, включая
18 пространственных зон (3 радиальные полосы × 3 зоны
полярности × север/юг). Цель — 0.825 (−17.5%).
Размеры самого блока и поры **не изменяются**.
Приемка — только после независимого curved343/729QP аудита
реально построенной M1V, а не по числу Tet10 или числу
построенных точек.

Предыдущая попытка с совершенно одинаковым коэффициентом
предписанного h во всём объёме дала в Gmsh настоящие локальные
Q от0.749 до1.096. Поэтому сейчас используется одно математически
гладкое C¹ поле размеров Tri6/Tet10 с **калибровочной компенсацией
ремешинга**: на основе измеренных 18 зон М0→ошибочная M1
встроена пространственно сглаженная оценка прежнего перекоса.
Это **не физически адаптивная κ(x)**: целевой фактический
коэффициент уменьшения объёма всюду остаётся одинаковым 0.825,
κ=1. Из-за нелинейной топологии Gmsh исходная калибровка
не гарантирует попадания в интервал. При нарушении хотя бы
одной зоны M1V останется непригодной для физики.

## Шаг 1. Установка

1. Скачайте ZIP `P10FX_R3_ONE_M1V_NATIVE_1D_SAVE_ALL_WINDOWS_20261122.zip`
   из указанной исследовательской ветки GitHub.
2. Распакуйте в совершенно новый каталог, например
   `G:\ildar\Stage3D07\P10FX_TOOLS_R3`.
3. Убедитесь, что старые файлы `M0.msh`, `M0.geo`,
   `M1.msh`, `M1.geo`, `sphere_pore_B6_refined.geo`
   остались неизменными внутри `G:\ildar\Stage3D07\meshes`.
4. Требуются установленный Python3, Windows11 и Gmsh4.15.2
   `C:\gmsh-4.15.2-Windows64\gmsh.exe`.

## Шаг 2. Проверка, без сетки

Двойным щелчком запустите
`01_P10FX_SAFE_PREFLIGHT_ONLY.cmd`.

Будут проверены exact SHA старых M0/M1 и всех исходников,
6018 точек C¹ поля, native Gmsh версия, `-parse_and_exit`
и настоящее выполнение MathEx при **только `-1` (линейная сетка)**
во временной папке. Пробная сетка удаляется; **3D не строится**.
Протокол Gmsh сохраняется в `LOCAL_RUNS/P10FX_PREFLIGHT_.../P10FX_GMSH_1D_FIELD_PROBE.txt`.
При `P10FX_PREFLIGHT_PASS` можно продолжить.
При STOP передайте только `P10FX_PREFLIGHT_STOP_EVIDENCE.zip`
из последней папки `LOCAL_RUNS\P10FX_PREFLIGHT_...`, если он создан;
иначе — `P10FX_CHECK_RESULT.txt`. Не запускайте 02.

## Шаг 3. Одна защищённая генерация

**После успешного шага2 и только один раз** запустите двойным
щелчком `02_P10FX_ONE_M1V_3D_ONLY.cmd`. 

Программа:

- Не требует никакого ручного ввода символов.
- Держит окно открытым; пишет `P10FX_MESH_RESULT.txt`.
- До native Gmsh создаёт уникальные local/profile one-shot
  маркеры. Их не удалять даже при ошибке.
- Выполняет только один Gmsh4.15.2 `-3 -nt2`,
  ≤900с, private≤8GiB, выход≤2GiB, затем 27QP QA.
- Создаёт новые
  `G:\ildar\Stage3D07\meshes\M1V_CANDIDATE.geo`
  и при successful QA `M1V_CANDIDATE.msh`, не меняя M0/M1.
- Сохраняет QA/лог/manifest и один
  `P10FX_M1V_MESH_EVIDENCE.zip` в
  `G:\ildar\Stage3D07\LOCAL_RUNS\P10FX_M1V_...`.

На вашем i7-7700K ориентировочно native Gmsh займет секунды–минуты,
27QP QA примерно 10–60с, Gmsh жёсткий предел 15мин;
**новая M1V ещё не строилась на Windows**, точное время неизвестно.

## Что передать

Один файл: **`P10FX_M1V_MESH_EVIDENCE.zip`** из новой run-папки.
Он включает оригинальную M1V.msh при размере ≤32 MiB.
При ошибке дополнительно передайте `P10FX_MESH_RESULT.txt`.
Ассистент проверит raw M1V независимыми 343/729QP по всему
объёму и только после **научного GO** подготовит безопасный
физический запуск; существующий `02_PHYSICS_LATEST_APPROVED_R.cmd`
на прежней отклонённой M1 сейчас запускать нельзя.

**Внутри P10FX FEM=0, approvals/M1V.json не выпускается.**
