# P10FP — Stage3D07 с нуля: M0 → M1 → … → MN, Windows 11

**Это новая воспроизводимая серия, не старый H0/M1/M2.**
Старый P10FN остаётся отдельной исторической ветвью данных.
Новый M0 будет создан один раз настоящим Gmsh, а не скопирован из H0.

## Первичная установка (один раз)

1. Распаковать архив в отдельную папку, например
   `G:\ildar\Stage3D07\P10FP_TOOLS`. Исходный проект не заменять.
2. Нужны Python 3 и существующий `C:\gmsh-4.15.2-Windows64\gmsh.exe`;
   MinGW C++20/OpenMP Qt Creator обнаруживается при первом расчёте.
   NumPy, tkinter, PowerShell, Git Bash и ручные подтверждающие фразы
   **не нужны**.
3. **Не копировать старые H0, P10DG M1, P10FB M2 в новые `M0.msh`,
   `M1.msh`, `M2.msh`**: новые имена принадлежат новой серии.
   Если файл `G:\ildar\Stage3D07\meshes\M0.msh` уже существует,
   программа сохранит его и остановится без перезаписи: необходимо
   отдельно разобраться в происхождении файла.
4. Запустить двойным щелчком `00_CHECK_PROGRAMS_NO_RUN.cmd`. Это только
   контроль исходных SHA/рецептов; никакой Gmsh/FEM.

## Шаг 1. Создать M0

Дважды нажать **`01_GENERATE_NEXT_MESH.cmd`**. Если `M0.msh` ещё нет,
кнопка автоматически выполняет чистую генерацию исходной M0:

- геометрия: та же 3D сферическая пора и канонические физические теги,
  что в исторической `sphere_pore_B6_refined.geo`;
- M0 не использует физические индикаторы; начальный градиент размеров
  необходим для геометрии поры/удалённой области, а не «адаптация по
  чувствительности»;
- M0 поле размеров C¹, от 0.461651 мм у поры до 7.597053 мм вдали,
  с гладким радиальным переходом от 1.5 до 18 мм;
- Gmsh `-3`, Tet10 и Tri6, 4 потока, максимум 900 с/8 GiB;
- 27-точечный detJ-контроль каждого Tet10 и локальная соседняя
  регулярность q; точные численные параметры сетки берутся из
  **реального** MSH, а не из расчётных размерных полей.

Файлы будут автоматически записаны:

```
G:\ildar\Stage3D07\meshes\M0.geo
G:\ildar\Stage3D07\meshes\M0.msh
G:\ildar\Stage3D07\LOCAL_RUNS\P10FN_MESH_M0_<timestamp>\
  P10FP_M0_MESH_EVIDENCE.zip
```

**Прислать мне только `P10FP_M0_MESH_EVIDENCE.zip`.** Он включает
исходную `.msh` при размере до 32 МиБ, QA, лог Gmsh и SHA. Я проведу
независимую геометрическую проверку; лишь после неё дам
`approvals/M0.json` с SHA-256, который нужно положить в папку
`P10FP_TOOLS\approvals`.

## Шаг 2. Физический расчёт M0

После полученного одобрения M0 двойным щелчком запустить
**`02_PHYSICS_LATEST_APPROVED_R.cmd`** (или `03_PHYSICS_M0_R.cmd`).
При первом запуске программа самостоятельно соберёт MinGW C++20
исполнитель из SHA-проверенных исходников P10W/P10DL.

Физика: R / EDV_VAR / ξ=0, `j6`, `jpeak`, `jen`, B6=5 мм,
6 шагов по150 с; новая прямая история и аналитическая сопряжённая
задача **на одной M0**, без центральной FD по геометрии. Ограничения:
до 6 часов, private RAM до 40 GiB (не более доступной RAM−8 GiB),
выходные файлы до 12 GiB. Предварительно проверяется свободная память.

После завершения из `LOCAL_RUNS\P10FN_PHYSICS_M0_R_...` прислать
**`P10FN_M0_R_PHYSICS_EVIDENCE.zip`**. Внутри пять физических CSV,
разложение `(r,θ,φ,t)`, stdout/stderr, параметры и SHA. Огромная
двоичная прямая история хранится локально, но не передаётся.

## Шаг 3. M0 → M1: общее относительное сгущение

**Только после** моего анализа M0-физики я выдам новый
`recipes/ACTIVE.json` с привязкой к реальному SHA M0. Первое сгущение
M0→M1 задаётся одинаковым полем `κ(x)=1` по всему объёму:

\[
h_1(x)=h_0(x)(1-0.20)^{1/3}.
\]

Т.е. целевой характерный объём уменьшается на 20% во всей области;
это **не гарантия**, что каждое фактическое Gmsh-соседство уменьшится
строго на20%. Физические зоны, качество изогнутых элементов, поверхность
поры и объёмные 343/729QP будут проверены после реальной генерации.

Положить присланный `ACTIVE.json` вместо `recipes/ACTIVE.json`
(изменяется только этот файл, исходники программы не меняются).
Ещё раз нажать **ту же кнопку** `01_GENERATE_NEXT_MESH.cmd`:
получится `meshes/M1.geo`, `meshes/M1.msh`, новый evidence ZIP.
После моей геометрической проверки положить новый `approvals/M1.json`,
затем снова запустить физику, прислать результат и получить M2-рецепт.

## Шаги M2, M3, …, MN

Вся дальнейшая последовательность одинакова:

1. После анализа физики Mk я выпускаю **только новый** файл
   `recipes/ACTIVE.json` со своим проверенным полем `κ_k(x)`;
2. `01_GENERATE_NEXT_MESH.cmd` строит M(k+1) без перезаписи предыдущих;
3. мне присылается его mesh evidence; я проверяю сетку;
4. после одобрения SHA запускается `02_PHYSICS_LATEST_APPROVED_R.cmd`;
5. мне присылается physics evidence; я сравниваю всю согласованную
   последовательность и формирую следующий рецепт.

Правило начиная с M2:

\[
h_{k+1}(x)=h_k(x)[1-\alpha_k\kappa_k(x)]^{1/3},\qquad
0\le\kappa_k\le1,\quad 0.15\le\alpha_k\le0.25.
\]

Поле κ класса C¹ в текущем выпуске задаётся гладкими радиальными и
полярными окнами. Азимутальное окно может быть реализовано в следующей
версии только после отдельного физического обоснования; явная равномерность не требуется,
глобального ограничения прироста Tet10 нет. В `κ=0` областях целевой
размер не меняется. В `κ=1` зонах целевое уменьшение объёма в интервале
15–25%; реальные отклонения от цели анализируются независимо.

## Дополнительные кнопки

`06_PHYSICS_LATEST_TZ.cmd` и `07_PHYSICS_LATEST_Y20.cmd` запускают
другие направления формы **в рамках той же исходной EDV_VAR/ξ=0
постановки**; это отдельные полные физические решения, не перерасчёт
производной R по формуле. Более широкая GH3/модельная серия требует
отдельных аттестованных профилей.

## Важные ограничения

- Новый M0 **не равен** старой H0 побайтно, старые результаты нельзя
  автоматически включать в новую последовательность.
- `P10FP_M0_MESH_EVIDENCE.zip` — **не** физический результат;
  программа сама не выдаёт одобрение на FEM.
- Сохранённые одноразовые маркеры не удалять для повтора после сбоя.
  Новую исследовательскую попытку мы оформим отдельной версией.
- Все `.msh/.geo` — только в `G:\ildar\Stage3D07\meshes`, все расчёты,
  манифесты и evidence — только в `LOCAL_RUNS`.
- Нативная проверка эталонного Gmsh 4.13 (Linux, диагностическая версия)
  выполнена для M0, M1 и пробной M2. M0: 8031 Tet10, M1: 10120 Tet10;
  все 27 контрольных QP каждого Tet10 имеют положительный detJ.
  Для M2 проверена работоспособность кода поля, но её локальные градиенты
  размеров пока **не признаны приемлемыми**. На Windows у пользователя
  Gmsh 4.15.2: его фактические результаты проверяются по evidence.
