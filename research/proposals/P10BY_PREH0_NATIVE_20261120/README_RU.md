# P10BY — безопасный подготовительный этап перед H0 (без физического расчёта)

20.11.2026. **Только review/native unit.** Это не Windows One Click, не патч рабочего `G:` и не разрешённый FEM.

## Что содержится

- `P10BY_temporal_thermal_qp_native_unit.cpp` — проверяет *заданные* (не решаемые) тепловые поля `theta_n` и множители `psi_n` на синтетической сетке 2×Tet10+удалённая Tri6. Для `R` и искусственного `top`, в сетках времени `6×150`, `12×75`, `18×50`, `36×25` проверяет каждый шаг `QP==CSR`, сумму 100 radial/polar объёмных ячеек плюс отдельную Robin-строку, сумму по истории, число QP и 101 CSV-строку/шаг; отдельно проверяет **STOP при двух искажениях CSR** (mass и robinload). Сами CSV физической сетки не генерирует.
- `P10BY_unitonly_entry.cpp` — запрещает физический CLI: включает **именно `<P10BX>/src/stage3d10p_partial_audit.cpp`** с диагностическим макросом, но main вызывает только наследованный `p10i::run_tests()`. Этот файл был проверен Linux полной компиляцией C++20 `-O2` и unit exit 0.
- `P10BY_PINNED_SHA256.txt` — точные SHA-256 всех **35** неизменённых исходных `src/` и `tests/` из исторического Git `90fd2559...`.
- `P10BY_readonly_source_gate.py` — локальная независимая SHA-проверка **35+5** исходных/proposal файлов; test с порчей буфера **только в памяти**. Использовался нами на Linux; **не требуется запускать его пользователю на Windows**.
- `CMakeLists.txt` — *проект* ограниченного read-only CMake native-only target: `p10by_temporal_native_unit`, `p10by_optin_dependency_selftest`; 35+5 SHA-преград, запрет точного пользовательского пути `G:/ildar/Stage3D07`. **CMake configure/build не проверены** в этой Linux среде (`cmake: command not found`), поэтому это не выпущенный Windows tool и требует отдельного clean validation.

Требуются три независимые директории: (1) `P10BY_PINNED_ROOT` — exact 35 source dependencies из `90fd2559...`, (2) `P10BY_P10BX_ROOT` — опубликованная review-only P10BX proposal, (3) `P10BY_P10BW_ROOT` — опубликованная P10BW proposal. Ничего не сливать в `master` или пользовательское рабочее дерево.

## Два исполненных Linux native-теста

Оба компилируются с `g++ -std=c++20 -O2 -Wall -Wextra -Wpedantic` и заголовками из указанных трёх каталогов:

1. Синтетический temporal `P10BY_temporal_thermal_qp_native_unit.cpp`: 8/8 серий, 144 шага, 14 544 поклеточные строки, max `5.107025913276e-15` abs, 2/2 порчи обнаружены, все 8 временных сумм закрыты.
2. Обёртка `P10BY_unitonly_entry.cpp`: полная компиляция диагностической P10P единицы без выхода к физическому FEM, `P10I_PRODUCTION_ADJOINT_OK`, exit 0. Старые warnings P10M/P10I исходников остаются. Команда `g++ -MM` дополнительно проверила, что подключён **proposal P10P**, не исходный P10P: `proposal_P10P=true, pinned_P10P=false, P10BW_header=true`.

Оба stdout воспроизведены побайтово. CMake не испытывался из-за отсутствующего `cmake` (инцидент зарегистрирован, без ложного OK). Полный H0 и `--preflight` **не выполнялись**: в P10P даже `--preflight` вызывает `H::solve_forward`.
