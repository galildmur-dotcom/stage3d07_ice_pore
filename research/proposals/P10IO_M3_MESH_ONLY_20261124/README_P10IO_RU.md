# P10IO — первый защищённый запуск Gmsh M3 (только сетка, FEM=0)

**Исправление R2 24.11.2026:** первая R1 попытка остановилась за `0.575 с` на `gmsh.open()` из-за отсутствовавшего в ZIP транзитивного `sphere_pore_B6_refined_rotated.geo`; 3D-сетка НЕ была построена, FEM=0. Исходный R1 marker **сохранить навсегда и не повторять**. R2 — новая отдельная исправленная попытка с новой marker, полной проверкой всего графа `Include` перед запуском Gmsh и новым ZIP evidence. R1 архив НЕ использовать.

Новая M3 строится на точной прежней `P10GT_HXT10.geo` → `M0_ROTATED.geo` (сфера уже параметрически повернута на 90°) и **не создаёт новую геометрию поры**. Кандидат исходно имеет статус `CANDIDATE_UNVERIFIED`, даже если Gmsh завершился с кодом 0.

Используется утверждённая κ P10IM с долями 90% механика и 10% тепло, непрерывное C² поле P10IN и прежняя исходная size-callback M2. Относительный к M2 размер имеет дополнительный фактор `exp(-0.1435943054*κ_new - δpatch*w)`, где север `δpatch=.10320395427`, юг `.20008119936`. Поправки являются **предварительными**: эмпирическая модель региона даёт прогноз .65/.65, независимый кубический QP-bin proxy .673/.522. Реальный Veff после построения ещё неизвестен; D029 regional target [.50,.75] — отдельный последующий контроль.

## Запуск на Windows 11

1. Распаковать **исправленный R2** архив в новую папку `G:\ildar\Stage3D07\P10IO_M3_MESH_ONLY_R2` (НЕ поверх R1/P10IE/M2). Не переносить ни старый marker, ни старый output.
2. Двойной клик `01_P10IO_PREFLIGHT_NO_GMSH_NO_FEM.cmd`. Ожидаем `P10IO_R2_PREFLIGHT_PASS_NO_GMSH_NO_FEM sources=7 geo_includes=3`, `P10IO_R2_PREFLIGHT_EXIT=0`. Этот шаг **не строит сетку** и **не тратит** маркер.
3. Двойной клик `02_P10IO_ONE_M3_3D_MESH_ONLY.cmd` — **ровно одна попытка**. Требуется доступный из Python `gmsh==4.15.2` (тот же API, что на предыдущих P10IB/P10IE этапах), NumPy. Готовая программа Qt/C++ здесь не нужна. В окне появляются стартовое сообщение, счётчик времени/памяти/лога раз в **30 секунд**, завершение и путь к ZIP. Gmsh лог отдельно: `P10IO_GMSH_LOG.txt`.
4. **При любом STOP не повторять второй файл**: новый одноразовый `P10IO_R2_ONE_3D_ATTEMPT_CONSUMED.marker` создаётся до первого запуска Gmsh 3D. Вернуть диагностический архив даже при ошибке. Ни старый R1, ни P10IE markers не трогаются.

Ограничения: одна 3D meshing attempt, Gmsh4.15.2 HXT10, NumThreads4, ≤15 минут wall, ≤8GiB private по опросу каждые 0.5с, ≤32MiB журнал, ≤250MiB MSH. При обычном поведении M2 генерация занимала секунды, но на ПК i7-7700K закладывать **1–5 минут** с запасом до 15 минут. Gmsh сама не имеет здесь Windows Job hard memory limit, поэтому лимит памяти контролируется внешним процессом по поллингу. 3D физика и аналитическая сопряжённая задача **не запускаются**.

## Что прислать

Один `P10IO_R2_M3_UNVERIFIED_EVIDENCE.zip` из папки запуска: marker/guard log/worker result и новый raw `P10IO_M3_CANDIDATE_UNVERIFIED.msh` (при успехе). Не отправлять исходный полный проект.

После получения ZIP я независимо проверю: исходная CAD и физические теги, curved Tet10 minSICN≥.20/minSJ≥.40/gamma≥.15, положительный detJ по 27/343/729 точкам, closure объёма и **фактическое** Veff(M3/M2) в поддержанных физических полярных patches north/south d0–.5мм/|μ|≥.8 с N_eff≥30 и drift343→729≤1%; q остаётся диагностическим. До этого M3 не считается принятой и её FEM не разрешён.

Если `01` остановится на отсутствии `gmsh` Python API, пришлите строку ошибки. Ничего переустанавливать и не запускать Gmsh вручную до выяснения не требуется.
