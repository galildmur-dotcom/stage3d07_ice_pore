# Stage3D07 / P10FU — один корректирующий кандидат M1B

**Это не физический расчёт.** Программа создаёт только одну новую
кандидатную сетку на принятой M0, с учётом отрицательного результата
P10FT на M1. Исходные M0 и M1 не изменяются.

## Что было установлено

На исходной M1 стандартная равномерная цель объёмов 0.80 была
реализована глобально (0.79538), однако в приполярном
слое d=0–100 мкм при |μ|≥0.8 с 729QP объём M1/M0 равен:
север **0.844779**, юг **1.095906** (укрупнение!).
Нужен контролируемый эксперимент с размером южной поровой поверхности
и прилегающих элементов, не переписывающий предыдущий результат.

## Научная идея пробной коррекции

Одно гладкое поле h(x) для построения 1D/2D/3D (включая Tri6 и Tet10):

\[
h_{M1B}(x)=h_{M0}(x)
  \bigl(0.8[1-0.25w_S(x)]\bigr)^{1/3},
\]

где h_M0 — **ровно** закреплённое M0 C¹ поле,
а `w_S(x)\in[0,1]` — произведение двух C¹-функций:
сохранение полной южной поправки при d≤0.1 мм и μ≤−0.8,
обнуление при d≥0.5 мм или μ≥−0.55; плавные переходы между.
На северном полюсе сохраняется исходная целевая объёмная пропорция0.8;
в южном ядре **номинальная h³-пропорция0.60**.

Важно: 0.60 — сознательный **калибровочный параметр исходного поля**,
а не разрешение реально уменьшить физический характерный объём
на 40%. Он выбран как осторожная поправка с учётом того, что
первое однородное предписание 0.80 реализовалось на юге как 1.0959:
простейшая мультипликативная модель даёт прогноз
`1.0959×(0.60/0.80)≈0.822`, **не являющийся доказательством**.
**После Gmsh требуется 0.75≤Veff(M1B)/Veff(M0)≤0.85
по обеим полярным шапкам**. Предыдущий опыт показал, что
предписанное h³ в Gmsh не определяет реальный Veff локально.
При выходе из полосы M1B будет отклонена, даже если detJ положительны.

## Установка — без изменения старых каталогов

1. Скачайте архив `P10FU_R1_ONE_M1B_CORRECTIVE_WINDOWS_20261122.zip`
   из исследовательской ветки GitHub.
2. Распакуйте в **совершенно новый** каталог, например
   `G:\ildar\Stage3D07\P10FU_TOOLS_R1`.
3. Не переносите в этот каталог никакие старые MSH/GEO/one-shot
   markers; все исходные M0/M1 должны оставаться в
   `G:\ildar\Stage3D07\meshes`.
4. Нужны Windows 11, Python 3, Gmsh 4.15.2 в
   `C:\gmsh-4.15.2-Windows64\gmsh.exe` и ваши существующие
   файлы `M0.msh`, `M0.geo`, `M1.msh`, `M1.geo`,
   `sphere_pore_B6_refined.geo`.

## Два двойных щелчка

**Первый:** `01_P10FU_SAFE_PREFLIGHT_ONLY.cmd`.

- Проверяет SHA всех исходников и **реальные** SHA M0/M1 из
  прошлых научных этапов.
- Выполняет 4102 математические проверки размера по x,y,z.
- Вызывает Gmsh лишь с `-parse_and_exit` на временных
  копиях GEO: **не генерирует сетку**.
- Результат виден в оставшемся открытым окне, также записывается
  в `P10FU_CHECK_RESULT.txt`.
- При `P10FU_PREFLIGHT_PASS` переходите ко второму щелчку.
  При STOP не запускайте 02, передайте `P10FU_CHECK_RESULT.txt`.

**Второй:** `02_P10FU_ONE_M1B_3D_ONLY.cmd`.

- Требует успешную проверку 01 не старше 24 часов.
- Создаёт **два независимых one-shot маркера** до запуска Gmsh.
  Не удаляйте и не переименовывайте их даже при ошибке.
- Ровно один новый 3D Gmsh `-3 -nt 2`; контроль
  ≤900 секунд / ≤8 GiB private / ≤2 GiB выходных файлов;
  затем 27QP QA и копирование сетки только при PASS.
- Никаких запросов на ввод символов или разрешений в программе нет.
  Окно остаётся открытым, сообщение записывается в
  `P10FU_MESH_RESULT.txt`.
- Создаёт `G:\ildar\Stage3D07\meshes\M1B_CANDIDATE.geo`
  и, при успешной QA, `M1B_CANDIDATE.msh`.
- Логи и `P10FU_M1B_MESH_EVIDENCE.zip` — в новой подпапке
  `G:\ildar\Stage3D07\LOCAL_RUNS\P10FU_M1B_...`.

Ориентир на вашем i7-7700K: Gmsh примерно **от нескольких секунд
до нескольких минут**, 27QP QA примерно **10–60 секунд**;
жёсткий предел Gmsh 15 минут, плюс QA. Это оценка, а не
измеренный запуск M1B на Windows.

## Что прислать для научной приёмки

**Один файл**: `P10FU_M1B_MESH_EVIDENCE.zip`.
При удачном прогоне архив включает исходную M1B MSH, пока размер
не превышает 32 MiB. При ошибке присылайте также
`P10FU_MESH_RESULT.txt` из программы.

Ассистент независимо проверит точный SHA, 27/343/729QP, физические
границы, C¹ поле, реальное сгущение в двух полюсах и плавность
соседей. **Программа не создаёт `approvals/M1B.json` и не запускает
FEM.** Отсутствие разрешения на физический расчёт является
запланированным научным защитным условием, а не ошибкой генератора.

Не запускайте прежнюю `01_GENERATE_NEXT_MESH.cmd`, не заменяйте
`M1.msh` новой M1B и не копируйте прежнее `approvals/M0.json`
в качестве допуска для M1B.
