# P10EN R1 — одна новая M2 после изменения допуска пользователем на 15–25%

**Разрешено исследователем 22.11.2026:** один следующий защищённый опыт
создания 3D M2; допустимое **фактическое** уменьшение регионального
характерного объёма при `kappa=1` **15–25%**. Плавность обязательна,
азимутальная равномерность не требуется; при `kappa=0` цель — сохранить
предыдущий локальный размер. **Никаких FEM в пакете нет.**

## Что именно меняется

Оригинальная M1 — только `P10DG_M1_CANDIDATE.msh`, SHA
`ca6b6b6588dc72c5dd3ed2e92e24794560ee2407e350c8a44858e9c3c7d0360f`.
После P10EM доказан фактический P10EK STOP: старая M2 на севере
уменьшила эффективный объём на27.58%, что больше нового верхнего
предела25%. Её не использовать для физических расчётов и не
повторять использованный P10EK one-shot.

Один новый P10EN B GEO отличается от **exact pinned P10EK Alg5**
только числом **`alpha=0.17` вместо0.20** в гладком 3D размерном поле
`h(x)=h_M1(x)*(1-0.17*kappa(x))^(1/3)` и двумя поясняющими комментариями.
Та же CAD с порой и B6, прежняя M1 Threshold Field2,
гладкая `kappa`, единый размер для поверхности и объёма,
поверхностный Delaunay5, 3D Tet10/HXT, Gmsh4.15.2. Не вводится
дополнительного множителя на поверхность. Цель `V_target/V_M1=0.83`
при `kappa=1` **не является гарантией** фактического результата.

Оценка по одному прежнему α=0.20 эксперименту при приближённой
линейности: север ≈23.44%, юг≈16.73%, оба полюса≈20.10%. Это только
калибровочная гипотеза; дискретная перестройка Gmsh может изменить
результат. После P10EN требуется независимая 27/125/343/729QP проверка
в тех же физических регионах и на северной/южной полярных половинах;
порог `0.75<=Veff(M2)/Veff(M1)<=0.85`. Геометрическая QA
сама по себе **не** допускает FEM.

## Кнопки Windows (НЕ выполнять больше одной P10EN попытки)

1. Скачать ZIP P10EN из GitHub и распаковать в **совершенно новую** папку,
   желательно `G:\Downloads\P10EN_R1_ONE_M2_3D_ALPHA17_WINDOWS_20261122`.
   **Не** в `G:\ildar\Stage3D07` и **не** поверх P10EA/P10EF/P10EK.
   Должны быть Windows 11, Python3 и ранее подтверждённая
   `C:\gmsh-4.15.2-Windows64\gmsh.exe` (SHA остаётся закреплённым).
2. Двойной щелчок `01_P10EN_SAFE_PREFLIGHT_ONLY.cmd`. Если `PASS`,
   перейти к следующему пункту в течение24ч. Если STOP — **не** нажимать02,
   прислать `P10EN_EVIDENCE.zip` из последней папки `P10EN_R1_RUNS`.
   Кнопка01 безопасно проверяет исходники, оригинальную M1 SHA, C1
   поле по 17075 точкам, Windows Gmsh `-version` и `-parse_and_exit`
   для A/B GEO, 27QP QA, RAM/disk и незанятость только **новых** P10EN
   one-shot markers. `gmsh -3`, FEM и markers в01 не запускаются.
3. **Ровно один раз** открыть `02_P10EN_ONE_M2_3D_ONLY.cmd`. Ввести
   дословно в консоли:

   `RUN ONE P10EN M2 3D MESH`

   Перед Gmsh `-3` создаются две новые эксклюзивные метки
   `P10EN_R1_RUNS/P10EN_R1_ONE_3D_USED.json` и
   `%LOCALAPPDATA%/Stage3D07/P10EN_R1_ONE_3D_<M1_SHA>.json`.
   **Даже ошибка/тайм-аут расходуют разрешённую попытку**. Метки
   не удалять и кнопку02 после них не запускать.
4. Прислать **только один** `P10EN_EVIDENCE.zip` из последней созданной
   подпапки `P10EN_R1_RUNS`. При размере новой M2 **до32MiB** ZIP
   автоматически включает её исходную `.msh` для независимого
   пространственного аудита, так что отдельное вложение не потребуется.
   При большем `.msh` ZIP сохраняет только малые журналы; raw будет
   запрошена отдельно. **В публичный GitHub raw MSH не отправлять.**
   Внутренние старые имена `P10EA_*` у inherited QA/mesh файлов не
   означают, что запускалась старая P10EA: смотреть manifest revision
   `P10EN_R1_ONE_NATIVE_3D_M2_ALPHA17_BAND15_25_MESH_ONLY`.
   **ВНИМАНИЕ:** старый файл `QA/P10EA_M1_M2_9_ZONE_VOLUME_COMPARISON.csv`
   содержит *исторические* подписи цели для `alpha=0.20`, поскольку его
   pinned-исходник сохранён точно. Для P10EN использовать **новый**
   `QA/P10EN_ALPHA17_9_ZONE_COMPARISON.csv` и
   `QA/P10EN_ALPHA17_GEOMETRY_AND_TARGET_CONTRACT.json` с корректным
   полем `alpha=0.17`; они включаются в evidence автоматически.
   И те и другие медианы непарные, независимый 3D QP gate выполняется
   **после** передачи raw M2.

## Ограничения ресурсов и окончание опыта

- До Gmsh: свободно RAM≥16GiB, диск≥4GiB.
- Gmsh `-3 -nt 2 -format msh2`; wall≤900с, polled private≤8GiB,
  mesh≤750MiB, log≤16MiB. QA curved27QP wall≤300с/private≤8GiB.
- На том же i7‑7700K предыдущая P10EK native M2 заняла≈0.61с,
  QA≈10.45с, polled private≈0.25GiB. Для P10EN ориентир от десятков
  секунд до нескольких минут; **защитный предел до20мин**, это
  оценка, а не гарантия. Никаких новых задач Qt Creator и FEM нет.
- При STOP передать исходный ZIP, новые маркеры сохранить.
  При геометрическом PASS всё равно **не запускать физический расчёт**:
  сначала независимая проверка фактического диапазона15–25%. Только
  после этого новая прямая история M2, затем сопряжённая **на той же M2**,
  без старых H0/M1 caches и с `ANALYTIC_TET10`.
