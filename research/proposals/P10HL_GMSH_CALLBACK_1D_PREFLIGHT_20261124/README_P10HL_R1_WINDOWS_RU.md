# P10HL R1 — проверка настоящего интерфейса Gmsh 4.15.2

Из P10HK получено подтверждение корректности прямого непрерывного κ на 20 000 точках пользователя: max ошибка 6.6613e−16, 45.28 мкс/запрос. Следующий вопрос: действительно ли шестой аргумент `lc` функции `gmsh.model.mesh.setSizeCallback` представляет исходный фоновый размер.

**Ограничение:** построить разрешается только одну искусственную прямую длиной 5 мм, находящуюся снаружи поры; единственный вызов Gmsh `gmsh.model.mesh.generate(1)`. Исходные M1, CAD, физические расчёты, двумерная и трёхмерная сетки не затрагиваются. Запись `.msh` отсутствует.

1. Распаковать архив в отдельную папку.
2. Запустить `01_P10HL_ONE_SYNTHETIC_LINE_1D_ONLY.cmd` двойным щелчком.
3. Прислать только `P10HL_RESULT.json` и `P10HL_LOG.txt`; при остановке — `P10HL_ERROR.txt` и `P10HL_LOG.txt`.

Нужен Python с **NumPy и Python-модулем Gmsh версии 4.15.2**. Скрипт сначала ищет импортируемый `gmsh`, затем `C:\gmsh-4.15.2-Windows64\lib\gmsh.py`. Если API недоступен, **останавливается без 1D запуска**, а не устанавливает что-либо автоматически. Отсутствующий модуль при необходимости устанавливается пользователем штатно в Python как `python -m pip install gmsh==4.15.2`.

Ожидаемое время на i7-7700K: **2–20 секунд**. Если обнаружено `LC_DIFFERS_FROM_BACKGROUND_CONSTANT_REQUIRES_ANALYSIS`, это полноценный диагностический результат — **не запускать M2**. Положительный результат пока относится лишь к синтетической постоянной величине; реальный исходный `Field[7]` требует отдельного испытания.
