# P10HG R3 — корректный порядок средних узлов Tet10

В исходном P10HE/P10HF программа успешно создала 3D `SS PostView`, native Gmsh `-parse_and_exit` прошёл. **Но** вычисление ошибки C²→C⁰ в средних узлах Tet10 содержало ошибку: для последних двух ребёр были переставлены узлы. Поэтому показанные в предыдущем P10HE QA максимальное расхождение 0.73247, p95 0.02406 и число 1098 пороговых случаев **пока недостоверны**. Это ошибка нашей проверки, не доказанная ошибка поля.

По документации Gmsh 4.15.2 правильный локальный порядок 6 рёбер тетраэдра:

`(0,1), (1,2), (2,0), (3,0), (3,2), (3,1)`.

Новый R3 исправляет **только** эту нумерацию в независимом контроле средних узлов и не меняет узловые κ, SS PostView, геометрию M1, математическую модель, веса механических компонентов, источники 4D, коэффициент размера 0.17 или native Gmsh. Зависимость только от Python3+NumPy, без SciPy.

1. Распакуйте P10HG R3 в новый каталог.
2. Запустите только `01_P10HG_CORRECTED_EDGE_QA_NO_MESH.cmd`.
3. Сначала пройдёт синтетический контроль правильной нумерации Tet10, затем тот же source-only расчёт реальной M1 и только Gmsh `-parse_and_exit` без построения сетки.
4. Передайте новый `P10HE_SOURCE_ONLY_EVIDENCE.zip` из каталога P10HG R3.

Используется уже существующий оригинальный `P10GT_HXT10_EVIDENCE.zip`, он ищется автоматически как и в P10HF. Старые P10GT/P10HC/P10HD one-shot markers не затрагиваются. Никакие новые 1D/2D/3D mesh или FEM не выполняются. При STOP прислать evidence или текст окна.
