## Ресурсный лимит P10DA (программный, не аппаратный)

Истинный U0 runtime/RAM/размер истории **ещё не измерен**. Ориентир из реального P10CD H1: 19 412 Tet10, 407.813 с, около 2.56 ГБ peak polled private, 409.19 МБ файлов. Отношение числа Tet10 U0/H1 = 90 725 /19 412 = **4.67**; грубое линейное масштабирование даёт ~32 мин, ~12 ГБ, ~1.91 ГБ. Это **не верхние границы**: дорогие нелинейные/сопряжённые решатели могут расти быстрее.

| Параметр | P10DA предел |
|---|---:|
| Свободная физическая RAM перед стартом | ≥20 GiB |
| Свободный диск у извлечённого пакета | ≥8 GiB |
| Стенка часов после solver start | 3600 с (60 мин) |
| Peak *опрашиваемой* private памяти дочернего EXE | 32 GiB |
| *Опрашиваемые* новые файлы `U0_PHYSICAL_RUN` | 4 GiB |
| OpenMP | 4 потока |

Опрос раз в секунду и вызов `kill()` при превышении. Мгновенные пики между отсчётами, память прочих процессов, дефицит pagefile и собственные ошибочные выходы ОС полностью не ограничиваются. Не запускать параллельно тяжёлые задачи. При любых проблемах — **STOP без повтора**.

## Что даст и чего НЕ даст первый U0

* Первый физический signed `D_R jpeak`, отдельно global mechanical/thermal, три механические компоненты, temporal components, 10 радиальных ×10 полярных тепловых бинов ×6 шагов, отдельный top Robin. Контроль 5 806 400 curved volume QP на шаг; 606 local rows и 6 audit rows; независимая программная сверка global и per-step QP/CSR.
* Грубые абсолютные распределения, знаки, взаимное погашение, остаточные невязки, срезы по времени — **данные для выбора следующих диагностик и индикаторов**, без притязания на локальную сходимость.
* Имеющиеся 20 Tri6 стенки и отсутствие corner-centroid в d=0–100 мкм исключают утверждение, что U0 разрешает тонкие физические слои. Нельзя считать пик на одном грубом элементе истинным индикатором локальной ошибки.
* В текущем pinned EXE нет полного требуемого D-017 **3D φ-разбиения signed механики и тепла**; механические числа пока глобальные, тепловые бины 2D (r,θ,t). Поэтому **M1 нельзя автоматически строить по ним**. Сначала аудит U0, затем при необходимости подготовка аттестованного 4D экспорта или независимого остаточного/энергетического индикатора, и только затем адресное сгущение.
* Две сетки H0/H1 в предыдущей истории не дают сходимости U0. Никакой заранее заданной толщины будущих элементов, числа узлов, полярного предпочтения или обязательной итоговой M3 не выбираем.

## Статус

Linux Python compile и synthetic selftest разрешены и не вызывают FEM; Windows SDK/API, сам EXE и U0 доступны только на ПК исследователя. Поэтому **P10DA physical runs=0** до возврата evidence.
