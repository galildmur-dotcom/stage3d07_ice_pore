# P10CH — отдельный экспериментальный модуль разбиения (r, θ, φ, t)

Это **не** патч для установленного Windows-решателя и **не** разрешение на FEM. Входные локальные вклады должны быть вычислены независимым дискретным сопряжённым алгоритмом и уже взвешены по времени. Модуль только сортирует их по независимым координатным корзинам с контролируемой суммой.

Файлы:

- `p10ch_4d_partition.hpp`: 4D пространственно-временные корзины, 6 signed contributions, отдельно выход за радиальный support и boundary accumulation;
- `p10ch_4d_unit.cpp`: детерминированная синтетическая проверка двух полюсов, четырёх азимутов, трёх временных шагов, непересекающегося radial bin, outside и boundary.

Локальная проверка Linux C++20 (20.11.2026):

```text
g++ -std=c++20 -O2 -Wall -Wextra -Werror p10ch_4d_unit.cpp -o p10ch_4d_unit
P10CH_4D_SYNTHETIC_UNIT_OK bins=1080 steps=3 polar=10 phi=12 axis=1 outside=1 signed_total=-5.826159707085067e-06 conservation_abs=2.202285662861181e-20 FEM=0
```

Ограничения:

1. **Не** вызывается реальный solver, `stage3d10w`/`stage3d10p` или P10BA/P10BX; термомеханическая формула и сопряжённые поля не тестируются.
2. Для физического вывода `φ` нужны настоящие координаты QP в пользовательском C++; текущие CSV `P10BB/P10BE/P10CD` уже проинтегрированы по `φ`.
3. Для математически полярной оси при `x=y=0` угол `φ` неопределён; тест назначает сектор 0 и считает такие точки отдельно. У QP на точной оси нет конечного углового объёма; не интерпретировать как физический азимутальный максимум.
4. Внешние за пределом радиального окна вклады не удаляются, а учитываются отдельно; это важно для строгого разбиения. Граничные Robin и поверхностные вклады считаются отдельно во избежание двойного счёта.
5. Перенос в production потребует отдельной проверки актуальных исходников, источников QP для `geom/equil/history/thermal`, интерфейса history, проверок на Windows и отдельного допуска к FEM. Нельзя объявлять 4D поле физически вычисленным по этому тесту.
