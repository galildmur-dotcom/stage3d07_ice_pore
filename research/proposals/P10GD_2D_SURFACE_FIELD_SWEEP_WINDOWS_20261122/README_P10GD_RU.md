# Stage3D07 — P10GD: безопасная диагностика топологии поверхности M1V→M1W

**Научный статус:** у M1W curved Tet10 geometry PASS, но только 10/18
пространственных зон удовлетворяют требованию 15–20% уменьшения
фактического объёма относительно M0. Поэтому M1W **не утверждена**,
физику M1W **не запускать**. Это исследование проверяет, как
меняется **дискретная топология поверхности поры** при плавном
изменении параметра размера. Оно **не** генерирует новую объёмную
сетку, не запускает FEM и не обещает 3D GO.

## Что делает программа

- Строго проверяет SHA существующих M0, M1V и M1W `.msh/.geo`,
  CAD, исходников и закреплённые результаты измерений.
- Использует девять C¹ полей размера с `θ = 0, 0.125, 0.25, ..., 1`
  между _исходным полем M1V_ (`θ=0`) и _полем M1W_ (`θ=1`).
  Объёмная физическая κ(x) остаётся равномерной и в этих тестах
  не меняется; поле `h` лишь диагностирует генератор Gmsh.
- На каждом поле запускает **только native Gmsh `-1` и `-2`**;
  в `-1` разрешён `-save_all` для сохранения элементов кривых,
  а в `-2` — **без `-save_all`**, чтобы сохранить физический тег поры.
- Считает реальное количество и длины сторон Tri6 в **шести
  знаковых угловых секторах** (`N/S`×`polar/taper/off`), записывает
  `.geo`, диагностические `.msh`, логи, JSON, ZIP. Файлы создаются
  **только внутри новой папки** `LOCAL_RUNS/P10GD_SURFACE_SWEEP_...`.
- **Никогда** не запускает `-3` или FEM, не создаёт/перезаписывает
  `M1X` в `meshes`, не трогает `approvals` и одноразовые markers.

Девять вариантов **не** означают девять попыток объёмной генерации.
Даже если данные окажутся информативны, следующему 3D кандидату
понадобится **другое имя**, одноразовый запуск и полноценный 729QP
аудит всех 18 объёмных зон. Поверхностный Tri6-тест **не является**
пропуском к физике.

## Одно действие, без ввода символов

1. Распаковать ZIP **в новую папку**
   `G:\ildar\Stage3D07\P10GD_TOOLS_R1`.
2. Убедиться, что Windows11, Python3 и Gmsh4.15.2 присутствуют, а
   исходные `M0`, `M1V_CANDIDATE`, `M1W_CANDIDATE` не изменены в
   `G:\ildar\Stage3D07\meshes`.
3. Дважды щёлкнуть `01_P10GD_2D_ONLY_NO_3D_NO_FEM.cmd`.
   Окно **останется открытым**, ничего вводить/подтверждать не нужно.
4. Прислать **один** файл из новой папки
   `G:\ildar\Stage3D07\LOCAL_RUNS\P10GD_SURFACE_SWEEP_...\P10GD_SURFACE_SWEEP_EVIDENCE.zip`.
   В случае раннего STOP без ZIP — `P10GD_SURFACE_RESULT.txt` рядом
   с CMD. Не требуется запускать никаких других CMD.

Результаты помогут установить, какие вариации поля порождают
непредсказуемые скачки поверхностного разбиения. Это **контрольный
эксперимент**, а не критерий выбора окончательной 3D сетки.
