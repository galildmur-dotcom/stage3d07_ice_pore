# Stage3D07 — P10GM R1: короткая диагностика Gmsh 1D

**Только диагностика, не новая M1.** P10GL однократный `-3` уже израсходован.
**Не запускать P10GL `02` ещё раз, не удалять старые маркеры**.

## Основание

Присланный журнал `P10GL_GMSH_3D.log` SHA256
`ea1689134efa4505a2ceb5cd2655fa8ae1bbdafdf0387e1f1ed6a515764fcdc0`
обрывается на `Meshing 1D`, `curve 14` и `curve 17`; доказательств 2D/3D
нет. При ручном закрытии после ≈15 мин отчёт и ZIP не создались.

Цель — выяснить, воспроизводится ли задержка на строго ограниченном `-1`
и отличается ли обработка нового составного поля от исходного. Подтверждённая
прежняя P10GJ native 3D занимала ~0.50 с. **Нельзя утверждать, что Gmsh
имеет конкретный баг, пока эксперимент не проведён**.

## Условия и запуск

1. Скачать/распаковать **новый ZIP** в отдельную папку
   `G:\ildar\Stage3D07\P10GM_TOOLS_R1` (папку не смешивать с P10GL).
2. Двойной щелчок `01_P10GM_PREFLIGHT_NO_MESH.cmd`. Он проверит неизменность
   P10GK исходников, полей на 10 201 точке, SHA прежней M0, SHA/version
   `C:\gmsh-4.15.2-Windows64\gmsh.exe`. **Ни одной сетки** на этапе 01.
3. Только при `P10GM_PREFLIGHT_PASS_NO_MESH`, в течение 24 часов, **один раз**
   двойной щелчок `02_P10GM_ONE_1D_DIAGNOSTIC_ONLY.cmd`. Вводить символы и
   пути не нужно. Окно **показывает живые сообщения Gmsh и время каждые 2 с**.
4. Дождаться итога: не более ~90 с чистого Gmsh + несколько секунд проверок,
   сохранения/упаковки. **Не закрывать окно во время этих ~2 минут**, даже
   если текущий Gmsh не пишет новые строки: программа печатает `HEARTBEAT`.
5. Прислать **ровно один файл** из
   `G:\ildar\Stage3D07\LOCAL_RUNS\P10GM_1D_FIELD_DIAG_*\P10GM_1D_PROBE_EVIDENCE.zip`.
   Если ZIP нет — прислать `P10GM_02_RESULT.txt` либо скриншот/текст окна.

## Три проверки (новая 1D-only однократная попытка)

| Случай | Фоновое поле | Изменение относительно P10GK |
|---|---|---|
| A_F3_BASELINE | Исходное F3 | Убрана только южная поправка; hscale тот же |
| B_F6_LINKED | P10GK исходный F6 | F3, F4, F5 связаны в MathEval |
| C_F7_INLINE | Алгебраически то же, что F6 | Подстановка F4/F5 внутрь единой формулы F7 |

Для A/B/C неизменны OCC геометрия, поворот оси поры, физические группы,
исходная M0 C¹ F3, `MeshSizeFactor=0.9378887276834518`, алгоритм HXT10
в настройках (но HXT **не исполняется**: только `-1`). Без `-2`, `-3`, FEM,
построения окончательной M1, изменения original M0 или frozen D-027.

После случая A STOP другие тесты не выполняются: проблема может быть не в
новой поправке. После B TIMEOUT случай C всё равно выполняется для различения
гипотез. Три попытки каждая ограничены 30 сек, ≤8 GiB private RAM, 2 threads,
и уникальны внутри собственного рабочего каталога. Программа создаёт
независимые P10GM local/profile маркеры **до первого native `-1`**. При
любом STOP/закрытии **не повторять 02**, результаты разбирать отдельно.

## Допустимый вывод

- A PASS, B TIMEOUT, C PASS: вероятен эффект связанного вычисления F4/F5;
  это не доказательство внутреннего бага Gmsh, C не одобрена для 3D.
- A PASS, B TIMEOUT, C TIMEOUT: вероятна тяжёлая/аномальная оценка нового поля.
- A TIMEOUT: источник задержки не локализован до P10GK, 02 остановлен.
- Все PASS: задержка в P10GL пока не воспроизведена на 1D; причину 3D
  или предыдущего зависания нельзя считать установленной.

**Ни один исход 1D не разрешает следующий native `-3` или FEM.** Неизменные
научные критерии: global QV729 [0.80,0.85]; южный/северный физический полюс
0–500 мкм при достаточном N_eff QV≤0.98; curved Tet10/поверхности/градация
и 343/729 QP; прежние 18/18 — только диагностика.
