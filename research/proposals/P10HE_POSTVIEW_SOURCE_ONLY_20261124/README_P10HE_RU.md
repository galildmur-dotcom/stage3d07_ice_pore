# P10HE — вычислить κ в узлах реальной M1 и создать Gmsh PostView без новой сетки

P10HD `-1` был остановлен по времени300с, RAM0.246GB, большой `MathEval` медленен при фактической генерации. Здесь исходный непрерывный C² κ(x) вычисляется **один раз** в Python на **уже полученной M1 Tet10**, а Gmsh получает готовые числовые значения через стандартный scalar `PostView` в файле `.pos`. Никакой новый M2, FEM или `gmsh -1/-2/-3` не вызывается.

1. Скачайте пакет и распакуйте в новый самостоятельный каталог, например `G:\ildar\Stage3D07\P10HE_TOOLS`.
2. Убедитесь, что сохранён исходный `P10GT_HXT10_EVIDENCE.zip` (SHA pinned) из прежней успешной попытки в `G:\ildar\Stage3D07\LOCAL_RUNS` или `G:\ildar\Stage3D07\P10GT_TOOLS_R1` либо `G:\Downloads`. Физическую M1 не запускать вновь!
3. Запустите двойным щелчком `01_P10HE_BUILD_POSTVIEW_NO_MESH.cmd`. Требуются Python 3, numpy, scipy, исходный Gmsh4.15.2 (только `-parse_and_exit`). Без дополнительных запросов разрешения и без запуска физики.
4. Передайте `P10HE_SOURCE_ONLY_EVIDENCE.zip`. При STOP передайте тот же ZIP; он содержит `P10HE_SOURCE_QA.json` с причиной.

Выходной `P10HE_M1_MECHANICAL_KAPPA.pos` — скалярная 3D `PostView` **SS (scalar tetrahedron)** на первопорядковых хордах существующей M1 Tet10; значения в каждой вершине вычислены из исходной C² функции. Построенное по этим значениям интерполяционное поле **C⁰, а не C²**, что отдельно требуется исследовать, особенно около криволинейной стенки поры. Программа считает max/p95/median расхождения на Tet10 midside nodes между оригинальным C² и линейной интерполяцией, не выдавая этот источник за геометрически принятый M2.

Сохраняется исходное P10GT M1 baseline `Field[7]` (только физически подтверждённая source), а новый `Field[40]=PostView` задаёт κ, `Field[43] = F7*(1-0.17*F40)^(1./3.)` — **только номинальную цель** 17% уменьшения локального объёма при κ=1. Фактический D-025 15–25%, оба полюса, неполярная QA, физика на M2 — только после последующего mesh-only этапа с отдельной научной проверкой.
