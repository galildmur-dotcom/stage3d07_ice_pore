# P10DD R1 — программа для полного физического локального разложения M0=H0

**Назначение:** отдельный новый EXE `stage3d10dd_m0_h0_full4d` (Windows/MinGW, C++20, OpenMP), **на точной ранее просчитанной H0**, `mode R`, `EDV_VAR`, `xi=0`, `6×150 с`, `B6 cutoff=5 мм`, `jpeak`. **Подготовка и тесты не являются новым МКЭ.** Сам факт численного исполнения H0 с полным экспортом будет установлен только по Windows evidence.

## Что изменилось в расчётной программе

Новый compile flag `STAGE3D10DD_FULL4D` включается **только** в новом EXE. В существующих P10W/P10P без этого флага ничего не меняется. После каждого обратного шага механики данные точной аналитической формы `P10V`, механический adjoint `lambda_n`, будущие EDV multipliers и неустойчивые температуры используются для дополнительной свёртки **во всех 27 QP каждого Tet10**. Разделены подписанные:

1. `explicit_objective` — вариация нормированного по `V_B6` интеграла `jpeak`, включая общую производную знаменателя.
2. `equilibrium` — локальная свёртка механической сопряжённой переменной с геометрической производной невязки.
3. `history` — локальная свёртка `e_d/e_v` со следующими по времени сопряжёнными множителями.

Тепловой adjoint `psi_n` свёртывается **во всех 64 QP каждого Tet10** с shape mass и diffusion, а вклад `Robin stiffness + Robin load` интегрируется на верхних Tri6 отдельно (16 QP/face), без ложной приписки ближайшему объёмному кольцу. Все термические QP суммы каждого шага сравниваются с **неизменённым** существующим CSR contraction; все механические QP компоненты каждого шага — с существующими `P10V` component totals; итог 6 шагов — с глобальным `P10W` для `jpeak`. Отрицательные компоненты **не** берутся по модулю, сверхкомпенсации сохраняются. STOP при нарушении замыкания.

Пространственные корзины: 10 радиальных (`0, .02, .05, .1, .25, .5, 1, 2, 5, 15+ мм` от поверхности), 10 равномерных интервалов `mu=cos(theta)` (в CSV приводятся **границы theta в радианах**), 12 равномерных интервалов `phi` на `[-pi,pi)`, и 6 **отдельных** временных шагов. `1200×6+6=7206` строк QP CSV с отдельной строкой TOP_ROBIN на шаг. Азимут на оси математически не определён: QP на оси по соглашению попадает в φ0 и учитывается счётчиком axis QP. Высокие near-pole signed density не являются сами по себе индикатором ошибки.

Выходные файлы:

- `P10DD_SIGNED_R_THETA_PHI_T.csv` — полный знаковый 4D-разбор, два числа QP/объёма на ячейку и 6 физических компонент на шаг.
- `P10DD_FULL4D_CLOSURE_AUDIT.csv` — итог шагов, числа QP, геометрические объёмы, Robin площадь.
- `P10W_ANALYTIC_ADJOINT.csv`, `P10W_COMPONENTS.csv`, `P10W_STEP_COMPONENTS.csv` — неизменённые эталонные глобальные/механические значения.
- `P10DD_EVIDENCE.zip` — автоматический небольшой архив результатов + native Windows ExitCode, EXE/mesh/cache SHA, лог. Перед статусом `completed_4d_verified` **независимый Python-аудит `P10DD_audit_evidence.py`** проверяет 7206 строк, числа 27/64 QP для точной H0, подписанные суммы шагов против P10W step/global и отдельный Robin. Полную сетку, forward cache, VTU в GitHub и чат не передавать.

## Компиляция на Windows 11 — без изменения исходного G:\ildar\Stage3D07

1. Скачать один исходный архив P10DD с исследовательской ветки GitHub, **распаковать в новую отдельную папку**, например `G:\ildar\P10DD_R1_ISOLATED`. Не распаковывать поверх рабочего `G:\ildar\Stage3D07`.
2. Открыть в Qt Creator `P10DD_R1_ISOLATED\CMakeLists.txt`, выбрать *Desktop Qt MinGW 64-bit Release* как для прежнего проекта. CMake использует **только** исходники этого архива (не грязный рабочий проект). **Выбрать цель `stage3d10dd_m0_h0_full4d` и собрать**, а также цель `p10dd_4d_synthetic_unit`. Никакой физический расчёт CMake сборкой не запускается. `STAGE3D07_SOURCE_ROOT` по умолчанию равен этой папке.
3. Запустить один раз `p10dd_4d_synthetic_unit.exe`: ожидается `P10DD_4D_SYNTHETIC_UNIT_OK`. Далее у нового `stage3d10dd_m0_h0_full4d.exe` проверить `--help` и `--selftest` — тоже без FEM. Python `P10DD_audit_evidence.py --selftest` даёт отрицательный контроль ошибочного замыкания.
4. Если принято решение выполнить **отдельный** ограниченный H0 adjoint replay, в новой папке дважды щёлкнуть `01_PREPARE_OR_RUN_P10DD_M0.cmd`. Программа потребует вручную ввести полный путь нового EXE и **путь существующего H0 `forward_history.bin`**; она проверит точную H0 SHA и другие барьеры. Только после отдельной введённой фразы `RUN ONE H0 P10DD` откроется одна новая попытка. Без H0 cache по умолчанию **STOP**, повторный nonlinear forward не запустится случайно. Сам факт предыдущего P10CA native ExitCode=UNKNOWN не исправляется данным новым запуском задним числом.

## Точные параметры, лимиты и STOP

`stage3d10dd_m0_h0_full4d.exe --mesh "G:\ildar\Stage3D07\meshes\H0.msh" --out "<НОВЫЙ_КАТАЛОГ>" --mode R --steps 6 --dt 150 --cutoff-mm 5 --threads 4 --reuse-forward "<СТАРЫЙ_ВАЛИДНЫЙ_H0_CACHE>"`.

`--reuse-forward` **не** означает отсутствие физической работы: будет новый обратный механический (18 решений) и тепловой сопряжённый проход; старый H0 cache содержит **только прямую историю**. Проверяется mesh signature, layout, 6×150, cutoff5, побайтовое совпадение температур с восстановленным тепловым forward; несовместимый cache → STOP. Выйти в новый каталог, никогда не перезаписывать старый результат. Пары forward+adjoint внутри этого прохода используют **одну и ту же H0** (D-012).

Проверенные ранее H0 P10CA R1: **104.424 с** / **~0.895 GiB** private peak; это старая программа без 4D экспорта, не ресурсный bound. Предварительный план для P10DD H0 с cache: **около 2–8 минут**, ожидаемый private RSS порядка **1–3 GiB** (оценка, не измерение). Жёсткий программный polling-STOP: 900 с wall / 8 GiB private / 1 GiB новых результатов; требуется ≥3 GiB свободного диска. Исходный H0 mesh и прежние run/cache не изменяются. Marker создаётся **до** физического процесса и блокирует автоматические повторы даже при STOP. Реальный Windows нативный ExitCode берётся прямо из `subprocess.Popen.wait()`, не из PowerShell `$LASTEXITCODE`.

**Статус подготовки:** Linux `g++` C++20 `syntax-only`/link, стандартный `P10I` selftest, native synthetic 1200-bin/6-step/negative closure прошли. Не проверены пока реальная H0 27QP/64QP геометрия в новой программе, Windows MinGW сборка, physical gradient/4D per-step closure на H0 и физический режим возмущения. P10DD — экспериментальная отдельная версия, не окончательно аттестованный FEM результат. В научную адаптацию M2 допускаются лишь данные, прошедшие Windows full4D numerical evidence + независимый аудит.
