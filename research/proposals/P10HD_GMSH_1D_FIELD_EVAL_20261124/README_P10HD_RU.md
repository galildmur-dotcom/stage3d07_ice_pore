# P10HD — первый реальный расчёт выражения адаптивного поля в Gmsh

Исходный P10HC успешно прошёл `-parse_and_exit`, но реальная оценка математического выражения `Field[40..43]` ещё не проводилась. Этим пакетом выполняется **только один одномерный сеточный пробник** четырёх специально созданных отрезков: север и юг от поры, два экваториальных азимутальных направления. Исходная трёхмерная CAD/сетка M1/M2 не меняется, никаких 2D/3D MSH и FEM.

1. Распакуйте ZIP в новый каталог, например `G:\ildar\Stage3D07\P10HD_TOOLS`.
2. Запустите `01_P10HD_PREFLIGHT_NO_MESH.cmd`. Должен быть статус PASS; выполнится только native `-parse_and_exit`.
3. Если PASS, запустите **один раз** `02_P10HD_ONE_NATIVE_1D_ONLY.cmd`. Ограничение Gmsh -1: wall 300с, жёсткий Windows Job private RAM 4GiB, log 6MiB, MSH 16MiB, 2 потока. Новые P10HD one-shot markers не позволяют повторять попытку без анализа ошибок. Старые P10GT/P10HC markers остаются нетронутыми.
4. Пришлите `P10HD_ONE_1D_EVIDENCE.zip`. Если 01 STOP — пришлите `P10HD_PREFLIGHT_EVIDENCE.zip` и текст ошибки; кнопку 02 не нажимать.

Нужны Windows 11, установленный Python launcher `py -3` и Gmsh 4.15.2 в `C:\gmsh-4.15.2-Windows64\gmsh.exe`. Не нужен Qt, MinGW/CMake, SciPy, FEM/adjoint. Один самостоятельный лимитированный `-1` пробник после parse; никакого автоматического Gmsh `-2/-3` и M2 GO.

**Важно:** Field[7] в этом диагностическом GEO — константа, а Field[44] искусственно повышает контраст для проверки фактического вычисления `κ`. Это не геометрия M2 и не закон её адаптации. После успешного -1 ещё надо исследовать физическую интерполяцию на 3D CAD и объёмный критерий D-025 15–25%.
