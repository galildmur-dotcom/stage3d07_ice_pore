# P10GJ R1 — единственная новая объёмная HXT10 M1 (Gmsh 4.15.2), без FEM

**Разрешение исследователя получено 23.11.2026** на подготовку и
однократную native Windows `-3` попытку M1 **без физических расчётов**.
Ни P10GJ source-only PASS, ни native 27QP PASS не означает M1 GO:
для D-027 ещё обязателен независимый 343/729QP и макрозонный аудит.

## Научная постановка

Исходная закреплённая M0 (SHA256
`926a9c903765ce77fd560300d10614d3cece3d4cd4d7813027e45e92d33870d6`)
не изменяется. Одна новая M1: та же точная OCC сфера R=1 мм,
но поворот **только CAD-параметрической оси** на 90° вокруг X до
Boolean; то же исходное поле M0 C¹ `Field[3]` и глобальный
`Mesh.MeshSizeFactor = 0.825^(1/3) = 0.9378887276834518`.
Только HXT (`Mesh.Algorithm3D=10`), MSH2.2 ASCII, Tet10/Tri6,
физические группы 1–9; нет PostView, анизотропии или адаптивного
индикатора на этапе M0→M1.

Основание: реальный пользовательский P10GH (Gmsh4.15.2):
`q_corner,min` на поре исходная→поворот `0.32150→0.59008`, у
физических полюсов минимум `0.51692/0.32150→0.86080/0.88283`.
Сама по себе эта 2D геометрия **не гарантирует** 3D плотность:
локальная P10GE Gmsh4.13 показала отрицательный 3D результат.

## Предрегистрация D-027 — до попытки Gmsh -3

Все формулы и абсолютные пределы зафиксированы до генерации в
`P10GJ_D027_GATE_POLICY.json` и защищены контрольными суммами.
**Кнопка 01** вычисляет только по неизменной исходной M0 численные
пороги (mean-ratio slivers Tet10 и p95/p99 скачков характерного
размера соседей) и сохраняет `P10GJ_D027_FROZEN_GATES.json`.
SHA этого файла блокирует его изменение между 01 и 02. Контроль M0:
физические метки, closed pore/B6, signed curved Tet10 27QP,
соседние размеры, архивные M0 343/729QP, Gmsh version/exe,
побайтовые GEO/SHA, native `-parse_and_exit`. **Ни одной новой
1D/2D/3D сетки в 01 нет**.

Для будущей M1 проверяются независимые hard gates:

- совпадение CAD/объёма до 0,5%, радиус до `1e-8 м`,
  замкнутые сферы (Euler=2), все физические группы 1–9;
- pore Tri6 `q_min≥0.50`, `p05≥0.70`, физические север/юг
  `q_min≥0.75`, 7QP curved Jacobian positive, area ratio
  каждой сферы в `[0.99;1.01]`;
- положительные corner/curved Tet10 detJ на 27/343/729QP;
  mean-ratio q и соседняя градация по замороженным из M0 порогам;
- **глобально** `0.80≤Veff(M1)/Veff(M0)≤0.85`; сначала оценка
  по 27QP, затем независимая строгая 343/729QP;
- на достаточно населённых (`M0 N_eff≥50`) фиксированных
  физических макрозонах не допускать огрубления свыше 5%,
  в объединённой физической полярной зоне `0≤d≤0.5 мм` —
  требовать `q≤0.98` (как минимум 2% уменьшение `Veff` относительно
  M0); макрозонные q не меньше0.65;
  `|q343−q729|≤0.02`. Все 18 подписанных зон и `N_eff`
  публикуются, **18/18 больше не hard gate**.

Последние независимые 343/729QP ещё **не выполняются кнопкой 02**:
для них нужен первоначальный `.msh` из evidence ZIP, который
ассистент аудирует отдельно. Следовательно, `02 PASS` = только
предварительно допустимая геометрия 27QP, **не M1/FEM GO**.
Все локальные пороги специально являются проверяемыми инженерными
критериями текущей кампании, а не универсальными оценками ошибки FEM.

## Порядок на Windows 11 — два двойных щелчка, без команд

1. Распаковать отдельный ZIP в **новую** папку
   `G:\ildar\Stage3D07\P10GJ_TOOLS_R1`.
2. Двойным щелчком `01_P10GJ_PREFLIGHT_FREEZE_GATES.cmd`.
   Окно остаётся открытым. Только при строке
   `P10GJ_PREFLIGHT_PASS_GATES_FROZEN_NO_3D` разрешена 02.
   При STOP 01 — **02 не запускать**, прислать `P10GJ_01_RESULT.txt`.
3. При PASS 01 **не позже 24 часов**, **ровно один раз** двойным
   щелчком `02_P10GJ_ONE_HXT10_3D_ONLY.cmd`.
   Никакого ручного ввода или подтверждения не требуется.
4. При любом итоге 02 отправить **один**
   `G:\ildar\Stage3D07\LOCAL_RUNS\P10GJ_M1_ROTATED_HXT10_*\P10GJ_M1_HXT10_EVIDENCE.zip`.
   Если ZIP не создан, отправить только `P10GJ_02_RESULT.txt`.
   **После STOP 02 не повторять. Маркеры не удалять.**

## Ресурсы и сохранность

- Не более одной нативной `gmsh.exe -3`, не более **900 с (15 мин)**,
  hard Windows Job private memory ≤**8 ГиБ**, `-nt 2`, свободная RAM
  до запуска ≥12 ГиБ, свободный диск ≥4 ГиБ. Файл MSH ≤128 МиБ.
- Оценка на i7-7700K для этой небольшой (~10 тыс. Tet10) цели:
  ориентировочно **от десятков секунд до нескольких минут**,
  но численно достоверного прогноза Gmsh 4.15.2 нет; при 15 мин
  watchdog остановит процесс. QA27 после Gmsh может добавить минуты.
- Генерируются **только новые** файлы в `LOCAL_RUNS/P10GJ_*`;
  канонические `meshes/M0.*`, старые M1/M1V/M1W и их markers не
  изменяются и не удаляются. Нет FEM, VTU, GH3, `.json` approval.
- Отдельные permanent local+profile P10GJ markers создаются **до**
  Gmsh. После их расходования любая попытка запуска 02 невозможна.
- Python3 stdlib (никакого NumPy/Gmsh Python API для кнопок).

Если мы получили mesh-only evidence, ассистент выполняет 343/729QP,
публикует 18 signed q, macro bins, QA+статус D-027 и **лишь потом**
запрашивает отдельное разрешение на fresh forward/adjoint FEM.
