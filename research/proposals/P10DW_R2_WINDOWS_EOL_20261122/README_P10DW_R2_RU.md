# P10DW R2 — исправлен Windows CRLF STOP при подготовке точного GEO

**Источник и статус:** P10DW R1 (21.11.2026) прошёл автономные исходниковые тесты, но **оригинальный Windows P10DW-01 от 22.11.2026 остановился ДО любого Gmsh**. Первичный ZIP `P10DW_EVIDENCE.zip` SHA256 **`d173de50c73167e3badbfe42c3fabb87b2ad345ac47f44623585a7da16655acc`**; 6/6 CRC, traceback `P10DW_STOP: generated inline candidate altered`, нативных parse=0, native1D=0, 3D M2=0, physical FEM=0.

**Причина доказана побайтно:** на Windows исходная R1 строка `Path.write_text()` записала `\r\n` вместо исходных `\n`. В `GEO/B_EXACT_INLINE_F6.geo` Windows SHA **`af8411f8deccd14b1905809b5a2e6ca04b9671789101acbc8b8233d89d10654a`**, а после замены *только* `\r\n → \n` SHA становится **`32f8f959002cbd41539e355a80437c2ca3be12fdd3ba12de31eadf2c021b9561`**, **точно** как опубликованный P10DV GEO. Никакой ошибки математического κ/геометрии или ошибки Gmsh здесь не было: Gmsh не запускался. Исходная CAD SHA `8029a6ed22bcf312701cd6abc46bbe5575e52df16fd5218dd936b01d5cd6fcf0` в оригинальном ZIP совпала.

R2 **не** меняет формулу, CAD, Field2 Threshold, исходную M1, параметры сетки, ресурсы/таймауты, командные аргументы Gmsh или имена однократных P10DW-маркеров. **Изменены только две операции записи generated GEO**: `write_text(..., encoding="utf-8")` заменено на `write_bytes(text.encode("utf-8"))`; метка источника `REV` и тексты R1→R2 обновлены. R1 архив и пользовательский STOP сохранены без изменения, не перезаписывать их. Дополнительно R2 проверяется на синтетической Windows CRLF-трансляции перед выпуском.

Старую R1 папку с полученным STOP и все marker/историю сохранять. Для R2 требуется Python3 и оригинальный Gmsh4.15.2 SHA256 `317c43391e5b1fab3a1dd80dc5245dad6e2d087910f4b8ebc234bd6d4b8f41a1` (по умолчанию `C:\gmsh-4.15.2-Windows64\gmsh.exe`).

## Кнопка 02: НЕ ЗАПУСКАТЬ

`02_P10DW_ONE_INLINE_F6_1D_ONLY.cmd` входит в исходный ZIP для следующего **отдельно разрешаемого** этапа. Она может выполнить **ровно один** native `gmsh -1` после свежего R2 preflight и точной ручной фразы `RUN ONE P10DW INLINE F6 1D`, с пределами15с wall/2GiB private поллинг/20MiB msh/1MiB log, 2 threads. Два одноразовых P10DW marker (в `P10DW_RUNS` и `%LOCALAPPDATA%\Stage3D07`) расходуются непосредственно до запуска, STOP не даёт права повторить. **R1 и R2 используют общую идентичность маркеров**, чтобы исключить повтор даже из разных распаковок. Старые P10DO/P10DQ/P10DR/P10DT маркеры и H0 forward cache не трогать. Любая M2 `-3`, curved27QP и физический FEM требуют ещё более позднего отдельного решения.

**Научная граница:** даже успешный R2 native parse не докажет исполнения F6 на геометрических кривых, качество/объёмы 3D Tet10 или сходимость `D_R jpeak`. Целевой объём по κ остаётся `Vtarget_M2/Vtarget_M1=1−0.20κ`, κ∈C¹∩[0,1] — математическая конструкция P10DV, не фактическое уменьшение объёмов сетки.
