# P10DR R1 — разделить исходные F3/F4 и их состав, только Gmsh 1D

В P10DQ реальные Windows A (Field2) и B (`F2` через MathEval) прошли за 0.22/0.43 с, C (`F2*(1-0.02*F5)`) завис на 1D и был остановлен за 25 с. P10DQ D/E **не исполнялись**. Исходная P10DO -3 израсходована (900-с STOP). **Ничего не повторять в P10DQ/P10DO.**

P10DR — **новый отдельный диагностический однократный** набор из 7 вариантов. Во всех диагностических формулах используется неизменный исходный `F2` и *исключительно тестовое* реберное масштабирование `F2*(1−0.02*Q)`, где `Q∈[0,1]`. Это 0–2% по целевому размеру, то есть до 5.8808% по целевому объёму, **не новая методика M2**. Физически согласованное будущее M2 требование остаётся `Vtarget2/Vtarget1=1−0.2κ` и `h2/h1=(1−0.2κ)^(1/3)`.

| Вариант | Q | Что различает |
|---|---|---|
| A_FIELD2_REFERENCE | отсутствует, `Background Field=2` | быстрый контроль той же CAD |
| B_F3_RAW_REFERENCE | `F3` | численная оценка/ссылка на радиальную ветку |
| C_F4_RAW_REFERENCE | `F4` | численная оценка/ссылка на угловую ветку |
| D_F3_F4_RAW_PRODUCT | `F3*F4` | совместная ссылка без smoothstep |
| E_F3_RADIAL_SMOOTHSTEP | `1−F3²(3−2F3)` | отдельная радиальная нелинейность |
| F_F4_ANGULAR_SMOOTHSTEP | `F4²(3−2F4)` | отдельная угловая нелинейность |
| G_F3_F4_INLINE_SMOOTHSTEP | `(1−F3²(3−2F3))*F4²(3−2F4)` | композиция гладких выражений **без ссылки `F5`** |

Все семь запускаются **по одному** даже после отдельного `TIMEOUT` (чтобы наблюдать обе независимые ветки), и каждый запускается **ровно один раз**. Это не семь отдельных однократных экспериментов: после подтверждения один *неповторяемый* диагностический набор; STOP не открывает повтора. Уже неудачный `F5` из P10DQ повторно **не запускается**.

Для чистого разделения зависимостей в варианте B/E **объявлен только исходный F3** (не F4), в C/F — **только исходный F4** (не F3), в D/G — оба; A не объявляет F3/F4. **Field[5] не объявляется ни в одном** из семи вариантов. Исходные формулы F3/F4 извлекаются без редактирования из pinned `P10DN_M2_FIELD20.geo`.

## Две Windows кнопки

1. Распакуйте ZIP в **новую папку**, строго отдельно от `G:\ildar\Stage3D07` и старых P10DO/P10DQ. Python 3, установленный Gmsh 4.15.2. По умолчанию `C:\gmsh-4.15.2-Windows64\gmsh.exe` точный SHA256 `317c43391e5b1fab3a1dd80dc5245dad6e2d087910f4b8ebc234bd6d4b8f41a1` (при другом пути можно выставить `P10DR_GMSH_EXE`, но SHA обязана совпасть).
2. Запустите `01_P10DR_PREFLIGHT_ONLY.cmd`. Программа проверит 7 исходных SHA, исходные F3/F4/F5/F6, 6 аналитических точек, RAM/disk, Gmsh SHA/version и **7 нативных GEO `-parse_and_exit`**. Никакого 1D-меширования, FEM или marker эта кнопка не выполняет. Если `P10DR_READ_ONLY_PREFLIGHT_OK`, можно перейти к п. 3; иначе пришлите evidence и остановитесь.
3. Запустите `02_P10DR_ONE_1D_DIAGNOSTIC.cmd`, введите **точно**:

   `RUN ONE P10DR 1D DIAGNOSTIC`

   Новые P10DR local и `%LOCALAPPDATA%\Stage3D07\P10DR_1D_...json` маркеры создаются непосредственно перед первым `gmsh -1`. P10DO/P10DQ/P10DG/P10DL маркеры не читаются/не изменяются, старые `.msh`, `forward_history.bin` и H0 untouched. Ни маркеры, ни попытку **не сбрасывать** даже при коде 2.

**Лимиты:** 7 последовательных только `gmsh -1`, ≤15 секунд **каждый**, ≤105 с суммарно нативной сетки; 2 потока, ≤2 ГиБ private, ≤20 МиБ `.msh`, ≤1 МиБ log на вариант. Перед началом ≥8 ГиБ доступной RAM и ≥1 ГиБ диска. Preflight плюс обработка могут увеличить общее время; ориентир около 1–3 минут, не измерено на этой версии. Новый `.msh` M2 не создаётся: результат 1D не является проверкой 3D сетки или сходимости.

## Передать ровно один файл

В `P10DR_RUNS\P10DR_1D_...\` автоматически появится `P10DR_EVIDENCE.zip` с manifest, реальными GEO/SHA, полными небольшими 1D логами и tail. **Пришлите только его**. Код возврата 2 при отдельных TIMEOUT ожидаем для безопасного STOP и не означает физического сбоя FEM — FEM=0. До независимой проверки ZIP нельзя менять исходную M1, порождать новую M2 2D/3D или запускать физическую прямую/сопряжённую задачу.
