# P10GR R1 — комплексный подбор параметров адаптивной сетки Gmsh

Дата 23.11.2026. **ПОДГОТОВКА source/unit, реальных P10GR native Gmsh пока 0.** Это отдельный новый одноразовый эксперимент, не повтор P10GP. Перед запуском `02` необходимо отдельное явное разрешение исследователя. Нет 3D/FEM.

## Проверяемая гипотеза

Предыдущий P10GP R2 показал: поправка `alpha=0.06`, южный переход от `mu=-0.8` до `mu=-0.6`, `Mesh.Algorithm=5` уменьшила median edge south на 5.48%, но ухудшила pore `q_corner,min` с 0.5901 до 0.5000 и максимальную соседнюю градацию с 1.789 до 2.011. P10GR проверяет, существует ли компромисс с меньшим ухудшением качества и соседней градации.

Фиксированные входные: исходный P10GP R1 ZIP и поле F3 раскрыто в самодостаточный MathEval F7; одна и та же rotated OCC геометрия поры/B6, физические теги, `Mesh.MeshSizeFactor=0.9378887276834518`, `Mesh.ElementOrder=2`, `Mesh.HighOrderOptimize=1`, Gmsh4.15.2. Радиальное C¹ окно исходное P10GK — 0–0.5мм плато + спад 0.5–1.0мм от стенки, неизменно. Для **поверхностной** Tri6 подбор радиальной ширины был бы неинформативен, поскольку вся стенка поры имеет d=0; вместо этого меняется угловая ширина южного перехода.

## Предварительно зарегистрированная матрица: ровно 20 случаев

- 2 алгоритма Gmsh: `Mesh.Algorithm=5` (Delaunay) и `6` (Frontal-Delaunay).
- Для каждого алгоритма — один исходный контроль `alpha=0`, и девять вариантов: `alpha ∈ {0.03,0.06,0.09}` × `mu_end ∈ {-0.7,-0.5,-0.2}` при неизменном южном плато `mu≤-0.8`.
- Нет 2D/3D смены CAD-параметризации, нет изменений boundary sizing или глобального size factor в этом опыте. Это позволяет изолировать влияние двух факторов формы поля и 2D алгоритма.

Старый P10GP `alpha=.06`, `mu_end=-.6` — независимая зафиксированная историческая контрольная точка и **не запускается повторно**. Новые результаты сравнивать с её численными характеристиками, но не выдавать отдельные запуски за воспроизводимость старого one-shot.

## Статистика для каждого варианта

1. Gmsh native command/version, source hashes, wall seconds, peak RAM, PASS/STOP, SHA MSH и журнала.
2. Tri6 physical2–9, поры и B6, curved surface Jacobian>0, площадь, точность радиуса, числа элементов/узлов.
3. Характерные длины рёбер в physical north/south/equator, median/min/max; отношение к **собственному baseline того же алгоритма**.
4. Качество `q_corner` min, p05, median, south/north min.
5. Соотношения медианного размера угловых рёбер у соседних Tri6: p95/max на всей поре, в физическом северном и южном секторах. Резкое изменение connectivity не считается гладким только потому, что h(x) C¹.
6. Итоговый CSV сравнения по всем прошедшим случаям; исходные MSH/логи включаются в один evidence ZIP, чтобы можно было перепроверить вычисления.

Исследовательский screening, **не критерий принятия 3D**: south median edge ratio≤0.98; north и equator в ±3% от baseline данного алгоритма; pore qmin≥0.45; max adjacent size ratio≤2.2. Эти пороги выбирают кандидатов для последующего анализа, но не являются физическим D-027 GO или доказательством оптимальности. Если ни один случай не проходит, все измерения всё равно сохраняются, победитель автоматически не назначается. При выборе сравнивать Парето-компромисс сгущение/качество/соседняя градация/число элементов.

## Windows после отдельного разрешения

1. Распаковать самодостаточный ZIP в новую папку `G:\ildar\Stage3D07\P10GR_TOOLS_R1`.
2. Двойной щелчок `01_P10GR_PREFLIGHT_NO_MESH.cmd`: SHA, 20×2001 математических проверок, 20 native `-parse_and_exit` без сетки, срок proof 24 ч.
3. При PASS и **отдельном разрешении** ровно один раз `02_P10GR_ONE_20_CASE_2D_SCAN.cmd`. Последовательные native Gmsh `-2 -nt2`, hard ≤90с на случай, приватная память ≤2GiB, MSH≤4МиБ, log≤2МиБ, heartbeat каждые2с. Запрещены `-3` и FEM. На STOP дальнейшие случаи не выполняются, но результаты уже сделанных сохраняются. Два новых постоянных one-shot markers до первого `-2`, не удалять и не повторять при любом исходе.
4. Отправить **ровно один** `LOCAL_RUNS\P10GR_SCAN_*\P10GR_SCAN_EVIDENCE.zip`, содержащий `P10GR_MANIFEST.json`, `P10GR_COMPARISON.csv`, GEO/MSH/log по случаям. При отсутствии ZIP — `P10GR_02_RESULT.txt` или текст окна. Не присылать EXE, другие сетки, FEM cache.

На ПК i7-7700K практическое время вероятно несколько десятков секунд на все 20, исходя из P10GP 2D ~0.5с на случай, но гарантировать это нельзя: верхняя оценка для native части **30 минут** (20×90с), плюс QA/упаковка, RAM≤2GiB на Gmsh. Если расчёт станет слишком медленным, один из случаев будет ограничен watchdog; **02 не повторять**. M1 STOP, FEM0, D-027 unchanged. Только по итогам отдельного независимого анализа разрешено предлагать следующий 3D mesh-only опыт.
