## 3. Научный контроль сетки после генерации

- Оба mesh: ASCII MSH2.2, 9/9 физических групп с названиями, H0 SHA, H0 10845 nodes/7388 Tet10/136 pore Tri6, M1 фактические размеры и физическая граница поры. CAD ice domain volume `V=0.06×0.06×0.05−4π(0.001)^3/3` сверяется с суммой из curved Tet10 27QP.
- В отличие от выборочного P10CT: **на каждом Tet10 обеих сеток проверяются все 27 искривлённых QP determinant**, отдельно знаки corner determinant, качественный минимум, геометрия поровой Tri6 поверхности. Даже 27/27 положительных не доказывают jacobian >0 между QP и не означают пригодность для FEM без следующего контроля.
- Сохраняются фактические radial ×μ группы: 0–20мкм, 20–100мкм, 100–500мкм, 0.5–1.5мм, 1.5–5мм, 5–18мм, >18мм ×10 μ-бинов. Сравниваются непарные медианы объемов/длин и число Tet10; широкий gate `0.65≤median(V_M1)/median(V_H0)≤0.95` при `N_M1>N_H0`. Выход за него — **STOP для разбора**, не автоматическая повторная генерация/адаптация. Отсутствует факторная декомпозиция причин приполюсных вкладов и любой FEM sensitivity field.
- Собирается один небольшой `P10DE_EVIDENCE.zip`: паспорт, исходные/новые SHA, native exit, QA JSON, профили CSV, конец Gmsh лога; большая `P10DE_M1_GRADED.msh` остается на ПК. Только этот архив (либо STOP) нужен следующему чату. Результат `P10DE_M1_GEOMETRY_QA_OK_NO_FEM` — проверка геометрии, не shape-derivative convergence.

## 4. Что реально протестировано / STOP

В текущем контейнере **нет исполняемого Gmsh 4.15.2 и нет исходного H0.msh**; импорт Python `gmsh` обозначает одноимённую папку репозитория, не реальный пакет Gmsh. Поэтому **M1 не построена** и нельзя утверждать фактический `N_{Tet10}`, размер поровых Tri6 или runtime.

Локально прошли Python `py_compile` и извлечённый из ZIP native stdlib `--selftest`: исторические P10CT/P10CK/P10CP тесты, synthetic own-MSH2 parse, все 27 QP, негативный искривлённый Tet10 с положительным corner determinant и отрицательными curved QP; ZIP SHA9/9 и CRC10/10. Повреждение nearSize в извлечённом GEO дало контролируемый **SHA STOP**, случай попытки в Linux создал только **STOP evidence** без одноразового marker и без Gmsh. Код Windows process private monitoring использует 64-битный HANDLE через явную `ctypes.wintypes.HANDLE`, но **реальный Win32 runtime не запускался** и его следует независимо подтвердить полученным Windows evidence. Оригинальный P10DD real full4D уже проверен и не повторяется.

**Следующее действие:** исследователь выполняет ровно одну кнопку `01_RUN_P10DE_M1_MESH_ONLY.cmd`, после завершения передаёт только `P10DE_EVIDENCE.zip`. Ассистент независимо разберёт её, сравнит истинные параметры H0/M1 и только затем подготовит отдельный ограниченный протокол M1 физического FEM (пока **не разрешён**). Адаптивная M2 лишь после завершения полной пары M0/M1.
