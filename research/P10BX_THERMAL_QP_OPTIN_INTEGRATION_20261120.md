# P10BX — изолированная opt-in интеграция точной тепловой QP-декомпозиции в P10P/P10W

**Дата:** 20.11.2026. **Уровень свидетельства:** нативная компиляция + маленький operator unit + штатный dependency selftest. **Нет нового FEM, физических QP/CSV, Windows-сборки или проверки исторического EXE.**

## 1. Постановка

P10BV обнаружил, что P10P уже использует точную дискретную тепловую shape-производную P10L, но сохраняет только глобальную сумму. P10BW математически проверил отдельный QP-аккумулятор против exact P10L CSR на синтетических криволинейных Tet10. Цель P10BX — под флагом диагностики **встроить** этот аккумулятор в реальное место теплового обратного прохода P10P, сохранив исходную глобальную формулу и добавив отдельный пошаговый паритет. Проверить, что весь бинарный P10W переводимый модуль компилируется, а обёртка проходит собственные operator units. Физический запуск не согласован и не выполняется.

Прямая формула исходной P10P для шага `n` и `jpeak`:

\[
 g_n^{\rm th}=\psi_n^\top\{M'(\theta_n-\theta_{n-1})+
 \Delta t\,K'\theta_n-\Delta t\,b'\,T_{\rm amb}(n)\}.
\]

Новая диагностика получает из **того же backward шага** `psi_n` после `H::solve`, `theta_n`, `theta_{n-1}`, скорость аналитической P10W формы и `D.shape`; заново считает выражение original CSR для независимой локальной сверки и 64-квадратурную QP-сумму. Штатный `result[0][1].thermal` по-прежнему накапливается исходным P10P кодом, а не подменяется QP. Дополнительный проверяющий этап сравнивает обе суммы по всему времени. Диагностика активна только `STAGE3D10BX_THERMAL_QP_DIAGNOSTIC`; без `STAGE3D10W_ANALYTIC_SHAPE` компиляция диагностического пути намеренно запрещена.

## 3. Реализация

- До основного thermal `for`: требуется одна `DeltaPair` и аналитическая `pairs.front().velocity`; вектора записей `HeatQpRecord` только при макросе.
- Внутри `for (obs=0..2)`, `for (n=steps..1)`: исходный `H::solve` и суммирование `D.mul(D.mass,...)`, `D.mul(D.conduct,...)`, `D.robinload` **остаются**. Для `obs==1` вызывается `p10bx::audit_step` с теми же frozen fields; проверяется исходный скаляр шага, восстановленный CSR и QP-сумма.
- `P10BW` распределяет объёмные mass/diffusion по 10 radial×10 polar bins на физических QP, отдельно собирает топовую Tri6 Robin. Для каждой пары `n,obs=jpeak` сохраняются 100 bins + одна специальная строка `(-1,-1)` для top Robin, чтобы далёкая граница не попала в близкие к поре ячейки. Удержание памяти ~4.8 KiB/шаг плюс накладные объекты, без полного QP-трассирования.
- Допуск проверяющей обёртки: `abs(QP−CSR) <= 1e−10 + 1e−8*scale`, `scale=max(sum(abs QP components),sum(abs CSR components),abs CSR total)`; также отдельно mass и `diffusion+Robin` с тем же допуском. `K'` включает Robin-стiffness, поэтому его нельзя независимо трактовать как чистую диффузию.
- Прототип экспорта: `P10BX_THERMAL_STEP_AUDIT.csv` и `P10BX_THERMAL_QP_STEP_BINS.csv`; проверяются число строк и сумма по всей истории к не изменённому `grads[0][1].thermal`. **Физические CSV пока не существуют.**

Издержки полного физического QP-прохода не измерены (он не запускался): добавляется примерно `steps*(64×N_Tet10 + 16×N_top_Tri6)` QP-итераций на `jpeak` и повторное CSR умножение. Нельзя заранее обещать runtime H0/H2. Даже `--preflight` в исходном P10P вызывает `H::solve_forward`, поэтому мы его сознательно **не выполняли**.

Компилятор: Linux `g++ (GNU) 14.2`, C++20. Сборка напрямую `g++` из точных исходников; **не** CMake/MinGW/Windows. Все компиляции завершились exit 0:

| Проверка | Результат |
|---|---|

| Диагностический полный `stage3d10w_analytic_adjoint.cpp`, `-O0` и `-O2 -Wall -Wextra -Wpedantic` | оба compile exit 0; наследованные предупреждения `-Wmisleading-indentation`, `-Wunused-function` |

| Native unit: R `dt=150/75/50/25`, tz/y20 `dt=150`, искусственная moving-top Robin `dt=75` | **7/7** synthetic CSR↔QP, максимум `3.641531520771e−14` absolute и `4.726113378191e−14` scaled relative |
| Negative unit: неверная длина `psi` | **1/1** ожидаемое исключение |
| Исходный и opt-in P10W `--selftest`, включая release `-O2` | native exit 0, stdout **побайтово совпадает**: `P10I_PRODUCTION_ADJOINT_OK`, `P10W_DEPENDENCY_SELFTEST_OK analytic_coupling_verified=0` |

Итого `P10BX_THERMAL_STEP_NATIVE_UNIT_OK tests=8 ... physical_FEM_runs=0`. Точные stdout и технический STOP из-за первоначально пропущенной при компиляции `-I` директории P10BW (исправлено без изменения формулы) сохранены в `research/evidence/P10BX_NATIVE_INTEGRATION_20261120/derived/`.

**Важно:** штатный `--selftest` проверяет зависимые механизмы, **не исполняет** P10BX-hook внутри полноценного теплового reverse `reverse_scan`; поэтому нельзя заявлять, что шаговый паритет на реальной H0/H2 сетке уже пройден. Пройдена именно native-компиляция full translation unit и независимая проверка функции, которую вызовет этот путь.

## 5. Научный результат и ограничения

P10BX уменьшает техническую неопределённость подключения P10BW: теперь есть конкретное место вызова на P10P `jpeak`, checked frozen-field contract, потенциальные 100-bin тепловые пошаговые CSV и native обратная проверка с original CSR. **Но опубликованные H2 тепловые числа P10BE остаются только глобальными**; не получены температурные поля `theta_K`/их локализация и реальное тепловое radial/polar распределение. 64 thermal QP и 27 mechanical QP различаются, их QP индексы смешивать нельзя.

Отсутствуют: новый физический FEM, измерение overhead/памяти на H0, реальный шаговый CSV и конечная сверка на физической сетке, независимый Windows build P10BX, история compile SHA исторического `P10BE_H2.exe` (`UNKNOWN`). `SPATIAL_CONVERGENCE_NOT_PROVEN`, temporal convergence полной `D_R jpeak` не доказана; это не решение о механизме dt-эффекта и не научный error estimate. D-012, same-mesh forward/adjoint, аналитическая Tet10 геометрия и запрет FD в production остаются.
