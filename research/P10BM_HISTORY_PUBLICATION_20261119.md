# P10BM — разрешённая публикация полной локальной Git-истории

Дата решения: 19.11.2026. **Статус: процедура подготовлена, push с ПК пользователя пока не выполнен.**

## Основание и явное разрешение

Исследователь после получения P10BL заявил: «Выбираю вариант А. Разрешаю публикацию всей достижимой локальной Git-истории Stage3D07 (56 коммитов) в отдельной ветке публичного GitHub. Подготовь безопасную процедуру».

P10BJ/P10BK: локальный проект `G:\ildar\Stage3D07`, `HEAD=90fd2559c0224ac0a7d2dbe2fe081a6a319080e4`, ветка `research/p10bi-local-seven-sources-20261119`, родитель и локальный master `c0498f6dc98628b62eff996a76844297c7a35094`, в HEAD изменены ровно семь проверенных исходников. После коммита осталось 0 staged, 7 unstaged, 4 untracked записей, не включаемых в push. Единственный remote `origin` использует `https://github.com/galildmur-dotcom/stage3d07_ice_pore.git` для fetch/push; upstream отсутствует.

P10BL: 56 достижимых коммитов, 1122 объектов, 818 blobs, 248 деревьев, 15 217 564 байта несжатого содержимого blobs, крупнейший 1 450 900 байт. Ноль имён с подозрительными шаблонами **не означает** проверки содержимого файлов на конфиденциальность. Родительский SHA ранее не найден через GitHub API; push может передать старую историю. Пользователь теперь явно разрешил такой охват.

## Ограниченная операция

Создан `tools/P10BM_PUBLISH_HISTORY_ONECLICK_20261119.zip` (CMD + Windows PowerShell 5.1), инструкция в `tools/P10BM_PUBLISH_HISTORY_20261119/README_RU.md`.

Скрипт до отправки сверяет точные Git root/ветку/HEAD/родителя/master, 56 коммитов, семь путей последнего коммита, 0/7/4 статусов, единственный ожидаемый remote GitHub, отсутствие mirror/custom refspec/hooks. Через **сетевой, но только читающий** `git ls-remote --exit-code --heads` убеждается, что целевая удалённая ветка `refs/heads/research/p10bi-local-seven-sources-20261119` отсутствует; при существующей ветке с иным SHA прекращает работу. После предпросмотра требует точный ручной ввод `PUSH 56`. Повторяет проверки перед отправкой.

Только после подтверждения выполняется **одна** команда Git push с явным refspec `HEAD:refs/heads/research/p10bi-local-seven-sources-20261119`, без force, mirror, tags и recursive submodule push. После этого повторным `git ls-remote` проверяет удалённый SHA. Не выполняет patch, merge, fetch, pull, reset, clean, stash, Git commit, FEM и не включает локальные unstaged/untracked записи. Не использует старую PORE-кнопку. Локальную ветку не переключает и не перенастраивает `origin`; штатная GitHub-авторизация может потребоваться.

**Сбой/неоднозначный результат:** если команда push была отправлена, но проверка не прошла, повторять самостоятельно нельзя — remote может уже содержать коммит; анализировать отчёт. Никаких force-push или автоматических откатов. Сценарий ещё не испытывался на пользовательском Windows. Авторизация на GitHub не обходится.

## Ожидаемое доказательство

Пользователь пришлёт **только `P10BM_PUSH_RESULT.txt`**. Успех следует признавать лишь при `RESULT=P10BM_REMOTE_BRANCH_PUBLISHED_AND_VERIFIED` (или `ALREADY_PUBLISHED_VERIFIED_NO_PUSH`) с точным SHA `90fd2559c0224ac0a7d2dbe2fe081a6a319080e4` на целевой удалённой ветке. После этого независимо через GitHub проверить наличие точного коммита/ветки и включить прямую ссылку в `START_NEW_CHAT.md`, `docs/PROJECT_STATE.md`, `docs/RESEARCH_LOG.md`.

Даже после успешного push Git-история и работоспособность старых `.exe` — **разные доказательства**. Исторические P10BE EXE нельзя приписывать SHA `90fd...` без независимого compile log, compiler/CMake и EXE SHA. Полная пространственная сходимость аналитической форменной производной не доказана и остаётся следующим научным приоритетом.
