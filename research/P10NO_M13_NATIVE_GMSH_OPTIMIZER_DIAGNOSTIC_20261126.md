# P10NO — встроенная оптимизация Gmsh на M13 R2 (без сохранения изменённой сетки)

Основание: P10NN дал лучший `minSICN=.1997515453156264`, `minSJ=.32769396084300884` при порогах `.20`, `.40`. Единственный нарушающий Tet10 — №9478. Касательный источник-эксперимент не решил D031.

Исследование Gmsh 4.15.2 API: `gmsh.model.mesh.optimize(method, force=True)` поддерживает `HighOrder` и `HighOrderElastic`; `force=True` нужен при работе с импортированными дискретными сущностями. Параметр `Mesh.HighOrderFixBoundaryNodes=1` документирован как фиксация всех граничных узлов при high-order optimization. **Наличие параметра не считается гарантией**: измеряются координаты всех граничных узлов и связность каждого Tet10 до/после.

## На Windows 11

1. Распакуйте ZIP в новую папку.
2. Требуются Python с `numpy` и `gmsh==4.15.2`.
3. Запустите `P10NO_RUN_NATIVE_OPTIMIZERS.cmd`. В окне каждые ~30 секунд отображается прогресс. Поочерёдно выполняются `HighOrder`, `HighOrderElastic`; для каждого процесса предусмотрен watchdog 300 секунд.
4. Пришлите **2–4 небольших файла**: `P10NO_HIGHORDER_RESULT.json`, `P10NO_HIGHORDERELASTIC_RESULT.json` (или одноимённые `*_TIMEOUT.json`, если был тайм-аут) и `P10NO_GMSH_OPTIMIZATION_LOG.txt`.

Два прогона запускаются в отдельных процессах, каждый с чистой исходной M13 R2. Оптимизация **изменяет сетку в оперативной памяти**. Исходная MSH не перезаписывается. В ходе эксперимента не вызывается `gmsh.model.mesh.generate`, не сохраняется оптимизированная MSH, не запускается FEM и не расходуется один-shot маркер создания производственной сетки.

Программа проверяет размерность/идентификаторы Tet10, связность всех 18 004 Tet10, физические группы поверхностей 2..9, наличие и координаты всех поверхностных узлов, затем канонические `minSICN`, `minSJ`, `gamma`, `minDetJac` на всех элементах. Изменение хоть одного граничного узла или связности помечает эксперимент **неприемлемым** независимо от качества. Даже успешный тест не присваивает обозначение M13 R3 и не разрешает FEM: нужен отдельный этап верификации и принятия новой сетки.

Официальная документация: https://gmsh.info/doc/texinfo/ (API `gmsh/model/mesh/optimize`, опция `Mesh.HighOrderFixBoundaryNodes`).
