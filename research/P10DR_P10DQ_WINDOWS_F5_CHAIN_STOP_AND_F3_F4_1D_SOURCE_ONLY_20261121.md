## 3. Новая диагностика P10DR R1, не производственная M2

Исходное CAD + Threshold F2 **байт-в-байт** из ранее выпущенного P10DQ ZIP. Исходные F3/F4/F5 формулы сохранены. P10DR **не** пересоздаёт исходный M1 и не изменяет P10DO. Для всех тестов кроме A временный `Field[6]` равен `F2*(1−0.02*Q)`, где математически `Q∈[0,1]`; целевой размер `h/h1∈[0.98,1]`, а целевой объём `Vtarget/V1∈[0.98³,1]=[0.941192,1]`. 2%-ная проба по размеру **диагностическая, не предложенная M2** и не подменяет целевую M2 формулу `Vtarget(M2)/Vtarget(M1)=1−0.2κ`.

Семь отличающихся проверок с индивидуальными native логами: определения F3 и F4 включаются в GEO **только когда на них ссылается Q**; A не включает ни одно из них. Field[5] **ни в одном** P10DR варианте не определяется, чтобы избежать повторного обращения к уже проблемной цепочке F5.

1. A: только F2 — повторный контроль 1D в **новой** отдельной диагностической последовательности (не повтор старого one-shot P10DQ).
2. B: `Q=F3` — радиальная ссылка.
3. C: `Q=F4` — угловая ссылка.
4. D: `Q=F3*F4` — их совместная ссылка без smoothstep.
5. E: `Q=1−F3²(3−2F3)` — только радиальный smoothstep.
6. F: `Q=F4²(3−2F4)` — только угловой smoothstep.
7. G: `Q=(1−F3²(3−2F3))*F4²(3−2F4)` — полная κ-арифметика, **но без ссылки на Field[5]** (не запускать повторно исторический P10DQ C).

Изоляция F3/F4 требует обе независимые ветки **даже если один вариант остановлен**. Поэтому тестовый набор продолжает только до окончания семи **различных** вариантов; для каждого лимит 15 с (весь native mesh wall ≤105 с), 2GiB private/20MiB mesh/1MiB log/2 потока. Preflight 7 native GEO `-parse_and_exit`, SHA pins7/7, Gmsh exact binary/version, свободная RAM≥8GiB/диск≥1GiB. Только после 7 parse PASS и **ручной** фразы `RUN ONE P10DR 1D DIAGNOSTIC` создаёт два **новых** эксклюзивных P10DR marker сразу перед **первым** `gmsh -1`. Старые маркеры не читать и не удалять.
