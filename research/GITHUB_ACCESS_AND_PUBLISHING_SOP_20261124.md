# Stage3D07 — доступ к GitHub и публикация из новых чатов

Репозиторий: `galildmur-dotcom/stage3d07_ice_pore`.

Активная исследовательская ветка: `research/p10bb-w5b2-20261118`.

## Проверенный порядок

1. В начале чата прочитать `master/START_NEW_CHAT.md`, актуальные правила исследования и `research/GITHUB_ACCESS_AND_PUBLISHING_SOP_20261124.md`. Прочитать remote HEAD исследовательской ветки через подключённый **GitHub connector**.
2. У агента есть доступ к установленному подключению GitHub (`mcp__codex_apps__github_*`). **Обычный `git push` через HTTPS в исполнительном контейнере не равен доступу через GitHub connector**: в данном окружении Git CLI не имеет credential helper и завершился `could not read Username for 'https://github.com'`. Это не означает отсутствие доступа к GitHub API. В первую очередь использовать подключённые GitHub инструменты, включая `github_create_blob`, `github_create_tree`, `github_create_commit`, `github_update_ref` для атомарной публикации набора файлов.
3. До записи проверить текущий HEAD, предка и названия целевых файлов. Публиковать через один commit и безопасное fast-forward обновление ref с `expected_sha`; не выполнять force push. После записи снова прочитать HEAD и проверить опубликованные пути и SHA256 артефактов.
4. Запрещено записывать в репозиторий пароли, токены, cookies, содержимое credential helper или конфигурацию аутентификации с секретами. Подключение определяется инструментами на момент нового чата, оно не гарантировано навечно.
5. Пользователь **24.11.2026 явно разрешил** публичную публикацию P10IJ пакета с ранее локальным `M2.msh`. Это разрешение относится к этому конкретному M2 и P10IJ, не ко всем возможным личным или приватным входным данным.
6. Если GitHub connector перестал быть доступен, сообщить точную ошибку и подготовить локальный коммит/пакет; не писать «нет доступа» только на основании ошибки `git push`.

Для проекта применяется также одноразовая политика Gmsh/FEM markers и запрет автоматического повторного физического расчёта после STOP. Авторизация публикации в GitHub **не** является авторизацией повторного тяжёлого FEM.
