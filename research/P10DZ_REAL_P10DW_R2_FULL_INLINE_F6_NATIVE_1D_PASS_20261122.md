# P10DZ — реальный Windows P10DW R2 native 1D с полным inline F6 PASS; однократность исчерпана, 3D M2 ещё не проверялась

**Дата:** 22.11.2026. **Уровень доказательства:** оригинальный Windows native Gmsh4.15.2 `-1`, полный stdout log, оригинальный JSON/Generated GEO, независимый аудит source и отрицательные тесты. **Это не 2D/3D сеточный QA, не FEM, не доказательство пространственной сходимости.** При аудите на машине ассистента новый Gmsh не запускался.

## 1. Ранее было установлено / новый независимый вопрос

В реальном P10DO `gmsh -3` с **вложенными MathEval F3/F4/F5** 900с остановился на 1D кривых14/17, marker P10DO израсходован. P10DU по настоящим Windows P10DT журналам и Gmsh4.15.2 `Field.cpp` обосновал source-level самоблокировку `MathEval→MathEval`; короткие прямые inline пространственные выражения без вложенности проходили за~0.2с. P10DV алгебраически точно развернул **исходную** радиально-полярную κ C¹∈[0,1] в одно **494-символьное** `Field6=MathEval` с единственным F2=Threshold и прежним `Vtarget_M2/Vtarget_M1=1−0.20κ`, `h2/h1=(1−.20κ)^(1/3)`. P10DX исправил только R1 Windows CRLF output; P10DY подтвердил два настоящих `-parse_and_exit` на R2. **Новая независимая проверка:** завершится ли **именно полное** inline κ20 выражение при `gmsh -1` без старого 1D timeout? Это отличает проблему нереентерабельности от возможной перегрузки самого длинного выражения в реальном field evaluation.

## 4. Научный вывод и следующий отдельный рубеж

**Подтверждено:** исходная C¹ κ математически идентична P10DN и ограничена [0,1], целевой локальный объёмный множитель 1−0.20κ; выпущенный R2 проходит настоящие Gmsh4.15.2 GEO parses и **один** быстрый нативный 1D smoke с полной inline F6 без повторного входа MathEval. Это снимает выявленный 1D blocker **для данного поля/геометрии/бинарника в этом опыте**. Но **не** проверены реальные 3D Tet10 M2, curved27QP детерминанты и pore/CAD/quality, spatial κ field sampling Gmsh, 9 локальных radial×|μ| сравнений realised/unpaired volumes M2 vs оригинальная принятая M1, полный physical M2 FEM, shape gradient convergence и причина полярной межсеточной чувствительности. Нет основания объявлять достижение на реальных Tet10 «уменьшено ровно на 0–20%» без реального M2 QA.

**Единственный следующий научно-технический шаг к рассмотрению, пока НЕ РАЗРЕШЁН:** отдельно согласовать **новую ревизию и одно** ограниченное native Windows **M2 mesh-only** по точно pinned P10DV F6, оригинальной original P10DG M1 SHA и той же CAD. Предварительно source/geometry preflight и оценка ресурсов, маркер **нового** M2 one-shot непосредственно до `gmsh -3`, мониторинг native wall/private/output, full Gmsh log; затем независимый curved27QP, pore/CAD/quality, M1/M2 9-zone realized volume QA и global statistics без потолка узлов, **никаких physical forward/adjoint/FEM**. Старая P10DO попытка consumed и не запускается снова, P10DW R2 `02` тоже consumed; исходную M1 не заменять H0/U0.
