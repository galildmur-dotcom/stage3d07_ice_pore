# P10GH R1 — аудит P10GG STOP и новый байтово стабильный Windows-выпуск

**Дата:** 23.11.2026. **Статус:** техническая ошибка источников P10GG
установлена, исправленный выпуск P10GH подготовлен и локально проверен.
**Реального native Windows Gmsh `-2` в P10GH пока нет; 3D=0, FEM=0.**
Ни одной новой M1 не принято. D-027 остаётся действующим решением:
глобальный интервал 0.80–0.85 по `Veff`, качества curved Tet10 и
физический охват — обязательные; `legacy 18/18` только диагностика.

## Входное свидетельство пользователя

Единственный полученный `P10GG_02_RESULT.txt` (SHA256
`84fed93f34bb1052e6ca38a28dd058da25ca424e1eb26d0dcb9d9fff7a78ec83`):

```text
P10GG 02: ONE protected original plus rotated Gmsh -2 pair. No 3D/FEM.
P10GG_STOP: RuntimeError('P10GG_STOP: generated GEO changed since preflight')
CHECK_EXIT_CODE=2
```

Исходный P10GG `write_geos()` открывал выходные `.geo` в текстовом режиме
`open("x", encoding="utf-8")`; Windows записывает строки с `CRLF`, тогда
как `source_selftest()` вычисляет `SHA256(contents.encode("utf-8"))`, то
есть `LF`. P10GG 01 уже сохранил хеши записанных Windows-файлов, затем
P10GG 02 `proof_gate()` ошибочно сравнил их с LF-хешами до записи и
остановился. **В исходном коде проверка `proof_gate()` стоит раньше
создания двух permanent markers и раньше обоих `-2`.** Следовательно,
по трассе исполнения P10GG не пытался строить 2D-сетки. Физическое
отсутствие маркеров на компьютере исследователя отдельно не проверялось;
новый запуск защищён от случая, если они всё-таки есть.

Это технический STOP сравнения байтов, а не наблюдение качества Gmsh,
сходимости или механического поведения льда. Старую 02 не повторять,
старые файлы не переписывать и маркеры не удалять.

## Точное исправление P10GH

1. Создан отдельный `P10GH`, исходные канонические `M0.geo` и
   `sphere_pore_B6_refined.geo` с неизменными SHA; тот же исходный и
   повёрнутый OCC, тот же Delaunay/Tri6, `MeshSizeFactor=0.825^(1/3)`.
2. `write_geos()` открывает созданные `.geo` в **двоичном эксклюзивном**
   режиме `xb`, записывает `contents.encode("utf-8")`, проверяет SHA-256
   **фактических** байтов каждого файла против `source_selftest()`. Так
   Windows не может заменить `LF` на `CRLF` незаметно.
3. Добавлены регрессионные тесты для разницы LF/CRLF, байтовой записи
   всех шести `.geo`, и полной mock-цепочки `01 → proof_gate` с теми
   же хешами (ранее mock-тест пропускал исходный дефект).
4. У P10GH собственные `PROOF`, result-файлы, директории и отдельные
   permanent markers, не затрагивающие P10GG. Наличие любого старого
   P10GG marker блокирует P10GH **до** нового Gmsh.
5. Остальные ограничители сохранены: один штатный проход из **двух**
   Gmsh4.15.2 `-2`, ≤120 с / ≤2GiB / 2 потока на каждый, MSH2.2 Tri6,
   независимый QA физических поверхностей 2–9, обоих полюсов, радиусов,
   Jacobian. Не выполняются `-3`, FEM, изменения канонических `meshes`.

## Единственный разрешённый следующий эксперимент

Исследователь распаковывает новый ZIP в **новую** папку
`G:\ildar\Stage3D07\P10GH_TOOLS_R1` и выполняет
`01_P10GH_PREFLIGHT_ONLY.cmd`. При `P10GH_PREFLIGHT_PASS_NO_MESH`,
не позже 24 часов, ровно один раз выполняется
`02_P10GH_ONE_2D_PAIR_ONLY.cmd`. Не запускать старый P10GG 02.
При PASS предоставить один
`LOCAL_RUNS\P10GH_CAD_POLES_*\P10GH_CAD_POLE_2D_EVIDENCE.zip`.
При STOP предоставить только соответствующий
`P10GH_01_RESULT.txt` / `P10GH_02_RESULT.txt` (или ZIP evidence, если
создан). **После STOP 02 не перезапускать.**

По полученному реальному 2D ZIP независимый аудитирует q_corner,
полярные элементы, Jacobian/radius/группы. Ни поверхностное улучшение,
ни текущие автономные тесты не означают GO для объёмной HXT10 M1/FEM.
