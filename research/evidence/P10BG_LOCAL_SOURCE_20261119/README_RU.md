## Изменённый инженерный вывод

Предыдущее условное предложение «подготовить патч для переноса в локальные `src/`» **снято**: ничего переносить на `G:` не нужно, там уже находится ровно тот набор, который представлен в отдельной кандидатной ветке GitHub `research/p10bg-source-integration-20261119` (в кандидатной ветке только CRLF→LF на штатных путях).

**Остаются два разных вопроса:**

1. **Windows CMake/MinGW Release.** Проверить именно текущую локальную конфигурацию Qt Creator без тяжёлого FEM: собрать и запустить `stage3d10v_analytic_shape_unit`, `stage3d10y_analytic_shell_unit`, `stage3d10be_temporal_unit` без аргументов, а `stage3d10be_temporal_polar_audit` — с `--selftest`. Ожидать соответствующие `*_OK` из локальных исполняемых модулей. Подробные указания в `P10BH_WINDOWS_UNIT_CHECK_20261119.md`.
2. **Версионирование Windows исходников.** После успешной локальной сборки и проверки статуса дерева согласовать адресную фиксацию именно этих семи файлов в локальном Git, отдельно от возможных других изменений. **Не** делать `git pull` исследовательской ветки поверх локального `master`, не сбрасывать грязное дерево и не вызывать старый PORE push; его `origin` может указывать на GitFlic. Сам кандидатный GitHub commit `b29aa40b...` не является пользовательским локальным commit SHA.
