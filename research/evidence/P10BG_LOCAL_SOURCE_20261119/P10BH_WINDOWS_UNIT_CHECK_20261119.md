# P10BH — минимальная проверка действующей сборки Qt Creator/MinGW Release

Дата инструкции: 19.11.2026. Выполнять **на пользовательском компьютере** в проекте `G:\ildar\Stage3D07`. До этой проверки все 7 актуальных исходников имеют `EXACT_SHA256` с зарегистрированными оригиналами; Git локально `master`, HEAD `c0498f6...`, 5 `M` и 2 `??`. Никаких файлов из GitHub на ПК заменять не требуется.

## Шаги в Qt Creator

1. Открыть **существующий** проект `G:\ildar\Stage3D07\CMakeLists.txt` в Qt Creator и выбрать свою обычную конфигурацию **MinGW Release**. Не переключать ветку Git и не запускать полную FEM-цель.
2. Собрать цель `stage3d10v_analytic_shape_unit` и запустить без аргументов. Проверить `P10V_ANALYTIC_SHAPE_UNIT_OK`.
3. Собрать цель `stage3d10y_analytic_shell_unit` и запустить без аргументов. Проверить `P10V_ANALYTIC_SHAPE_UNIT_OK` и `P10Y_ANALYTIC_SHELL_UNIT_OK`.
4. Собрать цель `stage3d10be_temporal_unit` и запустить без аргументов. Проверить **шесть** строк: P10V/Y/AZ/BA/BD/BE `*_UNIT_OK`. Для P10BE ожидаются `dt25_steps=36 polar_rows=7200 audit_rows=72`. Это синтетическая геометрия Tet10, не сетка H2.
5. Собрать цель `stage3d10be_temporal_polar_audit`; в настройках запуска цели указать **только** аргумент `--selftest` (без `--mesh`, `--out`, `--steps`, `--dt`). Проверить P10I, P10W dependency, P10Y, P10BD, P10BE `*_OK`. Строка `P10W_DEPENDENCY_SELFTEST_OK analytic_coupling_verified=0` ожидаема: selftest зависимости не равен полной аналитической верификации.

Если CMake не предлагает цели из шагов 4–5, остановиться и прислать текст сообщения конфигурации, **не** применять новый патч и не удалять текущий каталог сборки. Перед повторной сборкой не нужно удалять старые `.exe`, checkpoint, `LOCAL_RUNS` или `meshes`.

## Время, память и минимальные результаты

Оценка для i7-7700K/64 ГБ, Qt Creator MinGW Release, после успешной конфигурации: компиляция четырёх целей ориентировочно **5–20 минут суммарно**, сам запуск unit/selftest обычно **до 1–2 минут**; память до **2–4 ГБ** на один процесс компилятора (приближённая оценка, не фактическое измерение Windows). Ни одна цель не должна решать большую FEM-задачу или читать крупную сетку при аргументах выше. Запускать по одной цели за раз.

Для проверки в чате прислать **только три небольших текстовых фрагмента/файла**:

- `P10BH_BUILD_OUTPUT.txt`: последние сообщения компиляции выбранных целей, указание `Release`, имя используемого компилятора и ошибки, если они есть.
- `P10BH_UNIT_OUTPUT.txt`: полный вывод `stage3d10be_temporal_unit`.
- `P10BH_SELFTEST_OUTPUT.txt`: полный вывод `stage3d10be_temporal_polar_audit --selftest`.

Их можно сохранить копированием текста из вкладок **Compile Output** и **Application Output** Qt Creator. Не нужно присылать `.exe`, весь каталог build, mesh, VTU, checkpoint или повторно семь исходных файлов. Если пользователь не находит опцию конкретной цели или сохранение выводов, следующим безопасным инженерным шагом будет отдельно подготовленный автоматический логгер для существующего build-каталога, но без догадок о путях компилятора.

После этих тестов согласовать фиксацию семи исходников в локальном Git, отдельно от иных возможных изменений, и только затем инфраструктуру синхронизации с GitHub. Успешная современная сборка не доказывает дату/исходники старых P10BE EXE и не доказывает пространственную сходимость полной форменной производной.
