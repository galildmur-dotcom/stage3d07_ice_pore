## Техническая диагностика

В `P10BI_Check_Commit.ps1` выполнялось `git switch -c` под `$ErrorActionPreference='Stop'` с `2>&1`. Git for Windows штатно может выводить сообщение `Switched to a new branch ...` через stderr при коде возврата 0. В Windows PowerShell 5.1 такой вывод в этих условиях может превратиться в завершающее исключение. Строка отчёта совпадает с этим симптомом; это **сильная диагностическая гипотеза**. По пути исполнения P10BI остановка находится на шаге переключения, до `git add` и `git commit`. Однако фактический конечный `git branch`, HEAD и индекс после остановки **не измерены отдельным Windows отчётом**, поэтому факт созданной ветки пока условен.

## Восстановление P10BJ

Подготовлен отдельный пакет `tools/P10BJ_LOCAL_COMMIT_RECOVERY_ONECLICK_20261119.zip`, [инструкция](../../../tools/P10BJ_LOCAL_COMMIT_RECOVERY_20261119/README_RU.md). В нём native stderr учитывается без исключения по тексту, реальный код возврата Git проверяется отдельно. Восстановительный сценарий **не вызывает `git switch`** и **не создаёт ветку**: требует точное состояние на ветке `research/p10bi-local-seven-sources-20261119`, старый HEAD, отсутствие staged файлов, статусы 5 ` M` + 2 `??`, семь SHA-256. После независимого backup и только по ручному `COMMIT 7` выполняет адресный локальный коммит и аудит списка семи файлов. При любом ином состоянии он остановится с отчётом.

**Запросить только один новый файл** `P10BJ_RESULT.txt`, никаких копий исходников, EXE или больших FEM-расчётов. Не запускать старый P10BI второй раз, не использовать старую PORE кнопку push, не менять ветки вручную. Локальный коммит, даже после успешного восстановления, не устанавливает происхождение исторических P10BE EXE и не меняет научные выводы по P10BB/P10BE.
