# P10BN Windows: диагностическая остановка R1 до клонирования и сборки

**Дата:** 19.11.2026. **Уровень источника:** пользователь вставил в чат текст консоли, **не загрузил** оригинальный файл `P10BN_RESULT.txt` и не передавал `P10BN_EVIDENCE.zip`. Файл `USER_PASTED_OUTPUT.txt` — наша точная по смыслу транскрипция ключевых строк, а не утверждение о побайтовой копии исходного отчёта. Не приписывать ей SHA-256 первичного Windows отчёта.

## Причина, установленная по коду

В первой редакции `P10BN_Clean_Build.ps1` две строки строили статус как `$object.Staged + '/' + ...`. Поле `Staged` — целое число (`Int32`), поэтому PowerShell 5.1 применяет арифметическое `+` и ошибается при преобразовании строки `"/"` в число. Вторая строка в `finally` повторяла тот же дефект, поэтому `ORIGINAL_FINAL_READ_FAILED=YES` — **вторичная ошибка самого диагностического кода**, а не сообщение о порче исходного дерева.

Остановка наступила **после чтения исходного HEAD, до `PREFLIGHT=OK_READ_ONLY_ORIGINAL` и до предложения `BUILD P10BN`**. По явной последовательности операций скрипта на этом пути `git clone`, `git checkout`, `cmake -S/-B`, `cmake --build`, EXE и FEM ещё **не выполнялись**. Новый каталог вывода/отчёта создан; существующий Stage3D07 скриптом не изменялся. Отдельное повторное Windows подтверждение статуса пользователя пока не получено, поэтому не выдавать отсутствие внешних изменений за измеренный факт.

## Исправление R2 и условия продолжения

Обе операции заменены явно строковым форматированием `('{0}/{1}/{2}' -f staged, unstaged, untracked)`; остальные выражения сложения просмотрены на ту же проблему. Старый архив `P10BN_CLEAN_BUILD_ONECLICK_20261119.zip` теперь **архивный, с ошибкой; НЕ запускать**. Новый пакет `tools/P10BN_CLEAN_BUILD_ONECLICK_R2_20261119.zip` содержит исправленные CMD/PS1/README, отдельное уникальное имя ZIP не позволяет незаметно спутать версии. Точный манифест `TOOL_REVISION=P10BN_R2_STATUS_FORMAT_FIX` появляется в отчёте. Не удалять `G:\ildar\P10BN_ATTEST_20261119_170306_6872`: это историческая диагностическая папка, а R2 создаст свою новую.

**Статус:** исправление опубликовано как код; Windows повторное испытание R2 ещё не получено. Нужен **один** `P10BN_EVIDENCE.zip` из новой папки после R2. При новом `P10BN_STOPPED` остановиться и проанализировать отчёт, а не повторять. Исторические EXE и научная пространственная сходимость из этого события не следуют.
