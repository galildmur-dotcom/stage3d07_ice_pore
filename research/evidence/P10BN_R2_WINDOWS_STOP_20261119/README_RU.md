Причина — проверочный код P10BN R2 явно разрешал только генераторы `Ninja` и `MinGW Makefiles` и намеренно отвергал `NMake Makefiles JOM`.

## Что необходимо установить перед продолжением

Имя каталога `Desktop_MinGW_Release` **не доказывает** используемый компилятор. По официальному руководству CMake `NMake Makefiles JOM` использует **jom/NMake**-совместимую цепочку, а `MinGW Makefiles` — `mingw32-make`; это **разные генераторы**, и нельзя автоматически подменять один другим без проверки компилятора и окружения.

Нынешний R2 отчёт **не содержит** значений `CMAKE_CXX_COMPILER`, `CMAKE_MAKE_PROGRAM`, компиляторного ID и доступности инструментария: скрипт остановился до их вывода. Поэтому для безопасного продолжения создан строго читающий `tools/P10BO_TOOLCHAIN_AUDIT_ONECLICK_20261119.zip` (CMD/PS1/README). Он выводит в один `P10BO_TOOLCHAIN_REPORT.txt` только разрешённый набор параметров из существующего CMakeCache и метаданных компилятора, не отправляя весь cache, не делая clone/build и не меняя пользователя Git. Научные CSV P10BB/P10BE не затрагиваются.

**Следующий пользовательский ввод:** один `P10BO_TOOLCHAIN_REPORT.txt`. Только после его анализа решать, использовать ли JOM со своим компилятором, MinGW Makefiles, Ninja, или отдельно корректно инициализировать другое окружение Qt Creator. Старый P10BN R2 не запускать повторно до этого решения. Исторический EXE build SHA остаётся `UNKNOWN`, пространственная сходимость полной D_RJ не доказана.
