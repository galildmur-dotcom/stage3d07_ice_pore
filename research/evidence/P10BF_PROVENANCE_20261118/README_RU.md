Исследователь передал оригинальный **`stage3d10az_probe_export.hpp`** отдельно от архива P10BF (188 строк, 9364 байта), SHA-256 `9bf6b9729da9e2ff698ef8f890fcc88b8d3fb2ef787708992605a72d0ec8e57d`. Его текст согласован с вызовами `p10az::write_step_probe` в сохранённом `stage3d10p_partial_audit.cpp` на уровне подключаемых имён; полноценная компиляция пока не состоялась.

**Следующий подтверждённый разрыв** — `src/stage3d10v_analytic_shape.hpp`. В версии этого файла из действующего GitHub-дерева **нет `ice3d::p10v::QpProbe`** и нет четвёртого поля указателя QP в `ShellAudit`. Между тем P10AZ/P10BA и сохранённый тест их используют. Повторная независимая компиляция `stage3d10v_analytic_shape.cpp` с макросами P10Y/P10AZ/P10BA/P10BD/P10BE завершилась ошибкой `error: 'QpProbe' in namespace 'ice3d::p10v' does not name a type`. Это доказанный пробел исходников GitHub, **не признак неправильного результата FEM** и не основание придумывать отсутствующую реализацию. В текущей Linux-среде нет CMake и Windows MinGW, поэтому CMake/Windows сборка отдельно не проверялась.

Манифест первого экспорта сообщает `HEAD=c0498f6dc98628b62eff996a76844297c7a35094` на ПК, но этот коммит не доступен в исследовательской ветке GitHub. Файл `stage3d10v_analytic_shape.hpp` не был отмечен как локально изменённый, поэтому его актуальная реализация, вероятно, уже входила в пользовательский Git HEAD — **это вывод из статуса, а не независимо проверенный факт**.

**Решение о публикации:** оригинал P10AZ добавить к отдельно архивированному снимку. **Не перезаписывать действующие `src/`, `tests/`, `CMakeLists.txt`** этим набором, пока не получена зависимость QP и не проверена связная сборочная цепочка. Исторические EXE по-прежнему нельзя привязать к чистому Git SHA.
