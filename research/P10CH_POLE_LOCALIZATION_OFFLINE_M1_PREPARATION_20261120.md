# P10CH — локализация полярной межсеточной разности и кандидат M1 (20.11.2026)

**Статус:** `P10CH_OFFLINE_INDICATOR_OK_NO_FEM`; отдельный C++20 4D synthetic unit `PASS`, **не интегрирован** в действующий Windows FEM. **Ни одного нового физического запуска**, новой `.msh` или численно рассчитанного 4D физического поля нет. Это исследовательская проверка локализации, а не установление природы ошибки.

## 1. Вопрос и проверяемая гипотеза

Почему различия в геометрической производной `D_R jpeak` при изменении пространственной сетки и временного шага особенно велики у оси `±z`? Различаем (i) реально высокие физические вклады/градиенты, (ii) локальную чувствительность дискретизации и (iii) особенности квадратичной квадратуры, объёма, координатной параметризации, ориентации нагрузки и компенсации больших signed частей. **Разность двух вычислений не равна доказанной абсолютной ошибке любого из них.**

Объект сравнения — механическая локальная составляющая на `t=900 s` для пространственных пар H4W4B2→H4W4B20 (независимое дополнительное объёмное сгущение) и H4W4B2→H4W5B2 (сгущение около поры), и ранее опубликованная временная локальная разность H2 `dt=50−25s`. Полярные полосы равной ширины по `μ=cosθ`; `θ=0` соответствует `+z`, `θ=π` — `−z`. **Полоса 0 и полоса 9** совместно охватывают 20% диапазона `μ`; не являются буквально точками полюсов.

В каждом из 200 физических интегральных `(d=r−R, μ)` bins суммируется `φ`. Поэтому доступных данных **недостаточно для восстановления φ-поля** или для утверждения, что максимумы совпадают с математическими точками оси. Отдельные временные шаги H2 — иной mesh и методическая ось; сравнивается локализация, не значения производных как если бы это была одна пространственно-временная серия.

## 3. Измеренные результаты

Определяем долю крайних полярных полос `P=Σ_(bands 0,9)|Δ_K|/Σ_all|Δ_K|`, отдельно для каждого сравнения. Это **L1 доля межрасчётной разности**, не доля значения самой производной и не оценка истинной ошибки.

| Проверка | Полярная доля абсолютной разности |
|---|---:|
| Spatial H4W4B2→H4W4B20 | **87.00575%** |
| Spatial H4W4B2→H4W5B2 | **87.79656%** |
| Temporal H2 `dt=50−25s` | **94.45117%** |
| Доля квадратурных точек baseline H4W4B2 в крайних полосах | **20.49956%** |
| Доля интегрального QP volume baseline в крайних полосах | **20.03495%** |

`Σ|Δ|`: spatial bulk `0.03224464138 1/m`, spatial wall `0.04114914935 1/m`, temporal H2 `0.02274965410 1/m`. Подписанные суммы spatial bulk `+0.00115488965 1/m`, spatial wall `−0.00474191592 1/m`. Большое отличие `Σ|Δ|` от `|ΣΔ|` подчёркивает компенсацию знаков; нельзя реконструировать физический сценарий по одному global сравнению.

**Наблюдение:** ни численность QP, ни объём двух крайних полос в исходной сетке сами по себе не объясняют разницу 87–94%. Это не доказывает, что полярный пик является физической сингулярностью, и не локализует его в `φ`.

## 4. Только пробный индикатор M1, без построения сетки

Для каждой из 200 ячеек вычислены две абсолютные spatial разности механических локальных интегралов, разделённые на базовый интегральный QP объём ячейки `V_K`; каждая ранжирована в [0,1]. Согласованный приоритет `I_K=min(rank(|Δ_bulk,K|/V_K), rank(|Δ_wall,K|/V_K))`. Формула специально требует, чтобы **обе** независимые пространственные перестройки выявляли ячейку, а не одна. Степень временного несогласия H2 экспортируется для *описания*, **не входит** в выбор.

Выбраны **40 из 200** ячеек как верхние 20% по `I_K`; 31 из 40 в двух крайних полосах. Они собирают **81.00092%** spatial bulk L1 и **77.72263%** spatial wall L1, а описательно — **81.51792%** temporal H2 L1. `143/200` ячеек имеют один знак двух spatial разностей; среди top40 — `31/40`. Сравнение с альтернативным ранжированием без деления на объём: `37/40` совпадают. Максимальные относительные изменения интегрального объёма ячейки между сетками: **15.67%** bulk, **19.77%** wall; их надо исследовать отдельно при планировании metric.

Это **не** апостериорная оценка ошибки, не целевая гарантированная адаптивная сетка, не доказанная локальная сходимость. Нет `φ`-информации, точного Gmsh size field/mesh, метрики анизотропии, метрики качества Tet10 и отдельного численного временного контроля. Не подменять механический интеграл плотностью, не смешивать `m⁻¹` с делением на `m³` при интерпретации физики (деление на объём применяется **только для ранжирования**).

Подготовлены отдельно `research/proposals/P10CH_4D_UNIT_20261120/p10ch_4d_partition.hpp`, `p10ch_4d_unit.cpp`, `README_RU.md`. Это минимальный **синтетический** C++20-контейнер для интегральных `G^α_{K,n}(t_f)` по `(r,μ,φ,n)`, отдельного `boundary`, сохранения `outside`, с шестью signed компонентами `geom/equilibrium/history/thermal_mass/thermal_diffusion/thermal_robin` (соблюдать семантику и отсутствие двойного учёта). Точки с математически не определённым `φ` на оси учитываются отдельным счётчиком. В реальный solver и анализ истинных сопряжённых формул контейнер ещё не подключён.

## 6. Открытые причинные гипотезы и следующий единственный этап

1. **Нагрузка и физика:** ориентация граничных условий вдоль `z`, геометрия конечного блока, реальное повышение локальной напряжённости и вес `jpeak` могут концентрировать производную у `±z`; для решения нужно сравнение signed самих компонентов, а не только mesh differences.
2. **Дискретизация:** кривизна Tri6 поры, качество/ориентация Tet10, радиально-угловое разрешение, влияние внутреннего поля скорости формы `V` и его продолжения на объём, инварианты `r,μ,φ` могут давать локально повышенную чувствительность; проверить mesh-only без FEM.
3. **Алгебра и история:** явная геометрия vs equilibrium vs EDV history vs thermal mass/diffusion/Robin и локальные компенсации по знаку. При известных 2D CSV доступны частично только mechanical explicit/equilibrium; полное физическое 4D разложение требует доработки счётчиков на реальных QP.
4. **Временная ошибка:** P10BE `dt=50−25s` даёт локальный L1 1.72234% относительно принятой нормировки и лишь слабое снижение по сравнению с `75−50s`; независимое временное влияние на форму spatial индикатора пока не устранено.

**Следующий минимальный этап P10CI (без FEM):** mesh-only геометрический аудит физически существующих H4W4B2/H4W4B20/H4W5B2 `.msh` и исходных генераторов: ячейки `I_K`, число/качество/анизотропия Tet10, углово-азимутальная плотность, `V_K`, поле продолжения скорости формы; затем сформировать обратимо проверяемый Gmsh metric/size-field **кандидат M1** с independent quality/budget gates. Подключение экспериментального 4D exporter к действующей ветке — отдельный source-level проект после точной ревизии Windows C++.
