# P10CA R1 — реальный H0: численная сверка QP/CSR успешна, native ExitCode не получен

**Дата:** 20.11.2026. **Состояние:** `P10CA_R1_REAL_H0_NUMERICAL_QP_CSR_PASS_NATIVE_EXIT_UNKNOWN`, не `PHYSICAL_QP_VERIFIED_EXIT0`. Это протокол анализа полученного от исследователя Windows `P10CA_EVIDENCE.zip`, а не сообщение о новом расчёте. Новый FEM на компьютере ассистента не запускался, повтор H0 не предлагается автоматически.

## 1. Непосредственное свидетельство и технический исход

Архив пользователя: **39257 байт, SHA-256 `bd7e9a55e40a95f1e4e5b58c8de77796fcfa0b3c057f804d9614b05d70b39605`**; `unzip -t` PASS **13/13**. Содержит подлинный `P10CA_RESULT.txt`, `P10CA_RUN_MANIFEST.json`, configure/build/help/selftest/physical stdout/stderr и пять физических CSV. Первоначальная R1 программа неизменна, её `P10CA_RESULT.txt` **фиксирует `RESULT=P10CA_STOPPED: P10CA_STOP physical ExitCode unavailable`**. Манифест честно указывает `physical_attempted=true`, `physical_verified=false`.

**Тем не менее, в физических stdout есть** все шесть `P10K_FORWARD` шагов, обратный проход 6/6, 18 механических adjoint solves, `P10BX_THERMAL_QP_INTEGRATED_OK ... original_gradient_unchanged=1`, `P10W_COMPONENT_AUDIT_OK` и `P10W_ANALYTIC_ADJOINT_OK ... geometry_partial=ANALYTIC_TET10 central_fd_evaluations=0`. Программа завершила запись пяти физических CSV. **Это сильное свидетельство фактического вычисления, но не доказательство OS native exit0:** Windows `Start-Process -PassThru` в данном запуске вернул пустой `ExitCode` после ожидания процесса. Точная платформенная причина не диагностирована; нельзя заменять отсутствующий код завершения предположением «0». По состоянию протокола **не запускаем solver второй раз**.

До/после original Windows HEAD строго `90fd2559c0224ac0a7d2dbe2fe081a6a319080e4`, dirty counts `0/7/4`, fingerprint `bb376579544e328291674fa91d20c7b8a4b9d4a306fd7a3af47c172cedb75258`; сценарий не изменял исходное дерево. SHA H0 mesh, вычисленный на Windows: `e28d6049afc4b20b474152d315952361b01dce7052f7642d03a20ce8274d41f8`; SHA Windows EXE: `17c31f426245317271245e340d68fa5de1e4eb144b7be986167505e14cbed924`. Сами mesh/EXE **не входили** в компактный архив, поэтому их SHA известны только из Windows gate/manifest, не перепроверены локально по соответствующим байтам.

Для каждого шага: уникальность 100 ячеек + top, `thermal_qp_count=472832` (всего **2836992**), `top_robin_qp_count=2592=162×16` (за шесть шагов **15552**), объём, отдельные mass/diffusion/robin суммы, total QP против CSR и индивидуальный допуск. ## 4. Что нового даёт распределение по пространству

Сумма по шести физическим шагам для теплового `D_R jpeak`:

| Расстояние от стенки поры | Тепловой вклад, на м | Доля от результирующей суммы |
|---|---:|---:|
| 0–2 мм, 7 радиальных интервалов | **−0.002776101573** | −4.18% |
| 2–5 мм | **+0.069155653656** | +104.18% |
| ≥5 мм | 0 | 0% |
| **Всего** | **+0.066379552083** | 100% |

Последние два внешних интервала за 5 мм содержат тетраэдрические точки, но их производная равна нулю **по конструкции cutoff-support поля скорости формы**. Это не свидетельство независимой физической малости удалённого воздействия. На H0 разрешение стенки поры около **0.452 mm** по медианному ребру; деление QP на bins 0–0.02 mm **не** означает физического разрешения геометрии 0.02 mm. Эти QP интервалы — разбиение интеграла на имеющейся сетке.

Полярные пояса с `cosθ∈[−1,0)` дают **−0.06894537393**, а с `cosθ∈[0,1]` **+0.13532492601**, суммарно **+0.06637955208**. При группировке по **знаку самого вклада** (а не по геометрической полусфере) сумма отрицательных поясов равна −0.07548881031, положительных +0.14186836239. Наблюдается значительная знакопеременная компенсация. График `P10CA_H0_THERMAL_RADIAL_POLAR.png` и производные таблицы содержат **только исходный H0**. Топовый Robin QP интегрировался `2592` раза на каждом шаге, но его **числовой вклад равен нулю**, что согласуется с нулевой скоростью формы на удалённой верхней границе; интерпретация ограничена конкретным полем скорости/данной дискретизацией.

## 5. Следующая проверяемая граница исследования

H0 тепловой QP/CSR numeric parity **подтверждён независимо**, но R1 физический запуск оставил формальный `native_exit=UNKNOWN` и `physical_verified=false`. Сохраняем оба факта. Без новой санкции **не повторять H0, не запускать H1/H2**, не выдавать это за spatial или temporal convergence. Технический follow-up: исправить процессный exit-code capture **в изолированном будущем инструменте**, предварительно протестировав его только на безопасном `--selftest`; не приписывать новый тест завершению предыдущего процесса. Научный follow-up при отдельном решении: провести согласованное сравнение H0 с другой сеткой/временем на **той же** аналитической Tet10 постановке и без central FD, сначала обосновать минимальную ресурсную смету.

**Публикуемые доказательства:** первичный ZIP без исключения (`input/P10CA_EVIDENCE.zip`), пять исходных CSV (в ZIP), derived independent audit, radial/polar summary CSV, график и source скриптов. Никакого большого forward-history BIN, mesh, EXE или VTU в GitHub. `SPATIAL_CONVERGENCE_NOT_PROVEN`, сходимость полного `D_R jpeak` по времени не доказана, historical P10BE_H2 EXE SHA UNKNOWN.
