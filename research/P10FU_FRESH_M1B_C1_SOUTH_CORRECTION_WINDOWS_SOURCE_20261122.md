Дата 2026-11-22. Продолжение P10FT; исследовательская ветка
`research/p10bb-w5b2-20261118`.

## Статус

**`P10FU_SOURCE_ONLY_READY / NEW_M1B_3D_NOT_RUN / FEM=0`.**

Подготовлена независимая от старого `01_GENERATE_NEXT_MESH.cmd`
одноразовая программа Windows Gmsh для нового **M1B_CANDIDATE**.
Записи `M0.msh/M0.geo`, отклонённые `M1.msh/M1.geo`,

## Причина корректировки

Строгий P10FT fixed-physical-region curved729QP контроль новой M1:

| d0–100 мкм, \|μ\|≥0.8 | Полученный Veff(M1)/Veff(M0) | Допуск D-025 |
|:--|--:|--:|
| Север | **0.844779** | 0.75–0.85 (PASS) |
| Юг | **1.095906** | 0.75–0.85 (STOP) |
| Оба полюса вместе | **0.964846** | не заменяет отдельные полюса |

Глобальная средняя M1/M0=0.795382 близка к 0.8,
но по исходным Tri6 южный polar median edge
0.379621→0.395280 мм **укрупнился**.
Нужен контроль именно совместной 2D/3D дискретизации поры.
Замечание: плавный исходный размер h не гарантирует плавность
размеров *реальных* Tet10 после Gmsh; смежные q проверяются по
новому raw MSH.

## Кандидатное поле, без подмены критерия D-025

Исходный принятый `M0.geo` оставлен побайтно,
SHA256 `ac6981b04d205cc00bf50ddbaf6722c884af7189ef4e3e743253c754f69e62aa`.
Сохранены OpenCASCADE CAD, физические теги 1–9,
3D Algorithm10/HXT, surface Alg5, quadratic Tet10 и
HighOrderOptimize=1.

Для исправления первого однородного шага введено **одно**
непрерывно дифференцируемое C¹ поле длин

\[
h_{\mathrm{M1B}}(x)
 =h_{\mathrm{M0}}(x)
 \{0.8[1-\beta w_S(x)]\}^{1/3}, \quad\beta=0.25,
\]

где `r=|x-(0,0,0.03)|`, `d=r−0.001`,
`μ=(z−0.03)/r`, `s(u)=v²(3−2v)`, `v=clamp(u,0,1)`,

\[
w_S(x)=
\left[1-s\left(\frac{d-0.0001}{0.0004}\right)\right]
\cdot s\left(\frac{-\mu-0.55}{0.25}\right).
\]

На северном полюсе и вне локальной южной полярной шапки
`w_S=0` и **первичная номинальная цель h³ остаётся 0.8**.
При южном полюсе `μ≤−.8, d≤.1мм` `w_S=1`,
предписанная **h³-цель 0.60**. Между этими областями поле
имеет непрерывные первую производную и значения. Отдельного
разрывного surface-поля не вводится, что сохраняет единый
размерный контракт для 1D, Tri6 и Tet10. От Gmsh не
требуется никакой равномерности по φ.

Почему β=.25, если научный допуск всего15–25%?
Потому что это **калибровочная поправка к целевому h**, а не
предписание реальному `Veff` уменьшиться на40%. На первом
настоящем M0→M1 при h³=.8 в южной области *реальный* Q=1.095906.
При условном сохранении наблюдаемого multiplicative bias
новое h³=.6 даёт ориентир `1.095906*(0.60/0.80)=0.821929`.
**Это не эмпирически подтверждённый закон, не прогноз с
гарантией и тем более не scientific GO**: Gmsh remeshing
может перестроить topology не линейно. Приёмка возможна
только по 729QP реальным эффективным объёмам **0.75–0.85**
в двух раздельных фиксированных физических шапках.

## Исходниковые проверки, уже выполненные

Программа `scripts/p10fu_build_m1b_windows_release.py`
детерминированно собирает release ZIP и проверяет:

1. source SHA inventory для 9 файлов и точный SHA M0 GEO;
2. равенство выражения MathEval/параллельного независимого
   пространственного C¹ закона в **4102** точках (максимум
   расхождения **1.36e−16**);
3. native Windows-only mode на Linux корректно STOP,
   Gmsh/FEM попыток **0**;
4. повторное извлечение ZIP + selftest PASS;
5. умышленное изменение README в *временной копии*
   приводит к source SHA STOP; оригиналы не меняются;
6. скопированная canonical 27QP QA повторно
   прочитала предоставленную реальную отклонённую M1:
   10048 Tet10, все detJ>0, полный QA parity PASS.

Ни Linux Gmsh 3D, ни native Windows preflight/3D/QA для
**самой новой M1B** здесь не запускались. Поэтому
наличие программного ZIP означает готовность **к одной
защищённой проверочной генерации**, а не готовность
к физическому R.
