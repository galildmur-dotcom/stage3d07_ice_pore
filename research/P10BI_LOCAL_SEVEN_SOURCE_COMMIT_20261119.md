## Инструмент

`tools/P10BI_LOCAL_COMMIT_ONECLICK_20261119.zip` содержит ровно:

1. `01_P10BI_CHECK_AND_COMMIT.cmd` — двухкликовая Windows-точка входа;
2. `P10BI_Check_Commit.ps1` — PowerShell 5.1, проверка и опциональный локальный коммит.

SHA-256 упаковки: `c9f43fb9b10c52c89c16595be21fb89b8950ed91123c066eae33657f408c0f58`; `unzip -t` завершён успешно. Скрипты содержат ASCII для штатной Windows PowerShell/cmd кодовой страницы.

Развёрнутая инструкция в `tools/P10BI_LOCAL_COMMIT_20261119/README_RU.md`.

До смены Git-состояния скрипт проверяет точные HEAD/ветку, отсутствие уже staged изменений, семь ожидаемых статусов и семь SHA-256; побайтово копирует все семь файлов за пределы проекта и сверяет резервные копии. Enter завершает `DRY_RUN_ONLY_NOT_COMMITTED`. **Только** точная ручная фраза `COMMIT 7` допускает повторную проверку, создание `research/p10bi-local-seven-sources-20261119`, `git add --` семь известных путей и `git commit --only` с явными семью путями. После коммита проверяются ветка, HEAD и список изменённых путей.

Скрипт никогда не делает push/pull/fetch/reset/clean и не запускает FEM. В случае сбоя автоматической отмены изменений нет; если новая локальная ветка уже была создана, повторный запуск без анализа отчёта запрещён. Существующие другие unstaged изменения не включаются в коммит. Не использовать исторический `PORE_GIT_TOOLS_20261113/01_APPLY_PATCH_AND_PUSH.cmd`.

## Запрашиваемое доказательство

После распаковки обоих файлов и запуска CMD исследователь присылает **только `P10BI_RESULT.txt`** из появившейся папки `P10BI_CHECK_*`. В нём должны быть `BACKUP_OK` ×7, ожидаемые статусы и один из двух терминальных результатов:

- `RESULT=DRY_RUN_ONLY_NOT_COMMITTED` — пользователь отказался от коммита; Git без изменений;
- `RESULT=LOCAL_COMMIT_OK_NO_PUSH`, `HEAD_AFTER=<local SHA>`, `BRANCH_AFTER=research/p10bi-local-seven-sources-20261119`, `COMMIT_CONTENTS=SEVEN_VERIFIED_SOURCE_FILES_ONLY` — локальная фиксация произошла;
- либо `RESULT=P10BI_STOPPED: ...` — причину исследовать по отчёту, не повторять слепо.

Ни один из этих результатов на момент публикации **не получен**. PowerShell-скрипт ещё не испытан в пользовательской Windows; Linux не располагает Windows Git/PowerShell 5.1 для непосредственного выполнения. Создание локального коммита не публикует его на GitHub. Даже при успехе P10BI нет ретроспективного доказательства Git SHA исторических P10BE EXE: будущий воспроизводимый запуск потребует отдельный лог сборки, Git HEAD, параметры компилятора, SHA собранных EXE и повторные unit/selftest.

## Дальше

1. Получить `P10BI_RESULT.txt`; сверить точный `HEAD_AFTER` и список семи файлов, прежде чем менять настройки remote или GitHub ветку.
2. При успешном коммите определить безопасную схему связи независимых историй Windows master и GitHub research. Не использовать force-push, blind pull и старую PORE-кнопку.
3. Только затем аттестовать новую сборку и вернуться к приоритету пространственно-временной сходимости *полной* производной (`J_h` и `dJ_h/da`, `a=R,t_z,y_{20}`), не смешивая её с уже верифицированным локальным полярным аудитом P10BB/P10BE.
