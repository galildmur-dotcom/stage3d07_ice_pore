# P10EV — одна новая M2 по C¹ полю P10EU: Windows mesh-only пакет (22.11.2026)

**Санкция:** исследователь прямо разрешил один новый опыт M2 после
предыдущего P10EU. **Исполнение пока не выполнялось**: новый нативный
Gmsh=0, FEM=0, новая M2 отсутствует, старые P10EK/P10EN D-025 STOP.
Пакет содержит одну разрешённую защищённую кнопку mesh-only на Windows,
а не физический запуск.

## 2. Новый одноразовый сценарий, без смешения с P10EN

Исходник research/proposals/P10EV_C1_JOINT_M2_WINDOWS_20261122/P10EV_one_click_m2.py
имеет собственные revision, директорию P10EV_R1_RUNS, preflight proof
P10EV_R1_PREFLIGHT_PASS.json, локальный marker P10EV_R1_ONE_3D_USED.json,
глобальный marker в LOCALAPPDATA/Stage3D07 с суффиксом SHA M1 и
строгое ручное подтверждение

RUN ONE P10EV M2 3D MESH

Первый запуск 01_P10EV_SAFE_PREFLIGHT_ONLY.cmd:

1. требует Windows и новую отдельную папку вне
   G:\ildar\Stage3D07; старые исходные RUNS не читаются и не меняются;
2. проверяет исходные SHA, исходный P10DG M1, точный исполняемый
   Gmsh 4.15.2 SHA317c4339..., версии, RAM/диск;
3. запускает два **parse-only** Gmsh: точный baseline M1 Field2
   и новый C¹ Field6; Gmsh -3 **не запускает**;
4. выполняет source-only C¹ pin и унаследованную curvature/27QP
   синтетику с отрицательной инверсией, создаёт proof на 24ч;
5. заканчивается P10EV_PREFLIGHT_PASS_NO_NEW_M2_NO_FEM или STOP.

Второй запуск 02_P10EV_ONE_M2_3D_ONLY.cmd:

1. требует свежий proof и снова весь preflight, верные M1 и Gmsh;
2. запрашивает точную строку подтверждения;
3. **до единственной Gmsh -3** атомарно расходует новый локальный и
   глобальный маркеры; при прерывании/STOP 02 повторять **нельзя**;
4. запускает только mesh-only -3, -nt2, -format msh2, с wall limit
   **900 секунд**, private RAM **8GiB**, mesh **750MiB**,
   full log **16MiB**, затем geometry QA limit **300 секунд**;
5. геометрия проверяется original P10EA curved27QP QA. Старый 9-zone
   столбец исходного alpha=.20 в этом QA **не относится к новому
   C¹ полю**; P10EV создаёт отдельный JSON, где адаптивность
   явно **PENDING_INDEPENDENT_343_729QP**, никакого FEM GO;
6. сохраняет журнал, manifesto/STOP, QA, исходный GEO и RAW M2
   в одном P10EV_EVIDENCE.zip, когда raw MSH≤32MiB. Для более
   крупной MSH сохраняет её локально и требует отдельной передачи.

В функции Gmsh запрещены FEM/thermal/mechanical, old one-shot reuse,
очистка run каталогов, force Git и перезапись старых файлов. В отличие
от P10EN, новый runner **не** выполняет alpha17 target-override:
эта модель физически неприменима к P10EU C¹.

## 3. Проверка упаковки и отрицательные испытания

Исходники собраны скриптом scripts/p10ev_build_one_m2_bundle.py
с SHA-пиннингом оригинального P10EN ZIP и всех новых файлов, генерацией
P10EV_R1_SOURCE_SHA256.json и детерминированными ZIP метаданными.
После распаковки ZIP в новую временную Linux папку выполнен
P10EV_C1_ONE_M2_SOURCE_ONLY_SELFTEST_PASS:

- старые P10EA/P10EK/P10EN источники проверены на SHA;
- новый P10EU GEO и JSON проверены на точные SHA;
- унаследованные 27QP synthetic/negative QA PASS;
- новый синтетический pair of one-shot markers создан **только**
  во временной директории и второй вызов consume_one_shot отвергнут,
  использованные marker-файлы сохранились;
- тест --preflight-only на Linux закончился **ожидаемым STOP:
  Windows required**, без вызова Gmsh и без marker consumption;
- CRC45/45, byte-for-byte equality с исходниками PASS.

Независимый дополнительный отрицательный тест: из ZIP извлечена
отдельная временная копия, в её новый P10EU GEO добавлена тестовая
строка; запуск P10EV --selftest закончен exit2 и штатным
P10EV_STOP: tampered source P10EU_M2_C1_JOINT_SURFACE_VOLUME_SOURCE_ONLY.geo.
Оригинальный ZIP и реальные one-shot markers не менялись.

Пользовательский Windows preflight и новая M2 **пока не выполнялись**;
настоящий parser Gmsh нового Field6 будет впервые проверен на
Windows кнопкой 01. При parse STOP 02 запрещён, нужно исследовать лог,
не повторяя native mesh вслепую.

## 4. Время, ресурсы, пользовательский следующий шаг

ПК исследователя Windows 11/i7-7700K/64GB RAM. Предыдущий P10EN опыт
занял менее секунды native Gmsh и около десяти секунд QA, но новый
MathEval сложнее и по нему нет реального native профиля.
Планировать **1–5 минут** на нормальный полный цикл при
благоприятном парсинге/разбиении, без гарантии; жёсткая остановка
15 минут Gmsh + 5 минут QA. До начала необходимо ≥16GiB
доступной RAM и ≥4GiB свободного диска.

**Следующее действие пользователя:** распаковать новый P10EV ZIP
в отдельную папку; 01 → при PASS, в течение24ч 02 ровно один раз;
передать **один P10EV_EVIDENCE.zip**, не переписывая старые журналы.
Оригинальная M1 должна быть доступна по полному пути.
См. README_P10EV_RU.md внутри ZIP.

## 5. Обязательный независимый gate до всякой физики

Новый raw M2 будет верифицирован против той же исходной M1
на криволинейном Tet10 Jacobian27QP и отдельно по северной/южной
физическим 3D шапкам d=0..100мкм, |mu|≥0.8 с 343→729QP.
**D-025 GO только если обе реальные величины Veff(M2)/Veff(M1)
при κ=1 входят в [0.75,0.85]**. При κ=0 размер стремимся
сохранить; соседние объёмные перепады и площадь Tri6 диагностируем
для плавности, но не выдумываем новых hard-gates на Tri6, азимутальную
равномерность или глобальное +25% Tet count.
Только при geometry+D-025 GO просить **новое отдельное разрешение**
на forward+adjoint 4D signed thermomechanical FEM на **одной** M2.
