# P10BP — новая изолированная MinGW Release сборка после P10BO

Дата: 19.11.2026. **Статус: скрипт подготовлен, на пользовательском Windows ещё не выполнялся.** Пакет предназначен для следующей проверки происхождения **новых** EXE из опубликованного Git SHA, а не для повторения P10BE_H2 многочасового FEM.

## Основание

Первичный `P10BO_TOOLCHAIN_REPORT.txt` подтвердил: `CMAKE_CXX_COMPILER=C:/mingw64/bin/g++.exe` существует, compiler ID `GNU`, версия `13.1.0`, target `MinGW`; старый генератор Qt Creator `NMake Makefiles JOM`, make cache `jom`, а `jom.exe` в обычном PATH отсутствует. Хотя имя каталога `Desktop_MinGW_Release`, его прежнюю CMake-конфигурацию **не копировать** в новую сборку. Для отдельного MinGW build согласно документации CMake подходит генератор `MinGW Makefiles` и `mingw32-make.exe`.

**Не установлено**, есть ли `C:\mingw64\bin\mingw32-make.exe`: отчёт P10BO проверил только PATH, где mingw32-make не найден. Поэтому P10BP вначале строго проверяет этот **абсолютный путь**. Если EXE нет, программа **останавливается до clone/build**, не предпринимая установки или поиска неподтверждённого инструментария.

## Как выполнить (одна кнопка)

1. Скачать только **новый** [`P10BP_MINGW_CLEAN_BUILD_ONECLICK_20261119.zip`](../P10BP_MINGW_CLEAN_BUILD_ONECLICK_20261119.zip), распаковать в отдельную папку, например `G:\ildar\PORE_GIT_TOOLS\P10BP`. Старые P10BN R1/R2 не запускать.
2. Дважды щёлкнуть `01_P10BP_MINGW_CLEAN_BUILD.cmd`.
3. Программа **только читает** старое рабочее дерево и Qt Creator CMakeCache, сверяет Git HEAD/status, `GNU 13.1.0`, `g++ -dumpmachine`, наличие `mingw32-make.exe`, CMake и ожидаемую прежнюю JOM конфигурацию. Она не меняет существующий `G:\ildar\Stage3D07`. При недостающих инструментах сохранит диагностический отчёт и завершится без сборки.
4. **Только если** видите `NEW_MINGW_MAKE_FOUND=YES` и `PREFLIGHT=OK_READ_ONLY_ORIGINAL`, можно вручную ввести `BUILD P10BP`. Enter без текста — сухой прогон, никакого клонирования.
5. После подтверждения новая GitHub копия в `G:\ildar\P10BP_ATTEST_...\source` фиксируется на exact SHA `90fd2559c0224ac0a7d2dbe2fe081a6a319080e4`; новый каталог `build` собирает ровно четыре цели P10V, P10Y, P10BE unit, production `--selftest`. Записываются configure/build logs, SHA-256 каждого **нового** EXE, первичные stdout/stderr/exit маркеры, Git SHA/status до/после. Ни один тяжёлый FEM run не запускается.
6. Отправить ChatGPT **один `P10BP_EVIDENCE.zip`** из новой выходной папки (путь появится в окне). Если `RESULT=P10BP_STOPPED`, не повторять до разбора первичного отчёта; никаких ручных Git Bash/PowerShell команд не требуется.

## Ограничения

- Отдельная независимая сборка с **новым генератором MinGW Makefiles**, не побитовое воспроизведение исторического Qt Creator JOM/EXE. Нельзя присваивать историческому P10BE_H2 исполнению новый Git SHA.
- Старые Git `0/7/4` не чистятся, рабочий исходный каталог и старый `build/Desktop_MinGW_Release` не меняются; новая папка/архив остаётся рядом в `G:\ildar`.
- Ориентир на i7-7700K: **5–20 минут**, память **2–8 ГиБ** (оценки); свободное место желательно ≥3 ГиБ. Новая сборка ещё не проверена на Windows и может потребовать коррекции локального инструментария.
- Сам ZIP результатов не отправляется в GitHub автоматически; перед публикацией проверять, допустимы ли локальные пути в журналах.
- Отсутствуют новые FEM данные и доказательство пространственной сходимости полной геометрической производной. Малые unit/selftest не заменяют этот этап.
