# P10BJ — завершение прерванного локального коммита после P10BI

Дата: 19.11.2026. **Не запускать прежний P10BI повторно.** Это отдельная восстановительная программа именно для состояния, наблюдаемого в полученном `P10BI_RESULT.txt`.

## Что произошло

P10BI подтвердил SHA-256 **7/7**, создал семь резервных копий и получил `COMMIT 7`, но завершился со строкой `RESULT=P10BI_STOPPED: Switched to a new branch 'research/p10bi-local-seven-sources-20261119'`. В Windows PowerShell 5.1 обычный вывод `git switch` в stderr при строгом `$ErrorActionPreference=Stop` мог быть воспринят как исключение. По пути исполнения P10BI остановился **до** `git add` и `git commit`. Появление ветки вероятно, но окончательный текущий HEAD/индекс пользовательского Git пока не подтверждены новым отдельным запуском.

## Безопасное восстановление

Два файла ZIP: `01_P10BJ_FINISH_LOCAL_COMMIT.cmd`, `P10BJ_Finish_Local_Commit.ps1`. Распаковать **оба в одну новую папку**, дважды щёлкнуть CMD. Сценарий **не создаёт ветку**, а требует точное сочетание:

SHA-256 архивного ZIP `P10BJ_LOCAL_COMMIT_RECOVERY_ONECLICK_20261119.zip`: `64d200f680e11d9fab68e22e58c9a114c8d8ab0b5645fd770e6aba7f75556893`. Проверка структуры `unzip -t` пройдена (ровно два файла).

- `G:\ildar\Stage3D07` как корень Git;
- текущая ветка — `research/p10bi-local-seven-sources-20261119`;
- текущий `HEAD=c0498f6dc98628b62eff996a76844297c7a35094`;
- пустой Git index (никаких уже staged файлов), пять точных ` M`, два `??` по семи установленным путям;
- семь SHA-256, совпадающих с оригиналами P10BG/P10BI.

До коммита снова создаёт резервные копии **в папке запуска, вне G:\ildar\Stage3D07**, сверяет SHA и печатает список путей. После этого **только** ввод `COMMIT 7` приводит к `git add --` семи путей и `git commit --only` с явными путями. На Enter завершается только проверка. Проводит проверку нового SHA, ветки и семи путей в коммите. Native stderr теперь учитывается вместе с реальным кодом возврата Git, чтобы обычное диагностическое сообщение не обрывало работу.

Остановить работу и прислать отчёт при любом несоответствии. **Не исправлять ветку вручную, не удалять папки, не запускать повторно без анализа.** `git push`, `pull`, `fetch`, `reset`, `clean`, `stash`, создание ветки и FEM не вызываются. Старый PORE `01_APPLY_PATCH_AND_PUSH.cmd` пока не использовать.

## Что прислать

**Только `P10BJ_RESULT.txt`** из новой папки `P10BJ_CHECK_*` рядом с распакованным CMD. Не присылать резервные исходники или EXE. В отчёте ожидается один из трёх исходов: `RESULT=LOCAL_COMMIT_OK_NO_PUSH` + `HEAD_AFTER`, `RESULT=DRY_RUN_ONLY_NOT_COMMITTED`, либо `RESULT=P10BJ_STOPPED: ...`.

Оценка на i7-7700K: 1–2 минуты, менее 100–200 МБ ОЗУ сверх Git и PowerShell, без FEM. Программа подготовлена, но на пользовательском Windows **ещё не запускалась**. Локальный коммит, даже успешный, не доказывает Git SHA ранее созданных EXE.
