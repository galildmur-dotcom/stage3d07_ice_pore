# P10CD R1 — безопасная инвентаризация H1 (NO FEM)

**Одна кнопка, только чтение:** `01_P10CD_H1_SAFE_READINESS.cmd`. Этот пакет **НЕ запускает ни EXE, ни --help, ни --selftest, ни --preflight, ни физический расчёт**; он не собирает проект, не меняет исходный Git, не создаёт расчётные папки на `G:\ildar\Stage3D07`.

1. Скачайте архив `P10CD_H1_READINESS_R1_20261120.zip` из GitHub и сверьте опубликованный SHA-256.
2. Распакуйте его **в новую папку вне** `G:\ildar\Stage3D07`, не поверх P10CA/P10CB. Запустите только `01_P10CD_H1_SAFE_READINESS.cmd` двойным щелчком.
3. Пакет прочитает точный H1 `G:\ildar\Stage3D07\P10M_MESHES\H1.msh`, сверит SHA/формат/счётчики Tet10/Tri6, точный прежний P10CA EXE SHA, Git HEAD и fingerprint, проверит наличие MinGW runtime директории. Результат сохраняется **рядом с распакованной кнопкой**.
4. Передайте **один `P10CD_EVIDENCE.zip`** из нового `P10CD_RESULTS_*`. Он содержит единственный `P10CD_RESULT.txt`. При STOP передайте тот же ZIP, не подменяйте сетку и не запускайте повторный FEM.

Ожидаемая продолжительность проверки: **примерно 10–60 с** (чтение и SHA сетки плюс Git status, зависит от диска). Нового диска менее 1 МБ, ОЗУ невелико; это **не** оценка времени H1 solver. Исходный Windows проект, mesh и EXE читаются, но не модифицируются. Никаких новых `*.msh`, `*.exe`, `*.bin`, checkpoint или VTU в evidence ZIP нет.

**Подтверждение готовности H1 не является разрешением физического H1.** Прежний P10AW H1 уже дал глобальную производную. Будущий физический запуск оправдан только для отсутствующего **локального теплового QP/CSR разложения jpeak по 10 радиальным ×10 полярным зонам, 6 шагам и отдельной top Robin строке**. Перед ним нужен новый однократный допуск исследователя на exact SHA/команду и предельные ресурсы. До этого — STOP.
