# P10CA R1 — одна физическая H0-проба: подготовка и однократный запуск

**Основание:** исследователь отдельно разрешил следующий этап после закрытого P10BZ R2 Windows native 2/2. Разрешение ограничено **одним физическим расчётом** на H0, режим `R/EDV_VAR ξ=0`, **6×150 с**, без H1/H2, GH3-кампании или многократных запусков. Сценарий не изменяет исходное рабочее дерево `G:\ildar\Stage3D07` и не запускает `--preflight` (в исходном коде он уже решает тепловую задачу).

## Результат, который проверяем

Нужно впервые получить на **реальном H0** равенство полной сопряжённой тепловой геометрической производной `D_R jpeak` в исходной CSR и в локальной квадратуре QP, 10 радиальных ×10 полярных слоёв + отдельный top Robin, для каждого физического шага и суммы. Основная производная — `ANALYTIC_TET10`, центральных геометрических FD нет. Параллельно исходный код рассчитывает `j6`, `jpeak`, `jen`; он использует `EDV`, `VAR`, `p=8`, регион наблюдения B6, температурную историю при `ξ=0`.

Исходная сетка — **только** `G:\ildar\Stage3D07\meshes\H0.msh`. Автоматический безопасный аудит перед сборкой проверит Gmsh 2.2 ASCII, `nodes=10845`, `Tet10=7388`, `pore Tri6=136`, `top Tri6>0`, вычислит **реальный SHA-256**. Если путь/формат/размеры не совпадают, пакет останавливается **до** физического solve; не подставляйте другую сетку и не меняйте файлы. Число top Tri6 заранее неизвестно и будет прочитано.

## Действия на Windows 11

1. Скачайте **только** `P10CA_H0_ONE_RUN_R1_20261120.zip` из исследовательской ветки GitHub, сверьте архивный SHA-256 с опубликованным отчётом и распакуйте **полностью в новый каталог вне** `G:\ildar\Stage3D07`, например `G:\Downloads\P10CA_H0_ONE_RUN_R1_20261120`. Не помещайте архив в существующие Qt/JOM build, `LOCAL_RUNS`, `meshes` или прежние One Click.
2. Дважды щёлкните **`01_P10CA_ONE_H0.cmd`**. Сначала скрипт **только читает** оригинальный Git HEAD/status, 44 SHA исторических/диагностических файлов и SHA своей CMake-конфигурации, проверяет известные MinGW GCC13.1.0/CMake4.4.3/OpenMP, точную H0 сетку и свободное место.
3. Если видите `READ_ONLY_GATE=PASS`, введите **`PREPARE P10CA`**. CMake создаст **новую** папку сборки рядом с инструментом и соберёт только `p10ca_h0_analytic_qp.exe`: точные P10BX/P10W/P10BW исходники + исторический Windows helper `win_process_memory.cpp`/`Psapi`. Сначала исполняются безопасные **`--help` и `--selftest` без FEM**. Любая ошибка вызывает STOP и не переходит к физике.
4. Только после `SAFE_BUILD_AND_SELFTEST=PASS_NO_FEM`, просмотра SHA сетки/EXE, бюджета и второго вопроса введите точно **`RUN ONE H0 P10CA`**. **Это и есть момент запуска одного физического H0.** Просто Enter отменяет физику и оставляет build-only отчёт. До запуска создаётся одноразовый файл-маркер `P10CA_PHYSICAL_ATTEMPTED.txt` рядом с кнопкой; повторный запуск того же распакованного пакета будет отвергнут. Не копируйте пакет ради повторной физической попытки без нашего анализа первого результата.
5. Оценка при исправной H0: **2–6 минут**, низкая достоверность. Резерв/верхний ориентир **10 минут**, предполагаемая память до **8 ГиБ**, новый диск до **1 ГиБ**, OpenMP **4 потока**. Исполнитель опрашивает фактический процесс каждые ~0,5 с и прекращает H0 при **9 мин**, наблюдаемой памяти **~6 ГиБ** или новых выходных файлах **~0,75 ГиБ** — запас до целевых 10 мин/8 ГиБ/1 ГиБ. Это **оперативные программные STOP-пороги**, а не строгий аппаратный предел: мгновенный скачок между опросами не исключён. Не запускайте параллельно другие тяжёлые задачи.
6. После завершения в новой папке `P10CA_RESULTS_*` появятся `P10CA_RESULT.txt`, `P10CA_RUN_MANIFEST.json` (локальный паспорт, **не** автоматическая регистрация M01/M02) и **один `P10CA_EVIDENCE.zip`**. Передайте **только этот ZIP**. Он содержит короткие логи, CSV и манифест, но **не** `.msh`, `.exe`, `forward_history.bin`, checkpoints или VTU. Если возникнет STOP, передайте ZIP с причиной или один `P10CA_RESULT.txt`, если ZIP не создался. Не перезапускайте программу автоматически.

## Что значит успех

Требуются одновременно:

- нативный exit физического `p10ca_h0_analytic_qp.exe` **0**, `P10W_ANALYTIC_ADJOINT_OK`, `P10BX_THERMAL_QP_INTEGRATED_OK ... steps=6 ... exported_rows=606 original_gradient_unchanged=1`;
- `P10BX_THERMAL_QP_STEP_BINS.csv` **606** строк данных, `P10BX_THERMAL_STEP_AUDIT.csv` **6** строк, равенство CSR/QP в физической задаче в пределах допусков кода и независимого послойного контроля;
- `geometry_partial=ANALYTIC_TET10`, `central_fd_evaluations=0`, по исходному методу **18 механических сопряжённых шагов** (6 временных ×3 функционала); отсутствие `P10CA_STOPPED`;
- сохранены SHA сетки и **нового физического** EXE (не путать с unit-only EXE P10BZ), исходный Git HEAD/status и mesh SHA неизменны до/после.

**Границы вывода:** это будет свидетельство одной **H0** тепловой квадратурной локализации, но не доказательство пространственной/временной сходимости полной `D_R jpeak`. H1/H2/серии и изменение грязного Windows дерева **не разрешены**. Если готовая сетка H0 отсутствует, не создавайте её самостоятельно из старых скриптов без анализа.

**Исходная методика и критерии:** `research/P10CA_SINGLE_H0_THERMAL_QP_PHYSICAL_PROTOCOL_DRAFT_20261120.md`; публикация R1 подготовки и новые SHA — в текущем отчёте GitHub P10CA. На Linux была проверена компиляция точного изолированного source-level физического target, безопасные `--help`/`--selftest`, **без FEM**. Новый Windows compile и физический H0 пока **PENDING**.
