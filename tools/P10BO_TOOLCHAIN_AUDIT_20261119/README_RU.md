# P10BO — проверка фактического комплекта Qt Creator, только чтение

19.11.2026. **Статус: инструмент подготовлен, ещё не выполнялся на Windows.**

Причина создания: P10BN R2 успешно проверил сохранность исходного Git (`HEAD=90fd2559...`, status `0/7/4` до и после), но остановился в preflight с `Unsupported existing generator: NMake Makefiles JOM`. Это не ошибка FEM или компиляции: до clone/configure/build ещё не дошло. Не следует автоматически подменять генератор на MinGW/Ninja без определения фактического компилятора и make-программы.

## Запуск (одна кнопка, около 10–30 секунд)

1. Скачать [`P10BO_TOOLCHAIN_AUDIT_ONECLICK_20261119.zip`](../P10BO_TOOLCHAIN_AUDIT_ONECLICK_20261119.zip) из GitHub.
2. Распаковать в произвольную отдельную папку, например `G:\ildar\PORE_GIT_TOOLS\P10BO`.
3. Дважды щёлкнуть `01_P10BO_CHECK_QT_TOOLCHAIN.cmd`. Никаких подтверждений или команд вручную вводить не нужно.
4. Прислать **один** файл `P10BO_TOOLCHAIN_REPORT.txt` из новой папки `G:\ildar\P10BO_TOOLCHAIN_CHECK_...`.

Сценарий читает только `G:\ildar\Stage3D07\build\Desktop_MinGW_Release\CMakeCache.txt`, несколько строк `CMakeFiles/.../CMakeCXXCompiler.cmake` и список доступных программ (cmake, git, ninja, mingw32-make, jom, g++, cl). Он **не** выводит весь cache, файлы исходников или пароли, не выполняет Git/clone/pull/push, не конфигурирует и не компилирует проект, не запускает EXE/FEM. Изменяет только новую соседнюю папку отчёта; старый `Stage3D07` и оба прежних `P10BN_ATTEST` не трогает.

## Что будет дальше

По отчёту установим, использовалась ли фактически связка MinGW/GNU, MSVC/JOM или иной набор. Затем составим **адресный** безопасный P10BN build-runner из точного Git SHA. Если `CMAKE_HOME_DIRECTORY` не совпадает с действующим проектом или compiler/make отсутствуют, сначала исправим несоответствие конфигурации по отдельному решению. Предыдущий P10BN R2 **не повторять вслепую**.

Это диагностика воспроизводимости, не новый FEM и не доказательство пространственной сходимости.
