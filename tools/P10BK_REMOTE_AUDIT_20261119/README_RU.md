# P10BK — проверка связи локального Git и GitHub, только чтение

Дата: 19.11.2026. Выполнять **после подтверждённого P10BJ**, когда на ПК существует локальная ветка `research/p10bi-local-seven-sources-20261119`, HEAD `90fd2559c0224ac0a7d2dbe2fe081a6a319080e4`.

SHA-256 ZIP `P10BK_REMOTE_AUDIT_ONECLICK_20261119.zip`: `4d74905302116dba9b41c7f1d52e72258ed3f48c24a19880d2952b5c422eb9a5`; внутри ровно CMD+PS1, `unzip -t` OK.

## Для чего

Отчёт P10BJ доказал **локальный** коммит семи исходников, но `NO_PUSH`: новый SHA **не находится автоматически в GitHub**. Раньше ПК работал с GitFlic; не известно, какой адрес `origin` настроен **сейчас**. Поэтому до выбора способа передачи в GitHub надо узнать локальные сведения о ветках, родительском коммите, наличии других незафиксированных изменений и именах remote. Инструмент безопасно выполняет только читающие команды `git` (не использует сеть).

## Действия

1. Скачать `P10BK_REMOTE_AUDIT_ONECLICK_20261119.zip`, распаковать **два файла** в новую папку.
2. Дважды щёлкнуть `01_P10BK_CHECK_GIT_REMOTES.cmd`.
3. Прислать в ChatGPT **только `P10BK_REMOTE_REPORT.txt`** из папки `P10BK_CHECK_*`. Других файлов и команд не нужно.

## Что проверяется

- Точная ветка, SHA `90fd255…`, родитель `c0498f6…` и семь путей в коммите;
- Git SHA локального `master`;
- число staged, unstaged и untracked записей, без раскрытия посторонних имён файлов;
- имя upstream, названия remote и их **локально настроенные** fetch/push URL.

Учетные данные из URL и URL-параметры запроса маскируются в отчёте. Источник `git remote` показывает **только локальную настройку**, а не проверенную доступность или право записи на сервер. Команд `fetch`, `push`, `pull`, `switch`, `reset`, `clean`, `commit`, `stash` или FEM **нет**. Если состояние ветки не совпадает с P10BJ, программа прекращает работу; ничего не исправлять вручную, прислать отчёт.

Оценка: обычно менее минуты на i7-7700K, менее 100–200 МБ сверх Git/PowerShell, никаких больших расчётов. Выполнение на пользовательском Windows ещё не проверено. Дальнейший путь синхронизации будет выбран **после** анализа отчёта, без force-push и без подмены основной ветки `master`.
