# P10CB R1 — проверка кода завершения без физических расчётов

Это следующий **технический**, а не физический эксперимент Stage3D07. Код без `--mesh`, `--out`, `--preflight`, без CMake и без обращения к решателю FEM. Только безопасный `--help` и `--selftest` уже созданного EXE. Никаких H0/H1/H2 расчетов.

1. Скачайте ZIP, распакуйте в **новый каталог** вне `G:\ildar\Stage3D07`; прежний P10CA не удаляйте и не перезаписывайте.
2. Дважды щёлкните **`01_P10CB_SAFE_EXITCODE_TEST.cmd`**. PowerShell/Git вводить вручную не требуется.
3. Проверится точный оригинальный Git HEAD (read-only) и существующий P10CA физический EXE по заранее известным пути и SHA-256.
4. На Windows кратко проверятся два способа получения кода завершения: `.NET Process.WaitForExit + ExitCode` и прямой вызов `cmd.exe` с немедленным `$LASTEXITCODE`. Для каждого проверяется искусственный `exit 7`; для P10CA запускаются **только** по одному `--help` и `--selftest`, оба с таймаутами. Исторический `Start-Process -PassThru -Wait` лишь диагностируется на искусственном `exit 7`; пустой `ExitCode` в этом варианте не блокирует проверку.
5. При успешном окончании должен появиться `RESULT=P10CB_NATIVE_EXITCODE_SELFTEST_OK_NO_FEM`, при любой проблеме `RESULT=P10CB_STOPPED_NO_FEM`.
6. Пришлите **только `P10CB_EVIDENCE.zip`**, который скрипт положит в новую папку `P10CB_RESULTS_*`. Больших файлов, EXE, mesh, физической истории не передавать.

## Ресурсы и границы

Ожидаемая продолжительность 5–30 с (предварительная оценка), жёсткий таймаут 60 с на каждый запуск EXE. Дополнительное место — несколько килобайт для доказательств, RAM соответствует короткому selftest; физические сетки, checkpoints и history не создаются. Любой результат P10CB доказывает **лишь работоспособность нового способа захвата кода выхода в коротком тесте**. Он **не восстанавливает** недостающий код OS exit от уже завершённой физической попытки P10CA. Однократное разрешение D-015 израсходовано; новый FEM потребует отдельного согласия.
