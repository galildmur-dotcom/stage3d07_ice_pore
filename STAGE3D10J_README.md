# Stage 3D-10J — безопасный переход к настоящей сетке H0

Дата: 05.11.2026. Предпосылка — успешный `P10I_PRODUCTION_ADJOINT_OK`.

## Зачем нужен этот этап

Stage 3D-10I доказал корректность обратной дискретной рекурсии на двух
Tet10 в *основном* механическом коде, но не на реальной сферической поре.
Переход на HP4/HP8 или полномасштабное сопряжённое решение без оценки
геометрии и размера истории был бы преждевременным.

Новая утилита `stage3d10j_h0_geometry_preflight` **только читает**
`meshes/H0.msh` и проверяет на настоящей сетке:

1. Метки поверхности поры (8) и внутренней поверхности B6 (9),
   сохранение внешней границы и множества закреплённых степеней свободы.
2. Перенос узлов точно по формулам Stage 3D-08 для мод `R`, `tz`, `y20`:
   изменения ±5 мкм при радиусе поры 1 мм и отсечке 5 мм.
3. Положительность якобиана всех криволинейных Tet10 на 27 точках
   Гаусса и сферичность перемещённой поверхности поры.
4. Производную объёма льда: для `R` ожидается `-4πR²`, для `tz` и
   `y20` — нуль. Критерий: отклонение меньше 2,5% площади поры.
5. Предварительную оценку памяти в GiB на один снимок истории,
   полный массив состояния в точках квадратуры и *полную*
   линеаризацию Stage10C. Эти три оценки различаются: **их не надо
   суммировать**, поскольку они относятся к разным вариантам хранения.

В текущем этапе **нет** прямого решения механики, решения теплопроводности,
сопряжённой системы, записи checkpoint, изменения исходной сетки либо
перезаписи результатов Stage09/Stage10. Количество файлов записи — нуль.

## Установка в Qt Creator (Windows)

Корневой каталог исходников: `G:\ildar\Stage3D07`.

1. Из нового архива скопировать единственный исходник
   `src/stage3d10j_h0_geometry_preflight.cpp` в `G:\ildar\Stage3D07\src`.
2. Текст из `PATCH_CMAKE_Stage3D10J.txt` добавить **один раз** в конец
   существующего `G:\ildar\Stage3D07\CMakeLists.txt`.
   Сам `CMakeLists.txt` не заменять.
3. Перезагрузить CMake в Qt Creator, выбрать `Desktop MinGW Release`.
   Существующие исполняемые цели и каталог `build` не удалять.

Первая быстрая проверка компиляции и переноса (без чтения H0):

- Цель: `stage3d10j_h0_geometry_preflight`.
- Аргументы: `--selftest`.
- Рабочий каталог: `G:\ildar\Stage3D07\build\Desktop_MinGW_Release`.
- Успех: `P10J_SHAPE_TRANSPORT_SELFTEST_OK ...`.

Главная проверка на **реальной H0**:

- Цель: `stage3d10j_h0_geometry_preflight`.
- Аргументы: **пустая строка**.
- Рабочий каталог: `G:\ildar\Stage3D07\build\Desktop_MinGW_Release`.
- Автоматически используется исходная сетка
  `G:\ildar\Stage3D07\meshes\H0.msh`.
- Сохраняются все предыдущие материалы и результаты; ни один файл не создаётся.

Примерное время на Intel i7-7700K, 64 ГБ RAM: сборка **1–5 минут**;
`--selftest` **меньше секунды**; H0-проверка **приблизительно от
30 секунд до 5 минут** (определяется фактическим числом Tet10). Этот
служебный этап однопоточный, не использует GPU. Оценка времени не получена
из замера на вашем H0 и будет уточнена после прогона.

### Что прислать

Всего **четыре строки из окна Application Output**:

- `P10J_MODE mode=R ...`
- `P10J_MODE mode=tz ...`
- `P10J_MODE mode=y20 ...`
- `P10J_H0_GEOMETRY_PREFLIGHT_OK ...`

Если произошла ошибка — только строку `P10J_PREFLIGHT_ERROR ...` и
последние 5–10 строк вывода. Архив сетки, результаты на 200 ГБ,
VTU и `restart.bin` присылать **не нужно**.

## Научное ограничение и следующий переход

При деформации поры температура должна пересчитываться на новой области.
Механический сопряжённый градиент при фиксированной температуре **не
тождествен** полной геометрической производной нестационарного
термомеханического функционала, ранее посчитанной методом центральных
разностей в Stage09C. После положительного H0-прогона надо отдельно
проверить согласование тепловой истории и полей формы, затем подключить
сопряжённый решатель к H0 и сравнить производные для каждой моды и
функционала с прямыми разностями. До этого нельзя утверждать, что
получен проверенный градиент Хадамара на реальной поре.

## Локальная проверка исходного кода

Команда GCC 12+/MinGW на тестовой машине:

```sh
g++ -std=c++20 -O1 -w -fopenmp -I src src/stage3d10j_h0_geometry_preflight.cpp -o p10j_probe
./p10j_probe --selftest
```

Получено: `P10J_SHAPE_TRANSPORT_SELFTEST_OK modes=3 delta_um=5 cutoff_mm=5`.
Настоящего `meshes/H0.msh` в переданной копии исходников нет;
поэтому здесь **не заявляется** выполненный прогон на H0.
