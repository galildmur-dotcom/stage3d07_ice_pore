# Stage 3D-10H — реальный механический код и сохраняемая история

Дата: 5 ноября 2026 г. Предыдущее состояние: Stage 3D-10G успешно проверен
на Windows пользователя (P10G_CHECKPOINT_REPLAY_OK).

## 1. Что реализовано

1. Аналитический механический шаг `p10c` сопоставлен с настоящей сборкой
   `spatial_reology.cpp`, а не только с собственным тестовым решателем.
   Проверено 6 сочетаний E/ED/EDV × CONST/VAR по 3 шага, включая BCSR-JVP
   и три настоящих функционала Stage09B.
2. `stage3d10h_retained_history.hpp` добавляет *необязательные* именованные
   снимки последовательности состояний `u` и `qstate` в каталог
   `EDV_VAR/adjoint_history` или соответствующий каталог модели.
3. Снимки используют неизменный формат производственного `restart.bin`,
   но имеют отдельные файлы с FNV64 `.fnv64` для выявления случайной порчи.
   Исходный `restart.bin` и политика `--checkpoint-hours 6` не меняются.
4. Введён жёсткий бюджет дополнительного диска, рассчитываемый **до начала**
   расчёта. По умолчанию максимум 1 ГиБ. Для экспериментального режима
   пока запрещено сочетание `--resume` или несколько реологических моделей.
5. Тест восстанавливает полный 12-шаговый прямой расчёт из четырёх
   контрольных точек именно через `nonlinear_step` и `zeroMeanZ`; проверка
   побитного совпадения всех состояний успешна. Дополнительно проверяется
   отказ при нехватке бюджета, повторной записи и повреждении файла.

- Скопируйте `src/stage3d10h_retained_history.hpp` в одноимённый каталог.

  собственных изменений этой программы; в противном случае используйте

- Скопируйте `tests/stage3d10h_production_preflight.cpp` в `tests`.
- В конец `CMakeLists.txt` один раз добавьте содержимое
  `PATCH_CMAKE_Stage3D10H.txt`. **Не заменяйте весь CMakeLists.txt**.

## 3. Единственный необходимый запуск сейчас

- Qt Creator: `Desktop MinGW Release`.
- Цель: `stage3d10h_production_replay`.
- Аргументы: **пустая строка**.
- Рабочий каталог: `G:\ildar\Stage3D07\build\Desktop_MinGW_Release`.
- Потоки: 4, задаются внутри теста.
- Предварительная оценка времени на i7-7700K: сборка 1–5 минут,
  сам тест около 3–30 секунд; память небольшая, большие VTU не создаются.

Пришлите **одну итоговую строку** `P10H_PRODUCTION_REPLAY_OK ...`.
Если сборка или тест завершились с ошибкой — пришлите текст ошибки.

Локальный GCC-тест:


## 4. Необязательный новый режим основного решателя

После отдельного согласования можно добавлять к `stage3d06_spatial`:

```
--adjoint-snapshot-steps 4 --adjoint-max-disk-gb 1
```

Остальные обязательные параметры `--mesh`, `--temp-dir`, `--out`,
`--law`, `--modulus`, `--times`, `--quad` остаются прежними. Единица
`--adjoint-max-disk-gb` технически **ГиБ** (2^30 байт). Лимит относится
только к дополнительным `adjoint_history` и не включает обязательный
`restart.bin`, VTU, CSV и временные файлы. Если лимит превышен,
расчёт прекращается *до выделения нового комплекта контрольных точек*.
Пока поддержана одна реологическая модель и один вариант модуля.

**Не запускайте этот режим на HP4/HP8 до оценки дискового бюджета.**
На HP8 одна история EDV сама может занимать несколько гигабайт, и несколько
снимков могут потребовать десятки гигабайт.

## 5. Научный статус и следующий этап

Stage 10H подтверждает равенство производственной механической касательной
и аналитической линеаризации в малой тестовой области. Также проверено,
что P10F источники j6, jpeak и jen численно соответствуют производственным
функционалам. Контрольные точки теперь можно сохранять производственным
решателем без изменения старого `restart.bin`.

**Пока не реализованы:** обратный проход по полномасштабным HP-сеткам,
касательная к `zeroMeanZ` для сопряжённых переменных, тепловая сопряжённая
система и распределённый градиент формы поверхности полости.
Следующим этапом следует реализовать *реальную* механическую сопряжённую
рекурсию для сохранённых снимков и проверить её на H0/H2 по конечным
геометрическим разностям до любых многосуточных расчётов.
