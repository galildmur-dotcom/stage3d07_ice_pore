# Реестр запусков и отобранных результатов

`RUN_REGISTRY.csv` содержит **одну строку на фактический запуск программы**, а не на каждый выполненный тест/CSV и не на каждый аналитический раздел. Поэтому серия, давшая P10N, P10P и P10S аудиты, не должна автоматически превращаться в три повторных записи.

Правила:

1. `run_id` — точный ID существующей папки либо новый уникальный идентификатор для будущего запуска.
2. `git_commit` — полный SHA исходников, которые реально использовались для запуска. Для старых расчётов без доказательства писать `UNKNOWN_PRE_GIT` либо `UNKNOWN`, а не текущий HEAD.
3. `command_line` — дословные аргументы запуска, если сохранились; отсутствие не заполнять догадкой.
4. `raw_path_G`, `archive_path_F` — фактические каталоги; пока копия на F не подтверждена, `archive_path_F` оставлять пустым.
5. `verified` — только после проверки входных данных и результатов. Метка `OK` в консоли не равна научному статусу `validated`.
6. Небольшие проверенные CSV и отчёты сохранять в `summaries/` в Git. Полные поля `.vtu`, сетки `.msh`, истории и `.bin` оставлять за пределами Git.

Первую строку реестра заполним вместе после получения точных путей и хеша Git. Пустой заголовочный файл — сознательный выбор, чтобы не выдавать недоказанные метаданные за факт.
