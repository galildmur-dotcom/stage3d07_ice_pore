## 2. Возможности и ограничения повторного использования

`p10n::save_forward/load_forward` сохраняет температурные смещения, репинированные перемещения и предыдущее внутреннее EDV-состояние на **исходных Q3-точках** для каждого шага, исходные значения трёх функционалов и финальное состояние. Кэш содержит паспорт сетки и поблочные контрольные суммы; полная проверка реализуется при `load_forward`.

При загрузке одной собственной сетки и одного кэша можно пересчитать напряжения и восьмой момент без решения новых глобальных систем. Нельзя брать `State` на Q3 и без дополнительной модели считать его заданным на другой квадратуре: смена квадратуры здесь не выполнена.

## 3. Новый вычислительный инструмент

Исходный файл: `src/stage3d10ag_frozen_mask.cpp`. Цель Qt Creator/CMake: `stage3d10ag_frozen_mask`.

Он использует `p10n::load_forward` с проверкой mesh signature, всех FNV64-хешей в записи, временной сетки и cutoff. Для каждого сохранённого шага вычисляет Q3-якобианы Tet10, деформации из сохранённых перемещений, EDV stress через существующий локальный материальный закон, регуляризованные главные напряжения и исходный PeakMoment степени p=8.

Для неизменной истории сравниваются маски:
- **element_centroid_B6:** оригинальная маска целых Tet10 по центроиду первых четырёх вершин, r меньше 6 мм;
- **qp_radius_6p00mm:** Q3-точки с r меньше 6.00 мм;
- **qp_radius_5p99mm:** Q3-точки с r меньше 5.99 мм;
- **qp_radius_6p01mm:** Q3-точки с r меньше 6.01 мм.

Для каждой рассчитываются Q3-объём, числитель N8, нормированный восьмой момент, jpeak и сравнение с оригинальным jpeak из кэша. Одновременно дублируется аккумуляция в long double **только как локальный тест ошибки суммирования**, не повышение точности всего локального EDV-закона.

**Ключевое ограничение:** изменённые маски дают диагностические *значения функционала на фиксированных прямых состояниях*, но **НЕ производные формы**. При движущейся сферической области необходим вклад производной индикатора/границы. Любое изменение `jpeak` нельзя автоматически приписать различию `D_Rjpeak`.

## 4. Выполненная проверка кода

Самопроверка на двух искусственных Tet10 и шести кадрах:
- исходный P10K `evaluate_b6` и независимая локальная формула PeakMoment совпали по относительной ошибке **1.424961e-16**;
- штатный `p10n::save_forward` создал синтетический `forward_history.bin`, `p10n::load_forward` повторно прочитал его с проверкой заголовка и всех контрольных сумм: `cache_roundtrip=1`;
- компиляция GNU C++20 с -O2/OpenMP и сборка отдельной CMake-цели на Linux выполнены; реальная сборка MinGW/Windows и реальный H0 пока не выполнялись.

Порог остановки по реальной контрольной маске: относительное расхождение исходного jpeak и восстановленного значения **2e-5**, согласуется с текущим ограничением P10K instant parity. Если достигнуто, затем отдельно оценивается, достаточно ли оно строго для масштаба найденного эффекта маски; если нет, требуется ужесточить численный контроль до вывода о влиянии маски.

## 5. Минимальная следующая проверка на пользовательском ПК

1. Безопасно синхронизировать локальную ветку `master` с GitHub `origin/master` командой fast-forward (без `reset`, `clean`, `stash`).
2. Собрать `stage3d10ag_frozen_mask` в Qt Creator / Desktop MinGW Release.
3. Запустить `--selftest` и убедиться в `LIT08_SELFTEST_OK cache_roundtrip=1`.
4. Провести первый реальный опыт только на H0: `G:\ildar\Stage3D07\meshes\H0.msh` и `G:\ildar\Stage3D07\LOCAL_RUNS\P10W_H0_R_FULL_20261110\forward_history.bin` (объём кэша 136 MB).
5. Передать только `LIT08_FROZEN_MASK_PEAK.csv` и строку `LIT08_BASELINE_PARITY`. При несовпадении паспорта сетки программа остановится без изменения исходных файлов.

Следующий после H0 этап — пара W4B2/W4B20 с собственным кэшем и собственной сеткой в каждом прогоне. **Не смешивать состояния и сетки**, P10AO.

Оценка времени на пользовательском i7-7700K: CMake target 1–3 минуты, H0 после сборки ориентировочно 1–5 минут; W4B2/W4B20 в будущем ориентировочно 5–30 минут на файл при 4 потоках, точного измерения нет. Большие кэши читаются в RAM, но не перезаписываются.

Никаких результатов пространственной сходимости `D_Rjpeak` этот этап пока не доказывает.
