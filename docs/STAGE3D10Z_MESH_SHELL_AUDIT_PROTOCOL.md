# Stage3D10Z — P10Y геометрический аудит радиальных слоёв Tet10

Дата: 2026-11-13. Статус: **проверен самотест и синтетический MSH2**, на реальных H4/H4W2 расчёт ещё НЕ выполнен. Пространственная сходимость геометрических производных НЕ установлена.

## Зачем

P10Y относит аналитические вкладовые слагаемые механической производной к 10 физическим радиальным слоям по положению **квадратурных точек** Tet10. Классическая квадратура `volume_q(3)` исходной программы представляет 3×3×3 правила Гаусса после отображения Дюффи в тетраэдр: 27 точек на элемент. P10Z независимо повторяет эту геометрию и отнесение к слоям. Для контроля разрыва индикатора слоя вычисляется альтернативная `volume_q(4)` — 64 точки/элемент, **без FEM-решения**. Никакие исходники решателя и исходные сетки не изменяются.

Сферическая пора: R=1 мм, центр `(0,0,0.03)` м. Растояние до *номинальной* поверхности в мм: `d=(|x−center|−0.001)*1000`. Границы слоёв: 0;0.02;0.05;0.1;0.25;0.5;1;2;5;15;∞ мм. При d<0 точка отнесена к первому слою — как в P10Y. Исходный код P10Y раскладывает **только механическую** часть производной, тепловая не разбита на слои.

## Входы

- `G:/ildar/Stage3D07/P10M_MESHES/H4.msh` (исходный файл, не менять);
- `G:/ildar/Stage3D07/P10M_MESHES/H4W2.msh` (исходный файл, не менять).

Скрипт поддерживает **Gmsh MSH2 ASCII** и элемент типа `11` (`Tet10`). Утилита откажется анализировать MSH4 или бинарный формат; при необходимости экспортировать дополнительную копию `msh2` с помощью Gmsh, **не перезаписывая оригинал**. Координаты узлов интерпретируются в метрах. Реальную геометрию поры и порядок Tet10 следует независимо сверить с `src/tet10_shared.hpp` актуального коммита.

## Запуск через PORE ONE CLICK (без ручных команд)

1. Установить обновлённый `PORE_ONE_CLICK_STAGE3D07_P10Z_20261113.zip` двойным щелчком по `00_INSTALL_ONCE.cmd`. Установка создаёт четыре ярлыка на Рабочем столе; файлы программы остаются в `G:/ildar/PORE_GIT_TOOLS` вне Git-репозитория.
2. Через ярлык **PORE - 1 Apply patch and push** выбрать `Stage3D07_P10Z_MESH_SHELL_AUDIT_ONECLICK_20261113.patch`, проверить имя файла и подтвердить. В редакции P10Z этот инструмент умеет по отдельному явному согласию сохранять незакоммиченные изменения отслеживаемых файлов через Git stash, применять и коммитить **только** файлы патча и восстанавливать прежние изменения. Если восстановление не удалось, резервная копия сохранена в stash. Никакого `reset`, `clean`, принудительной отправки, удаления данных или изменения исходных `.msh` нет.
3. Через новый ярлык **PORE - 4 Run P10Z mesh audit** запустить диагностику. Скрипт проверяет Python 3/NumPy (разрешение на установку NumPy спрашивает), проводит самотест, открывает стандартный диалог выбора сетки при отсутствии ожидаемого файла, затем создаёт **новый** временно маркированный каталог в `G:/ildar/Stage3D07/P10Z_RUNS`.
4. После успешного расчёта инструмент автоматически формирует компактный ZIP в `G:/ildar/PORE_CHATGPT_EXPORTS`. Если упаковка была прервана, воспользоваться ярлыком **PORE - 3 Package run results** и выбрать папку результата P10Z.
5. Передать в чат только этот небольшой ZIP, содержащий три CSV/TXT-файла. Источники и сетки передавать повторно не требуется.

Ожидаемые пути к сеткам: `G:/ildar/Stage3D07/P10M_MESHES/H4.msh` и `G:/ildar/Stage3D07/P10M_MESHES/H4W2.msh`; при иной структуре выбрать существующие файлы в диалогах. **Qt Creator не требуется**; используется Python 3 + NumPy. Ожидаемое время на i7-7700K — примерно 2–8 минут (предварительная оценка, не измерение на реальных сетках); оперативная память обычно до 1 ГБ. Запуск не перезаписывает существующие выходные каталоги.

Ожидаемые маркеры: `P10Z_SELFTEST_Q3_OK`, `P10Z_SELFTEST_Q4_OK` и `P10Z_MESH_SHELL_AUDIT_OK`. Если программа завершилась ошибкой, прислать соответствующий лог `G:/ildar/PORE_GIT_TOOLS/logs/P10Z_*.log`.

## Выходные файлы — прислать только три

1. `P10Z_MESH_QP_SHELL_METRICS.csv`: для каждой сетки и каждого слоя число GP, интеграционный объём, математический объём полного сферического слоя, доля объёма, эффективное число точек по весам, число затронутых Tet10, число элементов, имеющих GP в нескольких слоях, квантильные показатели узлового радиального размаха и максимального ребра между вершинами.
2. `P10Z_RADIAL_CUMULATIVE.csv`: накопленный объём и число точек при радиальных порогах 0.005, 0.01, 0.015, ..., 5 мм. Демонстрирует устойчивость к изменению границ слоя.
3. `P10Z_MESH_AUDIT_LOG.txt`: паспорт и SHA-256 самих `.msh`, объём всей сетки, расхождение Q3/Q4 в ближних слоях, длительность диагностики.

**Не нужно** посылать ни `.msh`, ни большие `.vtu`, ни результаты ранее выполненных FEM-расчётов.

## Интерпретация

1. Сравнить `qp_count` и `effective_qp_count_weight` в 0–0.02 мм для H4 и H4W2. Простое большое число точек не гарантирует разрешения быстро меняющегося поля.
2. Сравнить `integration_volume_mm3` для Q3 и Q4 на **одной** сетке. Значимая разница показывает зависимость дискретной индикаторной геометрии слоя от квадратуры, но НЕ определяет ошибку геометрической производной.
3. Сверить оба объёма с точным объёмом полной оболочки: `4π/3[(R+b)^3-(R+a)^3]`. При 0–0.02 мм эталон `0.256387470854566` мм³. Геометрическая граница, заданная криволинейными Tet10, может отличаться от идеальной сферы. Для дальних слоёв эталон применим только при полном размещении сферы внутри физического тела.
4. Сравнить `radial_node_span_p50_mm` и `corner_longest_edge_p50_mm` с толщиной слоя. Узловой радиальный размах — **диагностическая прокси-метрика**, НЕ точный радиальный размер криволинейного элемента.
5. Оценить `tet10_with_qp_in_multiple_shells`: такие элементы особенно чувствительны к положению границы и выбору правила квадратуры.
6. Построить количественную разность Q4–Q3 по слоям и по радиальным порогам. Оба правила в пределах одной и той же геометрии не меняют механическое/тепловое решение.
7. Если внутренний слой существенно меняет интегральный объём при Q3→Q4, прежде длительного H4W4B2 P10Y необходимо проверить переназначение слагаемых по слоям: геометрическая субквадратура или сглаженный радиальный фильтр. Это **отдельный методический эксперимент**, не подмена P10Y и не вычисление точной ошибки.
8. Если Q3→Q4 показывает устойчивость объёма, это полезная, но лишь **необходимая диагностическая проверка**: поле сопряжённой производной может оставаться неразрешённым, а сходимость производной НЕ доказана.

P10Z **не вычисляет** локальные функционалы, напряжения, механические сопряжённые или тепловые вклады. Он не является ни тестом сходимости FEM, ни методом локализации точной ошибки, ни переносом полей между сетками.

## Самопроверка до реальных сеток

`--selftest` проверяет: число Gauss-точек, сумму весов (=1/6), разбиение единицы Tet10, сумму производных N, Kronecker nodal interpolation, аналитический объём аффинного тетра. Синтетический файл `tests/fixture_TET10.msh` проверен: на нём Q3 отнёс 0 точек к 0–0.02 мм, Q4 — 5 точек. Это **искусственно выбранная плохо разрешённая геометрия**, демонстрация чувствительности дискретного индикатора слоя, а не свидетельство поведения H4/H4W2.

Проверка версии: файл `P10Z_MESH_AUDIT_LOG.txt` содержит SHA256 обеих сеток. Git-коммит источников следует установить на ПК отдельно через экспорт источников **PORE - 2 Export source snapshot**; скрипт P10Z не приписывает пользователю неизвестный SHA.
