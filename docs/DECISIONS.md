## D-001. Квазистатическая механика — УТВЕРЖДЕНО

Механическое равновесие без инерционных членов; термическая часть нестационарная. При переходе к быстрым процессам инициирования трещины постановку потребуется пересмотреть.

## D-002. Сравнение реологических моделей — УТВЕРЖДЕНО

В исследовательском плане присутствуют `E`, `ED`, `EDV`, а также сравнение `E_inst=CONST` и `E_inst=VAR`. Выводы о влиянии этих вариантов пока не подменять планом сравнения.

## D-003. Геометрия и три первые моды — УТВЕРЖДЕНО

Рассматриваются `R`, `tz` и `y20`; сохраняется соглашение `V_n > 0` для расширения полости. Дальнейшая цель — градиент формы без ограничения этими тремя модами.

## D-004. Исключение центральных разностей — УТВЕРЖДЕНО КАК ТРЕБОВАНИЕ

Исключить центральные конечные разности из **основного вычисления геометрических частных производных**, а по возможности и из других внутренних производных. Предпочтение — аналитическому дифференцированию дискретных МКЭ-операторов, где удобно — автоматическому. Конечные разности допускаются как независимый контроль правильности. **Реализация и её полная проверка ещё не зафиксированы как завершённые.**

## D-005. Git и удалённое хранение — ВЫПОЛНЕНО

Локальный Git в `G:\ildar\Stage3D07` и закрытый GitFlic `https://gitflic.ru/project/ildar2026/stage3d07_ice_pore.git` с веткой `master` (по логу успешной отправки пользователя). Git хранит исходники, методическую документацию и небольшие проверенные научные результаты. Он не предназначен для сотен гигабайт расчётных полей и контрольных точек.

## D-006. Архивный диск F — ВЫПОЛНЕНО

Для копий дорогостоящих расчётов и Git-архивов используется `F:` (фактически `df -h`: 2.6T общий размер, 2.1T свободно до резервирования). `F:` и `G:` находятся на **разных физических дисках** — подтверждено пользователем. Рабочая программа остаётся на `G:`. Первичная копия четырёх основных расчётных каталогов общим объёмом около 241 ГиБ и автономный полный архив Git созданы на F.

## D-007. Стратегия для крупных расчётов — ПРЕДЛОЖЕНО, ТРЕБУЕТ УТОЧНЕНИЯ

Разделять данные на категории `A` (незаменимые, обязательно архивировать), `B` (воспроизводимые, но дорогие; сохранять при наличии места) и `C` (промежуточные, не требующие обязательного архивирования). Удаление категории C не разрешено автоматически: вначале требуется инвентаризация и явное решение пользователя.

## D-008. Объём проверки первой архивной копии — РЕШЕНИЕ ПОЛЬЗОВАТЕЛЯ

При первичном резервировании данных на F пользователь подтвердил успешное завершение копирования и **решил пропустить дополнительное сравнение исходного и архивного каталогов**. Это экономит время, но оставляет неустановленной побайтовую идентичность полных массивов данных. Не путать с проверкой автономного Git bundle, которая успешно выполнена отдельно. Новые научно критичные уникальные файлы при возможности проверять SHA-256.
