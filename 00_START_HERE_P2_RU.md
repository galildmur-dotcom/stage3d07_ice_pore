# Stage 3D-06-P2 — новый решатель с оптимизированным BCSR SpMV

Дата релиза: 11.10.2026. Цель: ускорение умножения разреженной блочной матрицы механической задачи на вектор без изменений физической модели, E/ED/EDV, начальных/граничных условий и функционала j6.

## Быстрый старт на Windows / Qt Creator / MinGW

1. Распаковать **полный ZIP** в новый каталог `C:/Users/Admin/Downloads/Stage3D06P2` (не смешивать с существующим `Stage3D06P` и не перезаписывать прежние результаты).
2. Открыть в Qt Creator **файл `Stage3D06P2/CMakeLists.txt`**. Выбрать `Desktop MinGW Release` (C++20, CMake); дождаться конфигурации CMake и сборки `stage3d06_benchmark_p2_legacy`, `stage3d06_benchmark_p2_projected`, `stage3d06_compare_restart`, `stage3d06_spmv_benchmark` и их зависимостей. OpenMP включён при наличии поддержки в MinGW.
3. Для двух целей `stage3d06_benchmark_p2_legacy` и `stage3d06_benchmark_p2_projected` установить одинаковые аргументы:

   `--mesh H0 --law EDV --modulus VAR --dt 300 --tend 600 --quad 3 --threads 4 --clean`

4. Запустить сначала `stage3d06_benchmark_p2_legacy`, затем `stage3d06_benchmark_p2_projected`. Обе цели самостоятельно запускают теплопроводность и механику, затем записывают `QT_RUN_STATUS.txt` и CSV. Данные **разнесены** по каталогам:

   * `LOCAL_RUNS_OPTIMIZED/benchmark_p2_legacy/H0_dt300_q3/`
   * `LOCAL_RUNS_OPTIMIZED/benchmark_p2_projected/H0_dt300_q3/`

   Параметр `--clean` очищает только соответствующий сценарий этой цели. Не используйте его на расчётах, которые нужно сохранить.

5. Запустить `stage3d06_compare_restart` со следующими аргументами, заменив абсолютный путь к проекту на собственный:

   `--baseline "C:/Users/Admin/Downloads/Stage3D06P2/LOCAL_RUNS_OPTIMIZED/benchmark_p2_legacy/H0_dt300_q3/mechanics/EDV_VAR/restart.bin" --optimized "C:/Users/Admin/Downloads/Stage3D06P2/LOCAL_RUNS_OPTIMIZED/benchmark_p2_projected/H0_dt300_q3/mechanics/EDV_VAR/restart.bin" --output "C:/Users/Admin/Downloads/Stage3D06P2/H0_P2_COMPARE.csv" --tol 1e-6`

6. В отчёте должен появиться `overall,...,PASS`. Сравниваются заголовки и размеры checkpoint, перемещения `u`, 6 компонент `e_d` и 6 компонент `e_v` для **каждой** точки квадратуры. Компоненты обрабатываются потоково, без загрузки всего H4 в оперативную память.

7. После успешного H0 можно выполнить H4 при **одном** шаге 300 с (для обеих целей одни и те же аргументы):

   `--mesh H4 --law EDV --modulus VAR --dt 300 --tend 300 --quad 3 --threads 4 --clean`

   Результаты будут в каталогах `.../H4_dt300_q3/`. Сначала сохраняйте результаты парного теста; 144-шаговую кампанию пока не запускайте.

## Отдельная проверка масштабирования SpMV

Цель `stage3d06_spmv_benchmark` использует **настоящий граф BCSR из файла сетки**; коэффициенты внутри блоков задаются детерминированными синтетическими значениями (то есть это тест производительности ядра, **не** физический FEM-расчёт). Запуск в Qt Creator:

`--mesh "C:/Users/Admin/Downloads/Stage3D06P2/meshes/H4.msh" --threads 4 --repeats 6 --tolerance 1e-12 --csv "C:/Users/Admin/Downloads/Stage3D06P2/P2_WINDOWS_SPMV.csv"`

Повторите при 1, 2, 4 и 8 потоках, изменяя только `--threads`. После каждой серии `--csv` дописывает строку. Сравнение старого и нового ядра выполняется с одинаковым коэффициентным массивом и одинаковым вектором. Фактическую производительность Windows надо измерить на компьютере пользователя; результаты Linux — только предварительные.

## Какие исходники изменены

- `src/mechanical.cpp`: старое `mul_legacy` сохранено; добавлено `mul_projected` с сохранением порядка суммирования компонент. Для него требуется инвариант PCG: в точках Dirichlet входной вектор равен нулю. Этот инвариант обеспечен самим PCG (`b`, `r`, `z`, `p`, `u`).
- `src/spatial_reology.cpp`: параметр решателя `--spmv legacy|projected`, **по умолчанию legacy при непосредственном запуске решателя**.
- `src/qt_benchmark_p.cpp`: две отдельные цели и выходные каталоги, параметр `--spmv`. Обычная исходная цель `stage3d06_benchmark_optimized` использует projected; исходная `stage3d06_benchmark_serial` остаётся прежней.
- `tests/p2_spmv_benchmark.cpp`: прямой тест точности и пропускной способности матричного оператора.
- `tools/stage3d06_compare_restart.cpp`: потоковый C++20-компаратор полных checkpoint.
- `scripts/p2_test_h0.py`, `scripts/p2_test_all6.py`: численная регрессия FEM.
- `CMakeLists.txt`: дополнительные цели и тесты; ничего не удалено из исходной модели.

## Выполнено и измерено здесь (Linux GCC 14.2, Release, OpenMP 4 потока)

| Расчёт | P2 legacy, с | P2 projected, с | Ускорение всей механики |
|---|---:|---:|---:|
| H0, EDV_VAR, 0–300 с | 1.6045 | 1.5419 | 1.041× |
| H0, EDV_VAR, 300–600 с | 1.6400 | 1.5583 | 1.052× |
| H2, EDV_VAR, 0–300 с | 14.5475 | 12.7511 | 1.141× |

На H2 умножение BCSR SpMV: **7.5799 → 6.0134 с (1.260×)**. 1577 итераций CG в обеих версиях. `j6` отличается относительно примерно на 1.36·10⁻¹³, максимальные нормированные расхождения полного checkpoint по `u`, `e_d`, `e_v`: 2.91·10⁻¹², 1.01·10⁻⁹, 6.25·10⁻¹⁰ (**PASS** при критерии 10⁻⁶). На H0 двухшаговые checkpoint **побайтно совпали**.

В отдельном SpMV-бенчмарке на **реальном графе H4** с синтетическими коэффициентами, 4 потока Linux: **1.237×** (точное совпадение выходных векторов). На 8 потоках: **1.260×** (данный CPU не эквивалентен i7-7700K). Результаты всех сеток H0–H4 и 1/2/4/8 потоков — `P2_VERIFICATION/P2_SPMV_LINUX_H0_H4_SCALING.csv`.

Регрессия **11/11 тестов P06/P2 — PASS**, в том числе все шесть сочетаний E/ED/EDV × CONST/VAR, две версии SpMV и локальное сравнение checkpoint. Последняя попытка запуска **всего** CTest (51 тест) не завершилась из-за внешнего ограничения времени; не считать 51/51 пройденными. Проверенные новые тесты выполнились успешно.

**Ограничения:** обновлённый P2 ещё не испытывался на реальном Windows/MinGW/Intel i7-7700K пользователя; пока не измерено ускорение полной кампании H4, Δt=25 с. Это **оптимизация ядра SpMV**, а не новое физическое исследование. Никаких сопряжённых производных или текста статьи не создавалось.
