# Stage 3D-06-P — оптимизированный прямой 3D FEM-решатель

**Версия:** Stage 3D-06-P, 11.10.2026. **Тип задачи:** прямая квазистатическая E/ED/EDV, Tet10, теплопроводность Robin. **Никаких сопряжённых производных или изменений j6.**

## 1. Как открыть проект в Windows / Qt Creator

1. Распакуйте ZIP в новый каталог, не поверх предыдущего пользовательского проекта с `LOCAL_RUNS` и checkpoint.
2. Откройте `CMakeLists.txt` из каталога `Stage3D06P` в Qt Creator.
3. Выберите существующий Kit **Desktop Qt, MinGW GCC 13.1, x64** (или другой C++20 MinGW), режим **Release**. Достаточно CMake 3.20+. Qt-библиотеки для математического кода не нужны.
4. Убедитесь, что при конфигурации показано OpenMP. При отсутствии OpenMP программа остаётся работоспособной последовательной, но не ожидайте ускорения от `--threads 4`.
5. Соберите выбранную цель и нажмите **Run** (консольный запуск без PowerShell):
   - `stage3d06_benchmark_serial` — неизменённая исходная программа в самостоятельной компиляции, H0 EDV_VAR, q3, Δt=300 с, t=300 и 600 с.
   - `stage3d06_benchmark_optimized` — новая версия на **4 потоках OpenMP**, с параллельной FEM-сборкой. Та же задача.
   - `stage3d06_campaign_optimized` — свободно задаваемая длительная кампания; безопасный небольшой preset H0 по умолчанию.
6. Новые результаты автоматически появляются в `LOCAL_RUNS_OPTIMIZED/benchmark_baseline`, `.../benchmark_optimized` и `.../campaign_optimized`. **Старый `LOCAL_RUNS` не трогается.**

Любую из трёх целей можно запускать с аргументами Qt Creator Run Configuration:

```text
--mesh H1 --law EDV --modulus VAR --dt 300 --tend 600 --quad 3 --threads 4 --clean
```

Для H3/H4 полного сравнения задайте **одинаковые аргументы** для двух benchmark-целей и используйте `--clean`, чтобы не засчитать автоматически возобновлённый вместо полного прогона расчёт. `--clean` удаляет только собственную папку данного benchmark-сценария (не пользовательский `LOCAL_RUNS`). Отдельно от обычной тестовой кампании следует изучить H4 с Δt=25 с, 144 шагами и q3; короткие испытания при Δt=300 с *не заменяют* этот расчёт.

Дополнительные аргументы launcher: `--preconditioner jacobi|sgs`, `--threads 1|2|4|8`, `--assembly-serial` (отключение параллельной сборки в оптимизированном решателе), `--dry-run` (проверить входные файлы и программы без запуска), `--clean`.

## 2. Что именно оптимизировано

* **BCSR 3×3:** один раз на сетку строится неизменяемый граф и индексы `element → 100 block offsets`; коэффициенты обнуляются для каждого нового Newton-слоя. Количество элементных позиций `100 × N_Tet10`, 4 байта каждая. Нет повторного поиска `lower_bound` при сборке матрицы.
* **EDV-history:** в line search копируется только пробный вектор перемещений. Старый временной слой `e_d, e_v` доступен исключительно на чтение. История коммитится только после сходимости Newton; checkpoint сохраняет исходный формат.
* **OpenMP 1/2/4/8:** пакет из **512 элементов** интегрируется параллельно, затем локальные матрицы, силы, `j6`, `jOmega` и полярные интегралы накапливаются в исходном порядке одним потоком. Матрица не подвергается гонкам `+=`. Параллельно выполняются SpMV, block-Jacobi и крупные векторные операции PCG.
* **Предобусловливатели:** проверенный 3×3 block-Jacobi по умолчанию. Экспериментальный symmetric block Gauss–Seidel (SGS) включается явно (`--preconditioner sgs`); меньше итераций **не обязательно** означает меньше времени. Не объявлен универсальным ускорением.
* **Кеш геометрии:** опциональный `--geometry-cache on|off`, по умолчанию **off**, поскольку измерения на H0 не выявили выигрыша. Хранятся только геометрические `detJ*w`, `gradN` и физическая позиция QP (не температура, не деформация, не EDV-state).
* **Калибровка `u_z`:** геометрические массы для условия нулевого среднего `u_z` вычисляются один раз. Физические граничные условия Candidate A не изменены.

## 3. Профилирование при прямом запуске решателя

Цель `stage3d06_spatial` принимает обычные аргументы исторической версии плюс:

```text
--profile --threads 4 --optimization on --parallel-assembly on --geometry-cache off --preconditioner jacobi
```

При `--profile` появляются `profile_per_step.csv`, `profile_cg.csv` и `profile_newton.csv` в `--out`. В `profile_cg` отдельно измеряются построение предобусловливателя, его применение, SpMV, скалярные произведения и векторные операции. `profile_per_step` включает wall и CPU, RSS, Newton/CG; `graph_once_s` — разовая подготовка графа. Стадии профиля **вложенные**: времена Newton line search содержат собственную FEM-сборку и не должны суммироваться напрямую с `assembly_s`.

## 4. Научные инварианты

Сохранены: 60×60×50 мм, сфера радиуса 1 мм на z=30 мм, фиксированная B6 радиусом 6 мм; Robin только сверху; неизменные ν=0,35, α, Sinha-нормировка мгновенного `E_inst(T)` и пара CONST/VAR; ED/EDV внутренние переменные, физические величины в СИ, Tet10/Q3/Q4, Candidate A и калибровка среднего `u_z`; `j6` именно по исходной спектральной мере, той же нормировке и фиксированной области наблюдения. Не появились инерция, shape-производные или статистические усреднения GH.

## 5. Испытания и ограничения

Проверено в **Linux GCC 14.2 Release, OpenMP, 4 доступных процессорных квоты**. Подробности в `P06_VERIFICATION/`: CSV с фактически измеренными интервалами, контрольные различия, CTest-логи, контрольные суммы сеток и исходников.

**Реальная сборка/скорость под Windows/MinGW 13.1 ещё не проверена** в этом окружении. Тем не менее сохранён изолированный `win_process_memory.cpp` без включения `windows.h` в FEM-физику, поддержка Qt Creator и Win32 `CreateProcessW`. Приёмка на i7-7700K должна пройти в Qt Creator с режимами 1/2/4/8 потоков и контролем CTest.

Хронологическая база H4 с Δt=25 с содержит подтверждённую внешнюю паузу сна Windows ≈18 534 с; этот выброс **нельзя использовать** в оценке ускорения. Сравнивать независимые задачи с одинаковым `dt`, `q`, моделью, ξ и допусками, используя медиану времени шага и распределения CG.

**Зависимости:** C++20, CMake, стандартная библиотека, OpenMP опционально, Python 3 только для дополнительных автоматизированных regression/CTest scripts (не для расчёта или native Run). `baseline_serial/` — буквальная копия исходников HANDOFF от 11.10.2026, не патченная.
