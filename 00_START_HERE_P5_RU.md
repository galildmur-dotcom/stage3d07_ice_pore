# Stage 3D-06-P5 — Additive Schwarz AS0/AS1 (C++20 / Qt Creator)

**Статус:** исследовательская версия, созданная поверх полного Stage3D06P4 без изменения физической модели. Ядро собрано GCC 14.2 Release на Linux c OpenMP и без OpenMP; тесты P5 пройдены; H0/H2 проверены на Linux. **Windows/MinGW требуется проверить локально; ускорение относительно Jacobi на H0/H2 не подтверждено.**

## 1. Что изменено

- `src/p5_schwarz.hpp` — одноступенчатый *аддитивный* метод Шварца для узловых блоков BCSR 3×3. Построение непересекающихся ядер связными BFS-кластерами (по умолчанию максимум 32 узла). Случай `as0` использует только ядра; `as1` расширяет каждое ядро на **все** соседние узлы по графу BCSR (один слой перекрытия).
- Внутри каждой подобласти используется локальный **Block IC(0)** из проверенного P4. Это **приближённое** подпространственное решение, а не точный локальный метод Холецкого. Предобусловливатель имеет вид `B = Σ R_s^T B_s R_s`, где `B_s` — симметричная положительно определённая обратная аппроксимация локального оператора. Веса перекрытия не используются, поэтому симметрия PCG сохраняется.
- Симметрическое исключение закреплённых DOF, положительные локальные опорные блоки, детерминированный порядок сборки поправки без atomic, независимые OpenMP-факторизации и применения.
- Топология разбиения кэшируется один раз при построении оптимизированной матрицы; коэффициенты локальных IC(0) пересчитываются при новой матрице Ньютона. Удерживается прежняя физика: E/ED/EDV, E(T), Tet10, теплопроводность, `Psi6`, условия закрепления, формат checkpoint и функции постобработки.
- `--preconditioner as0|as1`, `--schwarz-core 32` (1..1024); Jacobi/SGS/MC-SGS/MC-SGS-fast/IC(0) сохранены.

## 2. Первые действия в Qt Creator под Windows

1. Распакуйте *всю папку* `Stage3D06P5` в удобное расположение, например `C:\\Users\\Admin\\Downloads\\Stage3D06P5`. Не накладывайте архив поверх P4.
2. В Qt Creator откройте `Stage3D06P5/CMakeLists.txt`, выберите **MinGW 64-bit Release**, убедитесь, что `STAGE3D06P_OPENMP=ON` и OpenMP найден; при недоступности OpenMP можно собрать с `STAGE3D06P_OPENMP=OFF` (тогда P5 работает последовательно).
3. Соберите цель **`stage3d06_p5_qt_H0_as0`**. Эта цель подтянет `stage3d02_thermal` и `stage3d06_spatial`.
4. Запустите `stage3d06_p5_qt_H0_as0` **без дополнительных аргументов**. Это EDV/VAR, H0, Δt=300 c, t=300 c, квадратура 3, `as0`, core=32, `projected`, OpenMP 4 потока (если поддерживается). Генерация температурного поля и FEM выполняются автоматически.
5. Путь результата: `LOCAL_RUNS_OPTIMIZED/benchmark_p5_as0/H0_dt300_q3/` относительно каталога исходного проекта.
6. Если хотите дополнительно проверить вариант с перекрытием, выберите `stage3d06_p5_qt_H0_as1` без аргументов. Отдельный каталог `benchmark_p5_as1` не затрагивает предыдущие результаты.

Пришлите **только** четыре файла из папки `benchmark_p5_as0/H0_dt300_q3`:
`QT_RUN_STATUS.txt`, `mechanics/profile_cg.csv`, `mechanics/profile_per_step.csv`, `mechanics/G06_campaign.csv`.

Для прямого сравнения на Windows целесообразно запустить **уже существующую** цель `stage3d06_benchmark_p2_projected` со старыми параметрами и прислать аналогичные CSV только при необходимости; ранее этот контроль уже был получен.

### Аргументы для запуска через Qt Creator (не требуются для первого запуска)

- `--threads 4 --clean` — повторный прогон на четырёх потоках; **`--clean` удалит предыдущие результаты текущего сценария P5**, но не P2/P3/P4.
- `--threads 1 --clean` — тест одного потока.
- `--schwarz-core 16 --clean` — эксперимент с числом узлов ядра. Нельзя продолжать `--resume` при смене типа предобусловливателя или параметров в одном выходном каталоге, если цель — независимый замер времени. Повторный прогон выполнять с `--clean`.

## 3. Что установлено тестами, а что нет

Фактически выполнено на Linux GCC Release/OpenMP (четыре потока):

- 5 самостоятельных CTest проверок P5 — PASS: разбиение/покрытие, симметрия/положительная определённость, смешанные Dirichlet-DOF, 1/4 потока, PCG на искусственной SPD-матрице.
- 2 `--dry-run` теста Qt-лаунчеров — PASS. Аналогичные 7 тестов прошли при сборке **без OpenMP**.
- Полная регрессия H0 `Jacobi` против `AS0` и `AS1`: **6 из 6 сочетаний E/ED/EDV × CONST/VAR**, включая проверку checkpoint по `u`, `ed`, `ev` с порогом нормированного расхождения 1e-6 — PASS.
- H2 EDV/VAR: Jacobi vs AS0, тот же тепловой ввод, 4 потока, checkpoint (u, ed, ev) с порогом 1e-6 — PASS.

Скорость и масштабирование: смотрите `P5_VERIFICATION/P5_LINUX_RESULTS.csv`, полный журнал `P5_VERIFICATION/H0_ALL6_REGRESSION.log` и `P5_VERIFICATION/H2_CHECKPOINT.csv`.

**Итог:** сокращение итераций PCG пока не превращается в ускорение полного механического шага. На проверенных H0 и H2 быстрее Jacobi. Для производственных H3/H4 **оставить P2/Jacobi**. `AS1` на H2/H4 и Windows/MinGW до этого выпуска не проверялись.

## 4. Ограничения

1. Это одноуровневый аддитивный Шварц с **локальным IC(0)**. Это не глобальный многоуровневый метод, не гибрид с грубосеточной коррекцией и не точный локальный Cholesky. Теоретическую сеточно-независимую сходимость здесь не заявляем.
2. Перекрытие может дорого обходиться по памяти: локальные копии коэффициентов и факторов IC(0), независимые буферы; для H4 AS1 не рекомендован.
3. Измерения Linux и Windows нельзя смешивать в одну скорость: важно сравнивать на одной машине и с одинаковыми опциями.
4. Применение Шварца предполагает SPD после корректного наложения механических граничных условий; при неположительном локальном опорном блоке выбрасывается ошибка P4 IC0, автоматического сокрытия ошибки не предусмотрено.
5. Полный набор прежних целей/тестов сохраняется; старые исходные файлы в `baseline_serial/` не изменены. В P5 добавлены только новый код предобусловливателя, выбор метода в решателе, CMake/Qt-цели и тесты.
