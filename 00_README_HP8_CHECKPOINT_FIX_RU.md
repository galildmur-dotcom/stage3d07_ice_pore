# Stage 3D-09D5. Исправление записи контрольных файлов HP8 в Windows MinGW

## Диагноз
Журнал HP8: `stage3d06_spatial` завершил Newton/CG, создал VTU, затем остановился на `restart.bin.part` размером 2,8906 ГиБ. За 60 с размер не изменился, а CPU увеличился на 60,2 с (одно ядро полностью занято). В `src/spatial_reology.cpp` найден вызов `std::ofstream::write` на весь EDV state (~6,8 GiB) за один раз. Это вероятная проблема библиотеки MinGW при больших длинах I/O; не является окончательным стековым диагнозом.

## Исправление
В `src/checkpoint_chunked_io.hpp` добавлена порционная запись и чтение блоками 16 МиБ. Бинарный формат, порядок байтов, заголовок, контроль сигнатуры сетки и внутренние переменные EDV не изменены. Вывод прогресса каждые ~512 МиБ массива EDV. Добавлен независимый тест `stage3d09d5_checkpoint_test`, режим `--large` проверяет более 3 ГиБ на диске без расчёта FEM и удаляет созданный тестовый файл после завершения.

## Установка
1. Прервать прежний зависший запуск через Qt Creator Stop. Убедиться, что процесс `stage3d06_spatial.exe` отсутствует. Не считать `restart.bin.part` полноценным рестартом.
2. Распаковать PATCH в `C:\Users\Admin\Downloads\` поверх текущего `Stage3D07`. Не удалять `LOCAL_RUNS`.
3. В Qt Creator — Reconfigure CMake, Desktop MinGW Release; собрать цели `stage3d09d5_checkpoint_test`, `stage3d06_spatial`, `stage3d09c_shape_three`.
4. Проверить I/O: цель `stage3d09d5_checkpoint_test`, аргументы `--large --out C:\Users\Admin\Downloads\P09D5_IO_CHECK.bin`. Ожидается `P09D5_IO_TEST_OK bytes=3288334336 large=1`. Тест запишет и проверит >3 ГиБ, затем удалит файл. Сначала можно выполнить `--small`.
5. При успешном тесте дальнейший расчёт HP8 проводить с учётом того, что прежняя полная программа всё равно запустит шесть траекторий и сформирует примерно 7-ГиБ checkpoint на каждую; исходный пилот не завершился, его первая механическая задача потребуется заново.

## Важно
Не удалять все `LOCAL_RUNS`. Уже сохранённые истории первого механического шага пригодны для анализа, но без готового `restart.bin` запускатель не считает траекторию завершённой. Логическую корректность исправления проверяем малым и большим тестами. Требуется реальная проверка `--large` на Windows MinGW; Linux-сборка не равна Windows-тесту.
