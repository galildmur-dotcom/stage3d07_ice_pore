# Stage 3D-08D — стохастическая чувствительность функционала j6 (GH3)

**Дата:** 20 октября 2026 г. **База:** проверенный Stage 3D-08C; C++20/CMake, Qt Creator + Windows MinGW Release.

## Содержание обновления

Добавлен **новый исполняемый файл `stage3d08d_H0_gh3`**, который запускает неизменённые `stage3d08_geometry`, `stage3d02_thermal`, `stage3d06_spatial`. Геометрические моды: `R` (расширение радиуса поры), `tz` (вертикальный перенос центра), `y20` (осесимметричная сферическая гармоника Y20, нормированная как в P08C). При генерации сохраняются исходные внешние границы, B6 и Tet10-топология. Модель EDV/VAR, пространственная квадратура q3, dt=300 с, t_f=3600 с, амплитуда δ=5 мкм — по умолчанию.

Тепловая граничная нагрузка взята **без изменений** из `thermal.cpp`: `T_amb(t, ξ) - T0 = -3(1-exp(-t/300)) + 0.48 ξ` (K); ξ~N(0,1) — одна случайная величина, постоянная на каждой траектории. В `stage3d02_thermal` уже был аргумент `--xi`, но прежнее `--quad 3` обозначало **пространственное интегрирование**, а не GH3.

Узлы GH3 для **стандартного нормального закона**: `ξ=(-sqrt(3),0,+sqrt(3))`, вероятностные веса `(1/6,2/3,1/6)`. На каждом узле и для каждой моды используются `j_k(+δ)`, `j_k(-δ)` из новых/повторно используемых связных термомеханических расчётов. Каждый j_k — трапецеидальный интеграл Psi6 по времени, с Psi6(0)=7.5e-7, делённый на t_f, идентично Stage 3D-08C.

Сначала считаются `M_±=Σ w_k j_k(±δ)`, `V_±=Σ w_k (j_k(±δ)-M_±)²` (дисперсия без вычитания близких вторых моментов). Производные центральные: `D M=(M_+-M_-)/(2δ)`, `D V=(V_+-V_-)/(2δ)`. Эквивалентная устойчивая формула для D V: `2 Σ w_k (j_mid,k-M_mid) (D j_k-D M)`, где `j_mid,k=(j_k(+δ)+j_k(-δ))/2`; именно она используется, вторая проверяется на машинную точность. Величины `M_mid`, `V_mid` — **средние по двум возмущённым геометриям**, а не отдельные точные значения на исходной геометрии; отличие от номинальных моментов имеет порядок O(δ²). Для центральных производных **не нужны дополнительные три расчёта номинальной геометрии**.

Всего при δ=5 мкм: **18** траекторий FEM (3 моды × 2 знака × 3 узла GH). Если в прежних `LOCAL_RUNS` есть шесть полных и совместимых траекторий при ξ=0 из Stage 3D-08A/08C, они читаются без пересчёта и новых FEM-траекторий потребуется **12**. Иначе автоматически рассчитываются недостающие случаи; при необходимости можно потребовать наследование с `--reuse-xi0 require` либо запретить `--reuse-xi0 off`.

## Установка в существующий проект Windows / Qt Creator

1. Закройте Qt Creator. Для **существующего проекта** распакуйте **PATCH**-архив с папкой `Stage3D07` поверх `C:\Users\Admin\Downloads\Stage3D07`, сохранив все имеющиеся `LOCAL_RUNS`, `meshes` и другие данные. Подтвердите замену только `CMakeLists.txt`; новое `src/stage3d08d_gh3.cpp` и два отчётных Markdown/CSV-файла добавляются. Для чистой установки вместо этого используйте FULL-архив.
2. Откройте `Stage3D07/CMakeLists.txt` в Qt Creator, выберите **Desktop MinGW Release**, выполните переконфигурацию CMake.
3. Соберите/запустите **ровно одну цель** `stage3d08d_H0_gh3`. **Аргументы: пусто**. По умолчанию H0, q3, dt=300, t_f=3600, delta=5 мкм, EDV/VAR, все три моды, 4 потока (1 при сборке без OpenMP). Не запускайте одновременно несколько дорогостоящих решателей. Убедитесь, что Windows не переходит в спящий режим.
4. После окончания пришлите **4 небольших файла** из:

   `Stage3D07/LOCAL_RUNS/SHAPE_STAGE08/P08D/H0_dt300_q3_t3600_EDV_VAR_cutoff5p000mm_delta5p000um_modesR-tz-y20/`

   - `P08D_STATUS.txt` — должен содержать `status=SUCCESS`;
   - `P08D_SENSITIVITIES.csv` — итоговые производные математического ожидания/дисперсии по трём модам;
   - `P08D_NODES.csv` — значения j(+δ), j(-δ) и D j по трём GH-узлам;
   - `P08D_SAMPLES.csv` — контроль 18 траекторий с указанием источников (`EXTERNAL_XI0` или `LOCAL_FEM`).

**Не нужно пересылать** VTU, `.msh`, `restart.bin` или архивировать `LOCAL_RUNS`. При ошибке вместо этих файлов пришлите небольшой участок вывода Qt Creator с `P08D_ERROR` и, если есть, `P08D_STATUS.txt`. Незавершённые расчёты не удаляйте, обычный повторный запуск продолжает их по проверенным готовым ветвям. Не удаляйте существующие Stage 3D-08A/08C результаты.

## Дополнительные точные аргументы

- Быстрая проверка параметров без записей: `--dry-run`.
- Только повторная проверка завершённых результатов (без запуска FEM): `--report-only`.
- Требовать шесть пригодных старых ξ=0 траекторий: `--reuse-xi0 require`.
- Раздельный расчёт одной моды: `--modes y20` (в таком случае отдельная директория результатов; аргументы обязательно совпадают с выбранными экспериментом).
- Исследование H2: `--mesh H2 --modes R,tz,y20 --dt 300 --tend 3600 --quad 3 --delta-um 5 --threads 4`.
- Проверка математического ядра без FEM: `--selftest`.

При несовпадении хэшей сеток, `P08_SOURCE_GUARD.txt`, dt/t_f/ξ, числа временных шагов или механического checkpoint **чужой ξ=0 результат не наследуется**. Режим `auto` рассчитывает несовместимую ветвь самостоятельно; `require` завершает работу с ошибкой без перезаписи чужих данных. Повторно проверяются и локально сохранённые вычисления. Каталог Stage 3D-08D отделён от прежних этапов. Опция `--clean` отсутствует намеренно.

## Чего результаты пока не доказывают

Трёхузловая GH3 — приближение вероятностного интеграла; точна для полиномов ξ степени ≤5, но нелинейный j6(ξ) может потребовать проверки порядком квадратуры. Геометрическая центральная разность имеет формальную погрешность O(δ²) при достаточной гладкости. Численные результаты не являются дискретными сопряжёнными производными, полной оценкой погрешностей или доказательством сходимости по сетке / времени / числу стохастических узлов. Испытания H0 при t_f=300 с в `P08D_VERIFICATION/` — **только интеграционный тест**, не результат статьи при 3600 с. Windows MinGW проверяется на вашем компьютере.

**После получения H0 GH3 за 3600 с:** сопоставить D j(ξ=0) с P08A/08C при строго одинаковых H и dt, повторить ограниченный расчёт для H2/H3, проанализировать чувствительность к δ и допускам CG/Newton, затем оценить GH3 vs GH5 на выбранных контрольных случаях; H4 запускать лишь по необходимости.
