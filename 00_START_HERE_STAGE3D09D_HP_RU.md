# Stage 3D-09D — локальная уточнённая сетка HP у сферической поры

## Зачем

На H2→H3→H4 геометрическая производная `jpeak(p=8)` по моде `y20` меняется на 40+% за переход, хотя `j6` и `jen` существенно стабильнее. Изменение δ=5→10 мкм дало <0.01% для `jpeak`. Нужен *контролируемый* опыт именно по локальному разрешению около поверхности поры.

## Геометрия HP

`gmsh/sphere_pore_HP_local.geo`: неизменны внешняя коробка, точная сфера R=1 мм, фиксированная внутренняя граница B6 (6 мм), материалы, поверхностные теги 2–9, Tet10, MSH2.2 ASCII. Сохранено прежнее фоновое поле H3. В дополнение вводится локальная зона: размер на стенке 0.085 мм (H3:0.190; H4:0.135), на расстояниях до 0.30 мм от стенки — 0.085 мм; далее плавное увеличение. Примерно с 0.70 мм от стенки фоновое поле в точности возвращается к параметрам H3 (поле HP больше H3, используется их минимум). Параметр `localEnd=0.015 м` здесь служит для задания наклона поля, а не ширины зоны сгущения. Эти *заданные* размеры не тождественны действительной длине ребра.

## Генерация в Windows (Gmsh уже установлен)

1. Откройте `Stage3D07/gmsh/sphere_pore_HP_local.geo` в Gmsh. Нажмите **Mesh → 3D**, затем **File → Export** и сохраните **Gmsh MSH version 2 ASCII, Tet10** в `Stage3D07/meshes/HP.msh`. Надёжнее (если Gmsh есть в PATH) в командной строке запустить `Stage3D07/gmsh/GENERATE_HP.cmd`. Если gmsh.exe в PATH нет, передайте полный путь первым аргументом: `GENERATE_HP.cmd "C:\Program Files\gmsh\gmsh.exe"` (замените путь на фактический).
2. **Не переименовывайте H3 или H4 в HP.** Нужна заново сгенерированная сетка из HP-геометрии. Старые файлы не изменяются.
3. Проверка размера/тегов, если Python + NumPy доступны: `python tools/inspect_pore_mesh.py meshes/H3.msh meshes/H4.msh meshes/HP.msh --out LOCAL_RUNS/HP_MESH_CHECK.json` из корня Stage3D07. Требуется `MSH_PORE_SURFACE_AUDIT_OK`. Проверка проверяет реальные грани, а не только параметры Gmsh. Даже если Python недоступен, FEM-геометрия проходит полный Tet10-контроль в `stage3d08_geometry` при запуске 09C.

## Исследовательский запуск Qt Creator

**Цель:** `stage3d09c_shape_three` (она обновлена патчем; пере-собрать Release). Аргументы:

```text
--mesh HP --modes y20 --laws EDV --moduli VAR --dt 300 --tend 3600 --quad 3 --peak-p 8 --delta-um 5 --cutoff-mm 5 --threads 4 --reuse-p08d off
```

Будут рассчитаны три GH3-узла для двух знаков δ, по 12 шагов, 6 тепловых и 6 механических траекторий. Старые тепловые P08D/H3/H4 *не могут быть использованы*: на HP другая топология, координаты и матрицы. Для корректного сравнения `--reuse-p08d off` обязателен. Во время генерации возмущений `stage3d08_geometry` проверяет положительность детерминантов квадратичных Tet10 и неподвижность B6/внешних границ.

**Файлы для анализа:** только `P09C_STATUS.txt`, `P09C_NODES.csv`, `P09C_SENSITIVITIES.csv`, `P09C_SAMPLES.csv` из
`LOCAL_RUNS/SHAPE_STAGE09/P09C/HP_dt300_q3_t3600_GH3_p8_delta5p000um_modesy20_lawsEDV_EVAR/`.

После получения можно выполнить независимую проверку:

```text
python tools/audit_HP_results.py LOCAL_RUNS/SHAPE_STAGE09/P09C/HP_dt300_q3_t3600_GH3_p8_delta5p000um_modesy20_lawsEDV_EVAR
```

## Что утверждать нельзя

До получения результатов HP нельзя заявлять об устранении сеточной зависимости. Даже после HP, один дополнительный расчёт даст качественный контроль, но не гарантирует сходимость к непрерывной производной. Следует отдельно проверить зависимости от р-нормы, интегрирования B6, радиальных слоёв и корректности переноса деформации, если производные остаются нестабильными.
