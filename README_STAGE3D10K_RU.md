# Stage 3D-10K — проверка производной формы на настоящей сетке H0

**Назначение.** Проверить на полной квадратичной сетке H0 и реальной
термомеханической истории согласование трёх геометрических производных:
`j6`, `jpeak` (p=8), `jen` (контрольная плотность энергии). Механика —
квазистатическая EDV_VAR, геометрическое направление `y20`, тепловая история
`xi=0` по 300 секунд, область наблюдения — **B6**.

Это переходная проверка **гибридной** производной: в механике применяется
дискретный сопряжённый метод с полной историей `e_d`, `e_v`, а зависимость
температуры от геометрии находится двумя *независимыми нестационарными*
тепловыми расчётами на возмущённых сетках. **Аналитический сопряжённый
градиент тепловой задачи пока не реализован.** Результаты не являются
полной GH3-кампанией, доказательством пространственной сходимости
градиента или окончательной оценкой физического порога разрушения льда.

## Установка в существующий проект `G:\ildar\Stage3D07`

1. Сохранить текущие исходники и не удалять существующие CMake-цели.
2. Скопировать `src/stage3d10k_h0_coupled_pilot.cpp` в `src/` проекта.
3. Дописать текст `PATCH_CMAKE_Stage3D10K.txt` в конец `CMakeLists.txt`.
4. В Qt Creator выполнить **Configure**, затем собрать только цель
   `stage3d10k_h0_coupled_pilot` в `Desktop_MinGW_Release`.
5. Цель предполагает уже установленные P10H/P10I, `stage3d08_geometry`,
   `stage3d02_thermal` и исходную H0-сетку с физической границей B6.

## Запуск в Qt Creator

**Цель:** `stage3d10k_h0_coupled_pilot`.

Начать с проверки регрессии: аргумент `--selftest`, без расчёта H0.
Для основного трёхшагового теста задать **Arguments**:

```
--mesh G:/ildar/Stage3D07/meshes/H0.msh --out G:/ildar/Stage3D07/LOCAL_RUNS/P10K_H0_y20_3step_20261106 --steps 3 --dt 300 --mode y20 --delta-um 5 --threads 4
```

Если пользовательский `H0.msh` расположен не в `meshes/`, укажите полный путь
к реальному файлу, подтверждённому успешным P10J. Выходная папка **не должна
существовать** до запуска: программа преднамеренно не перезаписывает результаты.

**Оценка на i7-7700K, 64 ГБ:** 5–15 минут на трёхшаговую проверку,
для 12 шагов ориентировочно 15–60 минут; это предварительный диапазон,
зависящий от конфигурации MinGW, OpenMP и Windows. Использовать 4 потока.
Обычно память порядка 1–3 ГБ на H0, но это оценка, не измерение на Windows.
VTU не создаются. Контрольные снимки состояния EDV порядка 19 МБ каждый.

## Что прислать для проверки

1. Последнюю строку `P10K_H0_HYBRID_OK` либо `P10K_H0_HYBRID_FAIL`
   из Application Output Qt Creator.
2. `G:/ildar/Stage3D07/LOCAL_RUNS/P10K_H0_y20_3step_20261106/P10K_H0_COUPLED_CHECK.csv`.
3. Если запуск не прошёл: 10–20 последних строк Application Output.

Не требуется посылать сетки, все временные папки, файлы history/checkpoint,
полный каталог `build`, большие VTU или исходные 200 ГБ результатов.

## Смысл численной проверки

Для `m in {R,tz,y20}` и отклонения `delta` программа решает на исходной
геометрии и на двух соседних геометриях тепловую, затем механическую историю:

```
H0 -> T0(t) -> EDV_VAR nonlinear_step -> j0
H0+delta*m -> T+(t) -> EDV_VAR nonlinear_step -> j+
H0-delta*m -> T-(t) -> EDV_VAR nonlinear_step -> j-
```

Потом механический адъюнкт (с памятью внутренних переменных) даёт
`mechanical_partial_per_m` при фиксированной температурной истории;
`thermal_chain_per_m` учитывает `dT/ds` из полной тепловой истории
разностей; их сумма сравнивается с `(j+ - j-)/(2delta)`.
Численная производная имеет единицы «единицы функционала на метр».
Контроль состояния через P10H: checkpoint -> replay проверяется побитно.

Два ключевых условия точности: интегрирование `j` по **B6**, а также
использование **точно того же вертикального pin**, что и в production-
механике; дополнительное закрепление приводит к ложной производной.

## Статус

Локально проверено H0 при `delta = 5 µm`:

| Шаги Δt=300 c | Ошибка j6 | Ошибка jpeak | Ошибка jen | Невязка адъюнкта |
|---|---:|---:|---:|---:|
| 1 | 4.85e-5 | 7.12e-4 | 1.05e-4 | 9.67e-9 |
| 3 | 1.52e-4 | 1.43e-3 | 1.13e-4 | 3.70e-7 |

Паритет функционалов по B6 — на уровне 1e-14; replay механической истории
побитный. Условие `P10K_H0_HYBRID_OK` для этой диагностической проверки:
максимальная относительная ошибка трёх производных менее 0,5 %, невязка
адъюнкта менее 1e-5. Это *численные рабочие допуски для H0-пилота*;
для научной статьи нужны независимые проверки при уменьшении пространственного
и временного шагов и полноценная тепловая сопряжённая задача.
